<Callout title="New connections: we watch the first order">
  Ebda Store builds each provider from the provider's official documentation, and your own account is
  what proves it works. When you save your keys we check them straight away. The first real payment through a
  provider is watched by the Ebda Store team, so if anything is off we see it immediately and fix it.
</Callout>

## What is available

[Cash on delivery](/en/orders-and-cod/) and [InstaPay](/en/instapay/) (confirmed by hand) work without any account. Paymob, Kashier and FawryPay work with your own account, as described below.

## How connecting works

You use your OWN account with the payment company: the money goes to you, not to Ebda Store. Connecting is
only a credentials step in **Settings > Payments**:

1. Open the provider's card and pick **Sandbox** (test) or **Live**. Each mode keeps its own keys, so
   test keys never reach the live system.
2. Paste each value. Every field has a **Where do I find this?** link that opens the exact page in the
   provider's dashboard. Secret keys are saved encrypted and are never shown again: the page only
   shows "Saved ••••" and the last 4 characters.
3. Press **Save**. Ebda Store immediately makes one harmless call to the provider with your keys (the mode
   you just saved, Sandbox first); nothing is charged. You see one of: **Connected**, **Credentials
   wrong** (the provider refused them: check and save again) or **Provider not reachable** (your keys are
   saved; press **Test connection** again in a few minutes). A provider that has no safe test call is
   marked **unverified**: it still connects, and your first real order confirms it.
4. Once the check passes, switch the provider **on**. Changing a key later turns it off until it is
   checked again (press **Test connection** to re-run the check any time).
5. Copy the **webhook URL** shown on the card where the card asks you to (see below). That is how the
   provider tells your store a payment succeeded.

## Paymob

- **Secret key, Public key, API key:** Paymob dashboard > Settings > API Keys (under Developers) >
  View. Test keys start with `sk_test_` / `pk_test_`, live keys with `sk_live_` / `pk_live_`. The API
  key is the same in both modes.
- **HMAC secret:** shown next to your API keys in Paymob's settings. If you cannot see it, ask your
  Paymob account manager.
- **Integration IDs:** Settings > Payment Integrations, the "Integration ID" column. Enter one per
  payment method you want (cards, wallets, valU, kiosk, Apple Pay). Test and live integrations have
  different IDs. Apple Pay has live IDs only.
- **Webhook:** paste the webhook URL into the **Webhook URL** of every integration you entered
  (Payment Integrations > the integration > Edit > Save Changes).
- Kiosk payments cannot be refunded through Paymob.

## Kashier

- **Merchant ID (MID):** under your user name in the top bar of the Kashier dashboard (looks like
  `MID-1234-567`).
- **Payment API key** and **Secret key:** Kashier dashboard > Integrations. Switch "It's live data" on
  to see the live keys; test keys only work in Sandbox.
- The Kashier user who created the secret key needs the refund permission for refunds to work.
- **Webhook:** nothing to paste. Ebda Store sends the URL with every payment.
- **Every Kashier notification is double-checked.** Before a Kashier notification marks an order paid or
  records a refund, Ebda Store asks Kashier directly what that transaction really is, and only Kashier's answer
  is used. If Kashier cannot be reached, nothing changes yet and Ebda Store tries again a little later; the
  order page's payment events show each check.

## FawryPay

- **Merchant code** and **Secure key:** the FawryPay team sends them by email when your account is set
  up (staging and production values differ). For a test account, register at FawryPay's staging
  site; FawryPay contacts you to activate it. Using your real account straight away is fine too.
- **Webhook:** send the webhook URL to the FawryPay team as your notification (callback) URL.

## Geidea

<Callout title="Limited for now: unverified">
  Geidea is connected from its published documentation only, and it is **not shown to your customers at checkout yet** (you can connect it, it shows "Pending verification", and we switch it on for your store once Geidea confirms how its notifications work). Ebda Store can create a Geidea payment session for a
  customer, but Geidea has not published how it signs its payment notifications, so Ebda Store does **not** accept
  Geidea notifications yet and does not confirm a Geidea payment by itself. Confirm those orders by checking your
  Geidea dashboard until this is finished. Refunds are made from the Geidea dashboard.
</Callout>

- **Merchant public key** and **API password:** Geidea merchant dashboard > Settings > API credentials (test and
  live values differ). There is no safe test call, so saving keys shows "unverified" and the first real order
  is what proves the connection.
- **Webhook:** nothing to paste yet.

## Need another provider?

Ebda Store supports Paymob, Kashier, FawryPay and Geidea, plus cash on delivery and InstaPay. If you need another
payment or shipping company, use the **Tell us** link at the bottom of the Payments page.
