When you change the link of a product, a category or a blog post, Ebda Store makes an **automatic redirect** from the old link to the new one. So anyone holding the old link (from Google or from a message already sent) reaches the right page instead of a page that does not exist. You do not create these yourself: they are always made automatically, and you can see and delete them. The page is for the store owner only.

## Open the redirects

1. From **Settings** open the **Google visibility** card.
2. Press **Open redirects**. The **Slug Redirects** page opens.

## What you will see

A table with **From** (the old link), **To** (the new link), **Type** (product, category or blog post) and **Created**. Use **Search** to look up the old or new link. If there are many redirects you see the newest and press **Load more**.

If you have not changed any link yet you see "No redirects yet. They are created automatically when you rename a product, category, or blog post slug."

## Delete a redirect

Press **Delete** next to the redirect, then **Delete the redirect**. The old link stops sending visitors to the new one at once, and they land on a page that does not exist. The page cannot undo a delete. The feature needs a paid plan.

## When to delete one

- If a redirect was made by mistake (for example from a bulk product import).
- If you want to use the old link for something new. Also, if you give a new link back the name an old one had, the old redirect is removed by itself so the link opens the current page.

## Common questions

**I changed a product link and the old link gives a 404.** Open the page and search for the old link. If it is not there, the redirect was deleted, or the old link was not the product's link when you changed it.

**Can I create a redirect by hand?** No. Redirects are made when a product, category or post link changes, and the page is only for viewing and deleting.

**Do I have to fix chains of redirects?** No: if a link changed more than once, the redirect points to the current link directly.
