يستطيع ابدأ ستور إرسال طلب HTTPS من نوع `POST` إلى خادمك كلما تغيّر طلب أو منتج. هذه الصفحة عن الويب هوكس التي يرسلها ابدأ ستور **إليك**. أما ويب هوكس الدفع والاشتراكات التي يستقبلها ابدأ ستور فراجع [الويب هوكس](/ar/webhooks/).

الويب هوكس مشمولة في باقتي **Growth** و**Business**. أدِر النقاط من لوحة التحكم تحت **Settings, Webhooks** (لمالك المتجر فقط).

## قواعد النقطة

- HTTPS على المنفذ 443 فقط. ممنوع وجود بيانات اعتماد في الرابط، وممنوع عناوين IP، وممنوعة أسماء `localhost` و`.local` و`.internal`.
- يُحَل الاسم عند حفظه **وقبل كل إرسال مرة أخرى**. وإذا كان أي عنوان يُحَل إليه خاصاً أو loopback أو link-local (ومنه عنوان بيانات السحابة الوصفية) أو CGNAT أو غير عام بأي شكل، فلا يُرسَل الحدث.
- التحويلات **لا تُتَّبع**. استجابة `3xx` تُحتسب إرسالاً فاشلاً، لذا سجّل الرابط النهائي.
- أجب بأي `2xx` خلال **10 ثوانٍ**، وأجِّل الأعمال البطيئة إلى ما بعد الرد.

## الأحداث

| النوع                  | يُرسَل عندما                                                                                                |
| ---------------------- | ----------------------------------------------------------------------------------------------------------- |
| `order.created`        | يُنشأ طلب (دفع عند الاستلام) أو يكتمل دفعه الإلكتروني                                                       |
| `order.paid`           | يكون الطلب مدفوعاً بالفعل لحظة الإعلان عنه                                                                  |
| `order.status_changed` | تصبح حالة الطلب `shipped` أو `delivered` أو `cancelled`                                                     |
| `order.refunded`       | يُسترد مبلغ الطلب (`refund.partial` يخبرك إن كان الاسترداد جزئياً)                                          |
| `product.created`      | يُضاف منتج                                                                                                  |
| `product.updated`      | يُعدَّل منتج (`changedFields` يسرد ما تغيّر)                                                                |
| `product.deleted`      | يُحذف منتج                                                                                                  |
| `inventory.low`        | يتجاوز منتج حد المخزون المنخفض (للمتاجر المفعّل فيها تنبيهات المخزون؛ مرة واحدة كحد أقصى لكل منتج في اليوم) |
| `webhook.test`         | ضغطت **Send test event**                                                                                    |

طلب الدفع عند الاستلام يُدفع لاحقاً؛ تابعه عبر `order.status_changed`.

### البيانات الشخصية

لا تحمل الـ payloads بيانات العملاء افتراضياً. وإذا فعّلت **Include customer name, email and phone** لنقطة ما، تحصل أحداث الطلبات على `data.customer = { name, email, phone }` لتلك النقطة وحدها. وعندها تصبح أنت المتحكّم في تلك النسخة؛ ويحتفظ ابدأ ستور بسجل الإرسال 30 يوماً.

## التحقق من التوقيع

الهيدر `X-Ebda-Signature` بصيغة `t=<unix seconds>,v1=<hex>`، حيث `v1` هو HMAC-SHA256 بمفتاح سر نقطتك (`whsec_…`) على النص `<t>.<raw request body>`.

1. اقرأ بايتات الـ body **الخام** قبل أي تحليل JSON.
2. أعد حساب الـ HMAC وقارن بزمن ثابت.
3. ارفض الطلب إذا اختلف `t` عن ساعتك بأكثر من **5 دقائق** (نافذة منع إعادة التشغيل).
4. استخدم `id` (وهو أيضاً الهيدر `X-Ebda-Event-Id`) كمفتاح منع تكرار: فإعادة المحاولة، أو إعادة الإرسال، أو إعادة إرسال داخلية لنفس الحدث (مثلاً بعد callback دفع متأخر) تحمل **نفس** معرّف الحدث، فمنع التكرار عليه آمن.

```js
import { createHmac, timingSafeEqual } from 'node:crypto';

export function verifyEbdaWebhook(secret, rawBody, header, toleranceSec = 300) {
  const m = /^t=(\d+),v1=([0-9a-f]{64})$/.exec(header ?? '');
  if (!m) return false;
  const t = Number(m[1]);
  if (Math.abs(Date.now() / 1000 - t) > toleranceSec) return false;
  const expected = createHmac('sha256', secret).update(`${t}.${rawBody}`).digest();
  return timingSafeEqual(expected, Buffer.from(m[2], 'hex'));
}

```

يظهر السر **مرة واحدة** عند إنشاء النقطة أو عند توليد سر جديد. وتوليد سر جديد يسري فوراً: حدّث خادمك أولاً وإلا فشل التحقق في الإرسالات.

## إعادة المحاولة والإيقاف التلقائي

الإرسال الذي لا يحصل على `2xx` يُعاد حتى **6 مرات**: فوراً، ثم بعد دقيقة، و10 دقائق، وساعة، و6 ساعات، و17 ساعة (نحو 24 ساعة إجمالاً). وبعد المحاولة الأخيرة يُعلَّم كفاشل.

وعندما تفشل **10 إرسالات متتالية** تُوقف النقطة ويُبلَّغ مالك المتجر بالبريد الإلكتروني وفي لوحة التحكم. أعد تشغيلها من لوحة التحكم بعد أن يستجيب خادمك.

الأحداث التي تقع أثناء إيقاف النقطة (أو بعد انتهاء الباقة) **لا تُخزَّن ولا يُعاد إرسالها**: لا يُنشأ لها سجل إرسال، فلا يوجد ما يمكن إعادة إرساله. وللّحاق بما فاتك، اقرأ الطلبات أو المنتجات من الواجهة. زر **Resend** يعمل فقط على الصفوف الموجودة في سجل الإرسال، مثل إرسال فشل بعد استنفاد كل محاولاته.

## سجل الإرسال

تعرض كل نقطة آخر 50 إرسالاً مع رمز الحالة، ومقتطف قصير (أول 200 حرف) من ردّك، وعدد المحاولات، وزر **Resend**. وتُحفظ الصفوف 30 يوماً.
