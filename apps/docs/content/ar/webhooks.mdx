يستقبل ابدأ ستور ويب هوكس من بوابات الدفع والاشتراكات. (تبحث عن الأحداث التي يرسلها ابدأ ستور إلى خادمك أنت؟ راجع [ويب هوكس التاجر](/ar/merchant-webhooks/).) يجري التحقق دائماً على **البايتات الخام تماماً** كما أرسلتها البوابة، ولذلك تُركَّب هذه المسارات قبل محلّل JSON.

## ويب هوكس اشتراكات الفوترة

`POST /api/v1/webhooks/billing/:provider`

ترتيب العمليات: **التحقق من التوقيع، ثم منع التكرار بمعرّف حدث المزوّد، ثم التسوية**، وكلها داخل معاملة واحدة في قاعدة البيانات.

| المزوّد               | الهيدر                | الآلية                                                                                       |
| --------------------- | --------------------- | -------------------------------------------------------------------------------------------- |
| `kashier`             | `x-kashier-signature` | HMAC-SHA256 (hex) بمفتاح API الدفع، على الحقول المذكورة في `data.signatureKeys` بالـ payload |
| stub (للاختبارات فقط) | `x-stub-signature`    | `hex(HMAC-SHA256(secret, rawBody))`                                                          |

في Kashier يجب أن يسرد الـ payload الحقول الموقَّعة في `data.signatureKeys`، وأن تغطي هذه القائمة الحقول التعريفية المطلوبة، وإلا رُفض الحدث. ومقارنة التوقيع تتم بزمن ثابت.

| الحالة                  | المعنى                                                                 |
| ----------------------- | ---------------------------------------------------------------------- |
| `200`                   | عولج الحدث، أو هو تكرار (`duplicate: true`)، أو حدث متجاهَل            |
| `401 INVALID_SIGNATURE` | توقيع خاطئ أو مفقود. لم يُحلَّل شيء ولم يُخزَّن شيء                    |
| `500`                   | فشلت المعالجة. على البوابة إعادة المحاولة؛ ولم يُعلَّم أي شيء كمُستلَم |

## ويب هوكس الدفع

`POST /api/v1/webhooks/payment/:provider`

يربط كل تاجر حسابه الخاص في Paymob أو Kashier أو Fawry، وتوقّع كل بوابة الويب هوك بطريقتها. يجب أن يكون كل إرسال موقَّعاً؛ وبدون توقيع تجيب الواجهة بـ `MISSING_SIGNATURE` (من فئة `401`) وتسجّل المحاولة. ثم يُتحقق من التوقيع مقابل **السر الخاص بكل متجر** الذي حفظه التاجر:

| المزوّد   | مكان التوقيع                   | الآلية                                                                                                                                  |
| --------- | ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| `paymob`  | معامل الاستعلام `hmac`         | HMAC-SHA512 (hex) على 20 حقلاً من حقول الـ callback بترتيب ثابت (المبلغ، المعرّفات، أعلام النجاح / الانتظار / الإلغاء / الاسترداد، ...) |
| `kashier` | الهيدر `x-kashier-signature`   | HMAC-SHA256 (hex) على الحقول المذكورة في `data.signatureKeys`، ويجب أن تغطي الطلب والمبلغ والعملة والحالة                               |
| `fawry`   | `messageSignature` في الـ body | SHA-256 على حقول الإشعار مع إلحاق المفتاح الآمن للتاجر (هاش عادي وليس HMAC)                                                             |

تُطابَق الدفعة مع متجرها بمرجع المزوّد نفسه (مطابقة تامة عبر بحث ضيق في قاعدة البيانات)، ويُسجَّل الإرسال الموثَّق قبل العمل عليه، فالتكرار لا يغيّر شيئاً. والتوقيع الذي لا يتحقق لا يحرّك أي أموال أبداً.

| الحالة                       | المعنى                                                                                                                        |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `200`                        | قُبل الطلب. العمل في طابور دائم؛ والإرسال المكرر يُجاب بـ `200 Webhook already processed` حتى تتوقف البوابة عن إعادة المحاولة |
| `400 MISSING_TRANSACTION_ID` | الـ payload لا يحمل معرّف معاملة نتعرف عليه، فلا يمكن منع تكراره بأمان                                                        |
| `400 INVALID_PROVIDER`       | جزء المزوّد في المسار غير معروف                                                                                               |

## استقبال أحداثك أنت

لا يرسل ابدأ ستور حالياً ويب هوكس صادرة إلى التجّار. إذا كنت تحتاج أحداث الطلبات، فاستخدم [واجهة التاجر](/ar/merchant-api/) أو تواصل مع الدعم.

## تنفيذ المُتحقِّق (في نقطتك أنت)

إذا بنيت خدمة تستقبل callbacks من البوابات بنفس الأسلوب، فالنمط الآمن هو:

```js
import { createHmac, timingSafeEqual } from 'node:crypto';

export function verify(rawBody, signatureHex, secret) {
  const expected = createHmac('sha256', secret).update(rawBody).digest();
  const given = Buffer.from(signatureHex.trim().toLowerCase(), 'hex');
  return given.length === expected.length && timingSafeEqual(given, expected);
}
```
