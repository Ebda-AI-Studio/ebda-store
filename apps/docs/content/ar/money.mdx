كل مبلغ مالي في الواجهة هو **عدد صحيح من القروش** (الوحدة الصغرى للجنيه المصري؛ 100 قرش = 1 جنيه). لا توجد أسعار بأعداد عشرية عائمة في أي طلب أو استجابة.

| ما تقصده      | ما ترسله أو تقرؤه |
| ------------- | ----------------- |
| 1.00 جنيه     | `100`             |
| 249.50 جنيه   | `24950`           |
| 4,850.00 جنيه | `485000`          |

## القواعد

- حوّل عند حدود نظامك وليس في وسطه. خزّن واحسب بالقروش، ونسّق للعرض في النهاية.
- لا تمرّر القيمة عبر أعداد عشرية عائمة. العملية `249.50 * 100` غير آمنة في لغات كثيرة؛ فحلّل النص العشري بدلاً من ذلك.
- للجنيه المصري خانتان عشريتان بالضبط. القيمة بثلاث خانات غير صالحة وتُرفض، ولا تُقرَّب أبداً.
- الخصومات وضريبة القيمة المضافة والمبالغ المستردة تُحسب بالقروش ويقرّبها الخادم إلى أقرب قرش. لا تعِد حساب الإجماليات في جهة العميل، بل اعرض ما تعيده الواجهة.

## الاستيراد يستخدم الوحدات الكبرى حيث يُذكر ذلك

مستورِدا ملفات CSV وXLSX للمنتجات يقرآن الأسعار **بالجنيه، مكتوبة كما يكتبها التاجر** (`250` و`250.50` و`1,250.50` وصيغة تصدير Shopify `4850.00`)، وليس بالقروش: فالقيمة `24950` تعني 24,950 جنيهاً. ويحوّل المستورِد بصرامة: خانتان عشريتان كحد أقصى، والصف الذي فيه ثلاث خانات (`12.500` وهو ملتبس) أو سعر غير رقمي يُبلَّغ كخطأ في الصف ولا يُقرَّب. والاستدعاء `POST /stores/:storeId/bulk/import-preview` تجربة جافة تعيد الصفوف المحلَّلة بأسعارها بالقروش. والتصدير يكتب الأسعار بنفس صيغة الجنيه العشرية، فالملف المصدَّر يُعاد استيراده بنفس الأسعار. التفاصيل في [مركز المساعدة](https://help.ebda.app/en/products-and-csv-import/).

```js
// Display only
const egp = new Intl.NumberFormat('ar-EG', { style: 'currency', currency: 'EGP' });
egp.format(24950 / 100); // two-decimal display of 249.50
```
