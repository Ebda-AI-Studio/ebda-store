لدى ابدأ ستور ثلاث طرق لتحديد هوية المستدعي، وتعتمد الطريقة المناسبة على الواجهة التي تستدعيها.

| الواجهة                           | بيانات الاعتماد                                | الاستخدام                                                            |
| --------------------------------- | ---------------------------------------------- | -------------------------------------------------------------------- |
| واجهة المتجر العامة (`/public/*`) | لا شيء للقراءة؛ والمتجر يُحدَّد بهيدر          | الكتالوج والأقسام والسلة                                             |
| واجهة لوحة تحكم التاجر            | رمز وصول JWT (كوكي أو `Authorization: Bearer`) | إدارة المتجر كمستخدم مسجَّل الدخول                                   |
| MCP الإداري للتاجر                | مفتاح التاجر `x-merchant-key`                  | السكربتات ومهام CI ومساعدو الذكاء الاصطناعي العاملون لصالح متجر واحد |

## رموز الوصول

الاستدعاء `POST /api/v1/auth/login` يسجّل المستخدم دخوله. رمز الوصول هو JWT قصير العمر (نحو 30 دقيقة) يُضبط كوكي HTTP-only، ويمكنك إرجاعه بأي من الطريقتين:

```text
Authorization: Bearer <access-token>
```

الاستدعاء `POST /api/v1/auth/refresh` يستبدل كوكي التحديث برمز وصول جديد، والمتصفحات تتولى ذلك تلقائياً. والاستدعاء الذي لا يحمل رمز تحديث إطلاقاً (لا كوكي ولا body) يُجاب بـ `401` مع `code: "NO_REFRESH_TOKEN"`. تسجيل الدخول محدود المعدّل، ويُقفل الحساب 15 دقيقة بعد 5 محاولات فاشلة (راجع [حدود الاستخدام](/ar/rate-limits/)).

المصادقة متعددة العوامل (TOTP) اختيارية للتجّار وإلزامية لحسابات مشرفي المنصّة، وهؤلاء يحصلون على `403 MFA_SETUP_REQUIRED` على المسارات المحمية إلى أن يفعّلوها.

## كيف تعرف النقاط العامة المتجر المقصود

طلبات واجهة المتجر لا تحمل مستخدماً، بل تسمّي المتجر بأحد الهيدرين:

- `x-store-domain`: نطاق المتجر، مثل `amelia.ebda.app` أو دومين خاص موثَّق. النطاق `<slug>.ebda.app` يُحَل بالـ slug، وأي نطاق آخر يُحَل بالدومين الخاص. النطاقات المحجوزة أو المشوَّهة لا تُحَل إلى شيء، ولا تُحَل إلى متجر افتراضي أبداً.
- `x-store-id`: معرّف المتجر UUID.

وإذا لم يُحَل أي منهما إلى متجر فعّال، تُجيب الواجهة بـ `400 STORE_NOT_RESOLVED`.

## مفاتيح التاجر

مفتاح التاجر يصادق على **نقطة MCP الإدارية لمتجر واحد** وهي `POST /api/v1/mcp/admin/:storeSlug`. وهو بيانات اعتماد للجهاز: مفتاح لكل لابتوب أو مهمة CI أو زميل، حتى لا يؤدي إلغاء واحد منها إلى إخراج الباقين.

- أرسله في الهيدر `x-merchant-key`. تبدأ المفاتيح بـ `ebdam_` يليها 43 حرفاً آمناً للروابط.
- يظهر **مرة واحدة** فقط عند إنشائه. يُخزَّن فقط هاش SHA-256، لذا المفتاح المفقود يُستبدل ولا يُسترجع.
- للمفاتيح صلاحيات (scopes)، والافتراضي قراءة فقط.

| الصلاحية               | تسمح بـ                |
| ---------------------- | ---------------------- |
| `merchant:read`        | أدوات التقارير والعرض  |
| `merchant:write`       | إنشاء السجلات وتعديلها |
| `merchant:destructive` | حذف السجلات            |

- يستطيع المتجر حمل 20 مفتاحاً فعّالاً كحد أقصى. ويمكن أن تكون مدة صلاحية المفتاح من 1 إلى 730 يوماً.
- هذه الواجهة معطّلة افتراضياً (علم الميزة `merchant_mcp`). المتجر غير الموجود، والميزة المعطّلة، والمفتاح الخاطئ أو الملغي، كلها تعيد نفس الاستجابة `404 NOT_FOUND`، فلا يتعلم من يحاول التخمين شيئاً.

### إدارة المفاتيح

يدير المفاتيح مشرف متجر مسجَّل الدخول (أو مشرف منصّة) لديه صلاحية الوصول إلى المتجر:

| الطريقة  | المسار                                                 | الغرض                                                                                                       |
| -------- | ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/v1/stores/:id/integrations/merchant-keys`        | عرض المفاتيح (بيانات وصفية فقط، دون السر أبداً)                                                             |
| `POST`   | `/api/v1/stores/:id/integrations/merchant-keys`        | إنشاء مفتاح؛ الـ body هو `{ name, scopes?, expiresInDays? }`. النص الصريح للمفتاح يظهر في هذه الاستجابة فقط |
| `DELETE` | `/api/v1/stores/:id/integrations/merchant-keys/:keyId` | إلغاء المفتاح                                                                                               |

```bash
curl -X POST https://api.ebda.app/api/v1/stores/$STORE_ID/integrations/merchant-keys \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "name": "ci-reporting", "scopes": ["merchant:read"], "expiresInDays": 90 }'
```
