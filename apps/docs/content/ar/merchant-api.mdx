لوحة تحكم التاجر هي عميل لنفس الواجهة. كل ما يقع تحت `https://api.ebda.app/api/v1` وليس `/public/*` يحتاج مستخدماً مسجَّل الدخول (راجع [المصادقة](/ar/authentication/)) ويقتصر على المتاجر المسموح لهذا المستخدم بالوصول إليها.

## الحساب

| الطريقة | المسار            | ملاحظات                                         |
| ------- | ----------------- | ----------------------------------------------- |
| `POST`  | `/auth/register`  | إنشاء حساب (يستخدمه أيضاً نموذج التسجيل الذاتي) |
| `POST`  | `/auth/login`     | تسجيل الدخول؛ يضبط كوكيز الوصول والتحديث        |
| `POST`  | `/auth/refresh`   | رمز وصول جديد من كوكي التحديث                   |
| `POST`  | `/auth/logout`    | إنهاء الجلسة                                    |
| `GET`   | `/auth/me`        | المستخدم الحالي                                 |
| `GET`   | `/auth/me/export` | تصدير بياناتك الخاصة                            |

يؤكّد التجّار الجدد بريدهم الإلكتروني قبل الإعداد الأولي: الرابط يُستخدم مرة واحدة وصالح 24 ساعة (`POST /auth/verify-email`).

## المصادقة متعددة العوامل

| الطريقة | المسار                   | ملاحظات                                                  |
| ------- | ------------------------ | -------------------------------------------------------- |
| `POST`  | `/auth/mfa/enroll/begin` | بدء تفعيل TOTP؛ يعيد السر                                |
| `POST`  | `/auth/mfa/verify`       | التحقق من رمز TOTP من 6 أرقام، أو رمز احتياطي لمرة واحدة |
| `POST`  | `/auth/mfa/disable`      | إيقاف المصادقة متعددة العوامل (يتطلب رمزاً صحيحاً)       |

إتمام التفعيل يعيد رموزاً احتياطية تُستخدم لمرة واحدة، وتظهر مرة واحدة فقط.

## MCP الإداري للتاجر

الاستدعاء `POST /api/v1/mcp/admin/:storeSlug` يتحدث بروتوكول Model Context Protocol حتى تتمكن السكربتات ومساعدو الذكاء الاصطناعي من قراءة متجر واحد وتشغيله. ويتطلب `x-merchant-key` والصلاحيات التي أُنشئ بها مفتاحك. راجع [المصادقة](/ar/authentication/) لإنشاء المفاتيح وإلغائها.
