تُطبَّق الحدود لكل عنوان IP للعميل (ولكل متجر في القراءات العامة). كل استجابة محدودة هي `429` بالغلاف القياسي:

```json
{
  "success": false,
  "error": { "code": "RATE_LIMITED", "message": "Too many requests, please try again later." }
}
```

تُرسَل هيدرات `RateLimit-*` القياسية (الحد، المتبقي، إعادة الضبط) على المسارات المحدودة. اقرأها بدلاً من تثبيت الأرقام أدناه في الكود، فقد تتغير.

| النطاق                                                | الحد                                           |
| ----------------------------------------------------- | ---------------------------------------------- |
| أي كتابة (`POST` و`PUT` و`PATCH` و`DELETE`)، بشكل عام | 200 كل 15 دقيقة لكل IP. القراءات لا تُحتسب هنا |
| قراءات واجهة المتجر العامة (`/public/*`)              | 300 في الدقيقة لكل IP، مع حد احتياطي لكل متجر  |
| عمليات السلة                                          | 30 في الدقيقة                                  |
| الكتابات الأخرى على المسارات المحدودة                 | 30 في الدقيقة                                  |
| محاولات الدفع                                         | 10 في الدقيقة                                  |
| تسجيل الدخول ومسارات المصادقة الأخرى                  | 15 كل 15 دقيقة                                 |
| رسائل إعادة تعيين كلمة المرور                         | 3 في الساعة                                    |

## قفل الحساب

بمعزل عن تحديد المعدّل، يُقفل الحساب **15 دقيقة بعد 5 محاولات دخول فاشلة** خلال نافذة مدتها 15 دقيقة. وتسجيل الدخول الناجح يصفّر العدّاد.

## التراجع وإعادة المحاولة

عند `429`، انتظر حتى وقت إعادة الضبط في الهيدر `RateLimit-Reset` (أو `Retry-After` إن وُجد)، ثم أعد المحاولة بتراجع أُسّي مع تشويش عشوائي (jitter). لا تعِد محاولة كتابة ربما نجحت فعلاً دون فحص تكرار (idempotency) من جانبك.
