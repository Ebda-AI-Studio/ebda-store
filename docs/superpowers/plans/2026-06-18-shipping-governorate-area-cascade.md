# Shipping Governorate → Area Cascade (per-area merchant-editable fee) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** At storefront checkout the customer picks **Governorate (المحافظة)** then **Area (المنطقة)**; the shipping fee is resolved per **area** from a **merchant-editable** rate table, seeded for Wady Aljuz from their handwritten zone sheets.

**Architecture:** A canonical Kuwait governorate→area dataset lives in `@force/shared` (single source, replaces 3 duplicated hardcoded lists). A new additive Prisma model `ShippingAreaRate` holds one merchant-editable fee per `(store, governorate, area)`. `ShippingService.calculateShipping` resolves in priority: **per-area rate → legacy ShippingZone match → store default/first zone → 0**, so existing stores are untouched (fully backward-compatible). The storefront replaces its single governorate `<Select>` with two cascading selects; the admin gets a governorate-accordion area-fee editor. The order `shippingAddress` JSON gains `governorate`/`governorateAr`; `area`/`areaAr` become the sub-area.

**Tech Stack:** Next.js 16 (apps/web storefront, apps/admin), Express + Prisma + Neon Postgres (apps/api), `@force/shared` workspace, Zod validation, vitest (unit) + jest/supertest (integration) + Playwright (e2e). Amounts in **fils** (Int; ÷1000 = KWD).

## Design decisions (locked)

1. **Per-area fee, merchant-editable** (Ahmad confirmed). New table `ShippingAreaRate`, NOT an extension of the per-zone `ShippingZone.deliveryFee`. Existing `ShippingZone` stays for backward compatibility.
2. **Area list = shared canonical constant**, identical for every store. Prices are per-store seed data the merchant edits.
3. **The two Wady Aljuz sheets are complementary** → union of areas; where a price differs, sheet values are just seeds (merchant edits in UI). We seed with the **lower** of the two as a safe default and flag in the seed script comment.
4. **Backward compatible resolution order** in `calculateShipping`: per-area rate → legacy zone → default. No destructive migration of existing zones.
5. **No feature flag** — shipping is a core checkout mechanic (confirmed: `ShippingZone` CRUD is ungated today).
6. **Address shape:** add `governorate` + `governorateAr`; keep `area` + `areaAr` as the sub-area. Legacy orders (where `area` held the governorate) still render because the admin order view falls back to `area` when `governorate` is absent.
7. **UI target = the pecannbee/OSOSS checkout pattern** (Ahmad's screenshots, the competitor FWB migrates merchants off). Address form order, RTL, AR labels: **البلد** (country, defaults الكويت, clearable) → **المحافظة** (governorate, **searchable typeahead** dropdown) → **المنطقة** (area, **searchable typeahead**, filtered by the chosen governorate) → **قطعة** (block, required) → **الشارع** (street, required) → **الجادة** (avenue, optional) → **منزل** (house, required) → **الطابق** (floor, optional) → **شقة** (apartment, optional) → notes. A **delivery-method panel** ("طريقة التوصيل") shows _"حدد عنوانك لعرض خيارات التوصيل"_ until governorate+area are picked, then renders the resolved per-area fee. `AddressJson` already has `block/street/avenue/house/building/floor/apartment` — surface them in the form + both Zod schemas.
8. **Save-my-info (localStorage)** — a checkbox _"احفظ بياناتي لتسريع الدفع في المرة القادمة"_ with the privacy sub-note. When checked, persist contact + address (name/email/phone/governorate/area/block/street/avenue/house/floor/apartment/notes) to `localStorage` under a store-scoped key; on next checkout, prefill from it. A **"حذف البيانات المحفوظة" / clear** affordance removes it. **No PII to any server for this** — device-local only (privacy rule: no personal data in URLs/3rd-party; localStorage on the user's own device is fine).
9. **PAYMENT-SENSITIVE PR (Ahmad, explicit):** checkout touches the payment/order path. This PR **MUST run blast-radius analysis + the Opus AI reviewer** — do **NOT** use `SKIP_AI_GATE=1` on the pre-push hook for any commit here, and let the (now pre-push, per #228) blast-radius + AI-review run to completion. Treat any AI-review finding on the order/payment/total path as blocking until resolved. Add explicit regression tests that the order **total = subtotal − discount + shipping + tax** is unchanged for the no-area and free-shipping paths.

```sql
-- RLS: mirror shipping_zones (single FOR ALL policy, current_store_id() bypass)
ALTER TABLE "shipping_area_rates" ENABLE ROW LEVEL SECURITY;
ALTER TABLE "shipping_area_rates" FORCE ROW LEVEL SECURITY;
CREATE POLICY rls_shipping_area_rates_tenant ON "shipping_area_rates"

  USING (current_store_id() IS NULL OR store_id = current_store_id())
```
