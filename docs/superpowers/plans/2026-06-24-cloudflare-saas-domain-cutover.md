# Cloudflare migration finish — SaaS custom-hostname provisioning + dual-provider switch + local build + cutover tooling

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the FWB frontends migratable from Vercel to Cloudflare _immediately, per-tenant, without breaking Vercel_ — by adding a Cloudflare-for-SaaS custom-hostname provisioning path alongside the live Vercel one (switchable by env default + per-store override), a one-command local build/deploy setup, and a scripted per-tenant cutover tool.

**Architecture:** A `DomainProvider` interface abstracts custom-domain provisioning. `VercelDomainService` (existing, untouched behavior) and a new `CloudflareDomainService` (Cloudflare-for-SaaS Custom Hostnames API) both implement it. A `resolveDomainService(store)` picks the provider from `store.domainProvider ?? config.domainProvider ?? 'vercel'` — so every un-flipped store stays on Vercel (zero prod impact), and a canary store is flipped per-row. The Cloudflare build tooling (`open-next.config.ts`, `wrangler.jsonc`, CF devDeps) stays **git-ignored / local-only** (it can't be committed — `@opennextjs/cloudflare` isn't a tracked dep and breaks the Vercel/CI typecheck) but is generated by one setup script so a deploy is one command. A `cf-migrate-store.sh <slug>` script provisions the CF hostname, flips the store's provider, and prints the exact DNS the merchant sets.

**Tech Stack:** Express + TypeScript (`apps/api`), Prisma + Neon (`packages/database`), Cloudflare-for-SaaS Custom Hostnames REST API (`api.cloudflare.com/client/v4`), `@opennextjs/cloudflare` + `wrangler` (local-only), vitest (`apps/api/tests/unit`), Next 16 storefront on Cloudflare Workers (already merged, #314/#318).

**Decisions locked (2026-06-24, Ahmad):** (1) Build code-ready + unit-tested behind env; he wires live CF creds later. (2) BOTH gating models — `DOMAIN_PROVIDER` env default + per-store `domainProvider` override. (3) Scripted cutover tool + runbook.

**Prereqs / out-of-scope:** This builds the _code path_. Live activation requires Ahmad to: enable SSL-for-SaaS on a Cloudflare zone, create an API token (`Zone:SSL and Certificates:Edit` + `Zone:Zone:Read`), set the fallback origin, and set `CF_API_TOKEN` / `CF_ZONE_ID` / `CF_FALLBACK_ORIGIN` in Railway. Until then `CloudflareDomainService.isConfigured()` is false and the resolver safely no-ops the CF path (logs a warning, returns null) exactly like `VercelDomainService` does today when unconfigured. Cloudflare-Worker deploy of the apps is already proven (preview workers, #315/#318); this plan does not re-do it.

```ts
import { config } from '../config';
import { VercelDomainService } from './vercel-domain.service';
import { CloudflareDomainService } from './cloudflare-domain.service';

/** Canonical DNS row a merchant must create. */
export interface DomainDnsRecord {
  type: string;
  name: string;
  value: string;
}

/** Provider-agnostic status returned to the admin domain page. */
export interface DomainStatus {
  domain: string;
  verified: boolean;
  misconfigured: boolean;
  dnsRecords: DomainDnsRecord[];
}

/** The contract both VercelDomainService and CloudflareDomainService satisfy. */
export interface DomainProvider {
  readonly providerName: 'vercel' | 'cloudflare';
  isConfigured(): boolean;
  /** Attach a custom domain. Returns true-ish on success, null when not configured. */
  addDomain(domain: string): Promise<unknown | null>;
  /** Detach a custom domain (rollback / removal). */
  removeDomain(domain: string): Promise<boolean>;
  /** Current verification + DNS instructions, or null when not configured / not found. */
  getDomain(domain: string): Promise<DomainStatus | null>;
}

const PROVIDERS: Record<'vercel' | 'cloudflare', DomainProvider> = {
  vercel: VercelDomainService,
  cloudflare: CloudflareDomainService,
};

function normalize(p: string | null | undefined): 'vercel' | 'cloudflare' {
  return p === 'cloudflare' ? 'cloudflare' : p === 'vercel' ? 'vercel' : null!;
}

/**
 * Pick the provider for a store: per-store override → env default → 'vercel'.
 * `store` may be null (platform-level / no store context) → env default.
 */
export function resolveDomainService(
  store: { domainProvider?: string | null } | null | undefined
): DomainProvider {
  const perStore = normalize(store?.domainProvider);
  const chosen = perStore ?? normalize(config.domainProvider) ?? 'vercel';
  return PROVIDERS[chosen];
}

export function getDomainProviderName(
  store: { domainProvider?: string | null } | null | undefined
): 'vercel' | 'cloudflare' {
  return resolveDomainService(store).providerName;
}
```

```ts
import { config } from '../config';
import logger from '../lib/logger';
import type { DomainProvider, DomainStatus } from './domain-provider';

const CF_API_BASE = 'https://api.cloudflare.com/client/v4';

interface CfCustomHostname {
  id: string;
  hostname: string;
  status: string; // 'active' | 'pending' | 'pending_deletion' | ...
  ssl?: {
    status?: string;
    validation_records?: Array<{ txt_name?: string; txt_value?: string }>;
    validation_errors?: Array<{ message: string }>;
  };
}

/**
 * Cloudflare-for-SaaS custom-domain provider (Custom Hostnames API).
 * Mirrors VercelDomainService's surface so resolveDomainService() can swap them.
 * Inactive (no-ops, logs) until CF_API_TOKEN / CF_ZONE_ID / CF_FALLBACK_ORIGIN are set.
 */
export class CloudflareDomainService {
  static readonly providerName = 'cloudflare' as const;

  static isConfigured(): boolean {
    return !!(config.cfApiToken && config.cfZoneId && config.cfFallbackOrigin);
  }

  private static headers(): Record<string, string> {
    return { Authorization: `Bearer ${config.cfApiToken}`, 'Content-Type': 'application/json' };
  }

  private static base(): string {
    return `${CF_API_BASE}/zones/${config.cfZoneId}/custom_hostnames`;
  }

  static async addDomain(domain: string): Promise<CfCustomHostname | null> {
    if (!this.isConfigured()) {
      logger.warn({ domain }, 'Cloudflare-for-SaaS not configured, skipping custom hostname add');
      return null;
    }
    try {
      const res = await fetch(this.base(), {
        method: 'POST',
        headers: this.headers(),
        body: JSON.stringify({
          hostname: domain,
          ssl: { method: 'http', type: 'dv', settings: { min_tls_version: '1.2' } },
        }),
      });
      const json = (await res.json()) as {
        success: boolean;
        result?: CfCustomHostname;
        errors?: unknown;
      };
      if (!res.ok || !json.success) {
        logger.error(
          { domain, status: res.status, errors: json.errors },
          'CF custom hostname add failed'
        );
        return null;
      }
      logger.info({ domain, id: json.result?.id }, 'CF custom hostname created');
      return json.result ?? null;
    } catch (error) {
      logger.error({ err: error, domain }, 'CF custom hostname add threw');
      return null;
    }
  }

  private static async findByHostname(domain: string): Promise<CfCustomHostname | null> {
    const res = await fetch(`${this.base()}?hostname=${encodeURIComponent(domain)}`, {
      headers: this.headers(),
    });
    const json = (await res.json()) as { success: boolean; result?: CfCustomHostname[] };
    if (!res.ok || !json.success || !json.result?.length) return null;
    return json.result[0];
  }

  static async getDomain(domain: string): Promise<DomainStatus | null> {
    if (!this.isConfigured()) return null;
    try {
      const ch = await this.findByHostname(domain);
      if (!ch) return null;
      const verified = ch.status === 'active' && ch.ssl?.status === 'active';
      return {
        domain,
        verified,
        misconfigured: !verified,
        // Cloudflare-for-SaaS: one CNAME from the merchant's hostname to our zone target.
        dnsRecords: [{ type: 'CNAME', name: domain, value: config.cfFallbackOrigin }],
      };
    } catch (error) {
      logger.error({ err: error, domain }, 'CF custom hostname status threw');
      return null;
    }
  }

  static async removeDomain(domain: string): Promise<boolean> {
    if (!this.isConfigured()) return false;
    try {
      const ch = await this.findByHostname(domain);
      if (!ch) return true; // already gone
      const res = await fetch(`${this.base()}/${ch.id}`, {
        method: 'DELETE',
        headers: this.headers(),
      });
      const json = (await res.json()) as { success: boolean };
      return res.ok && json.success;
    } catch (error) {
      logger.error({ err: error, domain }, 'CF custom hostname delete threw');
      return false;
    }
  }
}

// Compile-time assertion that the class satisfies the provider contract.
const _assert: DomainProvider = CloudflareDomainService;
void _assert;
```

```ts
// PATCH /stores/:id/domain-provider — super-admin only. Flip a store between
// Vercel and Cloudflare frontend hosting (canary cutover). Does NOT move DNS.
router.patch(
  '/:id/domain-provider',
  authenticate,
  authorize('super_admin'),
  requireStoreAccess,
  async (req, res, next) => {
    try {
      const provider = req.body?.provider;
      if (provider !== 'vercel' && provider !== 'cloudflare') {
        return res
          .status(400)
          .json({ success: false, error: 'provider must be "vercel" or "cloudflare"' });
      }
      await prisma.store.update({
        where: { id: req.params.id },
        data: { domainProvider: provider },
      });
      res.json({ success: true, data: { domainProvider: provider } });
    } catch (e) {
      next(e);
```

## Task 7: `cf-migrate-store.sh` — per-tenant cutover + runbook

**Files:**

- [ ] **Step 1: Write `scripts/cf-migrate-store.sh`** — provision the CF custom hostname for a store's domain, flip the store's provider, print the DNS the merchant sets. Uses the same CF env the API uses; reads the store's domain from the DB via neonctl (read-only) — DOES NOT touch DNS itself.

```bash
#!/usr/bin/env bash
# Cut ONE store's frontend from Vercel to Cloudflare-for-SaaS.
# 1) creates the CF custom hostname, 2) flips Store.domainProvider='cloudflare',
# 3) prints the CNAME the merchant must set. DNS itself is changed by the merchant/you.
# Reversible: re-run with --rollback to set provider back to 'vercel' + delete the CF hostname.
# Usage: CF_API_TOKEN=... CF_ZONE_ID=... CF_FALLBACK_ORIGIN=cf.forcemediakw.com \
#        DATABASE_URL=... bash scripts/cf-migrate-store.sh <store-slug> [--rollback]
set -euo pipefail
SLUG="${1:?usage: cf-migrate-store.sh <slug> [--rollback]}"; MODE="${2:-}"
: "${CF_API_TOKEN:?set CF_API_TOKEN}"; : "${CF_ZONE_ID:?set CF_ZONE_ID}"; : "${DATABASE_URL:?set DATABASE_URL}"
CF="https://api.cloudflare.com/client/v4/zones/$CF_ZONE_ID/custom_hostnames"
psql() { command psql "$DATABASE_URL" -t -A "$@"; }

DOMAIN=$(psql -c "SELECT domain FROM stores WHERE slug='$SLUG' AND domain IS NOT NULL;")
[ -n "$DOMAIN" ] || { echo "store '$SLUG' has no custom domain — nothing to cut over." >&2; exit 1; }

if [ "$MODE" = "--rollback" ]; then
  ID=$(curl -s -H "Authorization: Bearer $CF_API_TOKEN" "$CF?hostname=$DOMAIN" | python3 -c "import sys,json;r=json.load(sys.stdin).get('result') or [];print(r[0]['id'] if r else '')")
  [ -n "$ID" ] && curl -s -X DELETE -H "Authorization: Bearer $CF_API_TOKEN" "$CF/$ID" >/dev/null && echo "deleted CF hostname $ID"
  psql -c "UPDATE stores SET domain_provider='vercel' WHERE slug='$SLUG';" >/dev/null
  echo "↩︎  $SLUG ($DOMAIN) reverted to vercel"; exit 0
fi

echo "→ provisioning CF custom hostname for $DOMAIN"
curl -s -X POST -H "Authorization: Bearer $CF_API_TOKEN" -H "Content-Type: application/json" \
  -d "{\"hostname\":\"$DOMAIN\",\"ssl\":{\"method\":\"http\",\"type\":\"dv\",\"settings\":{\"min_tls_version\":\"1.2\"}}}" \
  "$CF" | python3 -c "import sys,json;d=json.load(sys.stdin);print('  CF:',('ok '+d['result']['id']) if d.get('success') else ('FAILED '+json.dumps(d.get('errors'))))"
psql -c "UPDATE stores SET domain_provider='cloudflare' WHERE slug='$SLUG';" >/dev/null
echo "✓ $SLUG ($DOMAIN) provider → cloudflare"
echo
echo "MERCHANT DNS — set this ONE record, then watch SSL go active (minutes):"
echo "  CNAME  $DOMAIN  →  ${CF_FALLBACK_ORIGIN:-cf.forcemediakw.com}"
echo "Verify: admin → store → Domain (status flips to verified once SSL is active)."
echo "Rollback: bash scripts/cf-migrate-store.sh $SLUG --rollback"
```
