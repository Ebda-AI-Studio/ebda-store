## Confirmed gaps (action items)

**11 field-level gaps across 7 categories:**

1. **`hero.typography.heading` zone** (SEVERITY: HIGH) — Admin `SectionTypographyBlock` with `roles={['heading']}` wires a heading zone for hero (page.tsx:306-332). `HeroSettings` has the type, Zod saves it. But `HomePageContent.tsx` never calls `resolveSectionZone(layout.hero.typography?.heading, ...)` and `HeroBanner`/`HeroSlider` accept no `headingZone` prop (types.ts:262-320). Merchant's font/color/size override for the hero headline is silently ignored. **Fix needs**: add `resolveSectionZone` call in `HomePageContent.tsx`; add `headingZone?: ResolvedZone` to `HeroBannerProps` + `HeroSliderProps`; apply inline style to the `<h1>` in `HeroBanner.tsx`.

2. **`testimonials.title` / `titleAr`** (SEVERITY: HIGH) — Admin `SectionTitleFields` exposes the inputs; `TestimonialsSettings extends SectionTitleOverride` has the type; `HomePageContent.tsx:293-294` reads them; `TestimonialRow` accepts `title/titleAr`. But the Zod `testimonials` schema (routes.ts:262-270) is a strict object that does NOT list `title` or `titleAr` — they are stripped on every PUT save. **Fix needs**: add `title: z.string().optional()` and `titleAr: z.string().optional()` to the `testimonials` block in `layoutSchema`.

3. **`filterSidebar.enabled`** (SEVERITY: HIGH) — Admin toggle is wired + saves correctly. The storefront `apps/web/src/app/products/page.tsx` fetches `layout.productCardDefaults` but not `filterSidebar`. `ProductsFilterSidebar` is always mounted regardless of merchant preference. **Fix needs**: fetch `layout.filterSidebar` in `products/page.tsx`; pass `enabled` to `ProductsClient`; conditionally render `<ProductsFilterSidebar>` only when `filterSidebar.enabled === true`.

4. **`filterSidebar.defaultOpen`** (SEVERITY: MEDIUM) — Same root cause as #3. No `defaultOpen` prop exists on `ProductsFilterSidebar`. **Fix needs**: add `defaultOpen?: boolean` prop to `ProductsFilterSidebar`; use it to set initial collapsed/open state for the sidebar panel on first load.

5. **`productCardDefaults.cardGap`** (SEVERITY: MEDIUM) — PLP grid gap is hardcoded `gap-4` in `ProductsClient.tsx:552`. `cardGap` from `productCardDefaults` is fetched but not forwarded. `PecannbeeProductCard` doesn't accept a `cardGap` prop (it applies only to the grid container, not the card itself). **Fix needs**: apply `gridGapClass(productCardDefaults?.cardGap)` to the grid `<div>` className in `ProductsClient.tsx`.

6. **`productCardDefaults.showLabel`** (SEVERITY: MEDIUM) — Not passed by `ProductsClient`; `PecannbeeProductCard` doesn't accept or apply it. PLP always shows name + price block. **Fix needs**: add `showLabel` to props passed to `PecannbeeProductCard` in `ProductsClient`; `PecannbeeProductCard` needs to conditionally render the label block.

7. **`productCardDefaults.showHover`** (SEVERITY: MEDIUM) — Same as `showLabel`. `PecannbeeProductCard` always shows hover image-swap. **Fix needs**: same pattern — pass + gate the hover transition class.

8. **`productCardDefaults.typography.productName` / `.productPrice` / `.productCta`** (SEVERITY: MEDIUM) — All three zone fields are in the type, Zod, and admin. `ProductsClient` does not pass them to `PecannbeeProductCard`. `PecannbeeProductCard` does not destructure them from props (PecannbeeProductCard.tsx:57-72) — name/price/CTA use only pack-style CSS classes with no inline style hook. **Fix needs**: (a) `ProductCardProps` already has `productNameZone/productPriceZone/productCtaZone` (types.ts:505-507); (b) `PecannbeeProductCard` must destructure and apply them as inline styles (same pattern as `ProductCarousel.tsx:413-474`); (c) `ProductsClient` must compute the resolved zones from `productCardDefaults.typography` and pass them down.

9. **`storeName` global typography zone** (SEVERITY: LOW) — Admin `ZoneEditor` for `'storeName'` (page.tsx:1403) saves to `store.typography.zones.storeName`. But `ZONE_NAMES` in `apps/web/src/app/layout.tsx:358-381` does not include `'storeName'`, so no CSS rule is emitted. Additionally, no `data-zone="storeName"` attribute exists on any storefront element (confirmed by grep). **Fix needs**: (a) add `'storeName'` to `ZONE_NAMES`; (b) add `data-zone="storeName"` to the store name element in all 5 theme headers.

10. **`categories.typography.seeAll` zone in grid layout** (SEVERITY: LOW) — When `categories.layout === 'grid'`, `CategoryGrid` is rendered. `CategoryGridProps` (types.ts:559-608) has no `seeAllZone` or `seeAllHref` prop — the "See All" link simply does not exist in grid layout. 11. **`testimonials.typography.kicker` + `typography.subtitle` zone styling** (SEVERITY: LOW) — The zones save and are passed (`kickerZone`/`subtitleZone` reach `TestimonialRow` via HPC lines 584-585). ## Patterns observed

1. **Every field added after the original launch needs an explicit Zod listing** — the "Zod silent-strip trap" has hit `imageMobile` (2026-05-16), `reviewSection` (2026-05-16), `cardFrameSize` (2026-05-19), and now `testimonials.title/titleAr`. The pattern is: new type field added, admin UI wired, Zod schema not updated → saves succeed but data evaporates. The `testimonials` block is the only section that wasn't updated when `SectionTitleOverride` was extended.

2. **`productCardDefaults` is the most under-wired section** — 6 of the 11 gaps live here. The PLP (`ProductsClient` + `PecannbeeProductCard`) adopted `cardSize`/`cardAspect`/`cardShape`/`showCardFrame`/`cardFrameStyle`/`cardFrameWidth`/`cardFrameSize`/`cardFrameColor` (8 fields) but missed the 3 behavioral toggles (`cardGap`, `showLabel`, `showHover`) and all 3 typography zones. The homepage carousels (`ProductCarousel`) are fully wired for all 13 fields; PLP only partially caught up.

3. **Hero is the only section with NO typography zone consumer** — Categories/newArrivals/bestSellers/testimonials all have their heading zone plumbed through to the DOM. The hero heading zone exists in type + Zod + admin UI but hits a dead end at `HomePageContent.tsx` because neither `HeroBanner` nor `HeroSlider` were updated to accept a `headingZone` prop. This is surprising given the hero is the most prominent storefront element.

4. **Global zones were partially migrated** — `storeName` was added to `GLOBAL_ZONE_LABELS` (admin-side dictionary) and the `ZoneEditor` loop includes it, but the storefront `ZONE_NAMES` constant was not updated in parallel. The zone saves to the DB and loads in admin, but the CSS rule is never emitted.

5. **The `filterSidebar` section is structurally orphaned** — The controls (enabled + defaultOpen) are in the admin, typed, Zod'd, and saved. But the products page layout fetch only retrieves `productCardDefaults`, not the full layout object. `filterSidebar` has had no storefront consumer since the settings were first introduced.
