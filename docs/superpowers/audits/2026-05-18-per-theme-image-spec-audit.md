# Per-Theme Image Spec Audit

**Date:** 2026-05-18
**Scope:** Ebda Store — 5 themes (modern, elegant, classic, minimal, bold)
**Output format:** 9-surface × 5-theme matrix (45 cells) with current baseline, per-theme recommendation, and reference citation.

## Headline

The current `IMAGE_STANDARDS` table (design.md) uses a single zFloos-derived compact spec for all themes. The 5 themes have genuinely distinct merchant archetypes — luxury boutique (elegant), tech-startup DTC (modern), heritage retail (classic), editorial fashion (minimal), streetwear youth (bold) — whose source-image needs differ. This audit cross-references the Shopify theme spec (heavier, retina-first), the Ebda Store theme identity audit, the 2026-04-25 UI/UX audit's LCP findings, and the per-pack style tokens to produce a per-theme recommended source matrix. **Rendered storefront sizing stays structurally uniform; only the admin upload hints vary per theme.**

## 5-Theme Identity Probe

**modern** (`apps/web/src/templates/modern/Hero.tsx`, `ProductCard.tsx`, `CategoryGrid.tsx`) — The hero uses a 2-column split layout on desktop (`lg:grid-cols-2`) with the image in `aspect-[4/3] lg:aspect-[5/4]` and `rounded-2xl overflow-hidden shadow-2xl`. No full-bleed banner; the image is framed inside the content column. Product cards use `aspect-square sm:aspect-[3/4]` (mobile square, desktop portrait) with `group-hover:scale-[1.03] duration-700` image zoom and `rounded-2xl` frame. Category grid delegates to the shared `CategoryCard` with no per-theme aspect override (defaults to shared card-size). Decorative chrome: glow `bg-primary/5 rounded-3xl blur-3xl` behind the hero image. The glass-blur, gradient-shadow identity rewards crisp retina sources — but the 2-column split means the image renders at ~50vw max (not full-bleed), capping actual perceived quality gain from very large sources.

**elegant** (`apps/web/src/templates/elegant/Hero.tsx`, `ProductCard.tsx`, `CategoryCard.tsx`) — Hero is an asymmetric `60%/40%` split (`lg:w-[60%]` image, `lg:w-[40%]` text) with `aspect-[4/3] sm:aspect-[16/10]` on mobile, `object-contain lg:object-cover` (object-contain on mobile to preserve calligraphy text at the edges — Wady Aljuz-derived). Product card uses `aspect-square sm:aspect-[3/4]` (portrait on sm+), no border chrome (matches pack-styles hairline-only language), `duration-500` transitions. Category card defaults: `aspect-square sm:aspect-[2/3]` (tall portrait on desktop) + `rounded-md`. Elegant's portrait category tile is unique among the 5 themes. The `duration-700` hover and luxury-boutique identity (hairline borders at `/10` opacity) directly justify a higher source resolution — these merchants are Wady Aljuz-tier, photographed product.

**classic** (`apps/web/src/templates/classic/Hero.tsx`, `ProductCard.tsx`, `CategoryCard.tsx`) — Hero uses a `lg:grid-cols-2` split, image in `absolute inset-0 m-6` (inset with margin = image is framed, not bleed). `object-cover` fills the half-column. Product card: `aspect-square sm:aspect-[3/4]`, solid `border border-border` + `hover:border-foreground/35 hover:shadow` transition 500ms. Category card defaults: `aspect-square sm:aspect-[3/4]` + `rounded-sm border border-border/60`. Circular categories noted in identity audit, but the CardShape system handles that as a merchant config (not a per-theme default in the CategoryCard itself — confirmed: shape falls back to `aspect-square sm:aspect-[3/4]`). Heritage retail persona (serif everywhere, sharp corners) warrants a moderate bump from the zFloos compact baseline but not Shopify's max — these merchants often shoot traditional jewellery/perfume studio photos.

**minimal** (`apps/web/src/templates/minimal/Hero.tsx`, `ProductCard.tsx`) — Hero is a typography-led block (centered h1, no image constraint) followed by a separate full-bleed image at `aspect-[21/9]` (ultra-cinematic ratio, ~2.33:1). Product card: `aspect-square sm:aspect-[3/4]`, `bg-muted/30` (nearly transparent bg), opacity-only hover (`group-hover:opacity-85 duration-700`), zero chrome (no border, no radius). Minimal's ascetic identity explicitly does NOT reward heavier sources — the editorial/fashion persona has whitespace as the design statement, not image density. LCP constraint (04-25 audit §P0 #1) is strongest here since minimal's homepage is most likely to be typography-first. **Source sizes stay compact** — merchants choosing minimal are fashion labels who shoot editorial lookbooks, not 4K product photography.

**bold** (`apps/web/src/templates/bold/Hero.tsx`, `ProductCard.tsx`, `CategoryCard.tsx`) — Hero is full-bleed `min-h-screen` with `absolute inset-0` image + `bg-gray-950/65` overlay, `object-cover sizes="100vw"`. Product card: `aspect-square` only (no portrait upgrade) with `border-2 border-foreground/15 hover:border-foreground hover:translate-x-1 hover:-translate-y-1 hover:shadow-[6px_6px_0_0]` brutalist chrome, `duration-200`. Category card defaults: `aspect-square sm:aspect-[3/4]` + `rounded-3xl border-2 border-foreground` + offset shadow. Bold's full-bleed hero renders at `100vw` — the largest actual rendered size of any hero among the 5 themes. The brutalist identity (streetwear, high-contrast) benefits from wide hero sources. Product images render square — the brutalist tile aesthetic does NOT benefit from portrait sources.

## Headline Recommendations (Top 5)

1. **Elegant gets the biggest source bump** across all surfaces: hero grows to 1920×800 to fill the 60/40 split at tablet 16:10, products jump to 1200×1600 (2× retina for luxury pinch-zoom), and category portrait to 600×800. This is the only theme where Shopify's pinch-zoom spec is actually warranted — Wady Aljuz-tier luxury boutique is the primary live merchant.

2. **Bold gets the widest hero source** (2400×900) because it is the only theme rendering a full-bleed `100vw` hero image. At 4K monitors 1920px upscales; the brutalist identity amplifies rather than conceals pixel softness, so bold needs the wider crop most.

3. **Minimal stays entirely at the compact zFloos baseline** across all 9 surfaces. The ascetic editorial identity actively works against heavier sources — LCP + Egypt mobile + the opacity-only-hover philosophy all converge on "compact wins."

4. **Modern and classic get a moderate +33% product source bump** (600×800 → 800×1067) to serve retina desktop cards without reaching the luxury tier. Bold gets a shape change (portrait → square 800×800) to eliminate the 25% crop waste from the square-aspect ProductCard.

5. **Banner surfaces (bannerDesktop, bannerMobile) inherit the current spec for all themes** — promotional strips are uniform content and no theme identity specifically amplifies the banner surface enough to justify a separate per-theme brief to merchants.

## Open Questions for Ahmad Sign-Off

1. **Elegant hero height**: The recommended 1920×800 desktop source implies a ~2.4:1 aspect rather than the platform-locked ~2.74:1 (1920×700). The elegant hero is the only theme that does NOT share the 1920×700 aspect (it uses a 60/40 split with `aspect-[4/3] sm:aspect-[16/10]` on the image side). Should the elegant hero source have its own documented aspect (2.4:1), or should we force it to stay at 2.74:1 to match the shared landscape lock? The current code supports any landscape aspect on the image side.

2. **Elegant productPrimary at 1200×1600**: This is a 7 MB-range JPEG at high quality — significantly heavier than the compact spec. Is the Wady Aljuz / luxury-boutique tier the right trigger for this, or should we gate the 1200×1600 recommendation behind a per-store "photography tier" admin setting rather than baking it into the theme recommendation by default?

3. **categoryMobile is not a current surface key in IMAGE_STANDARDS** — the current table in design.md does not have a separate mobile-crop entry for category cards (unlike hero, which has a mobile crop entry). Should Sprint 6 introduce `categoryMobile` as a new key, or absorb mobile guidance into the `categorySquare` / `categoryPortrait` description fields?
