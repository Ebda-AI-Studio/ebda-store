# LIFE-6

> Section: Lifecycle emails and referral attribution (2026-10-22, branch `feat/lifecycle-emails`)

- Ruling LIFE-6 - one-click unsubscribe headers for lifecycle mail (Gmail/Yahoo bulk-sender rule). The one-click POST is the existing `POST /public/lifecycle-emails/unsubscribe?token=` (no login, CSRF-exempt `/public/`, token in the URL, form body ignored, idempotent through the UNIQUE optout row). Cost if wrong: a provider that retries the POST after a 5xx may get two optout attempts; both are no-ops after the first.
  Ruling PUBLIC-READ-LIMIT-1 (2026-10-22) — anonymous public reads are rate-limited by the in-colo Workers Rate Limiting bindings, not the Durable Object counters. Measured with the per-hop log: the two exact public limiters cost one ~110 ms Durable Object hop warm and 0.2-0.9 s on a cold shard on every storefront API read. `middleware/public-read-limit.ts` (mounted in front of the unchanged exact limiters in `routes/public.routes.ts`) applies to GET/HEAD requests with NO Authorization header and NO Cookie header only, with the exact limiters' own numbers (`PUBLIC_IP_LIMITER` 300/min per IP, `PUBLIC_TENANT_LIMITER` 6000/min per tenant, same key functions). Authenticated, cookie-bearing and write requests keep the exact Durable Object limiters; a missing or throwing binding falls back to them, never to "no limit"; a block answers the same 429 body. Residual: the bindings count per Cloudflare location, so a client spread over several locations at once can exceed the global figure; those requests are KV-cached reads, and the coarse 1200/min per-IP native guard in front of Express and the exact limiters for everything else still apply. Evidence: `tests/unit/public-read-limit.test.ts` (burst gets 429, tenant limit independent, authenticated/cookie/write keep the exact limiters, fallback on binding failure) and three defence-mutation entries, all killed. Cost if wrong: an anonymous read burst spread across locations is counted per location, so it is refused later than the exact limiter would refuse it.
  Ruling PUBLIC-READ-LIMIT-1 (2026-10-22) — anonymous public reads are rate-limited by the in-colo Workers Rate Limiting bindings, not the Durable Object counters. Measured with the per-hop log: the two exact public limiters cost one ~110 ms Durable Object hop warm and 0.2-0.9 s on a cold shard on every storefront API read. `middleware/public-read-limit.ts` (mounted in front of the unchanged exact limiters in `routes/public.routes.ts`) applies to GET/HEAD requests with NO Authorization header and NO Cookie header on an EXPLICIT ALLOWLIST only (categories, tags, size charts, redirects/resolve, the product list with no query beyond page/limit/sort/cursor, the product page), the tenant bucket being the RESOLVED store id (never a raw header; the exact tenant limiter's key prefers it too), with the exact limiters' own numbers (`PUBLIC_IP_LIMITER` 300/min per IP, `PUBLIC_TENANT_LIMITER` 6000/min per tenant, same key functions). Authenticated, cookie-bearing and write requests keep the exact Durable Object limiters; a missing or throwing binding falls back to them, never to "no limit"; a block answers the same 429 body. Residual: the bindings count per Cloudflare location, so a client spread over several locations at once can exceed the global figure; those requests are KV-cached reads, and the coarse 1200/min per-IP native guard in front of Express and the exact limiters for everything else still apply. Everything else, in particular any request carrying a search term (`X-Search-Query`, legacy `?search`/`?q`), `/search/suggest`, filters that reach the database, the feed, orders and wishlist, store resolution, and any unresolved store, is never eligible and keeps the exact DO limiters (unique-term scraping would multiply DB load, the AI embedding budget and search-log writes across locations). ACCEPTED: the 6000/min per-tenant backstop multiplies by the number of locations for cached catalogue reads, because those are served from KV (or one cache fill per 120 s) and cost almost nothing per extra request; the per-IP figure is unaffected for a single client. Evidence: `tests/unit/public-read-limit.test.ts` (burst gets 429, tenant limit independent, authenticated/cookie/write keep the exact limiters, fallback on binding failure) and three defence-mutation entries, all killed. Cost if wrong: an anonymous read burst spread across locations is counted per location, so it is refused later than the exact limiter would refuse it.
