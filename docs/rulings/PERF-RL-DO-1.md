# PERF-RL-DO-1

> Section: Pre-launch scaling fix 2026-11-09 (branch `perf/ratelimit-no-global-do`)

Ruling PERF-RL-DO-1 - no public request reaches a single global Durable Object instance, and a public request's rate limiting is ONE AuthState round trip. (1) The generic prefix cache generations with no id (`''`, `public:`, `public:products:`, `dir:slug:`, `public:store:resolve:`, ...) lived on the ONE `cachegen` base instance that every cache fill (3 serial reads) and every edge-hit validation worldwide read; they are now REPLICATED on all 64 store shards (`cachegenHome` = null): a read takes them from the shard the rest of its batch lives on (`cachegenAnchor`, a pure function of the name list: store id, else status host, else first leaf), a bump increments EVERY replica before the invalidation deletes. Leaf names without an id (`dir:slug:<slug>`) moved from the base instance to their own store shard. No write path bumps a replicated name today (every prefix bust carries a store id), so the fan-out costs nothing in practice and stays correct if one does. Generations are only ever compared with a value read from the same instance (a fill / edge stamp re-reads the same list), and `EDGE_STAMP_EPOCH` moved `v2:` -> `v3:` so no pre-change stamp can validate. (2) The public router's limiters (per-IP 300/min, tenant 6000/min, store-miss 20 misses/min, search 60/min) were separate express-rate-limit middlewares, each a serial AuthState call on a different shard (3 calls / 2 waves per store resolve, 4 / 3 with a search term). `prefetchPublicLimits` now sends every hit the request is about to make in one batch per shard, the per-IP family co-located on the client's shard (`shardKey`: `rl:{public,public-tenant,store-miss,public-search}:<subject>` -> `rl-client:<subject>`), and each limiter takes its prefetched result. Limits, keys, windows, headers, 429 bodies, skips and decrements are unchanged; a misprediction only costs time (no prefetched hit -> the limiter calls the DO itself; a prefetched hit no limiter took is `unhit` when the response ends; a failed batch falls back to the direct call). Not moved to the Workers Rate Limiting binding: it counts per location, which would loosen the exact per-client limits #473 set (store-miss, search) and the binding cannot count only 404s. Auth lockout / MFA / jti stay exact on AuthState, already keyed per user/IP across 32 shards (untouched). Evidence: `workers-test/public-do-calls.test.ts` (store resolve = 1 rate-limit call cold and warm; tenant reads and search <= 2; zero calls to the base `cachegen` instance; a cold fill reads ONE store shard; store-miss still 429s one IP at miss 21 while another IP gets 404), `workers-test/search-limiter-key.test.ts` green and still red when the search key collapses to a global value, `workers-test/latency-budget.test.ts` ceilings lowered (store resolve 3 -> 1 call, 3 -> 2 waves; product list / PDP 4 -> 3; cart add 16 -> 15; order create 31 -> 30), `tests/unit/public-limit-prefetch.test.ts`, mutations `cachegen-own-durable-object`, `cachegen-replicated-bump-fans-out`, `rl-prefetch-exact-key` all KILLED. Residuals: a tenant's exact `public-tenant` counter is still one shard per store (bounded by the 6000/min limit; anonymous catalogue reads use the native binding); the cold-fill guard still makes 3 serial generation reads per fill (before, after, after-write re-check), now on the store's own shard; a prefetched-then-released hit is +1 on its counter for the life of the request. Cost if wrong: a replicated bump that fails on some replicas leaves those replicas at the old value, so a fill anchored there could republish a pre-write listing for one TTL (the same residual a failed bump already had; checkout reads price and stock authoritatively).
