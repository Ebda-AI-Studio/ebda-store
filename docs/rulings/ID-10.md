# ID-10

> Section: Lifecycle emails and referral attribution (2026-10-22, branch `feat/lifecycle-emails`)

Ruling ID-10 (2026-10-24) - a signup's password is bound to the verification CODE it produced (`verification_tokens.pending`), never written to the user row by an unauthenticated request; an unverified row holds the unusable marker `!pending`. Verifying code X activates only the credential submitted with the signup that produced X; older codes are superseded; and `/otp/verify` also requires the PASSWORD chosen at signup (checked against the credential bound to that code before the code is consumed), so a code mailed because someone else typed the address can never activate their password on the owner's behalf. Evidence: Opus review found a takeover when a later signup overwrote an unverified row and the owner then verified the newest mail. Residual: three signup/resend/forgot requests per 15 minutes from anyone block the owner's own for that address (a nuisance; recovery is to wait the window). Cost if wrong: an owner who signs up twice must use the newest mail and type the password that mail was created with.
