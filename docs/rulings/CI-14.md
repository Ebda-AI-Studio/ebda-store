Ruling CI-14 (Store session, 2026-10-29; CI-2 scaling) - the daily aggregation fans out per store and no step can reach a Worker's 1000-subrequest limit. Before: `runDailyCiAggregation` ran every store in ONE handler, and each store's `rebuildWindow` did 90 R2 gets, so a few hundred stores would die before `publishCohort`, retry the same way, and stop the cohort and insights with no alert (the existing alert only fired for per-store failures). Now: (1) the Inngest job runs one `step.run` per store (`store-<id>`), each held by `budgeted()` to `MAX_R2_CALLS_PER_STORE` (400): a store past it throws `CiBudgetExceeded`, is reported and left out of the cohort, and the run goes on; (2) `rebuildWindow` lists the store's aggregate prefix ONCE and reads only the day files that exist (full history is about 102 calls per store per run, a new store about 10, a store with no data a handful); (3) the cohort is read in chunks of `COHORT_READ_CHUNK` (400) windows per step, each step returning a small JSON partial (`accumulateWindows` -> `mergeAccs` -> `finalizeCohort`), and a final step publishes; the cohort bytes are identical whatever the chunking. No incremental subtract-the-oldest-day window was built: a cell's first/last day cannot be recomputed after a subtraction, and the k-threshold span test reads them, so the exact merge of existing day files stays. Evidence: `tests/unit/ci-aggregate-budget.test.ts` asserts the per-store call ceiling (<= 110 at full history, <= 12 new, <= 8 empty, always under the 400 budget), the guard throwing before the 4th call reaches R2, chunked equals unchunked cohort bytes, one step per store, and that a failing store is reported while the run publishes; the old aggregate tests pass unchanged. Not verified: a real Inngest run with hundreds of stores, and R2 latency per step. Cost if wrong: a store with more than ~300 partition objects in two days would exceed the budget and be skipped every run (visible as the `ci.aggregation_store_failed` alert) until compaction lands; Inngest step output carries the cohort partial, so thousands of distinct cells across thousands of stores could approach its output size limit.
