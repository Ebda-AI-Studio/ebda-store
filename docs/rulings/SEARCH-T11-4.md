> Section: 2026-10-15 — Phase B1 Qamar (B1-\*)

Ruling SEARCH-T11-4 — every product-TEXT writer is pinned by `tests/unit/reindex-write-paths.test.ts`. It parses each `*.product.(create|createMany|update|updateMany|upsert)(…)` call in `apps/api/src` and reads the TOP-LEVEL keys of `data` (a `select: { name: true }` or a nested spread is not a text write); every text or dynamic call is listed per file with its count and how it keeps the index current: `product.service.ts` (create/update emit `product.upserted`, which the indexer consumes; bulkUpdate's `scalarData` is flags only), `ai-autofill.service.ts` (guarded AI writer for fill + balance, only when a written field is a doc field; balance revert), `ai.routes.ts` (hand-back clear), `bulk.service.ts` (import, once per run after its batches commit) and `bulk-ai-translate.ts` (per batch that wrote a product; runs under `runInStoreScope`, so the event is sent inline after that batch's writes). Raw SQL may not `INSERT INTO products` or `SET` a doc column (today's raw UPDATEs set `inventory` and `ai_field_sources`). Not text and not wired: soft delete (the stale query and the vector leg both require `deleted_at IS NULL`; hard delete cascades), status/price/stock/flags, variant writes (SEARCH-9), category rename (categories are not in the doc). Residual: a writer through a nested relation write (`products: { create }`) or a client variable not named `*.product` is not scanned — none exists today — and `search-index-backstop` finds any missed writer by content hash within 6 h. Cost if wrong: a product ranks by its old text for up to 6 h.
