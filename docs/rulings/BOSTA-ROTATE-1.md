# BOSTA-ROTATE-1

Ruling BOSTA-ROTATE-1 (Ahmad 2026-10-27, register line; filed as a file 2026-11-11) - a per-store Bosta webhook-secret rotation flow is deferred until a merchant actually uses Bosta. Evidence: Bosta signs nothing, so the callback URL carries the store's `webhookSecret` from its encrypted credentials (`apps/api/src/routes/webhook.routes.ts`, `POST /webhooks/shipping/bosta/:storeId/:token`); a bad token, unknown store and no-Bosta store are one identical 401; no store has Bosta enabled (the carrier-config migration disabled every enabled config until its credentials are tested, docs/ROLLBACK.md). A merchant can already replace the secret by re-saving the carrier credentials. Revisit when the first merchant enables Bosta. Cost if wrong: a leaked Bosta callback URL stays valid until the merchant re-saves the carrier keys by hand.
