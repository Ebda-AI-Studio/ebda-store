Ruling SHARIA-GOLD-1 (Ahmad, 2026-11-03) — an order with a gold line (`goldGate.snapshots.size > 0`, order_items.gold_snapshot) is paid in full online by default. Cash on delivery and installment (BNPL: valU, Kiosk, Kashier bnpl) are refused with 409 `GOLD_PREPAID_ONLY` in `OrderService.create`, `createAdminOrder` and `POST /payments/create` (one function, `assertGoldPaymentAllowed`, over the pure rule `checkGoldPayment`; the store Durable Object checkout `packages/repo/src/do/checkout.ts` runs the same rule; the DO admin-order path has no payment-method input, so it is not gated), and hidden at checkout for a gold cart (`/payments/config` returns `goldPrepaidOnly`); a gateway page for a gold order drops the valU/Kiosk integrations and Kashier `bnpl`. Card, wallet, InstaPay and Fawry stay allowed (paid up front). The merchant may switch it on: `store.settings.goldAllowDeferredPayment` (absent = OFF, only a literal true counts), written only by `PUT /stores/:id/gold-rates/payment-policy`, which needs `confirm: true` to turn it ON and writes an audit row; the key is server-owned, so the generic store-settings PUT cannot plant it. Evidence: research/2026-11-03-sharia-compliance-check.md section 2 (AAOIFI Std 57 and the Jordan fatwa require spot settlement for gold; Egypt's Dar al-Ifta reportedly permits jewellery installments, so the matter is contested and the merchant chooses). Cost if wrong: a merchant who wants COD or installments for gold must find and switch one setting, and a store that never reads it loses those two methods on gold orders only.
