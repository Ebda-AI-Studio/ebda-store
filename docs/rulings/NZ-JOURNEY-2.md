# NZ-JOURNEY-2

Ruling NZ-JOURNEY-2 - the workerd suite's identity stub now behaves like the real one where the merchant journey depends on it: it serves an ES256 JWKS (a per-run key from `vitest.workers.config.mts`, so a test signs a real `aud=store` access token) and `inviteUser` answers the EXISTING account for an address that already has one (`created: false`), as `apps/accounts` `inviteFor` does (`findUserByEmail` first). Without the second change the store created at onboarding was owned by a fresh random id and every later step answered 403, a test artefact, not a production defect. `EBDA_INSTAPAY_HANDLE` is set in the test vars so the billing step's InstaPay choice is exercised. Evidence: full `vitest.workers.config.mts` suite 27 files / 170 tests green with the stub changes. Not verified: whether production has the `EBDA_INSTAPAY_HANDLE` secret set (unset = InstaPay refused with 409 and go-live blocked with 402 for a merchant with no card). Cost if wrong: if production lacks the secret, a new merchant still cannot go live, and this suite would not show it.
