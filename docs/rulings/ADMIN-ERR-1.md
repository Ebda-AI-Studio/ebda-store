# ADMIN-ERR-1

Ruling ADMIN-ERR-1 - an API refusal the admin shows is always a fixed sentence in the admin's language: the server's `details.messageAr/messageEn` when sent, else ERROR_AR / ERROR_EN by code or status. A 5xx's server text ("Internal server error") is shown in NEITHER language, and in the Arabic UI an unknown code with English server text shows the generic `REQUEST_FAILED` sentence; in the English UI a 4xx's own English text is kept (it is written for merchants). `localizedApiMessage` (used by the XHR uploads, PWA icons, fonts, expenses OCR and now the tax document upload, i.e. every reader outside `apiRequest`) applies the same map as `apiRequest`. A failed save on a long form is shown in the `StickySaveBar` (`error` prop, `role="alert"`) where Save was pressed, not only in a banner at the top. Evidence: 2026-11-10 the onboarding photo upload printed "Internal server error" on the Arabic page, and the product edit page's 500 showed only «فيه تغييرات لسه ما اتحفظتش»; `apps/admin/src/lib/__tests__/api-error-map.test.ts` (4 of 7 new cases red on main) and `components/StickySaveBar.test.tsx` (red on main). Cost if wrong: an English-UI merchant loses a server's specific 5xx wording (a request id is still in the logs), and an Arabic-UI merchant sees the generic sentence for a 4xx the server did not translate until that code gets its own sentence.
