# BUNDLE-BUDGET-8

> Section: NEON-ZERO integration (2026-11-05)

**Ruling BUNDLE-BUDGET-8 - the API Worker raw bundle ceiling in `scripts/ci/worker-startup-budget.json` goes from 7,800,000 B to 8,300,000 B; the gzip (2,200,000 B) and startup CPU (140 ms) ceilings stay.** The integration of the NEON-ZERO PRs measured `worker.js` at 8,018,344 B raw (CI job 127155873030 on PR #443 measured 8,018,267 B), 2,162,735 B gzip, startup CPU min of 3 runs 114.3 ms on a loaded host. The previous reference, BUNDLE-BUDGET-7, was 7,682,914 B: the growth is +335 KB (+4.4%). I looked for an accidental heavy import first: the sourcemap's per-module source sizes show nothing Node-only or Postgres-only that should not be there. The growth is the feature itself: the Durable Object repository and SQL ops (`packages/repo/src/do`, 789 KB of source), the ported job bodies (`lib/inngest/functions`, 812 KB), the D1 platform clients and cutover code, the generated `prisma-meta.json` (579 KB) that the D1 and DO clients read, and the store-create path. The Postgres client (`.prisma` 491 KB, `@prisma/client` 343 KB) is still in the bundle until the final removal PR (N-17) deletes the Hyperdrive path; that PR is where the bundle shrinks again and the ceiling should come back down. 8,300,000 B is the measured size plus 3.5% headroom, not a round number.

Evidence: `node scripts/ci/worker-startup-budget.mjs --runs 3` (startup CPU 114.3 ms, under the 140 ms ceiling; bundle 8,018,344 B, the only failure), the sourcemap breakdown above, CI job 127155873030. Cost if wrong: a ceiling that is too loose lets the next feature walk toward the 10021 startup cliff unnoticed (the CPU gate is unchanged and is the one that guards the cliff); it is revisited in the N-17 PR.
