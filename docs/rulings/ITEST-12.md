# ITEST-12

> Section: Lifecycle emails and referral attribution (2026-10-22, branch `feat/lifecycle-emails`)

Ruling ITEST-12 - Two follow-ups to the full-tier greening. (1) `lifecycle-events` FK error under parallel runs: the file borrowed `/admin/stores?limit=1`, i.e. a store another file was creating or deleting concurrently (`affiliates_store_id_fkey`), and its return-timeline test silently skipped whenever that store had no order. It now creates and removes its own owner, customer, store and order. Root cause = missing per-file fixture isolation, not a lifecycle-writer ordering bug (the writer only inserts rows under the store it is given). No other test borrows a store (swept `stores?limit=1`, `store.findFirst` across tests/integration and tests/e2e). (2) Session time zone: the schema stores instants in `timestamp(3)` without zone; Prisma writes UTC wall time but SQL `now()` / `CURRENT_TIMESTAMP` defaults give the wall time of the SESSION zone, and the pg driver reads a bare `timestamptz` as if its wall text were UTC (probe: `SELECT now()` returned 18:30Z while the JS clock said 15:30Z on a +03 session). Production is UTC, so this was latent, but it was a real dependence on server configuration. Fixed in code, not only in the environment: every tenant transaction now also sets transaction-local `TimeZone = UTC` inside the one `set_config` statement it already sends (`tenant-gucs.ts`, no extra round trip, pooler-safe), `dbNowIso` in the citation-scan job selects `(now() AT TIME ZONE 'UTC')` (the one production `SELECT now()`), and the legal-policy function was already explicit. The three tests that backdated rows with a bare `now()` on the owner connection are explicit too. New `tests/integration/tenant-time-zone.test.ts` gives the connection a non-UTC zone and proves the override and the revert. The shared local test Postgres is now UTC (docs/ENVIRONMENT.md). Residual: DB-side defaults written OUTSIDE a tenant transaction (migrations, ops scripts, the owner connection) still follow the server zone, so the server stays UTC. Cost if wrong: one extra `set_config` argument per tenant transaction.
