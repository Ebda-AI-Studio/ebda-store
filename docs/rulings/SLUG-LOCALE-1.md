# SLUG-LOCALE-1

Ruling SLUG-LOCALE-1 - a product, category or page has ONE slug, the same under `/ar` and `/en`; this batch does not add per-locale slugs and does not rewrite existing slugs. QA-B7 (2026-11-11, Amelia Aurum) found `/en/products/<Arabic text>` on a store whose name is Arabic: the slug is generated from the name the merchant typed first (`slugifyWithFallback`), and the schema has a single `slug` column per row. Per-locale slugs need a column (or a slug table) per locale, a unique index per store+locale, a backfill, hreflang/canonical/sitemap/llms changes and a `slug_redirects` entry for every old URL; rewriting slugs in place without all of that 404s every link already shared, indexed or printed on a QR (`recordSlugRedirect` only covers merchant-initiated renames). An Arabic slug is a valid, indexable, readable URL (percent-encoded on the wire). Revisit as its own plan (schema + redirects + sitemap) if a merchant asks for English URLs. Cost if wrong: Arabic-named products show percent-encoded URLs when an English shopper copies the link, which looks untidy but never breaks.
