# WA-RPC-1

Ruling WA-RPC-1 - The Store's `WhatsAppBridge` exposes the 12 commerce RPCs ebda-whatsapp's `StoreBridge` calls (getStoreProfile, listCatalog, getProducts, createCheckoutLink, createOrderFromChat, getPaymentLink, recordCodOutcome, attachPaymentProof, getCustomerAddresses, saveCustomerAddress, getOrderStatus, listCustomerOrders), not the 8 the audit counted; the audit list omitted attachPaymentProof (PAY-INSTAPAY-1) and listCustomerOrders. Auth is the existing model (a Service Binding wired only in ebda-whatsapp's config; ID-19), with every call gated on store id shape, store resolves, link + entitlement, in that order, before any tenant read. Unresolved store answers `not_found`, an unlinked one `not_linked`; never a default store. Expected failures are data in the caller's result envelope, an unexpected error throws and the caller retries. Evidence: `apps/api/src/lib/wa/bridge/service.ts`, `tests/unit/wa-bridge/`. Cost if wrong: a caller method we did not list would 404 at runtime and surface as `unavailable`.
