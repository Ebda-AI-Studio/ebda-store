Ruling WA-COD-1 (Store session, 2026-10-25, Opus review) — a COD answer from WhatsApp acts only on an OPEN COD order (unpaid, a `cod`/`cod_pending` payment, status pending, or confirmed for a refusal), re-read under `SELECT ... FOR UPDATE` in the same tenant transaction as the status write, for a linked and entitled store, and never when the answer predates the order. The queue is account-internal and unsigned, so the Store re-derives every precondition; the seen-marker is only a short-circuit, the state transition is the idempotency guard. The Store does not emit `commerce_outcomes` for outcomes that came from WhatsApp (contract section 8). Cost if wrong: a COD answer ignored for an order the merchant already moved by hand.
