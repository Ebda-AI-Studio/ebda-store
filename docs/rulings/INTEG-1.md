# INTEG-1

Ruling INTEG-1 - the integration of the open PRs (#366 on top, then #300, #327, #365, #324, #328, #325 and the features) brought in two flows that read and wrote store-do models with `prisma`: the catalogue import (#329: jobs `catalog-import-run`, `catalog-import-create-drafts`, `catalog-import-uploads-sweep`, the request path in `catalog-import.service.ts`, `process-file.ts`, `page-ledger.ts`) and the Customer Intelligence hints (#336: job `ci-hint-calibration-weekly`, `ci-hints.service.ts`, `ci-calibration.service.ts`, `lib/ci/hints/gates.ts`). They are now ported, so `node scripts/cf/not-on-do.mjs` exits 0 (`postgresOnly` and `jobsAccepted` are empty). `CatalogImportJob`, `CatalogImportFile`, `CatalogImportItem`, `CiHintLog` and `CiStoreGate` join `DO_WRITABLE_MODELS` / `WritableModel` (non-money; their tables were already in the DO schema). Reads go through `storeDb`, writes through `storeWriter`. The one money-adjacent step, the variants of a draft product (stock columns), uses the DO op `importBatch` (replace-semantics on the product just created, `inventory` 0) on a DO store and the unchanged `withMoneyTx` path on Postgres. `catalog-import-run`, `catalog-import-create-drafts` and `ci-hint-calibration-weekly` are `ported` (the last also in `ALL_STORES_JOBS`: the platform check ranks all stores' rows together, so one cron run lists every store through `acrossAllStoresDb`); `catalog-import-uploads-sweep` touches only the private bucket and is `none`; `ci-aggregation-daily` stays `none`. Evidence: `tests/unit/integ-1-on-do.test.ts` (DO path for every flow, a double-fire case for every write, and a static scan), `tests/unit/do-writable-direct-readers.test.ts` (baseline entries removed). Residual: a failed `importBatch` after `ProductService.create` is compensated by deleting the draft (as on Postgres); the DO path of `importBatch` for a catalogue draft is exercised with a mock of the money client here and by the existing DO tests of the batch, not by a live DO. Cost if wrong: a DO store whose import variants misbehave gets a failed item (`VARIANTS_FAILED`) with the draft removed, never a half-built product; no store is flipped by this change (all are on Postgres).
