# B5-7

> Section: 2026-10-22 — Phase B5 Dahab (B5-\*)

Ruling B5-7 — the gift finder is one document section over category links and a price URL filter. Occasions are `occasion` blocks naming a category by slug (a store-scoped reference, checked by `collectRefs` / `validateDefinition` like a collection tile), budgets are `budget` blocks holding a cap in WHOLE POUNDS (`maxPrice`, converted to minor units only when the link is built, so a merchant never types piastres). The product list reads `minPrice` and `maxPrice` (integer minor units, the API's own params) and `category` from the URL (`lib/plp-url-price.ts`); a cap at or above the slider's natural ceiling (EGP 5 000) widens the slider to twice the cap so the cap stays a real restriction. `ProductsClient` does not write the range back to the URL (it never wrote the category either). While wiring it, `handleClearAll` was found setting the price maximum to 100 (a pound range, not "no limit"); it now restores the slider ceiling. Cost if wrong: occasions cannot overlap on one product beyond category membership; the range is not shareable after the shopper edits it.
