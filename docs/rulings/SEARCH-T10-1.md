# SEARCH-T10-1

> Section: 2026-10-15 — Phase B1 Qamar (B1-\*)

Ruling SEARCH-T10-1 — the embedding provider fails loud at boot, never degrades silently on a misconfiguration. `assertEmbeddingConfig` (`apps/api/src/lib/search/embedding-provider.ts`) runs once per isolate in `worker.ts` `prepare()` (cached on success only) and before `listen()` in `index.ts`; it throws on `SEARCH_SEMANTIC_ENABLED=true` with no provider, on half a REST pair (`CF_AI_ACCOUNT_ID` xor `CF_AI_API_TOKEN`), and on a flag value other than unset/`true`/`false`, and otherwise logs the resolved provider (`workers-ai`/`rest`/`none`) and ON/OFF. "No provider" is the explicit, logged OFF state: `getEmbeddingProvider()` returns `null` and search stays lexical (Review Focus 5); there is no stub that answers. The workerd smoke boots without the `AI` binding and writes `SEARCH_SEMANTIC_ENABLED=false` so a `true` in config vars cannot fail it for a reason production lacks. Evidence: `tests/unit/embedding-provider.test.ts` (20 cases; mutations — dropping the flag/no-provider throw, the half-pair throw, the 100-text split, the timeout, or changing `EMBED_DIMS` each turn the suite red); a workerd smoke run with the flag forced `true` and no binding answered 500 on every probe with the boot error, and the real smoke passes. The flag is a `wrangler.jsonc` var (default `"false"`), flipped only by a PR + `cf-api-deploy.yml` (round 1, review I2); `cf-api-deploy` refuses to deploy while a Worker secret of that name exists. Cost if wrong: a bad flag value delivered through a deploy takes the API down until the post-deploy `/health` probe rolls it back (the pre-deploy smoke forces the flag off and never sees it); a value set out of band (dashboard edit, `wrangler secret put` after the last deploy) creates a version with no probe, so every request, queue batch and cron run 500s until someone rolls back by hand.
