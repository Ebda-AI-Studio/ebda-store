Production was already safe (every caller sat under `publicStoreContext`, the bridge auth `runInStoreScope`, MCP `runInStoreScope`, admin callers under `tenantContext`; swept all 14 callers of `searchProductIds` / `searchProductIdSet` / `productSearchFilter` / `buildProductSearchWhere` plus `ebda_order_search_ids` / `ebda_customer_search_ids`). The definers keep their refusal: a contextless ADMIN call still throws. Cost if wrong: a storefront search in a context for another store would open its own short scope for the requested store (the caller has already authorised that store), so a caller passing an unauthorised id would search it; the route layer's store resolution is the only guard.
