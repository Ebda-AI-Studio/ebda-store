# D1016-NEW-1

> Section: 2026-10-16 — Ahmad's product decisions (FU46-Y02a/b, D1016-\*)

Ruling D1016-NEW-1 (Ahmad 2026-10-16, "New badge = merchant choice"; supersedes FU46-W1c-8) — the card "New / جديد" badge is a store setting, `theme.showNewBadge`, default OFF (CLAUDE.md UI rule 2: new visual features default off). It rides the StoreTheme JSON (rule 3: not API-gated) and is toggled in Page Builder → Product card defaults, between the brand badge and quick-add toggles (ar + en). With it off, NO card path shows the badge, not even for a product the merchant flagged `isNew` (`isNew` still drives the New-arrivals section). With it on, the old rule applies (explicit `isNew`, or created within 14 days). `isProductNew(product, now, theme)` takes the theme as a REQUIRED argument so a card path cannot forget it (typecheck); all 8 call sites (5 skins, shared card, shared carousel, Dahab card; the Dahab carousel and the 4 mappers render through them) pass `store.theme`. Cache: the flag is written by `StoreService.updateTheme`, which busts `public:store:*` (KV + memory), `public:products:<id>:*` and the storefront Next cache (`revalidateStorefront`) — NEVER-stale class not needed (a display preference), the existing theme invalidation covers it. Evidence: `apps/web/src/templates/card-new-badge.test.tsx` (37 red on main: every path × unset / off-with-isNew, DEFAULT_THEME off), `tests/unit/new-badge-setting.test.ts`. Production check: stores that relied on the always-on badge since W1c lose it until the merchant turns it on (Ebda is pre-launch). Cost if wrong: a merchant who wanted the badge does not discover the toggle; the page-builder hint names it.
