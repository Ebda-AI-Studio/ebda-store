Ruling WA-CONSENT-1 review 4 (Controller, 2026-10-25) — buyer-facing reads of consent state (`GET /public/cart/whatsapp-optin`, the account export) report a number's consent only when that number is PROVEN to be the account holder's (a delivered order of theirs); otherwise `{granted:false, proven:false}`, so nobody can type another person's number into their profile and learn whether that person opted in. Admin views are unaffected. Cost if wrong: a customer whose number is not yet proven sees an unticked box even if they consented earlier.
