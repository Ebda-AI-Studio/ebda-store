Ruling LOCALE-PATHS-3 - the locale-path 301 can never leave the request's origin (security review of S1, 2026-10-29). `/ar//evil.com` left `rest = //evil.com` and the middleware did `new URL(location, request.url)`, a protocol-relative open redirect that browsers would cache as a 301, live for every store once LOCALE-PATHS-2 turns the flag on. Now `decideLocalePath` refuses (no redirect, plain 404) a rest holding a backslash (raw or %5C) or whose decoded form starts with two slashes, and collapses leading slashes otherwise; the middleware builds the target from `request.nextUrl.clone()` with explicit pathname + search and returns 404 unless the target origin equals the request origin. The only other `NextResponse.redirect` in `apps/web/middleware.ts` (www to apex) builds from the request's own hostname and path, not user-supplied location text. Evidence: `tests/unit/web-locale-paths.test.ts` (ar and en, nine malformed tails). Cost if wrong: a malformed-but-harmless `/ar/<tail>` answers 404 instead of a redirect; a missed variant would be a cached off-site redirect on every store.
