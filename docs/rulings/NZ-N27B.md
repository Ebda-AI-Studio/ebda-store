# NZ-N27B

Ruling NZ-N27B (Ahmad 2026-11-24) - consent evidence is kept, the person around it is not. On user erasure `legal_acceptances.user_id` and `legal_notice_deliveries.user_id` become an opaque per-erasure pseudonym `erased:<uuid>`, `legal_acceptances.ip` and `user_agent` and `legal_notice_deliveries.error` become NULL, and the row stays (doc_key, version, accepted_at, source / status). A daily job NULLs ip and user_agent older than 12 months and deletes rows older than RETENTION_YEARS (7) from acceptance (deliveries: from creation). The user-FK cascade is dropped (Postgres migration 20261124100000); the D1 schema never had one. Basis: proof of consent and defence of legal claims, under the Law 151/2020 legal-obligation exemption already used in RETENTION-2; NOT counsel-verified (12-month window and basis). Note: `legal_notice_deliveries` has no ip/user_agent column. Evidence: `tests/unit/platform-subject-coverage.test.ts` (evidence tables), `tests/unit/legal-evidence-retention.test.ts`; mutation: dropping the scrub columns fails 3 tests. Cost if wrong: too short a window loses the ip/UA needed to rebut a dispute (version, time and pseudonym remain); too long keeps personal data past its purpose. No rollback for scrubbed values; code and migration roll back.
