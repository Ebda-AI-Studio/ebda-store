# FISCAL-ARCHIVE-1

> Section: 2026-11-15 - compliance fix: fiscal records of a deleted Durable Object store stay producible (branch `fix/fiscal-archive-on-do-delete`)

Ruling FISCAL-ARCHIVE-1 - A store on its Durable Object is deleted by closing the DO and retiring its D1 directory row (NZ-D14/D17); the DO keeps every fiscal row, but every read resolved the store through the retired row, so the records were retained and could not be produced (the Postgres-only `archiveFiscalRecords` of MONEYB-4 never ran for these stores). Now, AFTER the atomic close and BEFORE anything is deleted or the directory row retired, `archiveDoStoreFiscal` (`apps/api/src/lib/fiscal-archive-do.ts`) exports the store's fiscal documents (stored immutable payloads, numbering/serials, eta_uuid/eta_status on each document), the counters, the ETA receipts INCLUDING the exact signed submitted `document` (same legal basis and retention as the tax invoice payload, so no new class of personal data; excluded: `error_message`, which can echo buyer fields, and the internal `line_map`) and Ebda's own subscription VAT ledger (`billing_events` as `billing_record`s) into R2 `ebda-private` at `fiscal-archive/v1/data/<storeId>.ndjson.gz` plus `fiscal-archive/v1/manifests/<storeId>.json` (counts, sha256, bytes, `retainUntilMax` = latest issue date + `FISCAL_RETENTION_YEARS`). The data object is written, read back and checksum-verified before the manifest exists. FAILS CLOSED: any export error (DO read, missing bucket, read-back mismatch, would-shrink) raises a P1 alert, throws 503 `FISCAL_ARCHIVE_FAILED`, the existing compensating rollback reopens the DO this call closed, and nothing is deleted or retired; the delete is retried safely (a retry re-reads the unchanging closed DO and writes only when the checksum differs; it never replaces a longer archive with a shorter one). Super-admin `/tax-archive` (`GET /admin/fiscal-archive[/:storeId[/:docId/html]]`) lists deleted DO stores from the manifests and serves their documents with filters (`docType`, `q`) and a keyset cursor (`issuedAt:id`, newest first), rendering from the stored payload; a read verifies the checksum and refuses a tampered object. Backfill of already-deleted DO stores: `POST /admin/fiscal-archive/:storeId/backfill[?apply=1]` (super admin + MFA, read-only without `apply`, refuses anything that is not a retired DO store) with the read-only lister `scripts/ops/fiscal-archive-backfill-dry-run.mjs`. PII (PDPL): the archive carries only what the fiscal document legally contains (a plain receipt names no buyer; a tax invoice keeps the buyer name + address Art. 37 requires); no ETA error text (it can echo buyer fields), no customer tables; logs carry store ids and counts only. Erasure: the archive prefix is outside every purge/expiry prefix (`stores/`, `exports/`, `store-do-backups/`) and no erasure code references it (test `fiscal-archive-do.test.ts`); it is retained-fiscal, KEEP, like the DO tables `fiscal_documents` / `eta_receipts` already classified `legal-retention`; erasure of the closed DO leaves the archive byte-identical (test `workers-do/fiscal-archive.test.ts`). Second copy: `scripts/ops/pull-cf-backups.mjs` pulls `fiscal-archive/v1/` of `ebda-private` to the Mac (`ROOT/fiscal-archive/v1/`), sha256-checks every data object against its manifest, never overwrites a good local copy with a bad one, alerts P1 on any mismatch or missing object, and is excluded from the 30-day rotation (keep-forever; the local copy is unencrypted like the R2 original, under the user-only Mac backup root, mode 0600). Residuals (accepted): no purge job after `retainUntilMax` (nothing can expire before 2033); a deleted store's list is loaded and paged in memory (fine for one store's documents, revisit past ~100k documents). Cost if wrong: if a DO store is deleted through a path that does not call `StoreService.delete`, its records are still retained in the closed DO but unproducible until `backfill` is run for it.
