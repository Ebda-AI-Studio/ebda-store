Ruling R-TRIAL-ONCE-1 - one signup trial per owner, deleted stores included (money-abuse audit S17, issue #842). A store delete is a HARD delete (StoreService.delete removes the row, and the owner's profile with it when it was the last store), so counting the owner's stores incl. deleted has nothing to count; the trial is recorded when it starts, as a `system_settings` row `ebda.trial-used:<sha256(normalised email)>` (platform-global, survives every store/user delete, hash only). A create by an owner with that marker gets NO trial: `OnboardingService.createStore` provisions it as `starter` with `growthTrial:false` (go-live then needs a paid plan, `goLiveVerdict` PAYMENT_METHOD_REQUIRED), `StoreService.create` skips `startSignupTrial`. The marker is written after the store commits; a failed write is logged and never fails a store that exists. Card-fingerprint check at `card_setup`: NOT implemented, the billing flow keeps only token, last4 and brand (no fingerprint is available; the `connectionFingerprint` in payment-providers is a credential hash, unrelated). Evidence: tests/unit/onboarding-create-store-plan.test.ts, tests/unit/trial-eligibility.test.ts. Erasure/export: the marker is a one-way hash of the email with no profile data, kept on purpose after erasure and a store delete as fraud prevention (docs/RETENTION.md row); it is not part of a data export (nothing about the subject beyond "had a trial"). Plan rule (security review): `isFirst` and `trialEligible` are separate: an owner with no live store gets Growth only when trial-eligible, `starter` (unpaid, go-live needs payment) when the trial is used, and a store beyond the first stays `enterprise` only because `assertOwnerMayCreateStore` admits it solely when the owner's own plan allows more than one store and go-live of a child is decided by its billing parent (`childStoreCoverage`), never its own row. Cost if wrong: a merchant who legitimately erased their account and re-registers with the same email gets no second trial (support can delete the marker row); a different email still gets one.
