# BRIDGE-ACTIVE-1

Ruling BRIDGE-ACTIVE-1 - The WhatsApp bridge returns only ACTIVE, non-deleted products: `getProducts` (`catalogByIds`) now applies the same `status: 'active'` rule as `listCatalog` (`catalogPage`), so a draft or archived product (or a variant of one) is "not there" for Ebda Chat's cart check and its event sync, and is archived from the Meta catalogue instead of being pushed back (it used to flip-flop with the nightly pass). The order path needed no change: `createOrderFromChat` goes through the money engine whose `resolveCartPrices` refuses any non-active or deleted product with the typed `PRODUCT_UNAVAILABLE` (409, nothing written); `placeOrder`'s own lookups stay `deletedAt`-only on purpose so the refusal stays that typed out_of_stock rather than a bare not_found. Evidence: `apps/api/workers-do/wa-bridge.test.ts` "BRIDGE-ACTIVE-1" (real StoreDO: draft, draft-with-variant, archived-with-variant absent from getProducts and listCatalog; an order for a draft is `out_of_stock` / `PRODUCT_UNAVAILABLE`); mutation-checked (dropping the filter turns it red). Found by the independent review of ebda-whatsapp pr 78. Cost if wrong: if a merchant expects a draft product to stay orderable from WhatsApp, it will not be; the cart tells the customer the item is no longer available and the product returns the moment it is set active again.
