# BILLING-NONE-COPY-1

> Section: 2026-11-02 - QA sweep batch 1 (branch `fix/qa-sweep-batch-1`)

Ruling BILLING-NONE-COPY-1 - with `BILLING_PROVIDER=none` (InstaPay only, EBDA-FUNNEL-17) no card is ever charged: `resolveBillingProviderName()` throws, so no provider object exists, and trial end only charges a store with a provider AND a tokenised card (else it downgrades to Free or skips). The merchant Billing page therefore must not say "next charge". `getSubscriptionBillingState` returns `cardBilling` (false when the provider cannot resolve); when it is false, or the store chose InstaPay, the Plan & trial block reads "InstaPay payment due by <date>: <amount> (<interval>) for <plan>" plus "Your plan returns to Free if it is not paid by then" (ar Egyptian + en), and every amount line (card or InstaPay, billing page and onboarding) names the billing interval beside it. Origin: the 2026-11-02 QA sweep showed "next charge 31,410 EGP" for a Growth trial; that is exactly Growth's YEARLY price (9 x 3,490 EGP, plan-limits seed priceYearlyMinor 3141000) on a store that had picked yearly + InstaPay: the number was right, the label and the missing interval were the defect. The onboarding plan note no longer promises a charge on day 15. Evidence: `apps/admin/src/app/stores/[id]/billing/page.test.tsx` (provider none and InstaPay stores never render `trial.nextCharge`/`nextChargeLine`; a card store keeps it with the interval). Cost if wrong: a store paying by card while `cardBilling` is false (provider unset in production) would see a payment-due line instead of an automatic-charge line, which is the safer wording.
