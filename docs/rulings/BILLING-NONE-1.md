Ruling BILLING-NONE-1 - `BILLING_PROVIDER=none` is set as a plain var in `apps/api/wrangler.jsonc` (Track S5, M-032, 2026-10-29): billing is InstaPay-only until Kashier is approved (Rulings EBDA-FUNNEL-17, PAY-INSTAPAY-1). Before, production ran with the variable UNSET, which raised a P1 `Billing: BILLING_PROVIDER is not set` at every boot; `none` is the explicit acknowledgement, and card billing refuses cleanly (`resolveBillingProviderName` throws "Card billing is disabled") exactly as the unset case did, so no behaviour changes except the alert goes away. Evidence: `tests/unit/api-wrangler-billing-provider.test.ts`; `instapay-receipts`, `instapay-manual-payment`, `instapay-routes` integration suites (87 tests with `billing-kashier-provider` unit) green against a real Postgres with `BILLING_PROVIDER=none`. Turning cards on later means changing this var to `kashier` and setting the Kashier secrets. If a Worker SECRET named `BILLING_PROVIDER` already exists on ebda-api, delete it before the deploy (a secret and a var of one name collide). Cost if wrong: if Kashier is approved and this is forgotten, card billing stays refused with a clear error while InstaPay keeps working.
