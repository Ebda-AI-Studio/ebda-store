# PREMIUM-21

> Section: 2026-11-03 - Storefront premium defaults (PREMIUM-\*)

Ruling PREMIUM-21 - PDP buy block: one sold-out state, one WhatsApp row, the saving in words, trust and description get room. a sold-out PDP (no backorder) renders NO sticky bar: the inline disabled button is the one state, the stock text beside the stepper only says "pre-order", the stepper stays disabled; the sticky bar for a buyable product already waits for the inline CTA to leave the reachable area (`useAnchorOffscreen`). `ShareProductRow` drops its WhatsApp pill when `WaMeProductButton` renders (`useHasWaMeProductButton`), so the page has one WhatsApp row. A discounted product shows "You save X (-NN%)" next to the struck price; a selected variant uses ITS OWN compare-at only: `getProductPricing` never lends the parent's compare-at to a variant (stale-data class, its own comment), so a variant without one shows no saving. `TrustLine` is 15px ink with a check mark; the description is its own section (rule, heading, 17px/1.9). "Notify me when back" is NOT built: no back-in-stock subscription exists in the API (only merchant low-stock alerts), and inventing one needs a table, a consent flow and an email. Cost if wrong: a merchant whose variants all share a parent compare-at sees no saving line until the variants carry it.
