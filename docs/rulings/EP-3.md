# EP-3

> Section: Lifecycle emails and referral attribution (2026-10-22, branch `feat/lifecycle-emails`)

Ruling EP-3 (Task 9, 2026-10-22) - a look switch is previewed before it is applied, in the editor, on the merchant's own page. `POST /stores/:id/look/preview` runs the same pure code as the apply (`composeLookDocument`: `applyTemplateFamily` plus the fresh-store readiness drop) and returns the proposed home document, a change report (`diffTemplateFamily`: sections kept, added, dropped from the draft, design fields changed, content fields changed which must be empty, look-owned theme keys reset), and a revision token (`r<head>d<draft>p<published>`); it writes nothing. `PUT /stores/:id/look` accepts that token and answers 409 `DRAFT_MOVED` when the page moved since, before any write; the apply recomputes the document from the CURRENT draft, never from the preview payload. The preview draws the proposed SECTIONS and their design settings in the current skin; it does not draw the new skin's header, cards and buttons or the new theme, and the pane says so (`skinChange`). A look switch does not auto-publish: the result states draft or published as the page already does. Cost if wrong: a merchant who judges the whole look from the preview sees the current skin's chrome; the pane and the report say what is not drawn.
