# BARCODE-7

> Section: 2026-10-16 — Search program, PR 4, Task 13 (quality eval): SEARCH-T13-\*

Ruling BARCODE-7 - the packing slip (`PackingSlipService`, routes `GET /stores/:storeId/orders/:orderId/packing-slip` and `POST /stores/:storeId/orders/packing-slips`, admin viewer `PackingSlipViewer`) prints per order: store logo + name, the order number with the store's barcode shape (same size floor; slip widths 360 px A4 / 320 px 4x6 label, so the label falls back to plain for shapes that cannot meet 2 css px), date, ship-to name/address/phone, one row per physical line (bundle boxes list their components) with thumbnail, name, variant, SKU, quantity and a tick box, the item count, the CUSTOMER's order note, and the optional `settings.packingSlipNote` footer. It prints NO prices, totals or currency, and NOT the internal admin `notes` (they can say anything about the customer). There is no gift-note field in the schema, so "gift note" = the customer's order note + per-line personalisation. Access: `authenticate`, role store_admin/super_admin/staff, `requireStoreAccess`, `requirePermission('orders:read')`; the store is the URL's, queries carry `storeId`, bulk is strict-bodied and capped at 100 (UI blocks >100 too). Mounted before the order router. Cost if wrong: a role that should not print slips gets them (all staff have orders:read today), or a merchant wants prices on the slip (add an option, default off).
