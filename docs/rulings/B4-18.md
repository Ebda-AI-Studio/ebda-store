# B4-18

> Section: 2026-10-22 — Phase B4 Lamma (B4-\*)

Ruling B4-18 (fix wave 1) — a sticky sub-bar is part of the focus offset, and the strip really sticks. (1) `MenuSection` publishes the tab strip's height as `--sticky-extra` and `html { scroll-padding-top }` adds it to `--header-h`, so a Shift+Tab scroll clears header AND strip (2.4.11); one offset source replaces the group's own `scroll-mt`, the scroll-spy now picks the last group above the line, the active tab scrolls into view in the strip, and the strip follows the auto-hiding minimal header instead of floating below a gap. (2) FOUND while writing the Shift+Tab walk: `<html>` and `<body>` both carry `overflow-x: hidden`, which makes `<body>` a scroll container that never scrolls, so EVERY `position: sticky` descendant on the storefront is inert (measured in Chrome 156: the strip, the template headers, the PDP gallery, the cart summary and the filter rail all scroll away). Fixed only where this phase owns it: `html:has([data-part='menu-tabs']), body:has(...) { overflow-x: clip }` (clip keeps the horizontal clipping with no scroll container). The platform-wide change is NOT made here: it would make every sticky element on every template start sticking at once, untested. It is reported to the controller as a platform finding. Evidence: the spec drives Shift+Tab 40 times on the Table home and fails when the old header-only offset is restored (negative control in the same file). Cost if wrong: a page with the strip clips horizontal overflow instead of hiding it, identical to the eye.
