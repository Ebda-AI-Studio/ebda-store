# FP-5

> Section: Admin fix pass 2026-11-04, track T1 API core (branch `feat/admin-fix-t1-api-core`)

Ruling FP-5 - BE:F-2, settings lost-update. `StoreService.update` (settings), `updateFloatingWidget`, `setMcpWriteEnabled` and `setGoldAllowDeferredPayment` no longer merge against the copy `getById` read at the start of the request. On a POSTGRES-authoritative store ONE SQL statement does the write: `settings = coalesce(settings,'{}') || <patch>` (the keys the client sent, server-owned keys stripped) or `jsonb_set` for one key, so the merge is atomic in the database whatever the transaction shape. A `SELECT ... FOR UPDATE` followed by a separate UPDATE was tried first and is WRONG here: the `/stores` router runs under `storeScopeContext` (no request transaction), so each query is its own transaction and the lock is released before the update; `store.service.ts` says so at `readLiveSettings` so nobody reintroduces it. On a D1 + Durable Object store (`storeWritesToDo`) there is no statement across D1 and the DO, so the writer reads the row at write time and writes the merge; two writers inside the same few milliseconds can still interleave there. The client half (pages send only their own keys) is T4. `updateQrSettings` / `updateLabelSettings` keep their raw `jsonb_set`. Evidence: `tests/unit/settings-atomic-keys.test.ts` (the fake applies each statement as one step), `tests/integration/store-settings-atomic.test.ts` (real Postgres, interleaved writers keep both keys). Cost if wrong: on a DO store, one key written in the same few milliseconds as another writer's is lost, instead of every key written during the page's lifetime.

Superseded for Durable Object stores (2026-11-09, admin audit closure): a DO store no longer reads and merges at the service. `StoreService.update` (settings), the per-key setters and the branding bundle send a KEY PATCH to the StoreDO `patchSettings` op (`storePatchOnDo`), which merges only the sent top-level keys against the value the DO holds, inside one DO transaction, so the residual above is gone. Evidence: `packages/repo/test/rpc-settings-patch.test.ts`, `tests/unit/store-settings-patch-on-do.test.ts`.
