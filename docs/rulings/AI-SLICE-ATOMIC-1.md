Ruling AI-SLICE-ATOMIC-1 (2026-11-16, money builder, issue #845) - the per-store daily AI slice is reserved atomically before the model call, on the AuthState Durable Object counter (`redis.incrementRateLimit` = INCR + EXPIRE through the ioredis-shaped `CfRedis`), not in a D1 `UPDATE ... WHERE used < cap` row. `assertAiQuota` takes one slot (`lib/ai-store-reservation.ts`), then refuses when `ai_usage rows today + slots in flight (itself included) > cap`; the counter holds only IN-FLIGHT calls in two 120 s buckets (240 s key TTL), so it needs no seeding and no midnight reset, and the rows stay the source of truth for the day. A refusal gives its slot back at once. Amended 2026-11-16 after money review: `assertAiQuota` returns the slot as a handle and every reserving call site releases it in a `finally` (after the usage row is written on success, at once on failure or retry exhaustion); only a probe that makes NO model call may pass `reserve: false` (queue-depth-watch, an allowlist of one). The per-product generators (`generateProductFaqs`, `generateProductMetaAeo`) reserve and release the slot themselves, so the per-product routes and the bulk sweeps are both covered and the sweeps' outer pre-checks are gone. A second ratchet fails when `reserve: false` appears outside the allowlist or in a file that reaches a model call. `recordUsage` no longer releases anything. A static ratchet in `tests/unit/ai-quota-atomic-slice.test.ts` fails when a reserving call drops its handle or has no `finally` release. The bucket expiry (at most 4 minutes) is only the backstop for an isolate that dies mid-call. The global daily and monthly caps and the bulk interactive reserve are unchanged (still count-based). Why the DO and not D1: the primitive already serves the rate limiters and lockouts, needs no table, migration or per-store D1 hop, and the number only has to be exact for the seconds a model call lasts. Infrastructure failure falls open to the old count-only behaviour, like every limiter here. Evidence: `tests/unit/ai-quota-atomic-slice.test.ts` (20 parallel calls at cap-1 give exactly 1 success; fails on the old code). Cost if wrong: a call that dies with its isolate holds one slot for up to 4 minutes (the store never gains extra AI), and if the counter were unavailable the store is back to the pre-fix race.
