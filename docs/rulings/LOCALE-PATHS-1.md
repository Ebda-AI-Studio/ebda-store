Ruling LOCALE-PATHS-1 - storefront language in the URL (Ahmad 2026-10-26, before launch): a store that opts in serves its public indexable pages at `/ar/...` and `/en/...` (BOTH prefixed, the default language is not special); old URLs redirect (permanent to the store's default language, a temporary one to the cookie language when it differs; issued by the root layout from the store's own `settings.defaultLanguage`, because the middleware has no store; never cached); every prefixed page has a canonical and reciprocal hreflang (x-default = the default language) and the sitemap lists both. Cart, checkout, account, auth, search and file routes are never prefixed. Gate: `STOREFRONT_LOCALE_PATHS=true` + the store named in `STOREFRONT_LOCALE_PATHS_STORES` (store keys only: no language suffix, no `all`, fail-closed, independent of the tenant-routing flags). Every internal link, JSON-LD URL and breadcrumb on a prefixed page carries the prefix through one helper (`StoreLink`, `useStoreUrl`, `localizeJsonLdUrls`). Built dark; rollout through `docs/runbooks/locale-paths-canary.md` on one demo store at a time; `qa-walk-store-1010` is never touched and no store is deleted without Ahmad's word for that store. Evidence: `tests/unit/web-locale-paths.test.ts`; audit M-168. Cost if wrong: a store whose `settings.defaultLanguage` is changed later moves its redirect target and x-default (by design, and Search Console re-learns it); a new component that imports `next/link` directly would cost one redirect per click (the guard test stops it).
