# PERF-AUTHSTATE-2

Ruling PERF-AUTHSTATE-2 - On `GET /public/store/resolve` only, the three limiters run on the Workers Rate Limiting bindings instead of the AuthState Durable Object: the router-level per-IP read bucket (existing `PUBLIC_IP_LIMITER`, 300/min), the route's `storeResolveLimiter` (new `STORE_RESOLVE_LIMITER`, 30/min) and the unknown-store counter (new `STORE_MISS_LIMITER`, 20/min, counted LAZILY on the 404 path instead of a Durable Object read in front of every request). All three key on the forwarded shopper address (`req.ip`, Ruling RL-SSR-IP-6), never the storefront Worker's. Evidence (before, measured 2026-11-17 via the API's own `Server-Timing`): fresh unknown host handler 2.3-4.2 s of which auth-state 6 calls 2.3-4.8 s; known store after expiry 4.1 s of which auth-state 7 calls 4.2 s; no-database path auth-state 3 calls 1.1-1.4 s. After: this PR removes the prefetch batch (hits and the miss peek), the route limiter and the miss peek from the Durable Object path of this route; the one blocking Durable Object call left on a cache fill is the cache-generation read that must precede the fill (reading it in parallel with the fill is NOT safe: an invalidation landing between the data read and a later generation read would let stale data be cached as current, the NEVER-stale class). Semantics that are LOOSER than the limiters replaced, listed as asked: (1) the bindings count per Cloudflare location, so a client spread over several locations at once can exceed 30/min, 300/min or 20/min globally (Ruling PUBLIC-READ-LIMIT-1 residual, now also on this route); (2) the 20-miss limit answers 429 on the request that crosses the line instead of before the lookup, so the lookup behind that one request still ran (a cached negative or one D1 read of about 24 ms); (3) no per-tenant bucket keyed on the host (an attacker-chosen value would only buy fresh buckets; the per-address bucket still bounds). Unchanged on purpose: the exact Durable Object limiters for every write, every auth route, every authenticated or cookie-bearing request and every other public route; a missing or throwing binding falls back to them, never to no limit (a miss counter that throws fails open, as the Durable Object store did under `passOnStoreError`). Cost if wrong: a distributed scraper can probe unknown hosts or resolve faster than the old exact caps across several locations (bounded by the coarse 1200/min per-IP guard in front of Express and by D1 at about 24 ms per miss); removing the three bindings from `wrangler.jsonc` restores the exact limiters with no code change.
