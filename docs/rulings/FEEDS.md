# FEEDS

> Section: 2026-11-14 - product catalogue feeds for Google Merchant Center, Meta Commerce Manager and TikTok Catalog Manager

Plan: `docs/plans/2026-11-14-catalogue-feeds.md`.

Ruling FEEDS-1 - the feeds are gated by a NEW feature key `product_feeds`, in `STARTER_CORE`, so every paid plan has it and `free` does not: exactly the gate of `agent_feed` and `marketing_pixels`. It is a separate key so a `StoreFeature` override of the AI feed cannot switch the ad feeds off (or the reverse). No pricing was invented: this is the existing AI-first / marketing baseline. Cost if wrong: if Ahmad wants ad feeds as a paid add-on, the key moves out of `STARTER_CORE` into an additions array and a store loses the page until it is enabled; no data changes.

Ruling FEEDS-2 - ONE catalogue item id, `catalogueItemId` in `@ebda/shared`: product id for a simple product, VARIANT id for a variant, bundle id for a bundle, product id as `item_group_id` / `product_group`. The feed, the storefront pixel, the CAPI Purchase and Ebda Chat's `retailerId` all call it; `tests/unit/catalogue-item-id-contract.test.ts` pins them. The pixel previously sent the product id for variants and Purchase sent product ids, which cannot match a variant feed. Cost if wrong: renaming the contract later re-keys every merchant's ad catalogue (items look new, learning history is lost); the ids are uuids, so nothing else can drift them.

Ruling FEEDS-3 - TikTok gets its own CSV (`sku_id` column, its availability words); Google and Meta share one RSS 2.0 + `g:` XML (Meta documents the `g:` namespace as supported). TikTok's own page names `sku_id` as the identifier and does not say it accepts `g:` tags, so the safe format is the documented one. Cost if wrong: if TikTok also reads the Google XML, the CSV is redundant but harmless; if a TikTok optional column is rejected the merchant sees a row warning, not a failed feed.

Ruling FEEDS-4 - cache classes. Price, stock and availability are NEVER-stale in the shared cache layer: the cached part sits under `public:products:<storeId>:feedx:`, which `clearProductsRedis` drops on every product, variant, price, stock, category, bundle and order write path; the backorder entitlement is in the key; bundles (windowed) are applied per request. The edge/CDN and the platforms' own copies cannot be purged, so they are BOUNDED-stale at `s-maxage=300` (60 s for gold-rate stores), no stale-while-revalidate, shorter than the shortest platform fetch interval. Checkout re-prices from the database whatever a feed says. Cost if wrong: for up to 5 minutes (1 minute for gold) a platform can show the previous price or stock; Google can disapprove an item whose landing price differs from the feed until its next fetch.

Ruling FEEDS-5 - availability words. Google: `in_stock|out_of_stock|backorder`. Meta documents only `in stock|out of stock`, so a backorder line (buyable now) is `in stock`. TikTok: backorder is `available for order`. `preorder` is never sent: the data has no availability date and Google requires one. Cost if wrong: a backorder item shows as in stock on Meta although it ships late; the storefront still labels the pre-order.

Ruling FEEDS-6 - never guess. `google_product_category` is set only on a whole-word match of the product's own category names against a table whose every id was checked against Google's taxonomy file (or pinned by a `google_product_category` fact); no match = omitted. `gtin` only passes the GS1 checksum, a variant never inherits its parent's barcode; otherwise `mpn` (from an `MPN` fact) or `identifier_exists=no`. `brand` is a `Brand` fact else the store name, flagged in health. `shipping` is sent only when every active delivery rate is identical. Cost if wrong: a missing category or brand lowers ad quality, never validity; a wrong category would be a policy problem, which is why none is guessed.

Ruling FEEDS-7 - parts. A feed file holds 5000 items and ends on a product boundary; `?part=N` selects it; each part is its own source on the platform. Chosen over one unbounded file because a Worker cannot hold or cache (KV 25 MiB value limit) a very large XML. Cost if wrong: a store over 5000 items must add several sources; the admin page says so.

Ruling FEEDS-8 - `link` is the product URL for every variant (the PDP has no variant preselect URL yet). Cost if wrong: a shopper who clicks a red-dress ad lands on the product with no colour preselected.
