Ruling ID-18 (2026-10-25) - integrator client tokens (identity contract v1.3 r2, PR #10 on ebda-whatsapp). Built exactly to r2: `POST /oauth/token` client*credentials with Basic auth is the ONLY mint (no RPC mints, ID-12); aud is bound to the client row and a request with an Origin header is refused; secrets are `ebs*`+ 32 random bytes stored as HMAC-SHA256 with`CLIENT*SECRET_PEPPER`(fast keyed hash is sufficient for 256-bit secrets, missing pepper fails loud with 503); one uniform 401; limits use the existing accounts D1 atomic limiter (ID-7: 60 issues/hour/client, 10 failures/15 min per client+IP prefix, 200 per IP), not a Durable Object, because the table already provides count-first atomic admission; management routes read ownership from the Store directory at request time (STORE_DIRECTORY, there is no D1 membership table to read) and need a second-factor session <= 10 min; rotation overlap 24 h default (0-168 h), a third secret is refused;`Accounts.isRevoked(cli*...)`consults the clients table;`Accounts.deleteStoreClients`runs after the Store delete commits (retried, idempotent); the Store verifier refuses any`client`claim or`integration` role. Cost if wrong: a leaked pepper plus a D1 dump lets an attacker test guessed secrets offline (the secrets are 256-bit random, so guessing is not feasible); a store-delete whose client removal fails leaves dead rows until the hourly sweep removes them (they are already refused).
