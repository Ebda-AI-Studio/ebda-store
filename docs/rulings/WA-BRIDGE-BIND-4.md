# WA-BRIDGE-BIND-4 - buyer proof is secure by default

Ruling WA-BRIDGE-BIND-4 - `WA_BRIDGE_REQUIRE_BUYER_PROOF` is committed as `"1"` in `apps/api/wrangler.jsonc` and the code fails closed when it is unset (`buyerProofRequired`, `apps/api/src/lib/wa/bridge/proof-policy.ts`; only the exact value `0` relaxes). Before this, the flag was read as `=== '1'` and no committed config set it, so production was permissive (fail open) unless an operator had set it by hand. Chat (ebda-whatsapp #67) already sends the proofs, and the buyer-key backfill (WA-BRIDGE-BIND-3) is the prerequisite. Evidence: `tests/unit/wa-bridge/wa-bridge-proof-policy.test.ts` (fails when the wiring or wrangler var is reverted), existing `wa-bridge-bind-all.test.ts` strict cases. Deploy order: Store (this PR) first, then Chat (its fixtures/capability text only). Cost if wrong: an order with no stored `buyer_key` (backfill not run, or no usable phone) answers `not_found` to Chat's COD outcome until keyed; rollback is setting the Worker var to `0` (no redeploy of code needed).
