# CF-OPUS-2

Ruling CF-OPUS-2 (2026-10-30, INFRA-CF-1 Opus review) - A rollback refuses (or needs --accept-data-loss) when any Cloudflare-only table that holds a business fact changed after the flip. `scripts/cf/lib/rollback-coverage.mjs` lists the discardable derived/bookkeeping tables explicitly; every other changed table the replay does not carry (`instapay_order_receipts`, `payment_event_log`, `erasure_ledger`, any unlisted table) is lossy, for the plan walk and for DO runtime tables the old loop never visited (`tests/unit/rollback-cf-only-tables.test.ts`). Replay of `instapay_order_receipts` into `instapay_receipts` is not built: refusing is the safe side. Cost if wrong: an operator must pass --accept-data-loss or forward-fix for a rollback that could have been replayed.
