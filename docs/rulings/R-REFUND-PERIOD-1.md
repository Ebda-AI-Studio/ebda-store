Ruling R-REFUND-PERIOD-1 - a FULL card refund of the charge that paid the current period takes that period back (money-abuse audit S7, issue #840). `refundCharge` now rolls `currentPeriodEnd` back to `currentPeriodStart` the way the InstaPay void in `recordManualRefundInner` already does: status `past_due`, first dunning attempt counted (the retry key differs from the refunded charge's), so normal dunning collects again or downgrades. Only the newest paid charge (checkout / renewal / upgrade) can own the period, a partial refund never changes it, and a super admin sets `keepAccess: true` (admin button "Refund, keep access") for a goodwill refund; the choice is stored on the refund row so an async gateway confirmation applies it identically. Evidence: tests/unit/platform-billing-refund-period.test.ts. Cost if wrong: a mistaken full refund ends a paying merchant's period until they pay again (reversible with the keep-access refund or a manual period edit), whereas the old behaviour gave away a free month per refund.
