# PWA-MANIFEST-1

> Section: Launch follow-up 2026-11-10 (branch `fix/public-normal-browsing-404s`): the per-store PWA manifest never applied

Ruling PWA-MANIFEST-1 - the storefront reads the per-store PWA manifest from the route that exists (`GET /stores/public/<storeId>/manifest.json`), accepts it only when it passes `storePwaManifestSchema` (`@ebda/shared`) and answers within 3 seconds, and otherwise serves its own generic manifest; the API names no icon when the merchant uploaded none. Measured in production 2026-11-10 before the fix: the storefront asked `GET /public/<storeId>/manifest.json`, which is no route (404 `Cannot GET`, one store-miss per render), so every store has been served the generic manifest since the feature shipped; the real route answered 200 for all five demo stores (Qamar, Dahab, Jasmine, Lamma, Souq) with `start_url` and `scope` `/`, hex colours, a non-empty `name` and `short_name`, and two icons `/icons/icon-192x192.png` and `/icons/icon-512x512.png` that no app ships (404 on the storefront; `/icon-192.png` and `/icon-512.png` answer 200 `image/png`). Not cached at the edge: the API route sends no `Cache-Control` and the storefront manifest is `public, max-age=0, must-revalidate`; the storefront's own fetch is held in the Next data cache for 300 seconds under the tag `pwa:<storeId>`, which a PWA settings write clears. Either deploy order is safe: the new storefront against the old API refuses the relative icons and serves the generic manifest (today's behaviour), and the old storefront against the new API still asks the wrong path. Evidence: `apps/web/src/app/manifest.test.ts` (generic manifest on a rejected fetch, a hung fetch, a non-JSON body and 14 invalid manifests), `tests/unit/pwa-manifest-generation.test.ts` (no icon named when none is set).

Accepted residual, a visible change once both sides are deployed: a store whose merchant never opened the PWA settings is served the API's defaults instead of the storefront's generic values. For Qamar: `theme_color` `#141414` (the store theme) becomes `#0A0B0C` (the PWA default), the description becomes "تسوق في قمر" / "Shop at Qamar" in place of the store's own description, and `scope: "/"` is added; name, start URL, display, background and icons are the same. The alternative is for the API to emit only the values a merchant authored (about 25 more lines in `PWAService.generateManifest`), so that an un-authored store keeps exactly today's manifest.

Cost if wrong: an installed storefront app of a store without PWA settings shows a near-black browser bar and a generic description instead of the store's theme colour and its own description, until the merchant saves PWA settings or the API stops emitting defaults.
