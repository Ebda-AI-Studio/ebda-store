Ruling CI-5 (Store session, 2026-10-25) - the R2 sink writes the buyer index BEFORE the partition (compare-and-set on the index etag): an index entry for a partition that never landed is skipped by erasure, the reverse would leave an unerasable row. Partition files are named from the sorted event ids of the batch and created with `etagDoesNotMatch: '*'`, so a retry of the same group is idempotent. Cost if wrong: stale index entries (harmless, skipped), never an unindexed row.
