Ruling ITEST-4 (2026-10-27) - `ALTER ROLE ebda_app` in the integration suites goes through `tests/helpers/app-role-login.ts` (`setAppRoleLogin`), which retries only `tuple concurrently updated`. Roles are cluster-global, so two runs on one Postgres (several agents share the local PG17) collide on the role row (measured: 3 writers x 150 ALTERs gave 70 errors) and the loser's `beforeAll` fails, skipping every test in the file. The single failed run that prompted this (page-builder.test.ts, 47 tests skipped, right after `migrate deploy`) did not reproduce on a fresh database in 2 runs, nor in 3 runs under a 4-writer ALTER storm against the old code, so the collision is the likely but UNPROVEN cause of that run; the error text was not kept. All 16 integration files use it, and `tests/unit/no-bare-alter-role-in-integration.test.ts` fails on any bare `ALTER ROLE ebda_app` under `tests/integration` (self-tested on good and bad snippets). Cost if wrong: a flaky first run on a shared cluster, never a CI failure (CI has one cluster per job).
