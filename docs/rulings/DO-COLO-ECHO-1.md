# DO-COLO-ECHO-1

Ruling DO-COLO-ECHO-1 - The placement echo (`GET /admin/do-colo`, PERF-AUTHSTATE-1) is switched on only for a short, recorded investigation window and off again straight after. Mechanism (the repo's own pattern for plain vars, no secret): the repo variable `DO_COLO_ECHO` feeds `wrangler deploy --var DO_COLO_ECHO:<value>` in `cf-api-deploy.yml` (`off` when the variable is unset), exactly as `EBDA_SERVICE_LINES` does for the status Worker. Procedure: (1) set the repo variable to `on` and dispatch the API deploy, record the time in PR #936; (2) the controller calls the route from the logged-in super-admin browser session (no agent handles credentials); (3) delete the variable, dispatch the API deploy again, confirm the route answers 404, record the time. The route answers location codes and round-trip times only. Cost if wrong: while the flag is on the route wakes up to 37 Durable Objects per call for a super_admin with MFA, a few hundred milliseconds of work each; a forgotten flag is a diagnostic route left reachable by super admins only, so step (3) is the deploy to check.
