# CHAT-RECS-1 - Chat agent product recommendations ride the Store's own engine

Ruling CHAT-RECS-1 - `WhatsAppBridge.getRecommendations` reuses `recommendationService.getProductRecommendations` (Store #742: curated, AI picks, bought-together, vector neighbours, same category, merchant's automatic switch) and never forks it. The engine list is cached (BOUNDED-stale, 5 min), so the port takes only ids and order from it and re-reads every candidate from THIS store: `storeId` + `status: active` + `deletedAt: null` + `audience: public` + in stock (one cheapest in-stock variant per product), priced by the store row. Tenant is the bridge `storeId` (a resolved, linked store); seeds resolve inside that store only. After-order seeds come from the buyer's own order (number AND buyer key, same proof as `getOrderStatus`). Evidence: `tests/unit/wa-bridge/wa-bridge-do-port-recommend.test.ts`, `wa-bridge-recommendations.test.ts`, vector `bridge-recs-v1.json`. Cost if wrong: a stale cached id could surface a just-unpublished product for one request, but the re-read drops it, so the worst case is a missing card, not a wrong price or another store's product.
