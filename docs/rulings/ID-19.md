Ruling ID-19 (2026-10-26) - store membership for Ebda Chat (contract v1.4, WA-PRICE-1a). (a) Membership lives in the STORE (Store.ownerId + StoreStaff); accounts D1 has no membership table (the stores[] claim is computed from the Store directory at token time), so the read is a Store-worker RPC, not an Accounts RPC. (b) `WhatsAppBridge.listStoreMembers(storeId, asUserId) -> { items: [{ userId, displayName, role, addedAt }] }`: wired only in ebda-whatsapp's service binding, authorised by the calling user against LIVE membership (only the store's owner; FORBIDDEN otherwise, nothing read), active staff only, no e-mail or phone, throws (503 on the caller) when it cannot read. (c) Revocation: ebda-whatsapp re-checks `WhatsAppBridge.memberRole(storeId, userId)` on each staff request (NEVER-stale class: no cache, fail closed on error); no event queue, because removal must bite at the next request and a re-check is stateless. Cost if wrong: one extra indexed read per staff request; an event queue would add a failure mode (a lost event leaves access open).
