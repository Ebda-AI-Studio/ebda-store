# PRISMA-NULL-RPC-1

Ruling PRISMA-NULL-RPC-1 - Prisma's null sentinels (`Prisma.DbNull`, `JsonNull`, `AnyNull`) cross the StoreDO RPC as the tag `{ $t: 'pnull', v: '<name>' }`: the DO client (`packages/repo/src/rpc/client.ts`) tags them before the structured-clone `query`/`mutate` calls, the StoreDO revives them before prisma-lite, and the JSON codec (`encodeRpc`/`decodeRpc`, stock/money/settings RPCs) does the same instead of silently writing `{}`. Fixed once at the transport, not per call site (9 sentinel writes in `apps/api/src`). Evidence: production 2026-11-10 22:04:14Z `PUT /api/v1/stores/1bb14d0e.../products/e5ee7974...` 500 x2 `DataCloneError: Could not serialize object of type "QPe"`, where `QPe` is the bundle's `DbNull` class (`xDe(QPe,"DbNull")` in `dist-cf/worker.js`); the edit page sends `personalisation: null` on every save, which `ProductService` turns into `Prisma.DbNull`. The journey's edit-page PUT reproduces the same error on main and answers 200 after; `tests/unit/rpc-prisma-null.test.ts` pins the round trip. Cost if wrong: a Json column VALUE that is exactly `{ "$t": "pnull", "v": "DbNull" }` written through a structured-clone write would be read as the sentinel (SQL NULL); no Ebda field stores that shape.
