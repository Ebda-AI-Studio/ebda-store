Ruling P08-2 - Opus review of P08-1. (a) The auto-cancel sweep cancels an order only under the order row lock and after re-reading its paymentStatus (`paid`/`refunded` are never cancelled): `confirmed -> cancelled` is an allowed transition, so a webhook that paid the order after the provider answered "expired" used to be cancelled with the customer charged. (b) The webhook's payment write is guarded for every status: a late `pending`/`processing` or a replayed `completed` never moves a completed / refunded / partially_refunded / disputed payment off its state (`paymentStatusesNotOverwrittenBy`). (c) An order the merchant already moved to processing / shipped / delivered is marked PAID without touching its fulfilment status (webhook and pull-side), instead of failing `assertValidTransition(processing -> confirmed)` for ever with the money taken; only cancelled / refunded are refused. (d) When the claim is blocked because the order went terminal between the status read and the claim, both paths raise INVALID_STATUS_TRANSITION (the sweep turns it into its durable "captured money on a terminal order" trace and P1) instead of returning quietly. (e) Lock order is payment row, then order row, the same as the refund paths. (f) The real-Postgres test now runs the confirm inside `runInTenantContext` like a request.
