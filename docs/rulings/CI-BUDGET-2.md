# CI-BUDGET-2

> Section: 2026-11-02 - hosted-minutes budget (branch `ci/deploy-only-when-app-changed`)

Ruling CI-BUDGET-2 - a push to main starts a real deploy only for the apps whose deployable output can have changed. Editing shared files (`scripts/cf-build.sh`, a `cf-*-deploy.yml`, `package-lock.json`) used to start every deploy workflow whose `paths:` list named the file, and a controller watcher had to cancel them by hand while hosted minutes burned. Each `cf-<app>-deploy.yml` keeps its `paths:` trigger and gains a first `plan` job (a few seconds, no build) that runs `scripts/ci/deploy-plan.mjs` on the pushed range; the `deploy` job `needs: [plan]` and runs only when it answers `true`. The workflow's own `paths:` list stays the single source of what the app is built from; the plan only refines it: a file under `.github/` never deploys (a deploy workflow edit is config-only); `scripts/ci/deploy-guard.mjs` and `scripts/ci/workerd-smoke.*` are the deploy's own checks, not bundle inputs; `package-lock.json` deploys an app only when a lock entry inside that app's dependency closure (workspace links followed) changed; any other matching file deploys it. `workflow_dispatch` and `[force-deploy]` in the head commit message always deploy; a new branch, an unreachable base commit or an unreadable lockfile diff fails OPEN (deploys). A skipped deploy writes `SKIP <app>: <reason>` to the job summary. deploy-guard, the probes and the rollback are untouched. Evidence: `tests/unit/deploy-plan.test.ts` (workflow-only edit deploys nothing, an app edit deploys that app, a shared package edit deploys only the apps built from it, a shared script only the apps whose build runs it, lockfile closure, every workflow gated). Cost if wrong: a file that changes an app's bundle but is not in its `paths:` list is not deployed (it was not before either; add it to the list); a lockfile change that reaches an app through a dependency the lock does not record (an undeclared import) is missed until the next code change or a manual dispatch; the plan job adds a few hosted seconds to every push-to-main run.
