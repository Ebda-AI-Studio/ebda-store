# NAME-PAIR-2

Ruling NAME-PAIR-2 (2026-11-11, follow-up to NAME-PAIR-1) - the one-time product-name repair (`POST /admin/stores/:id/repair-product-names`) applies ONLY the product ids the operator passes after reading the dry run (`{ "apply": true, "productIds": [...] }`; apply without ids is a 400), and never overwrites an English name the merchant typed: a `name` in Latin script stamped `human` in `aiFieldSources` is left as it is, and only an EMPTY Arabic name may still be filled next to it (a placeholder pair whose Arabic is already filled is skipped as `merchant-english`); in a swapped pair the English that moves into `name` keeps the merchant's `human` stamp when the merchant typed it into the Arabic field. The report lists `applied` and `skipped` (with the reason) and the audit row records both. Evidence: `tests/unit/product-name-repair-apply.test.ts` (on the old code apply wrote every scanned row, including a merchant-typed English name). Cost if wrong: an operator must pass the ids explicitly, so a repair is a two-step action (dry run, then apply the chosen ids); no merchant-typed English name can be lost to it.
