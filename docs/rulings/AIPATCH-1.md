Ruling AIPATCH-1 (builder Phase 5, 2026-10-26) - AI page edits are a closed set of 7 structured ops (`packages/shared/src/builder/ai-patch.ts`) that reuse the editor's own reducer, not a JSON-Patch over the document. Reason: the reducer already enforces every registry invariant (cardinality, pinned sections, group/page placement) and a closed op set cannot name a path outside `sections`. The model gets section ids, declared setting keys and current scalar values only (a page document holds no buyer data); the merchant's text is a JSON string field the system prompt declares to be data. Every value must fit the declared control (range/select/colour/text without angle brackets); media, links and catalogue references are never set by the model. Propose (`POST /stores/:id/ai/builder-patch`, store scope, platform AI quota + per-store budget, feature `builder-patch` in ai_usage) saves nothing; apply puts the returned candidate into the editor's own undo history and saves it as a DRAFT through the normal autosave (`saveDraft`: rev-checked, fully validated, one Undo step, never published); there is no separate apply endpoint. Cost if wrong: a too-narrow op set makes some requests answer "could not turn that into a change"; widening it is one schema line plus a value-fit rule.
