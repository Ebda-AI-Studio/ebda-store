# SUBDOMAIN-SOON-2

Ruling SUBDOMAIN-SOON-2 - every coming-soon software product gets a `<label>.ebda.app` coming-soon page: crm, erp, invite, ads, quote, all from ONE template where only the copy differs (Ahmad via the coordinator, 2026-11-10). crm and erp already had theirs (#283, unchanged). New: `invite.ebda.app` (Ebda Invite), `ads.ebda.app` (Ebda Ads), `quote.ebda.app` and `quote-studio.ebda.app` (Ebda Quote Studio). Template (`renderStudioPage`, kind coming-soon with a product): wordmark header linking ebda.app; then in <main> the product name (h1), its one line (`p.lead`, the BRAND short line), the «قريبًا» / "Coming soon" label (`p.badge`), the actions (`a.cta` "notify me" to `https://ebda.app/contact/?topic=products#form`, `/en/contact/…` in English; `a.home` back to ebda.app), then the site map (live, help, coming soon) and the footer language switch. Arabic by default (Accept-Language or `?lang=en` for English). The `<title>` keeps the sentence form («ابدأ CRM جاي قريب.»). Every name and line comes from `BRAND.comingProducts`; `ComingSoonProduct` is now that list's ids plus `reserved`. crm and erp were upgraded to the same template (before: a sentence heading, a search box and the map; the search box stays on the 404 and the reserved page, hub and id unchanged). How: `invite`, `ads`, `quote`, `quote-studio` and `chat` join `STORE_EXTRA_RESERVED_SLUGS` (`packages/shared/src/hosts/reserved-slugs.ts`; the vendored foundation list stays untouched), so `parseStoreHost` calls them invalid and the storefront Worker's `unservedHostResponse` renders the studio page instead of looking up a store; `packages/shared/src/studio-pages` gains `invite` / `quote` in `ComingSoonProduct`, `COMING_SOON_LABELS`, the coming-soon lines and the site map's "next" list. All five home cards link to their pages (COMING-SOON-CRM-ERP-1). `chat` 301s to wa.ebda.app like `whatsapp` (WHATSAPP-HOST-REDIRECT-1). Evidence before (measured 2026-11-10): `quote.ebda.app` answered 404 "Page not found — Ebda Store" (`x-store-domain: quote.ebda.app`); `invite.ebda.app` answered 500 on three of four requests (one 404), also with `x-store-domain: invite.ebda.app`; `ads.ebda.app` answered the English store not-found page; the public API reports `STORE_NOT_FOUND` for invite and quote, and a read-only D1 SELECT on `ebda-platform` found 0 of 7 stores with slug invite, ads, quote, quote-studio or chat. After: neither host reaches the store lookup (`x-store-domain` absent), so the 500 path is no longer reachable from these hosts; its root cause in the store-not-found path is not fixed here (diagnosed separately). Tests: `tests/unit/studio-coming-soon-pages.test.ts` (every coming-soon label renders the SAME <main> element list in ar and en, with the BRAND name, line, label, CTA and home link, so a sixth label cannot drift; every BRAND.comingProducts id, `quote`, store, wa, whatsapp, chat, every service-line id and every studio label parses as platform or invalid, never a store), `tests/unit/web-cross-tenant-cache.test.ts` (all five hosts are 200 coming-soon pages in ar and en, never a store; chat and whatsapp 301 with the path kept), `tests/unit/store-host-resolver.test.ts` (never reach the database), `packages/shared/src/__tests__/hosts.test.ts` and `tests/unit/brand.test.ts` (reserved). Cost if wrong: a label someone wanted for a store slug is taken (low; D1 has no store on any of them, and the reserved-slug list is a one-line revert).
