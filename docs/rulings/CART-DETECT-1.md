# CART-DETECT-1

> Section: 2026-10-16 — Search program, PR 4, Task 13 (quality eval): SEARCH-T13-\*

Ruling CART-DETECT-1 (2026-10-21, review item 4) - abandoned-cart detection asks the EFFECTIVE entitlement, for push, SMS and email alike. `detectNewAbandonments` and the WhatsApp detection listed stores by "has an enabled `store_features` row for `abandoned_cart`". Every plan has `abandoned_cart` in STARTER_CORE and the plans engine sets the flag, so a store entitled by its plan has NO row and was never swept: no `abandoned_carts` row, so no push, SMS or email for it. They now list stores through `storeDirectory` (the RLS definer) and keep those where `featureService.isFeatureEnabled(id, 'abandoned_cart')` is true (baseline OR row, an override row still wins both ways); the WhatsApp path needs `whatsapp` the same way. Evidence: `tests/unit/abandoned-cart-detection-entitlement.test.ts` (baseline-only store swept, no-entitlement store skipped; red before), `cron-tenant-scopes.test.ts` updated. Residuals: the feature map is cached 5 min per store (BOUNDED-stale, so a plan change takes up to 5 min to start or stop detection); one feature-map read per store per 15-min sweep (Redis-cached). Cost if wrong: on first run after deploy every plan-entitled store starts producing abandoned-cart rows, so push/SMS reminders begin for stores that never had them (consent is still enforced per channel; email stays off until the merchant enables it). Integration proof is pending the DB slot.
