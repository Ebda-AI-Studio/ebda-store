# COD-RECEIPT-NUMBER-AT-PAYMENT-1

Ruling COD-RECEIPT-NUMBER-AT-PAYMENT-1 (Ahmad, 2026-11-20, on STORE-QA-125 / STORE-QA-67; extends COD-RECEIPT-LABEL-1). A sales receipt means money was received, so an UNPAID cash-on-delivery order gets no receipt number at placement: its order number (ORD-...) is its order confirmation, and the gapless `RCT-` serial is allocated when the cash is collected (the order is marked paid, bulk-marked paid, or delivered), once, idempotently (`issueSaleDocument` returns the existing document on a replay). No serial is reserved at placement, so an unpaid COD order that is cancelled leaves no gap and no cancelled-receipt row. A TAX INVOICE (verified VAT seller) is a tax document, not proof of payment, and still issues at placement. One rule, both backends: Postgres `FiscalDocumentService.issueSaleDocument` (placement passes `cod`, the settle paths `cod + paid`) and the Durable Object `issueSaleDocument` (defers on a first `cod` payment that is not paid; `codMarkPaidOp` and the delivered transition call it after settling). Printed documents of an order with no sale document and no payment read "Order confirmation"; legacy unpaid COD receipts still print as one (COD-RECEIPT-LABEL-1). Evidence: packages/repo/test/do-fiscal.test.ts (5 new cases, 2 mutations red), tests/integration/fiscal-documents.test.ts (11 green on a migrated local DB: no document and no serial at placement, one RCT serial at collection, replay issues nothing, delivered allocates it, cancelled never-paid COD has none, store-closure archive). NOT verified: tests/integration/repo-factory-orders-contract.test.ts (its 4 fiscal parity tests assume a receipt at COD placement and need the settle step; that harness did not run locally, "Unknown transaction status"); live. Residual: a merchant who paid a COD order by a path that does not go through these three settle points (none found; payment webhooks are online-only) would have no receipt until it is marked paid. Cost if wrong: a collected COD order missing its receipt number until the next settle call (the documents page then shows none for it).
