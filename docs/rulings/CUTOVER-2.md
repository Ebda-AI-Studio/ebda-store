Ruling CUTOVER-2 (2026-10-25) - migration tooling design (INFRA-CF-1 phase 4). (a) The source is only ever read: three independent locks (session `default_transaction_read_only`, `BEGIN ... READ ONLY`, post-connect assertion) and a Neon host needs `--allow-prod-read`. (b) A table is "equal" only when row count AND a sha256 over every migrated column match on both sides (`canon.mjs`), plus independent Postgres-side aggregates for Decimal, date, boolean and list columns, plus `PRAGMA foreign_key_check`; id|updated_at alone cannot see a transform bug in another column. (c) `__import` runs with foreign keys OFF per page (the categories tree and similar cycles cannot be paged in dependency order) and the foreign-key check is done once at verify time. (d) The import raises `do_flags.gold_reprice` inside its own transaction for `products` and `product_variants`, exactly as the repricer does, because the Ruling B5-13 triggers would otherwise reject every gold-rate row; the flag is cleared before the transaction ends. (e) `addresses` and `onesignal_subscriptions` hang off a user in Postgres, not a store: a row belongs to a store when its user is a customer, staff member or owner there; rows matching no store are reported UNPLACED, never silently dropped. (f) Analytics-class tables (`ai_usage`, `product_daily_views`, `search_query_daily`, `product_embeddings`, ...) are not imported anywhere; `--archive-dir` keeps them as NDJSON and embeddings are rebuilt from Product. (g) Postgres columns the new schema drops must be empty or listed in `RULED_DROPPED_COLUMNS` (the legacy WBS bridge, #220/#223); anything else with data stops the run. (h) After the flag flip `__seal` closes `__import` for good, so a re-run can never overwrite a write the DO accepted. Cost if wrong: (c) a corrupt foreign key would be caught only at verify, so verify must never be skipped; (g) a column ruled as dead that is not would lose data silently, so the list is reviewed against the dump before every run.
