Ruling WEBHOOK-ORDER-1 (2026-10-27) - payment webhooks authenticate FIRST. A missing or bad signature gets ONE constant 401 body before any lookup (no audit row, padded to a 150 ms floor, one per-source rate-limit bucket). On the per-store URL the signature is verified with that store's secret before the payment is looked up; a valid signature for a payment that does not resolve to THAT store, whether unknown or another store's reference, gets the identical `503 PAYMENT_NOT_YET_VISIBLE` + `Retry-After: 60` (M-050; no cross-store existence oracle); a valid signature for one of its own payments proceeds (200). The generic URL names no store, so an unresolvable reference there gets the constant 401. Evidence: `tests/unit/inbound-payment-webhook-routes.test.ts` (known vs unknown bad signature byte-identical; signature checked before lookup; valid + unknown = 503; store-A signature with a store-B ref byte-identical to unknown; valid + known = 200); detail in `docs/security/sec-hardening-2-webhooks.md`. Cost if wrong: a gateway on the generic URL whose callback beats the Payment row gets 401 and retries like any refusal instead of the 503 hint.
