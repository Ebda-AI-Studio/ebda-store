# LAZY-TX-3

> Section: Admin fix pass 2026-11-04, track T1 API core (branch `feat/admin-fix-t1-api-core`)

Ruling LAZY-TX-3 - BE:E-1, the admin stall. Express runs `router.param('storeId', tenantContext)` before the route's own `authenticate`, so every store-scoped admin request leased a pooled client and opened a 30 s interactive transaction first, then held it across the two identity RPCs (the pool is 6 per isolate; a 6-request dashboard burst could starve itself). `tenantContext` now (1) sends an anonymous GET/HEAD (no Authorization, no Cookie) under `/stores/<uuid>/...` (the admin namespace; the public storefront under `/public` keeps its one-transaction read, LAZY-TX-1/2) to the per-query store scope (`storeScopeContext`: no lease held; a public handler's queries each run in a short tenant transaction); writes keep the transaction for atomicity; (2) for an identity-service bearer token runs the live check FIRST (revocation + account state, 3 s budget each, account state shared and cached per FP-4), keeps the answers in a per-request memo, then opens the transaction, so `authenticate` inside it repeats nothing and no pooled client is held across an RPC; a failed pre-check is ignored there (the route's `authenticate` still owns the 401/403/503 and optional-auth routes keep their guest path). Server-Timing now carries `auth`, `identity`, `db-wait` and `handler` next to `request-tx`. The 33.5 s TTFB itself was a one-off and remains INFERRED; settle it by replaying 6 parallel dashboard requests before and after. Evidence: `tests/unit/tenant-lazy-begin.test.ts`. Cost if wrong: an anonymous public GET under a `/stores/:storeId` router loses the single-snapshot read of one transaction (each query is consistent on its own).
