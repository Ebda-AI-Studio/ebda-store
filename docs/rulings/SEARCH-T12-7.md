# SEARCH-T12-7

> Section: 2026-10-16 — Search program, PR 4 (P1c, hybrid ranking): SEARCH-T12-\*

Ruling SEARCH-T12-7 (coordinator security review: cache poisoning on `/public/products`) — a cached or shared copy of a storefront list is only ever served for a request with the same inputs. Verified first: the 120 s list cache was already keyed by `storeId` (no cross-tenant entry), and the payload does not vary by locale (it carries `name` and `nameAr`; the route reads no locale), so locale is deliberately NOT a key part. Confirmed and fixed: (1) a keyword-only fallback (vector leg wanted but unavailable: no searcher, a budget or the searcher's limit, race lost, provider or SQL failure) was cached for 120 s under the healthy key. The ranked path now reports `meta.degraded: true` (only then) and the route passes `getCached(…, { cacheIf })` (new option, `apps/api/src/lib/public-cache.ts`) so a degraded list is stored in NO layer, while a cached query vector or a by-design skip is a full answer. (2) The semantic mode was not in the key, so a flag flip served the other mode's lists for up to 120 s; it is now part of it. (3) Pre-existing, found by this review and fixed with it: the key joined raw values with `:`, `;`, `=` and `,`, so a value could borrow a delimiter (`?category=X:shoes&search=hat` and `?category=X&search=shoes:hat` built one key, as did `opt_Size=S;Color=Red` and `opt_Size=S&opt_Color=Red`): one URL could fill another's entry with wrong results. The key is now `public:products:<storeId>:` + `JSON.stringify` of exactly the options the service receives (ids sorted, parsed numbers) + the mode, so no value can collide with another; the `public:products:<storeId>:` prefix every product write busts is unchanged. Same class in typeahead: `public:suggest:<store>:<term.toLowerCase()>` folded non-ASCII letters the search does not fold (É vs é, Ruling SEARCH-2) so two different result sets shared one entry; it is now keyed by `normalizeArabicSearch(term)`, exactly what the suggestions are computed from. Other `getCached` keys were swept: PDP (`public:product:<store>:<slug|id>`), bundles (`public:products:<store>:bundles:v2:<slug>`), feed, categories, store and host resolve each embed a single value, so no delimiter can be borrowed. (4) HTTP: a hybrid-ranked response (`meta.ranked`) is sent `Cache-Control: private, no-store` (its content depends on the mode and on the provider's health at that moment, which no edge key sees); every other list keeps `public, s-maxage=60, stale-while-revalidate=300` with `Vary: x-store-id, x-store-domain`, so the flag-off response headers are unchanged. CACHE CLASS at the site: BOUNDED-stale 120 s, busted by `invalidateStoreProductCaches` on every product write. Evidence: `tests/integration/hybrid-search-cache.test.ts` (real Redis, real router, `ebda_app`): same query on two stores with the flag off and on; `accept-language: ar` vs `en` give identical payloads carrying both languages; budget exhausted → `degraded`, `private, no-store`, then the SAME URL returns the semantic hit once the budget is back; the two delimiter pairs; repeated/array `search` params; a flag flip off → on → off; the typeahead É/é pair (red before the fix); the flag-off edge header. Each guard was deleted in turn and a test went red (delimiter-joined key, `cacheIf` removed, ranked responses edge-cached, mode left out of the key). **Amended (Task 12 review M7):** a list key over `CACHE_KEY_MAX_BYTES` (400, leaving room for KV's `cache:` and namespace prefix under its 512-byte limit) is hashed: `public:products:<storeId>:sha256:<sha-256 of the canonical JSON>` (`boundedCacheKey`, `public-cache.ts`), so a 100-character Arabic term with option filters is cached instead of silently skipping KV, and a product write still busts it through the unchanged prefix (`hybrid-search-cache.test.ts` "a long request still caches": an 810-byte key before; `tests/unit/bounded-cache-key.test.ts`). Cost if wrong: a degraded result is recomputed on every request while the provider is down (no cache shield), which only costs database time on the already keyword-only path.
