# BUNDLE-BUDGET-7

Ruling BUNDLE-BUDGET-7 (2026-10-30, integration of all open Ebda Store PRs) - the API Worker bundle ceilings in `scripts/ci/worker-startup-budget.json` go from 7,800,000 B raw / 2,200,000 B gzip to 8,400,000 B / 2,350,000 B. Measured on the integrated tree (#366 + #300 + #327 + #365 + #324 + #328 + #325 + the 14 feature and fix PRs): `worker.js` 8,149,392 B (gzip 2,280,474 B), startup CPU 130 to 198 ms on a loaded host (the absolute 140 ms ceiling is enforced on quiet main/nightly runs; PRs use the relative gate), against 7,430,377 B on the stack before the features (BUNDLE-BUDGET-6). The +719 KB is feature code, not drift: `@cantoo/pdf-lib` for the catalogue import (449 KB after the CATIMP-4 stub of culori, html-entities and node-html-better-parser), the Customer Intelligence and catalogue-import job functions, the extra cf-schema tables (127 store tables) and the wallet GL.

Trimmed already and kept: exceljs bare build (BUNDLE-BUDGET-6), slim Prisma schema, slim mime-db, the three pdf-lib dependency stubs. Candidates not taken, with sizes from the esbuild metafile: zod v4 locales 259 KB (all 64 locales stay because the MCP SDK imports `zod/v4` as a namespace; needs a patched zod entry), pdf-lib standard font metrics about 150 KB (never used, imported by relative path so an alias cannot reach them), `prisma-meta.json` 266 KB (touches every prisma-lite consumer). Each is a separate change with its own test; the ceiling keeps 250 KB of room meanwhile.

Cost if wrong: a Worker over the platform limit fails the deploy loudly (`npm run -w apps/api cf:dry-run`); the Workers Paid limit is 10 MB (gzip) and this bundle is 2.28 MB gzip, so there is no platform risk, only less headroom for the next feature.
