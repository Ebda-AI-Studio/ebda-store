# INV-AUDIT-3

> Section: 2026-11-14 inventory audit P1-3 (branch `fix/inventory-p1-audit`)

Ruling INV-AUDIT-3 - every stock-quantity change on the StoreDO writes an `inventory_history` row with a reason and an actor, in the same section as the change: the variant stock grid (`setVariantInventory`), `setWarehouseStock` (same shape as `adjustWarehouseStock`: warehouse-row before/after, reference = warehouse id; `adjustWarehouseStock` now carries its actor too, P2-4 in part), the product bulk edit and opening stock (`bulkSetInventory`, opening stock is type `initial`), the CSV import (create, UPDATE carrying `inventory`, variant opening stock, and the units a variant replace takes away), and gold-rate variant creation. A write that changes nothing writes no row. The actor is the caller's `userId`, else the request's ambient scope user (`withActor` in `repo-factory.ts`); a cron/job has none and its rows carry no actor. A guard test (`packages/repo/test/stock-movement-guard.test.ts`) parses `packages/repo/src/do/*.ts` with the TypeScript compiler, DISCOVERS every function that writes a stock column or calls a stock primitive, and fails when one lacks a movement-row write and is not in its short reasoned exemption list (it found `createGoldVariant`, which nothing had listed; a stale exemption fails too). Evidence: new tests in `do-stock-ops.test.ts`, `do-stock-books.test.ts`, `do-catalog-import-history.test.ts`, `tests/unit/stock-client-actor.test.ts`, all red before the fix; workerd DO suites `import/stock/books/orders/jobs-money` green. Residual: the Postgres fallback paths for stores not on a DO (`VariantService.bulkUpdateInventory`, `ProductService.updateInventory`/`bulkUpdate`, `WarehouseService.setStock`, the PG import tx) still write no history row; no live store uses them (Ebda stores are on DOs) and the guard covers only the DO layer. No GL entry is added here (valuation journals are a separate decision, P2-9). Cost if wrong: a stock change reached only through a PG fallback has no ledger row, as before; every DO change is now explainable.
