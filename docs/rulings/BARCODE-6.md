# BARCODE-6

> Section: 2026-10-16 — Search program, PR 4, Task 13 (quality eval): SEARCH-T13-\*

Ruling BARCODE-6 - email barcodes are PNGs rendered on the Worker WITHOUT an SVG engine: resvg-wasm (~2.4 MB wasm) was rejected for the API Worker (13.5 MB raw / 2.86 MB gzip already); bars are rectangles, so a ~150-line rasteriser + hand-rolled PNG writer (`apps/api/src/lib/barcode-png`) draws them, and each shape's silhouette is pre-rendered once to a 1-bit 720px mask (`shape-masks.generated.ts`, 94 KB / 69 KB gzip, `scripts/gen-barcode-masks.mjs`). No new dependency. Measured in node: plain 0.5 ms, shapes 9-15 ms, 0.7-5.6 KB per PNG; plain is 616 px wide, shapes 720. Rendered post-commit inside the existing Inngest email fanout (`sendOrderConfirmation`, billing `payment_confirmed`), stored at `stores/<storeId>/barcodes/<hmac>.png` (keyed HMAC of store/kind/number/shape, no number or PII in key or pixels), absolute https `<img>` with width/height and alt "رقم الطلب N"; any failure, timeout (8 s) or `off` sends the email with the number as text only. Registry: no DB column holds these URLs, so `R2_DERIVED_*` in `lib/r2-references.ts` marks them derived: never orphans, expired after 400 days by the weekly sweep, reclaimed with the store prefix on offboarding. Ebda billing receipt email = the InstaPay `payment_confirmed` notice (card renewals send no receipt email today). Cost if wrong: drop the `<img>` (one helper) and the emails revert to text.
