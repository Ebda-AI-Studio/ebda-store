# CI-TRUFFLE-PARTIAL-1 - the Mac secret scan clones a full workspace

Ruling CI-TRUFFLE-PARTIAL-1 - the Mac `Check for secrets` step runs `scripts/ci/ensure-full-clone.sh "$AFTER"` before trufflehog clones the workspace. Evidence: store main run 44223670604 failed only that step on ebda-mac-1 ("could not fetch ... from promisor remote"; git: "aborting due to possible repository corruption on the remote side"): a persistent runner workspace keeps a partial-clone filter from an earlier job, so the depth-1 fetch leaves blobs missing and the local `git clone file://` aborts. Reproduced locally (depth-1 blob:none no-checkout workspace); unsetting the promisor config and `git fetch --refetch --depth=1` makes the same clone succeed. Pinned by tests/unit/ci-ensure-full-clone.test.ts (control + fix + ci.yml ordering; both mutations killed). Whatsapp and foundation CI have no trufflehog step (gitleaks only), so nothing to port. Cost if wrong: one extra full depth-1 fetch (tens of MB) on a Mac secret-scan job that finds the workspace partial; a no-op otherwise.

Who writes the filter (measured / inferred). The writers are the `plan` job ("Does this push change <app>?") of the nine `cf-*-deploy.yml` workflows (accounts, admin, api, docs, help, marketing, orders, status, web): `actions/checkout` with `fetch-depth: 0` and `filter: blob:none` (Ruling DEPLOY-PLAN-CLONE-1), on the shared `EBDA_LIGHT_RUNS_ON` pool, so on the same persistent `_work/ebda-store/ebda-store` the CI jobs use. Measured: ebda-mac-1 ran "Does this push change marketing?" (02:46:29Z) and "...api?" (02:47:01Z) before the failing Security Audit job (03:12Z). Inferred, not measured: that this left the filter in the workspace config (runner directories were not read).

Should the writers clean up after themselves? No. A post-step `git config --unset` in nine workflows is repetitive and unreliable (a cancelled or crashed runner skips it), while the consumer-side guard is one script that works whatever left the filter. Rule: any step that clones the workspace locally (today only the Mac trufflehog scan) calls `scripts/ci/ensure-full-clone.sh` first; `tests/unit/ci-ensure-full-clone.test.ts` pins that for the scan. The plan jobs keep their blob filter (it is what makes the full-history clone fast).
