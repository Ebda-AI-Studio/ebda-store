# EBDA-FUNNEL-17

> Section: 2026-10-07 — Signup funnel: plan choice, card on file or InstaPay, 14-day Growth trial (branch `feat/signup-funnel`, stacks on #10)

Ruling EBDA-FUNNEL-17 — InstaPay ONLY for now (Ahmad, 2026-10-07: no Kashier account). `BILLING_TRIAL_CARD_MODE` is kept, but unset now means `pay_at_trial_end` on every provider (it used to follow the provider's capability), so no default or production configuration shows a card. Card setup (`CARD_SETUP_UNAVAILABLE`) and hosted card checkout (`CARD_PAYMENTS_DISABLED`) are refused server-side unless `card_on_file` is set explicitly on a provider that can save a card without charging it. The gateway is resolved lazily, only when a card is actually charged, so an InstaPay-only deployment needs no `BILLING_PROVIDER` for go-live, reminders, overdue or suspension. The merchant billing page shows plans for reference with InstaPay copy and no card buttons. The past-due "could not charge your card" alert is hidden for InstaPay subscriptions. Evidence: `tests/unit/signup-funnel-card-d1.test.ts` + `tests/unit/signup-funnel-store-writes-d1-do.test.ts` "InstaPay-only default" and `tests/unit/signup-funnel.test.ts` "resolveTrialCardMode". Cost if wrong: turning cards on later is one env var plus the Kashier enablement in EBDA-FUNNEL-2.
