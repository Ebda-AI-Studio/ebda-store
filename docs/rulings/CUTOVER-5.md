Ruling CUTOVER-5 (2026-10-29, INFRA-CF-1 PR G part 1; amends CUTOVER-1, CUTOVER-2, CUTOVER-3, CUTOVER-4) - the cutover runbook's gates are code, and it describes the design that exists, not the one planned on 2026-10-25. (1) Coverage: `packages/cf-migrate/test/coverage.test.ts` fails when a table of the generated StoreDO or D1 schema has no migrate mapping (a Postgres twin in the plan, or an entry in `CF_ONLY_TABLES`) or no erasure classification, when a CF-only rule names a table that now exists in Postgres, and when the repo layer CREATEs a StoreDO table that is neither generated nor in `DO_RUNTIME_TABLES` (the money/stock/idempotency markers). (2) Verify: `verify-store.mjs` now also checks the Cloudflare-only tables (`commerce_outcomes`, `d1_outbox`, `do_flags`, `platform_audit_log`) by count AND sha256 against their ruled row sets (empty after import; `do_flags` may only hold `gold_reprice = 0`), `entity_index` against the store tables, and asks the DO for its table list (`GET __tables`): a table the cutover does not know fails the run. (3) The rehearsal (`scripts/cf/rehearse-cutover.sh`) is self-contained: it restores the newest dump into its own throwaway Postgres 17, runs the migrate gates, the 501 `*_NOT_ON_DO` guard and the write-freeze tests, then the whole sequence on local workerd, and ends in one `REHEARSAL PASS` line; it refuses any Neon URL and stops only the Postgres and workerd it started. (4) The runbook is checked against the code (`runbook-parity.test.ts`): D1 `ebda-platform` id, the super_admin `/api/v1/health` counts (public `/health` never carries them), `WRITES_FROZEN` covering crons, queues, Workflows and alarms (no Inngest step exists), `JOBS_ON_DO` with the first flip and `JOBS_CF_ALARMS`, the `CUTOVER_IMPORT_SECRET` steps, an accepted-or-gone rule for every `*_NOT_ON_DO` refusal and every `docs/cf` residual, Postgres read-only for 7 days with the CUTOVER-4 replay, then the Neon decommission after 7 clean days. (5) Two corrections found by the rehearsal: `CUTOVER_IMPORT_SECRET` is kept for the whole 7-day rollback window (rollback calls the DO `__diff`; the earlier "delete on day 1" would have disabled the replay), and the D1 selector column `stores.storage_backend` is exempt from the replay's "live data with no Postgres column" refusal because it is the switch, not data. Cost if wrong: a table added later with a wrong `CF_ONLY_TABLES` row set would make verify fail a correct import (a false NO-GO that costs a rehearsal, never data), and a selector exemption wider than that one column would let a rollback silently drop live data, which is why it names exactly `stores.storage_backend`.
