# QA-120-1

Ruling QA-120-1 - the InstaPay receipt reader normalises every printed value itself (Arabic-UI receipts, Amelia 2026-11-20: the time ٤:٣١ was read as 20:21). The model now ALSO copies amount, reference, date and time exactly as printed (`amountText` / `referenceText` / `dateText` / `timeText`); `normalizeReceiptExtraction` parses that printed text deterministically (`normalizeReceiptText`: bidi marks and Arabic diacritics dropped, Arabic-Indic and Persian digits to 0-9, Arabic decimal / thousands separators, `ص`/`م`/`صباحًا`/`مساءً`/AM/PM before or after the clock, Arabic and English month names) and it wins over the model's own conversion when it reads; otherwise the model's value is parsed with the same normaliser. The prompt names the digit mapping and says to ignore the phone's status bar clock and battery. Nothing personal is added (no new person field; the new keys carry only the four values). Evidence: tests/unit/instapay-receipt-reader-workers-ai.test.ts (QA-120 block, 2 mutations red). NOT verified: the real model's accuracy on genuine Arabic receipts (it can still misread the printed text itself; the approver still sees the flags and the screenshot). Cost if wrong: a wrong pre-fill the merchant must correct before submitting; nothing auto-approves.
