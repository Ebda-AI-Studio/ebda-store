# GUEST-RET-1

Ruling GUEST-RET-1 (2026-11-11, audit S2-7, ebda-foundation criterion 19, ebda-foundation PR #24) - a guest shopper can request a return with `POST /public/returns/guest`. Identity is the order number plus a second factor already on the order: the phone (compared after `normalizePhoneForStorage`, so `01001234567` equals `+201001234567`) or the email (trimmed, lower-cased); a factor that is given must match and at least one must be given. Only a guest order (`orders.customer_id` null) qualifies: a signed-in customer's order answers like a missing one and the shopper signs in. Every identity miss (no such order, a customer's order, wrong phone, wrong email, no factor) is ONE response, `404 GUEST_RETURN_NOT_FOUND` with one fixed message, echoing no phone, email, address or name; the compare is a SHA-256 plus `timingSafeEqual` and runs whether or not the order exists. The route is rate-limited per IP (10 per 15 min) and per (store, order number) (5 per 15 min), both keyed on a hash, fail-open on a store error like the other limiters, both answering the same `429 RATE_LIMITED` body. Once identity holds, the row is made by `returnCreate` on the StoreDO with `guest: true` (a Postgres-served store answers `409 RETURNS_NEED_DO_STORE`): delivered-only, the merchant's return window, the over-claim check. With no lines named the request is the whole order (a guest cannot see line ids). A request moves no money: the refund method is chosen by the merchant at completion, and a guest return cannot be completed to store credit (`GUEST_STORE_CREDIT`, no wallet to credit). `returns.customer_id` stays NOT NULL: a guest return stores the `guest:<orderId>` marker (Ruling GUEST-RETURN-MARKER-1, shared with the merchant-opened guest return of #1086; `packages/shared/src/guest-return.ts`), never NULL and never `''`, so no migration is needed and no reader can mistake it for an account (guard: `packages/shared/src/__tests__/guest-return.test.ts`). Status mails of a guest return go to the email on the order. Evidence: `tests/unit/guest-return-request.test.ts`, `apps/api/src/middleware/__tests__/guest-return-limiter.test.ts`, `packages/repo/test/do-returns.test.ts` (guest block), `apps/api/workers-do/returns.test.ts` (real workerd: a real guest return row with the marker, store credit refused). Cost if wrong: a shopper who mistypes one field cannot tell which one was wrong (deliberate), and a guest who knows an order number and its phone can file a return request for it (the merchant still approves, and no money moves until the merchant completes it).
