# NEVER-OVERWRITE-1

Ruling NEVER-OVERWRITE-1 (2026-11-11) - no automated job overwrites a stored product value. The one AI write layer (`writeAiFieldsGuarded`: the Postgres writer and the DO procedure `guardedAiWrite`) is FILL-ONLY by default: a field is written only when its stored value is empty (or is the `name === nameAr` placeholder of an Arabic-only product, NAME-PAIR-1), whatever its `aiFieldSources` stamp. An 'ai' stamp no longer licenses a refresh: the autopilot (`product.upserted`) and the daily sweep (incl. stale refresh) only fill gaps. This covers name, nameAr, description(Ar), meta titles/descriptions, searchTerms and every other AI-writable field. Only a merchant-initiated run may replace a non-empty AI value: hand-back "Switch to AI" (`onlyFields`) and the language-balance button/bulk (revert backup kept); they pass `overwrite`. `generateFill` also stops spending Gemini on such fields. Evidence: QA store 1bb14d0e product Signal Signet, nameAr «خاتم الإشارة» (ai-stamped) replaced by «سيجنال سيجنيت» at 01:04:42Z ~3 min after the last merchant save (the `name` edit put `name` in changedFields, which refreshed the ai-owned nameAr); no repair-product-names request in the 00:50-01:10Z Logpush window; `tests/unit/ai-fill-only.test.ts` (red on the old code). Cost if wrong: an AI translation is never refreshed after the merchant changes the English name; the merchant retypes it or uses Switch to AI.
