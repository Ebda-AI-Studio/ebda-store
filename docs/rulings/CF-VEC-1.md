# CF-VEC-1

Ruling CF-VEC-1 (2026-10-30, INFRA-CF-1 integration 2) - the Vectorize index `ebda-product-vectors` (1024 dims, cosine, personal/Whisky 11 Cloudflare account) is bound as `PRODUCT_VECTORS` in `apps/api/wrangler.jsonc`. For a store on its Durable Object: the jobs `search-product-index` and `search-index-backstop` write its vectors there (namespace = store id; the DO keeps `product_vector_state`), and the storefront vector leg (`vectorLeg` in `product-search.service.ts`) embeds the query, asks Vectorize for the nearest vectors (cosine distance = 1 - score, within SEARCH_VECTOR_MAX_DISTANCE, a product keeping its nearer doc/words vector), then asks the DO (`vectorVisible` read op) which of them are active, not deleted, public and vectored by this model, so a stale vector can never show a hidden product. FAIL-SOFT: a missing binding or any Vectorize/DO error returns no ids and `degraded: true` (keyword order, not cached as the full answer). A Postgres store keeps halfvec (`product_embeddings`) untouched. Evidence: `tests/unit/search-vector-leg-do.test.ts`, `tests/unit/jobs-blocked-search-on-do.test.ts`, `packages/repo/test/do-job-ops-b.test.ts` (vectorVisible). Cost if wrong: a DO store's semantic leg returns nothing and search degrades to keyword-only, never an error or a hidden product.
