# PERF-PREFETCH-1

> Section: Pre-QA sweep 2026-11-10 (branch `fix/preqa-p2-batch`), finding 12: 13 prefetches on the demo home before the visitor touches anything

Ruling PERF-PREFETCH-1 - a storefront link that is rendered once per category or once per tag (`/products?category=…`, `/products?tag=…`) sets `prefetch={false}`; single links keep the `next/link` default. Measured in production 2026-11-10 on `storedemo.ebda.app/en` at 390x844, no cookie, GET only: 13 requests with `rsc` and `next-router-prefetch: 1` fired on load and none were added by scrolling to the bottom. They were two per distinct URL (a route-tree request of about 240 bytes and a loading-shell request of about 4.1 KB): the four category chips (8), "See all" `?sort=newest` (2), the cart icon (2), and the header "Products" link (1, tree only). Every response was `cache-control: private, no-cache, no-store` with no `cf-cache-status`, so each one is a storefront Worker invocation that nothing caches; time to first byte ran from 77 ms to 1154 ms. The four chip shells are the same bytes (4118 to 4123) because the page is the same and only the query string differs, so the row cost two Worker calls per category for one shell. Fixed: `CategoryChips`, `CategoryRail`, `CategoryTiles`, `TagChips` and the category rows of `EmptyStateKit` and `StoreNotFoundBody` now set `prefetch={false}`, the setting `CategoryStrip`, both `CategoryCard`s and every product card already carried. `tests/unit/storefront-listing-links-no-fanout-prefetch.test.ts` walks the storefront source for such links, with one named single-link exemption (the product page's link back to its own category). Expected on the demo home after deploy (inferred from the trace, not measured on a deployed build): 7 requests, because the hero button still prefetches the abayas listing. Accepted residual: those 7 (hero button 2, "See all" 2, cart 2, header "Products" 1) stay, because each is one link to one page the visitor is likely to open next and a prefetched loading shell makes that tap feel immediate. Cost if wrong: a tap on a category chip waits for the server's first bytes (measured 77 ms to about 1.1 s on a cold Worker) before the loading skeleton appears, instead of showing it at once.
