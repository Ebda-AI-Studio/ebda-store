# PERF-AUTHSTATE-1

Ruling PERF-AUTHSTATE-1 - The cold storefront path (3-8 s on a cache miss, ~1.1 s on every API request that touches a limiter) is spent in calls to the AuthState Durable Object, not in D1 or KV. Evidence (measured 2026-11-17 from a Mac in Egypt with the API's existing `Server-Timing` header on `GET /api/v1/public/store/resolve`): fresh unknown host handler 2.3-4.2 s = auth-state 6 calls 2.3-4.8 s, d1 2 calls 24-80 ms, kv 2 calls 100-190 ms, io-waves 9; no-DB path (`x-store-domain: localhost`) auth-state 3 calls 1.1-1.4 s; known store right after expiry handler 4.1 s = auth-state 7 calls 4.2 s; the immediate repeat 193 ms; `/health` 15 ms with no auth-state call. Decision (main controller): (1) move the PUBLIC read limiter of the store-resolve route family off the AuthState DO onto the Workers Rate Limiting binding keyed by the forwarded shopper IP (RL-SSR-IP-6), keeping the DO limiters for writes and auth routes and listing any limiter whose per-colo, approximate semantics are too loose; (2) no serial cache-generation pair on the fill path; (3) MEASURE before any re-sharding: this PR adds a flag-gated super-admin echo (`GET /admin/do-colo`, `DO_COLO_ECHO=on`, off by default, location codes and round-trip times only) that reports where the Worker and a sample of AuthState instances (32 shards, global and per-store cachegen) run; if they are on another continent a locationHint / re-shard migration plan (new shard names, dual-read window) is written for review, not built. This PR is the measurement step (3) only. Cost if wrong: the echo is a read-only diagnostic behind a flag and a super_admin + MFA gate; left on, it wakes up to 37 Durable Objects per call (each empty), so it must be turned off after the investigation.
