# NT1-A-DEFAULT

> Section: Notifications matrix, WhatsApp column (2026-11-17, branch `feat/notifications-whatsapp-status`)

**Ruling NT1-A-DEFAULT - the Notifications matrix shows WhatsApp as a read-only status plus a link to Ebda Chat; per-event toggles come later, when Chat exposes per-event switches.** Once a store is linked, Ebda Chat sends the order messages itself (order confirmation on `order.created` unless COD / placed-in-chat / the Chat `orderConfirmations` switch is off, COD confirmation, shipping updates for shipped / in_transit / out_for_delivery / delivered / failed_delivery, a paid notice for InstaPay/link orders), so the Store column only reports who sends each event: "Sent by Ebda Chat" (store linked and entitled), "Ebda Chat not connected" with a connect link, "Not sent by WhatsApp" (payment failed, cancelled, refunded), or an explicit unknown state when the link read fails (unknown is not "not connected"). It uses only `GET /stores/:storeId/whatsapp-link`; no new Store->Chat call was added, and the delivery log stays in Chat. The `whatsapp` registry feature copy now describes this (no WABA or template picking by the merchant; WA-LEGACY-1); it stays `hidden: true` with no plan baseline change (WHATSAPP-OFF-1). The per-event `whatsapp` boolean the notification API accepts is still unused by the dispatcher and is not surfaced. Evidence: ebda-whatsapp `docs/store-link.md` events table and `src/core/store-link/events.ts`. Cost if wrong: a merchant cannot turn an individual WhatsApp message off from the Store.
