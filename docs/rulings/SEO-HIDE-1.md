# SEO-HIDE-1

> Section: 2026-11-10 - merchant "Hide my store from search engines"

Ruling SEO-HIDE-1 - a merchant can keep a live store out of search while preparing it: `store.settings.hideFromSearchEngines` (boolean, default off), written by `PUT /stores/:id/seo`, shown on the SEO page and as a chip on the Settings SEO card. When on, on the platform host and on a custom domain alike: every page's robots meta is `noindex, nofollow`; `robots.txt` stays crawlable (so the meta is read) with no sitemap; `sitemap.xml` is empty; `llms.txt` is a 404 with `X-Robots-Tag: noindex`; cart and checkout are untouched. Storage is the `settings` JSON, not a column: it is already in the public payload through `PUBLIC_SETTINGS_KEYS`, so no Prisma migration, no DO-schema change and no `store-resolver` field. No `X-Robots-Tag` header on HTML pages: middleware never resolves the store, and a per-request resolve there would cost every page view; the meta tag carries it. NEVER-stale: the write runs `bustStoreCaches` (Redis, storefront tags, edge-HTML epoch) and every storefront fetch feeding robots/sitemap/llms is tagged `store-domain:<host>`. Cost if wrong: a merchant who turns it off waits for search engines to re-crawl; a crawler that already cached the pages may keep them a few days after turning it on.
