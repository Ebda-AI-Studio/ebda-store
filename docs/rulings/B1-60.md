# B1-60

> Section: 2026-10-15 — Phase B1 Qamar (B1-\*)

Ruling B1-60 — W2b card tokens (L-01, M-03, K-01, L-12/LB-02), decision (f) applied per look, never platform-wide. Three optional look UI tokens join `LOOK_UI_TOKEN_KEYS` (theme PUT allow-listed, reset clears them): `cardCta: 'none' | 'quiet'`, `cardHover: 'none' | 'lift'`, `cardBadge: 'accent'`. Atelier = none / none / accent; Lookbook = quiet / (lift kept: motion expressive) / accent, heart `overPhotoChrome: 'soft'`; Vitrine = quiet / none / accent, heart `soft`. One helper (`templates/shared/look-card.ts`) decides on EVERY card path: the storefront card, the shared carousel, the 5 skin cards (through `ProductCardCta`'s `lookCta`), the PLP list row; the 4 mappers render through the first two. `none` renders no control (the card and its photo are the link); `quiet` renders only an outline add (`border-input`, look radius) for a product that can be bought now and has no options, so a sized product always opens its page to choose a size and a row never mixes "عرض" with "إضافة للسلة". Merchant > look: a stored `productCardDefaults.ctaMode`, a merchant badge colour or a stored token wins. The heart on a photo never reads the page foreground on ANY look store: `overPhotoMaterial` gives every look at least the white disc with fixed ink (#141414 @0.78, 15:1 on white), so the three designed dark looks (souq.night, jasmine.apothecary, lamma.notebook) are fixed too; `bare` (Atelier) is a glyph with a white 1px halo and a 44px hit area. No-look stores: the homepage characterization snapshots (5 skins x en/ar x 5 fixtures) and the Dahab snapshots are byte-identical; `look-card-w2b.test.tsx` pins the legacy heart, hover and chip classes. Cost if wrong: a fashion shopper on Atelier cannot add a simple (sizeless) piece from the grid, and pays one extra tap via the product page.
