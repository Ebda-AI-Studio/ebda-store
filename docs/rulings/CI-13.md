Ruling CI-13 (Store session, 2026-10-29; CI gaps) - the outcomes CI-9 said the stream lacked are now emitted from the real write paths, the fee hint reads the real shipping fee, and calibration can pause a feature for ONE store. (1) Events: `payment.failed` (closed `failureCode` declined|expired|cancelled, never provider text) from the two places that win the order's `unpaid -> failed` claim (pull-side `payment-confirm.service` and the webhook in `payment.factory`), sent through `sendEventAfterCommit` as `ci/payment-failed`; `cart.abandoned` (a reminder went out: `channel` email|notification, `step` 1-3, from `abandoned-cart.service.sendStep` and the recovery email's `sent` write) and `cart.recovered` (the order that replaced a reminded cart, hours from the FIRST reminder, only if a reminder had gone out); `merchant.onboarding_step` (`store_created`, `payment_methods`, `went_live` from `onboarding.service`, with seconds since the owner signed up and the template). A create-time provider throw is NOT an outcome (no committed order exists to attribute it to). (2) `orderId` is now nullable in the envelope for exactly `cart.abandoned` and `merchant.onboarding_step` (they have no order) and `parseEnvelope` refuses null on every other type and a value on those two; a minor change inside the v1 envelope (no key renamed or removed), sink and replay skip the order tombstone when there is no order. Consent and PII: the order-less events carry `buyerKey: null` (a cart reminder's contact is a reminder consent, not a CI one); `cart.recovered` and `payment.failed` use the order's buyer key like every other order event; `xstore` follows the store opt-in at event time. (3) Metrics: `return_by_shipping_fee` (COD shipments only, bucket f0 free, f1 <50, f2 <75, f3 <100, f4 100+ EGP), `payment_failure` (per provider, COD excluded, `n` settled / `hit` failed), `onboarding_step` (count and seconds per step), `cart_recovery` (per channel: `n` carts whose step-1 reminder went out, `hit` recovered, `sum` hours; the ANY row adds channels, so a cart reminded on two channels counts twice in `n`), plus insight rules for shipping-fee bands and failing providers; day files written before these metrics merge as empty. (4) Fee: `shipment.delivered|returned` carry `shippingFeeMinor` (`orders.shipping`, optional so old events stay valid) and the fee hint reads `return_by_shipping_fee`; the COD-amount proxy of CI-10 is removed from the hint (its metric stays for the insights page); events from before the field are not counted, so the hint says "not enough data yet" until fee-carrying outcomes reach the thresholds. (5) Per-store auto-gating: table `ci_store_gates` (Postgres migration `20261107000290_ci_store_gates` + rollback, `packages/cf-schema` store-DO, erasure class `no-pii`, RLS), written ONLY by the weekly calibration inside that store's own scope from that store's own `ci_hint_logs` (>= 30 resolved and more than 10 points off, no cohort rule since it is the store's own data); `evaluateStoreGates` throws on rows of two stores; `ci-hints.service` refuses a hint when the store's row exists (read straight from the database every time, NEVER-stale), the Smart hints page lists what is paused for the store and why, and the row is deleted when the store's own numbers line up again or age out of the 90-day window (a paused feature logs nothing new, so a pause lasts at most one window). The platform gate (CI-11) is untouched: a store can never close a feature for anyone else. The gap test now rounds to 6 places, so an exact 10-point gap is not "more than 10" (0.4 - 0.3 floats to 0.10000000000000003 and used to trip it). Evidence: `tests/unit/ci-gaps.test.ts`, `ci-store-gates.test.ts`, updated planner/hints/calibration tests; API bundle (wrangler dry-run) worker.js 7,676,812 B (< 7.8 MB). Not verified: the migration applied to a real Postgres, live queue/R2/Inngest delivery of the four new events, and real gateway failures. Cost if wrong: a gateway that reports failure twice with different payment ids makes two `payment.failed` rows for one order; a paused feature stays dark up to one 90-day window after a mis-measured calibration; the fee hint is empty for weeks after deploy until fee-carrying outcomes accumulate.
