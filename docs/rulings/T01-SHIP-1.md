# T01-SHIP-1

> Section: 2026-11-11 - open recount track T01, order money edges (S3-X6)

Ruling T01-SHIP-1 - a failed shipping lookup is refused, never booked as free delivery. The storefront checkout (`OrderService.create`) logged and shipped at 0 when `ShippingService.calculateShipping` threw, so a database blip silently undercharged the order and the merchant paid the courier. It now throws `SHIPPING_UNAVAILABLE` (503, retryable) before any stock, coupon or order write, so there is nothing to roll back; the shopper retries and gets the real fee. The admin manual-order path (`createAdminOrder`) refuses the same way unless the admin gave a `shippingOverride` (a negotiated fee does not need the lookup). The Durable Object checkout (`packages/repo/src/do/checkout.ts`) never had the fallback: its lookup throws through. An unpriced area on a store with area rates is still `AREA_NOT_DELIVERABLE` (unchanged); a store with no zones still charges 0 by design. Evidence: `tests/unit/order.test.ts` (the three T01-SHIP-1 cases). Cost if wrong: during a real shipping-table outage checkout refuses with a "try again" message instead of taking the order, which costs a sale for the length of the outage but never undercharges one.
