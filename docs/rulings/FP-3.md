# FP-3

> Section: Admin fix pass 2026-11-04, track T1 API core (branch `feat/admin-fix-t1-api-core`)

Ruling FP-3 - an impersonation token (`POST /admin/impersonate`, 1 h, the target's real role) is refused with 403 `IMPERSONATION_FORBIDDEN` by `rejectImpersonated` on: merchant MCP key mint, payment refund and payment retry, every payment-settings write (create, update, delete, toggle, credentials, connection test), `PUT /stores/:id/domain`, and `POST /stores/:id/staff`. Every audit row written during ANY impersonated request now carries `details.impersonatedBy` (the acting super_admin), filled from an AsyncLocalStorage scope that `authenticate` enters (`apps/api/src/lib/impersonation-context.ts`, read by `auditLog`), so the other ~200 call sites needed no edit; a caller that already sets the field keeps its value. Evidence: `tests/unit/impersonation-guards.test.ts` (12-route table -> 403, audit row names the impersonator). Cost if wrong: support cannot reproduce a merchant's credential, refund, domain or staff action while impersonating and must ask the merchant to do it (decision D1).
