# WA-RPC-3

Ruling WA-RPC-3 - `createCheckoutLink` signs a 30-minute HMAC token (HKDF label `ebda:wa-checkout-mac:v1`) carrying store id, variant ids, quantities and buyer key only, never a price, at `<storefront>/cart/from-wa?t=`; the summary prices come from the Store's own catalog rows and exclude shipping/fees/tax. The contract called `/cart/from-wa` 'existing', but no such route was on main, so this PR also ships the redeem (WA-RPC-F1, closed): the storefront page `/cart/from-wa?t=` (`apps/web/src/app/cart/from-wa/`) posts the token to `POST /public/cart/from-wa`, which verifies it (store-bound, 30 min), copies the lines into the visitor's session cart through `CartService.addItems` (re-priced by the Store, a line already in the cart is skipped so a refresh never doubles a quantity) and the page redirects to `/cart` with the token gone from the URL; an expired or invalid link still lands on the cart. Evidence: `workers-do/wa-bridge.test.ts`. Cost if wrong: a leaked link lets whoever holds it add those lines to their own cart for 30 minutes; it carries no price, no buyer detail and grants no order.
