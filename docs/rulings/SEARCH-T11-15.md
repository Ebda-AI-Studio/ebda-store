# SEARCH-T11-15

> Section: 2026-10-15 — Phase B1 Qamar (B1-\*)

Ruling SEARCH-T11-15 (review N-I1; refines SEARCH-T11-10) — a product is quarantined only on evidence. After a batch fails for good (non-retryably, or retryably on the last Inngest attempt), each product is embedded on its own in a memoized step: (a) a non-retryable rejection is a PERMANENT quarantine (`retryable = false`, `expires_at` NULL) until the text or the model changes; (b) a retryable failure gets ONE more single call, in its own memoized step, after a durable `step.sleep` backoff of 60 s (Workers AI limits are per minute); failing again is a TEMPORARY quarantine (`retryable = true`, `expires_at = now() + 24 h`), after which the product is re-admitted automatically (the skip predicate requires `expires_at IS NULL OR expires_at > now()`; a re-failure after expiry re-quarantines and counts as new); a success in either pass is written. If nothing succeeded and nothing was rejected outright it is an outage: the run fails (P1 via `alerts-failure-watch`) and nothing is quarantined. (c) Alerts: ONE P1 per indexer run that newly quarantined anything (`search-index.quarantine`, context `{ storeId, permanent, temporary }`), never one per product. The in-process `indexStore` follows the same rules (its backoff is `opts.retryBackoffMs`, default 60 s). Evidence: `tests/integration/product-index.test.ts` — a 429 burst on the batch and on one product's first single call quarantines nothing and embeds all three; a permanent rejection quarantines without expiry and raises one alert, and a second run makes no call and no alert; retryable-twice gives a 24 h quarantine via the `backoff-0` sleep and a `retry-0` step; an expired quarantine is re-admitted with the same text; two poisons raise one alert with `permanent: 2`; red before (7 failing); mutants without the second chance or without the expiry turn their case red. Cost if wrong: a product failing retryably twice, 60 s apart, is out of semantic search for 24 h.
