# STORE-EDGE-3

> Section: 2026-11-09 — production check of S2-REVIVE (STORE-EDGE-2, deployed at f219f0d0a)

Ruling STORE-EDGE-3 (2026-11-09) - three defects found by curling production after #481 deployed, fixed together. (1) KEY COLLISION: the demo layer (DEMO-EDGE-1) and the store layer (STORE-EDGE-1/-2) both wrote `caches.default` under the same key for a demo host (`https://<host><path>`). Each read the other's copy as a miss (the demo layer reads `x-edge-cached-at`, the store layer its meta header) and overwrote it, so the demo layer never hit and the store layer hit only every other request. Measured on `storedemo-souq.ebda.app/ar` with `Accept: text/html`, no cookie: MISS, MISS, then a store HIT, and `x-demo-edge: MISS` every time. Fix: store-layer keys carry `?__edge=store`. (2) ACCEPT: both layers required `Accept` to contain `text/html`, so curl, link-preview and social crawlers (`*/*` or no Accept) always bypassed. That is why the coordinator's plain `curl https://storedemo.ebda.app/ar` showed no `x-store-edge` at all, and it is also the first wave of a shared link. Fix: `*/*` or no Accept counts as a document request (`acceptsHtmlDocument`). RSC, prefetch and action requests are still refused by their own headers, and only a `text/html` response is ever stored. (3) NONCE IN LINK: Next writes the CSP nonce into the preload `Link` header too, and `renewNonce` replaced it only in the CSP header and body, so a cached page's font and style preloads carried a nonce the CSP no longer allowed. Fix: the `Link` header is renewed as well. Tests: `tests/unit/store-edge-cache.test.ts` (both layers over one cache: demo HIT from the second request, two separate entries; Accept matrix), `tests/unit/edge-cache-nonce.test.ts` (no render nonce left in CSP, body or Link). Cost if wrong: a crawler gets the same cookie-less HTML a first visitor gets (it never sees a personalised page, cookies and Authorization still bypass); two cached copies per demo page instead of one fighting over a slot.
