# CF-WRITES-3

Ruling CF-WRITES-3 (2026-10-29, INFRA-CF-1 PR D1c) - closes the cutover gate left open by CF-WRITES-2: every write to the `Store` row now goes through the settings write-through, so the StoreDO copy (`store_profile` / `store_config`) cannot drift from the authoritative row, and a CI guard fails on a new bypass. (1) Measured on the D1b tip with the TypeScript AST (not a grep): 39 direct `store.update` / `updateMany` / `upsert` calls (38 outside `StoreService` plus 1 inside it written as `withStore(id, async tx => ...)`, the look applier; CF-WRITES-2 counted 2 inside, the second no longer exists) and 4 raw `UPDATE stores SET settings = jsonb_set(...)` statements (QR and label settings in `StoreService`, the two setup-guide writers), which the grep in CF-WRITES-2 could not see. (2) Mechanism: `storeUpdate(db, args)` and `storeUpdateMany(db, args)` in `lib/repo-factory.ts` run the authoritative write on the CALLER'S OWN client (request `prisma` proxy, a `withStore` transaction, the extended client: tenant guard, RLS and the surrounding transaction are unchanged), then `copyStoreSettings`; `updateMany` copies only when a row matched; the result type comes from the Prisma args (`StoreGetPayload<A>`), so `select`/`include` callers keep their types. `syncStoreFields(storeId, ['settings'])` follows a raw jsonb write: it re-reads the named columns from the authoritative row and copies the WHOLE resulting value, so a partial JSON write reaches the DO as what Postgres actually holds. On `pg` (the default for every store) the copy is a no-op, so every moved site runs the very same Prisma call as before. The look applier uses the existing `updateStoreThrough`. (3) The copy now accepts every field a routed write can carry: a relation write (`credentials: { upsert }` on agent-key rotation) is reported `directoryOnly` instead of refused (`packages/repo/src/rpc/settings.ts`; platform models live in D1); an unknown field name is still refused; `plan` and `status` are mirror columns in `store_profile` and ARE copied (the D1 directory columns are domain verification, pending domain, billing suspension, email domain, deletedAt). (4) The guard `tests/unit/store-settings-routed.test.ts` walks every non-test file of `apps/api/src`, fails on any `X.store.update|updateMany|upsert(` not lexically inside `updateStoreThrough(...)` (allow-list: `lib/repo-factory.ts`, which holds the helper's own call) and on any raw `UPDATE stores` in a function that does not also call `syncStoreFields`; a negative-control test pins each bypass shape (multi-line `x.store\n.upsert`, a `tx` alias, the raw statement). Moved: bulk-AI SEO/AEO/GEO/translate (store-level SEO and footer links), admin store edit, agent key rotate and revoke, AI feature switch, best-sellers image, store layout, domain clear, typography, billing suspend/restore/plan sync/comp migration/subscription downgrade, domain claim (claim, cancel, release, fail, activate, llms.txt reset), feature plan, loyalty settings, onboarding activation, page-builder layout and theme/typography/chrome publish, plan service, provisioning status, PWA settings, tax profile and tax settings. Residuals, accepted: (a) a caller that rolls back its own transaction AFTER the copy leaves the DO ahead of the authoritative row until the next settings write converges it (same window CF-WRITES-2 accepted: the copy is synchronous in the request, there is no outbox); (b) a Prisma operator object in `data` (`{ increment }`, `{ set }`) would be stored verbatim by the copy - none of the 43 sites uses one (checked), the helper types do not forbid it, review catches a new one; (c) billing jobs that call `storeUpdate` outside a request pay one extra flag read per call (no cross-request cache by design, CF-REPO-1). Not done here, with reason: the bulk CSV import is not routed in D1c - its per-row write mixes stock and non-stock fields in ONE interactive `withMoneyTx` (inventory, opening-stock history, slug redirects into a D1 platform model, gold specs, barcode sequence) so it cannot be split without the stock operation it depends on; it stays on Postgres, listed with the D2a remainder in `docs/cf/repo-factory.md`. Evidence: guard test (red with 43 findings before the change, green after), `packages/repo/test/rpc-settings.test.ts` (relation, mirror and directory-only fields, unknown refused), `tsc --noEmit` on `apps/api` clean. Cost if wrong: with every flag at `pg` the moved sites run the same Prisma calls as before; a wrong copy is reachable only for a store the operator flipped to `do`, one D1 UPDATE back, and the guard turns the next unrouted writer into a red CI run instead of silent drift.
