Ruling SEARCH-T14-4 (Task 14 load test) — what the numbers mean. All measured on one Mac (4 CPUs for Postgres, Node API, Redis and k6 sharing the machine) with the API on Node, not workerd, no Hyperdrive/Neon network hop, and a FAKE embedder with injected latency (p50 80 ms / p95 300 ms, 2 % slow > 500 ms, 0.5 % errors; a bad-provider run p50 250 / p95 600 / 20 % slow / 2 % errors), never Workers AI. They show where the time goes and that the design has headroom; they do not predict production latency, which adds the Worker-to-Neon round trips (several per search, see the report) and real Workers AI latency. The 400 ms race caps the vector leg, so a hybrid search is bounded by ~400 ms + the database work.
