# VE-11

> Section: 2026-10-22 — Visual editor (VE-\*)

Ruling VE-11 (Task 7 security fix, 2026-10-22) — R2 object deletion is store-scoped, and a font URL must belong to the store that names it. Finding: a custom font that leaves a store's typography went to `deleteR2ObjectIfOrphan(url)`, the URL is merchant-controlled, and that function only asked "does any row still reference it" (the check is deliberately cross-store), never "is it this store's object": store A could name store B's R2 key, remove it, and delete B's object whenever B had not saved a reference yet (an upload not yet attached, an object only in a pending draft). The same flaw existed on main for every merchant-controlled URL that feeds the cleanup (typography PUT fonts, layout/hero slide and PWA images through `cleanupRemovedJsonUrls`, category, blog and page covers, store hero and og images, variant images). Fix, both layers: (1) `deleteR2ObjectIfOrphan` refuses a key outside `stores/<currentStoreId>/` (and any `stores/` key when no store is in scope), before it even looks for references (`mayDeleteKey`); (2) a custom font must be `stores/<thisStoreId>/fonts/...` and a Google font must start with `https://fonts.googleapis.com/`, checked on every page-document write, publish and rollback and on `PUT /typography` (`font-url-guard.ts`). Smart Palette carries only colour tokens (no URL). Seven defences are in the mutation record. Cost if wrong: an object a store legitimately owns outside its namespace (legacy flat keys, a cloned demo store's shared images, a user avatar cleaned up from a user-scoped request) is no longer deleted and leaks until the orphan sweep reclaims it, which is the safe direction.
