# CF-R6A-1

Ruling CF-R6A-1 (2026-10-30, INFRA-CF-1 PR R6a) - the admin command palette (products, orders, customers) and every product lexical search answer for a DO store from the StoreDO's own derived index, through two read money ops, `searchProducts` (`searchProductIdSet`, admin or storefront scope, the same words-AND, SKU and one-letter word-start rules) and `searchCustomers` (`matchingCustomers`: Arabic-folded names, any phone form via `digitsOnly`, e-mail, guest contact snapshots), both folding with the ONE shared TS helpers (`normalizeArabicSearch`, `buildCustomerPatterns`); `searchProductIdSet` and `matchingCustomers` in the services route to them when the store has a money client, the Postgres statement is unchanged, and the palette route reads its display rows through `storeRepo(...).db` (a DO store has no `Order.customer` relation, so the registered customer is attached by id after the read). Evidence: `tests/integration/repo-factory-admin-search-contract.test.ts` (the REAL router on real Postgres 17 vs the DO schema on SQLite: 15 terms, byte-equal bodies: hamza-folded Arabic, English, SKU, one letter, a name that is both customer and product word, a phone in 3 forms, a guest by name, phone and e-mail, an order number, no match, empty, `%`, and a role without permission), `apps/api/workers-do/palette-search.test.ts` (real workerd, no Postgres: 40 writers racing 40 searchers, a search after a committed write always finds the row; phone forms; another store sees none). Found on the way (fixed by Ruling CF-FIX-1): the DO order-search and palette treat `customers.id` as the id `orders.customer_id` holds, while migrated orders carry the platform `users.id`; the two agree only when the CRM row shares the user's id, otherwise the registered-customer arm of the order search finds the guest-style contact only. Cost if wrong: a palette result list that differs from Postgres for a store whose CRM ids differ from its user ids; it is read-only and the order list search keeps its own `ORDER_SEARCH_TOO_BROAD` refusal.
