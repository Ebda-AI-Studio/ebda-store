# B5-17

> Section: 2026-10-22 — Phase B5 Dahab (B5-\*)

Ruling B5-17 — a QUOTE, not a merchant-paid lock; the order snapshot is the lock from order creation through payment (Task 12). Quote on the cart line. For a gold line, add-to-cart stores `cart_items.quoted_unit_price` + `quoted_at`, read from the server's current price, never from the client. Cart GET returns `priceChanged` / `previousUnitPrice` per line when the current price differs. Checkout shows "السعر اتحدّث" with the new totals, and "متابعة" calls `POST /cart/acknowledge-prices` (quote := current). Order creation re-prices in two places. Before the money transaction it recomputes each gold line with `computeGoldUnitPrice` from the spec and the CURRENT rate, then asserts three things: the recomputed price equals the materialised price, else 409 `GOLD_PRICE_DRIFT` + P1, because that means a repricer bug; it equals the line's quote, else 409 `PRICE_CHANGED` + new prices; the rate is fresh, else 409 `GOLD_RATE_STALE`. And again inside `withMoneyTx`. It takes `FOR SHARE` on the `gold_rates_current` rows it priced from and re-checks their ids, so a rate write that committed between the check and the transaction becomes `PRICE_CHANGED`, never an old-rate order. The rate write takes `FOR UPDATE` on the same rows, so the two serialise. Every order path is covered. The same gate (`assertGoldLinesPriceable`) runs on `OrderService.create` (shopper and the MCP agent checkout), `OrderService.createAdminOrder`, and the payment-link draft order (`payment-links.routes.ts`). Admin and payment-link lines have no shopper quote, so they skip the quote check but not the drift and stale checks. A structural unit test fails if an `orderItem` create site does not call it. Why not a merchant-paid lock. Egyptian gold moves several times a day, and a lock makes the merchant absorb every move inside the window. Cost if wrong: one extra "متابعة" tap when the rate moves mid-checkout. The merchant still carries the move while an order sits unpaid (gateway session, InstaPay receipt, COD delivery), bounded by the existing unpaid auto-cancel.
