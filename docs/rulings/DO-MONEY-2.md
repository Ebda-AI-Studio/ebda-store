# DO-MONEY-2

> Section: Lifecycle emails and referral attribution (2026-10-22, branch `feat/lifecycle-emails`)

Ruling DO-MONEY-2 (2026-10-25) - phase 3 engines on the StoreDO, after the Opus whole-branch review (1 HIGH, 5 MEDIUM, 3 LOW; all fixed or ruled). FIXED with tests: a disabled variant is refused `VARIANT_INACTIVE` (was sold); a product WITHOUT variants backorders (feature flag AND product flag, stock goes negative, whole quantity `stock_taken`, `cost_price_deferred = 1`, as order.service.ts:1588-1641); a gold line is charged the RESOLVER's price (group percent_off applies) and the gate only validates and supplies the snapshot; a free-shipping coupon is judged on every loose line (Ruling B2B-M2), not only coupon-eligible ones; the idempotency replay also compares the bundle boxes; the gold port gained `decidePendingGoldRate`, `updateGoldSettings` (a changed rounding step reprices in the same section) and `repriceGoldProduct`; search `reindexStore`/`verifyProductIndex` are store-scoped, storefront ignores `includeDeleted`, the short-word test counts UTF-16 units like the Postgres caller. RULED, deliberately stricter than Postgres: the whole-order wallet reversal also nets earlier `return-credit:*` store credits (Postgres nets only `return-wallet-share:*`), because crediting a store credit and then returning the full wallet spend pays the customer twice; the cumulative refund cap already counts store credit. Residual: `featured` search order breaks name ties by binary compare (Postgres uses the DB collation); the search parity test against real Postgres runs only with `EBDA_SEARCH_PG_URL` (a throwaway Postgres 17), the FTS index is repo-layer owned (every product write path must call `upsertProductIndex`, the StoreDO bootstrap `ensureSearchIndex`). Cost if wrong: a customer with both a store credit and a wallet-paid order can get back less wallet money than Postgres would give; the merchant tops it up by hand and the stricter rule can be dropped by removing the `credited` term in `reverseOrderPayment`.
