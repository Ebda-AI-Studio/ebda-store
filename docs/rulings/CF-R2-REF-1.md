# CF-R2-REF-1

Ruling CF-R2-REF-1 (2026-10-30, INFRA-CF-1 integration 2) - `isStillReferenced` in `r2-cleanup.service.ts` (the per-URL check run before an image is deleted on replace) read only Postgres, whose rows for a DO store are sealed and stale, so an image used only by a DO store's product, variant or page could be deleted from R2. It now also reads, for every store that lives on its Durable Object, the references held in that DO (`collectDoStoreReferencedKeys` in `lib/r2-do-references.ts`: the `r2References` op over the shared registry, the same reader the weekly `r2-orphan-sweep` uses). The Postgres check stays (the platform tables `stores`, `users`, `system_settings`, `manual_payment_claims` are not on the DO). A DO that cannot be read, or a registry table its schema lacks, THROWS and the caller's catch keeps the object. Evidence: `tests/unit/r2-cleanup-do-references.test.ts` (DO reference keeps, none deletes, unreadable DO keeps, Postgres-only unchanged), `tests/unit/r2-cleanup-rls-bypass.test.ts`. Cost if wrong: a leaked R2 file (the safe direction), never a deleted live image.
