# SEARCH-T12-5

> Section: 2026-10-16 — Search program, PR 4 (P1c, hybrid ranking): SEARCH-T12-\*

Ruling SEARCH-T12-5 — the vector leg reads only vectors of the current model (`e.model = EMBED_MODEL`) and, in the same SQL, only storefront-visible products of the store (`p.status = 'active' AND p.deleted_at IS NULL`, `store_id` named on both tables under RLS): a vector left on a draft or soft-deleted product before the indexer prunes it never comes back. A vector for older text of a visible product may still match (BOUNDED-stale, SEARCH-11). The query-vector cache is NEVER-stale by construction (a vector for a fixed model and text never changes; the TTL only bounds memory) and holds at most 500 Float32 vectors (~2 MB). Query text is never logged. Evidence: `hybrid-search.test.ts` "soft-deleted and draft products never come back" (with a positive control), the two isolation cases (ebda_app with RLS + guard; the owner client, RLS bypassed, proving the `store_id` filter alone; red with the filter removed), "honours SEARCH_VECTOR_MAX_DISTANCE". Measured plan at 2 000 products in the store (4 000 in the table), as `ebda_app`: Index Scan on `product_embeddings_store_id_idx` + top-N heapsort, 5.7 ms execution. Cost if wrong: a renamed product can match its old words for up to the indexer's debounce + queue time.
