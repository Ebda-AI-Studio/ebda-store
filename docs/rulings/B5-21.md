# B5-21

> Section: 2026-10-22 — Phase B5 Dahab (B5-\*)

Ruling B5-21 — NEVER-stale cache layers a rate change must clear, and the one bounded residual (Task 10). What the rate write calls. `GoldRateService.applyRates` commits, then calls `invalidateStoreProductCaches(storeId)` (`apps/api/src/lib/public-cache.ts:317`) via `deferAfterTenantCommit`. The feed path calls it directly per store inside its `step.run`. The layers, each named in a test: 1. Redis/KV `public:products:<store>:*`: PLP lists and search results; PLP SQL sort/filter reads the materialised `p.price`. 2. `public:product:<store>:*`: the PDP. 3. `public:suggest:<store>:*`: search suggest. `ebda_product_search_doc` is text-only (name, name*ar, search_terms, description, description_ar; `product-search.service.ts:44`), so search \_docs* hold no price and need no rewrite; only cached _results_ do. 4. `admin:products:<store>:*`. 5. `public:bundles:v2:<store>` and the category caches (via `clearProductsRedis`). 6. The in-process `BoundedMap` fallback, cleared by the same `invalidateCached*` calls, plus the generation bump (FIX-001) so an in-flight fill cannot republish the old price. 7. Next data-cache tags `products:<store>`, `categories:<store>`, `bundles:<store>` (one `revalidateStorefront` POST): PLP, PDP, home carousels, sitemap, the `/feeds/products.json` and `llms.txt` upstream fetches. 8. The cart: no cache. `cartLineUnitPrice` reads the DB per request, and the client's prepainted cart (`contexts/cart-hydration.ts`) is replaced by the cart GET, whose `priceChanged` drives the notice. 9. Edge/HTTP caches we cannot purge: `/feeds/products.json` (`s-maxage=600, stale-while-revalidate=86400`) and `llms.txt` (`s-maxage=600`/`60`, SWR 86400). For a store with gold pricing enabled they emit `public, s-maxage=60` without SWR. This is the documented BOUNDED-stale residual of ≤ 60 s in third-party caches (crawlers, shopping feeds), written at the cache site. The rate reads themselves are never cached. The checkout gate, the admin rate page and the repricer read the DB directly. Cost if wrong: a shopping feed can show the previous price for up to a minute. Checkout re-prices from the DB and shows "السعر اتحدّث", so no one is charged it.
