## Ruling DEP-OPENNEXT-PREVIEW-1 — backport the Next 16.4 preview-props manifest fix into @opennextjs/cloudflare 1.19.11; boot the built Worker in CI (2026-10-27)

Decision: #256 (`next` 16.3.8 -> 16.4.3) returned HTTP 500 on every request on ebda-web, ebda-admin and ebda-orders and the deploy probes rolled all three back (runs 40426535937, 40426536147, 40426535843). Root cause, reproduced in local workerd: `Error: Unexpected loadManifest(/.next/server/preview-props.json) call!` thrown from `NextNodeServer.getPreviewProps` (Next 16.4 loads that file in its constructor; adapter 1.19.11 inlines only `*-manifest`/`required-server-files`/`prefetch-hints` JSON). marketing (static export) and accounts (static `wrangler deploy` of `dist`) never run the Next server, so they were unaffected. Fix: `scripts/ci/patch-opennext-preview-props.mjs`, run by `scripts/cf-build.sh`, applies the adapter's own one-glob fix (>= 1.20.12) to the installed 1.19.11 and throws if the shape is unrecognised. Adapter >= 1.20.12 is NOT adoptable: it peers `wrangler ^4.148`, and wrangler > 4.116.0 pins a miniflare 5 alpha (DEP-WRANGLER-1). No advisory reopens: `next` stays 16.4.3 and every #256 override is unchanged. Gate: `scripts/ci/next-worker-smoke.mjs` (CI `worker-dry-run`, web/admin/orders) boots `.open-next/worker.js` in local workerd and requests the deploy `--probe` paths; negative control with the patch removed returns 500 with the exact error above. Remove the patch + script when the adapter and wrangler can move together.
Cost if wrong: a future adapter-internal change makes the patch throw at build (fails the PR and the deploy build, never ships a broken Worker); the smoke boots the adapter worker without the Sentry/cache wrapper, so a wrapper-only fault is still caught only by the deploy probes.
