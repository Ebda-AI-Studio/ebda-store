Ruling BARCODE-1c - allocation. In-store EAN-13 only (GS1 prefix 20; 21-29 stay free for merchants who number their own stock), serial = highest existing 20-prefixed serial of the store + 1, so a code is never reused after a delete and never collides with a retail code. Auto-generation runs only for stores with the `inventory.barcode` feature, on product create (no variants), variant create, generated variant combinations and bulk import (after the import), and through "Generate missing barcodes" for existing items (<= 500 per call). It never blocks the create: a failure is logged and the row stays barcode-less. Typed codes: EAN-13 (13 digits) and UPC-A (12) need a valid check digit, anything else is Code 128 text (printable ASCII, <= 48); bulk import fails the ROW, not the batch, on an invalid or duplicate code. Shaped labels encode the code as Code 128 (a shape cannot carry EAN-13); plain labels print a true EAN-13. Cost if wrong: a Code 128 of 13 digits in a shape is not recognised as an EAN by a retail POS; the plain style is the one for retail.
