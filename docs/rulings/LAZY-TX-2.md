# LAZY-TX-2

> Section: Lifecycle emails and referral attribution (2026-10-22, branch `feat/lifecycle-emails`)

Ruling LAZY-TX-2 (2026-10-22) — LAZY-TX-1 extended to the anonymous product list (paging and sort only: `page`, `limit`, `sort`, `cursor`, single string values) and the product page (no query), both with no Cookie or Authorization. Their cached fills and every remaining database read in the handler (the `inventory.backorder` and `product_3d` feature reads, which stay per request and uncached by the route, as FU46-W1b-6 requires) now go through `readInStoreContext`, so a KV hit with a warm feature cache touches no tenant table, and the feature read, when its own cache is cold, runs in its own short store scope. The feature call was NOT moved into the cached fill: that would let an entitlement ride the cached payload, which Ruling FU46-W1b-6 and the `product_3d` precedent forbid. Search, filter, ids, option and unknown query keys never take the lazy path (they keep the request transaction and the search log). Same proof bar: `tests/integration/lazy-request-tx.test.ts` on a real `ebda_app` login (no ambient scope on arrival; a miss returns only the store's own product; a hit makes no Product/Category/Store query; forced unscoped model and raw queries throw on both routes; search/filter/ids/unknown-key/product-page-with-query keep the store scope), plus the `rls-ebda-app` and `tenant-guard-ebda-app` suites green. Cost if wrong: a new database read added to either handler outside `readInStoreContext` gets a `TenantScopeViolation` 500 (loud, never a leak).
