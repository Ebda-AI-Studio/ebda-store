Ruling CF-PLATFORM-1 (2026-10-28) - the per-store backend flag is D1 `ebda-platform` `stores.storage_backend`, bound to the API Worker as `PLATFORM_DB`, read on EVERY `backendFor` call with NO cache layer (NEVER-stale class: it routes money and stock writes; a TTL is not a control, and the flag writer `scripts/cf/flip-backend.mjs` is an out-of-process D1 UPDATE that cannot reach an isolate memo, so a cache would have no invalidation path; one primary-key SELECT per spike-route call is the price). Fail closed: an unresolved store id is 404 `STORE_NOT_FOUND` (never the first store), an unreadable D1 or an unknown value is 503 `STORE_BACKEND_UNAVAILABLE`, a deployed Worker without the binding is 503 `PLATFORM_DB_UNBOUND`; the `STORE_DO_ENABLED_IDS` + `x-ebda-backend` spike gate survives only where D1 is unbound in Node/local/test. A store with no D1 row yet is on Postgres: the flip UPDATEs an existing row, so a store never migrated into D1 cannot have been flipped (platform-to-D1 runs in the cutover window, runbook s6). The deploy applies the cf-schema platform migrations before the Worker (`cf-api-deploy.yml`) and refuses to build the deploy config without the repo variable `EBDA_PLATFORM_D1_ID`. Public `/health` carries only `platform_db: ok|unavailable`; the per-backend counts (which disclose the store count) are served by the super_admin `/api/v1/health` (`data.storage_backend`), and a 503 body is generic (the D1 error is logged server-side only). Evidence: `tests/unit/store-backend-flag.test.ts`, `apps/api/workers-test/platform-d1.test.ts` (real migrations, built Worker, /health counts follow a flag write immediately). Cost if wrong: a D1 outage returns 503 on the three Phase 0 spike routes (cart add, order create, product list) because they cannot know their backend, and a store created after the platform migration but before its D1 row exists reads as Postgres until PR C inserts the row on store creation.

Amended by CF-BACKEND-1 (2026-10-30, integration): `backendFor(storeId)` takes no request and the `x-ebda-backend` header is retired; the D1 read, no-cache and fail-closed parts of this ruling stand.
