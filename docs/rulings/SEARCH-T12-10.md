# SEARCH-T12-10

> Section: 2026-10-16 — Search program, PR 4 (P1c, hybrid ranking): SEARCH-T12-\*

Ruling SEARCH-T12-10 (Task 12 review I1; refines SEARCH-T12-7) — a SPENT daily query-embed budget is a stable keyword-only MODE until the next Cairo day, not a transient failure, so its lists are cached. Before, every refusal made the list `degraded` and uncacheable, so once a store's (or the platform's) budget was spent — by organic traffic or by ~1000 cheap unique queries — every weak search on it skipped every cache layer for the rest of the day (keyword leg, two `findMany`, facets and up to 7 DO operations per request): a day-long cache-off lever on Neon and DO cost. Now `takeQueryEmbedResult` (`apps/api/src/lib/search/embed-budget.ts`) returns the refusal reason; a daily-cap refusal marks the store (store cap) or the platform (query-wide or account-wide cap) spent until the next Cairo day start (in-isolate `BoundedMap`, BOUNDED by the day), and while marked it refuses with no Redis round trip; a configured cap of 0 reads as spent directly. The list cache key carries the mode for a search (`semantic: 'off' | 'on' | 'budget-spent'`; absent without a search, which never ranks), the vector leg is skipped entirely in `budget-spent` (no cached-vector exception, so every list of that mode agrees), and such a list is cached for 120 s only while at least 120 s remain before the next Cairo day (the 120 s TTL floor; with less, it is not cached), so no entry outlives the reset. Still never cached (`meta.degraded`): the searcher limit, a lost race, a provider or SQL error, no Redis, and the one request per isolate that DISCOVERS the spent budget (its key still says `on`). Evidence: `hybrid-search-cache.test.ts` "budget spent (cap 0): … IS cached" (second identical request: no service call), "budget spent by use: discovered once (uncached), then cached" (2 service calls for 3 requests), "a transient failure (provider error) is never cached" (2 for 2), and the recovery test (cap back → the same URL gets the semantic hit, because the mode key changed); `search-embed-budget.test.ts` (store vs platform scope, until = next Cairo day start, no Redis call while spent, a searcher refusal never marks). Deleting each guard turned a test red (mode never `budget-spent`, vector leg not skipped, degraded cached). Cost if wrong: another isolate keeps paying one uncached request (and one refused round trip) until it sees its own refusal, and a budget raised mid-day takes effect per isolate only after its mark expires at the day start (or a redeploy).
