# ADMIN-FIX-T2-GATES-1

> Section: ADMIN-FIX-T2-GATES-1 (2026-11-04, admin fix pass T2)

Ruling ADMIN-FIX-T2-GATES-1 - server gates where the UI already gates, and who may do what on a phone order. (D7) Gated server-side: wholesale list and reject (`b2b.wholesale`), coupon validate (`coupons`), loyalty join and `my-transactions` (`loyalty`); NOT gated: wholesale revoke / lapse (a downgraded merchant can still end access) and loyalty `my-points` (already answers `points: null` when the feature is off). (D9) Staff keep read access to the customer list but can browse only the first 500 rows and every staff list read writes a `customers.list_viewed` audit row; the owner is not capped. (S-23) A custom shipping fee on `POST /orders/admin` is refused for staff (`403 SHIPPING_OVERRIDE_FORBIDDEN`, same roles as the coupon and MOQ overrides) and audited as `order.shipping_override`; (S-33) super_admin no longer reaches `POST /orders/admin`, as for status and mark-paid (ORDER-MONEY-SUPERADMIN); (S-26) the coupon, MOQ and shipping override audit rows never reach the customer timeline. (S-31) A manual loyalty award (`POST .../loyalty/members/:id/award`) is `store_admin` only and refused under impersonation (FP-3): the points are spendable, so the platform super-admin does not mint them. (S-24) Percentage coupons are whole percents 1-100 at the route. Evidence: `tests/unit/t2-route-gates.test.ts`, `tests/unit/t2-order-overrides.test.ts`, `tests/unit/admin-order-coupon-override-route.test.ts`, `tests/unit/t2-tenant-scope.test.ts`. Cost if wrong: a downgraded merchant's storefront gets `FEATURE_DISABLED` on coupon validate / loyalty join instead of a soft answer, staff over-reach on customers stays possible but now visible, and a staff member must ask the owner for a custom shipping fee, and platform support cannot award a store's loyalty points.
