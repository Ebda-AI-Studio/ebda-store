Ruling P10-2 - Opus review of P10-1 (supersedes the 3-day give-up in P10-1 a). (a) A stuck charge is NEVER given up on blindly: a claim that was never sent and an answer that was lost look the same (pending, no transaction id), and failing the second kind sent a dunning retry under a NEW idempotency key, i.e. a second charge. The sweep now settles only on evidence: the gateway's definitive answer, or `null` = the provider authoritatively has no record (settled `failed`, reason not_found_at_gateway, enters dunning). Anything else (no lookup on the provider, no transaction id, gateway unreachable, a settle error) leaves the row pending and is named in one P1 per sweep; one failing row never stops the others. (b) Kashier implements `getChargeStatus` for a charge that HAS a transaction id (the documented transaction-details read, the same one that confirms webhooks); without an id it throws "cannot tell" (no documented lookup by merchant order id), so a Kashier answer lost before any id exists stays pending and P1 until an operator checks the Kashier dashboard: this is the residual, and the reason there is no automatic path to dunning for that case. (c) The billing anchor only continues a LIVE cycle: a period that starts now (lapsed, canceled, first payment, an operator override, a trialing subscription's first paid period) anchors on its own day, and `downgradeToFree` clears the anchor, so a stale anchor can no longer give a 4-day or 60-day "month". (d) `BILLING_PROVIDER=none` with `BILLING_TRIAL_CARD_MODE=pay_at_trial_end` boots; with `card_on_file` it fails at boot with a clear message instead of crashing in the provider resolver. (e) MERGE ORDER: P10 touches applySuccess / the renewal `start` / runBillingCycle like FOUNDING-1 does; merge P10 first, then FOUNDING-1 rebases (the free-month carry must be added to the ANCHORED end: set the anchor to the day of the new end when a carry is non-zero, and the stuck sweep must run before `sweepFreeMonthGrants`, which skips a store with an in-flight pending charge). Not done: no backfill for subscriptions that already drifted (a null anchor falls back to the drifted day); no throttle on the boot P1 beyond sendAlert's own title throttle. Cost if wrong: a Kashier charge whose answer was lost before an id existed waits for a human (P1 daily) instead of being retried.
