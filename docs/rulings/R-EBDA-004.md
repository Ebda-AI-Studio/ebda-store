# R-EBDA-004

> Section: 2026-10-07 — Tenant defence: code-level guard + RLS on everything (R-EBDA-003..008)

Ruling R-EBDA-004 — raw SQL policy: ALLOWLIST BY CONTENT, not a tagged helper. With an ambient store or user, `$queryRaw` / `$executeRaw` (and the Unsafe forms) are allowed and RLS is their layer; with NO scope, a statement that names a tenant, child, identity, user-keyed or `stores` / `store_credentials` table (FROM / JOIN / INTO / UPDATE / USING / TABLE) is refused, while definer calls, catalog queries and `set_config` pass. A tagged store-injecting helper was rejected: ~160 raw call sites, most already filter `store_id` explicitly and run in scope, and rewriting them buys nothing RLS does not already enforce. Evidence: `assertRawScoped` cases in `tests/unit/tenant-guard.test.ts` and the raw-SQL block of `tests/integration/tenant-guard-ebda-app.test.ts`. Cost if wrong: an in-scope raw statement that forgets `store_id` is held back by RLS alone (one layer, not two), and a contextless statement that names a table through a comma join or a CTE alias the regex does not read is not refused by the guard (RLS still returns nothing).

> Section: 2026-10-03 — Sentry backlog batch (branch `fix/followups13`, issues 2469–2473)

Ruling R-EBDA-004: the shipping layer (SP7, migration `20261005090000_sp7_shipping`). (1) One `ShippingCarrierProvider` interface evolved from Ebda Store's: `capabilities` (quote, label, webhooks, polling, `cod: true | false | 'unconfirmed'`), a per-call `CarrierCallContext` (non-secret settings, the callback URL), typed `CarrierError`s so an outage (retry) is told from a refusal (do not), cancel answering `cancelled | not_cancellable | failed`, optional `quote` and `getLabel`. Adapters: Bosta (REST v2, COD as an EGP decimal, tracking pushed to a per-store secret URL), Aramex (polled by the tracking cron; COD is REFUSED until the merchant records Aramex's written confirmation that COD is collected in EGP, because one integrator source says USD only; the old `amount / 1000` EGP is gone), and a manual carrier (the merchant types courier and tracking number). Every field not confirmed against a live sandbox is marked `UNVERIFIED:` in the adapter. (2) Bosta signs nothing, so its callback URL is `/api/v1/webhooks/shipping/bosta/:storeId/:token` with a server-generated per-store secret in the store's encrypted carrier credentials (compared in constant time; wrong token, unknown store and a store without Bosta are all the same 401; rotation stops the old URL at once). (3) Booking claims the shipment row (`creating`) before the carrier is called, so a double click or a retry books one parcel, the carrier dedupes on our reference where it can (Bosta by `businessReference`, Aramex by an adapter cache), and a failed booking leaves `creation_failed` with the reason. Confirming an order only sends `shipment/create.requested`: a carrier outage never touches the order, the Inngest job retries 6 times and pushes the merchant when it gives up or at once for a refusal retrying cannot fix. An InstaPay order awaiting confirmation, or an order the status machine will not ship, is refused before any carrier call. (4) Tracking merges by (status, timestamp): a replay is a no-op, a late old event is recorded in order without moving the status back, a finished shipment is not reopened; the poll cron finds shipments with one tenant transaction per store (`sweepAcrossStores`) and polls each in its own store scope. (5) COD reconciliation: `cod_remittances` (strict RLS; gross, fee and net per statement line in piastres, net = gross - fee enforced by a CHECK) is the ledger; a CSV statement is imported idempotently and each shipment's match (awaiting / partial / settled / over-remitted / mismatch) is COMPUTED on read by the pure matcher in `lib/cod-reconciliation.ts`, so partial remittances add up and totals satisfy `owed - collected = outstanding - over` and `collected = fees + net` to the piastre. (6) The shipping routes were context-less, which under strict RLS meant an empty settings page and rejected writes; they now pick a context per request (`shippingCarrierRouteContext`: reads one transaction, carrier calls and writes store scope). Evidence: `tests/contract/shipping-carrier.contract.ts` run for Bosta, Aramex and manual (`tests/unit/shipping-carrier-contract.test.ts`), `tests/unit/cod-reconciliation.test.ts`, `tests/unit/shipping-sp7-on-do.test.ts (ported off Postgres 2026-11-23)` (real Postgres, `ebda_app` login, loopback stubs), each mutation-checked. Cost if wrong: every `UNVERIFIED:` field (Bosta state codes and endpoints, Aramex sandbox host, domestic product codes, cancel) can be wrong until a real sandbox key is used; Aramex COD stays off until Aramex confirms EGP in writing.
