# B4-8

> Section: 2026-10-22 — Phase B4 Lamma (B4-\*)

Ruling B4-8 — `reorder` is a per-customer product source, as built. (1) The endpoint returns ids only and lives under `/public/customers/me/reorder` (the public router; `customers.routes.ts` is the admin customer CRM). (2) "Paid or delivered" is `paymentStatus = paid` or `status = delivered` (cash on delivery is paid at delivery), excluding cancelled and refunded. (3) The row resolves product data through the existing cached `/public/products?ids=` read in the browser, not through a new server join, so there is exactly one product-read path to invalidate; `canBuyNow` filters what the customer can buy now and the cart add re-checks. (4) The source is added to the `product-carousel` extras (`ExtraCarouselSource`, layout schema, registry, admin picker) and to `featured-collection`; the product spotlight does not take it. (5) "Reorder this order" uses `api.addToCart` per line and one cart refetch rather than `CartContext.addItem`, so a refused line does not raise its own error toast and the skipped count can be one sentence. Evidence: `tests/unit/customer-reorder-do.test.ts` and `apps/api/workers-test/customer-reorder.test.ts` (negative controls for another customer, another store, cancelled, unpaid, the fourth-oldest order, archived and deleted products), `tests/unit/reorder-row.test.tsx`. Cost if wrong: a customer with more than three recent orders sees only the last three; the row appears after hydration (a CLS jump, measured in the matrix).
