Ruling WA-BRIDGE-BIND-2 (2026-11-12, review of PR #640) - the WA-2 rebuild-and-compare check covers every bridge method, not only the two that carry a phone.

- Key-only methods (`getCustomerAddresses`, `saveCustomerAddress`, `getOrderStatus`, `listCustomerOrders`) take an optional trailing `phoneE164`; with it, the Store recomputes `buyerKeyFor(secret, phone)` and refuses a mismatch (`invalid`, constant-time). Order methods (`getPaymentLink`, `recordCodOutcome`, `attachPaymentProof`) take an optional `buyerKey`; with it, it must equal the key stored on the order (live state), and a mismatch answers `not_found`, identical to an unknown order.
- Why optional: ebda-whatsapp still sends the old shapes, and the byte-pinned fixture `tests/vectors/ebda-wa/bridge-v1.json` is shared with it; making the proof mandatory today would break every order lookup and COD outcome in production. `WA_BRIDGE_REQUIRE_BUYER_PROOF=1` makes it mandatory (fail closed) the moment Chat sends the proofs. Chat-side follow-up: send `phoneE164` on the four key-only calls and `buyerKey` on the three order calls, then set the var and drop the relaxed branch.
- Test for WA-1 at the real port: `wa-bridge-proof-audit.test.ts` runs `createDoPort().attachProof` and fails if the signed URL reaches the audit row.
  Cost if wrong: until Chat sends the proofs and the var is set, a caller that omits the proof is still trusted exactly as before (no regression, no new protection for that call); once strict, a Chat build that omits one gets `invalid`/`not_found` on that call.
