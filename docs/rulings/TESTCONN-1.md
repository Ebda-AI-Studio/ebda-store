# TESTCONN-1

> Section: 2026-10-29 - Close sweep 2 (N9, `fix/test-connection-fail-open`)

Ruling TESTCONN-1 - `NotificationConfigService.testConnection` never reports success for a channel it did not test. Before: every channel other than `sms` (push, whatsapp, anything) returned `{ success: true }` after a debug log (`notification-config.service.ts`, master N9). Now: push (`push` or the admin's `push_notifications`) checks the platform VAPID keys and that the store has at least one subscribed device (no notification is sent to a shopper), and fails with a reason otherwise; whatsapp (a separate product) and any unknown channel answer `{ success: false, message: "... not testable ..." }`. Sibling defect fixed in the same pass: the route answers HTTP 200 with `{ success:false }` for a failed test and the admin page only looked at the HTTP error, so even a failed SMS test showed a green tick; `notifications/page.tsx` now treats `data.success === false` as a failure and shows the message. Test: `tests/unit/notification-test-connection.test.ts` (seen red on the old code). Cost if wrong: a store with push set up but no subscribed device now sees a red "no device is subscribed yet" instead of a green tick, which is truthful but may read as a fault; VAPID reachability to the push services is not probed (a real send would reach a shopper).
