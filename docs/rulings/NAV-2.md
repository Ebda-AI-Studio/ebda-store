Ruling NAV-2 - the header-nav behaviour (Esc returns focus to the trigger, a pointer or focus outside closes, one menu open at a time, a plain link click closes, `aria-expanded` on the trigger) is ONE framework-free script, `SITE_NAV_JS` in `packages/shared/src/brand/index.ts`, served as a same-origin static file by marketing (`/site-nav.js`, written by `npm run site-nav-js -w apps/marketing`), docs and help (`/assets/site-nav.js`, written by site-kit's `writeSiteCss`) and status (a Worker route; its CSP gains `script-src 'self'`, still no inline code). The menus stay plain `<details>`, so without the script they still open and close. `tests/unit/site-nav-behaviour.test.tsx` runs the script in jsdom against each site's real header in ar and en and checks each site serves exactly that text; `apps/status/test/status.test.ts` checks the route and CSP on workerd. Cost if wrong: a change to the constant without re-running `site-nav-js` leaves marketing serving the old file (the test fails until it is regenerated); a site that drops the script tag keeps working as a plain disclosure but loses Esc and click-outside.
