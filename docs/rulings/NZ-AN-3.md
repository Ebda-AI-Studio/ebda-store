# NZ-AN-3

Ruling NZ-AN-3 (2026-11-04, NZ-INTEG-1; found by the N-15 route sweep with Postgres dead) - the merchant analytics aggregates of a store on its Durable Object are computed IN the DO: ten read ops (`packages/repo/src/do/analytics-reads.ts`: `analyticsPeriod`, `analyticsSales`, `analyticsItems`, `analyticsOrdersBy`, `analyticsCustomers`, `analyticsLowStock`, `analyticsStock`, `analyticsCashflow`) are the SQLite twins of the raw Postgres aggregates in `services/analytics.service.ts` (distinct customer key, profit lines, date_trunc buckets in the viewer's clock with Monday weeks, the variant-aware on-hand and stock-value rules, the cash-account trend), reached through `storeMoney(storeId)` (null for a Postgres store, which keeps its unchanged SQL). No Postgres fallback: a DO store never opens a Postgres statement for these routes. Customer names for the top spenders and recent orders come from the customer directory (`customerRows`), the backorder and reorder-rule reads from `storeDb`. The merchant AI switch (`lib/store-ai-switch.ts`, read by every `/ai/*` route) reads the Store row through the store's backend (NZ-AN-2). `store_usage_snapshots` joins the `ai-usage` family (`FAMILY_MODELS` and `cutover-platform-family.mjs`: one marker, the table is copied with `ai_usage`), the cross-store admin pages take their store list from the D1 directory (`d1ListStoreIds`, `d1StoreBriefs`) when it is bound. Evidence: `packages/repo/test/do-analytics-reads.test.ts` (each op on the real DO schema with data), `tests/unit/analytics-service-on-do.test.ts` (Postgres throws), and the sweep `SWEEP_FILTER='analytics|insights|ai-usage|/ai/usage|usage-history' SWEEP_STRICT=1` (`apps/api/workers-test/route-sweep.test.ts`, now switchable from the host through bindings). Residual: `GET /admin/super-admin/ai-usage/summary` and `/usage-history` are ported but still 500 because every `/admin/*` request opens a Postgres user-scoped transaction first (`adminUserContext` / `asPlatformOperator`); settle by moving that namespace's identity check to the identity service. Cost if wrong: an analytics figure computed by a DO op that differs from its Postgres twin shows a merchant a different number after the flip; the op tests pin each definition, and the Postgres SQL stays the reference.
