# ACCT-AUDIT

Source: `business/ebda/audits/2026-11-14-accounting-audit.md` (section 3, defects D-1 to D-11). Each finding was re-verified against `origin/main` at `5a00342fe` before it was fixed. Money rules held throughout: integer piastres, every journal DR = CR, postings idempotent on replay, corrections by reversal (nothing is deleted), Cairo day boundaries. The live ledger is the StoreDO; the Postgres twin was patched where the same code path exists and is otherwise untouched (Postgres is removed from production, so `tests/integration/accounting` covers only that removed path and was not run).

Ruling ACCT-AUDIT-1 - A PO receive pass posts only the DELTA over what that PO already booked to Inventory (`SUM(debit)` on 1200 for source `purchase_order`, sourceId `<poId>` or `<poId>:recv:*`), keyed `<poId>:recv:<cumulative received value>`. A replay finds its own key and posts nothing; the old single entry keyed `<poId>` is counted, so no history is rewritten. Historical impact: a PO that was received in parts BEFORE this fix is under-booked until the next journal job (or the nightly sweep, ACCT-AUDIT-5) runs for it; that run posts the missing remainder as a NEW entry dated at the PO's last receive date. Plan, not executed: list POs where `SUM(qty_received*unit_cost)` exceeds the 1200 debit booked to them, run `journalRepostMissing` once per store, check the trial balance and stock-value-vs-GL tie. Needs Ahmad for prod. Cost if wrong: a PO whose receipts were deliberately booked another way would get a second Inventory/AP posting; the delta rule only ever adds what is missing, and a wrong one is reversed by a manual reversal entry.

Ruling ACCT-AUDIT-2 - A receipt's OCR `total` is the GROSS (tax-included) amount, so the draft stores amount = total - tax (tax larger than total is treated as a misread and dropped). A receipt with only a subtotal is already net. Historical impact: OCR drafts created before this fix that carry the doubled VAT stay as they are; a merchant fixes an unposted draft in the edit screen, a posted one is corrected by a reversal plus a new entry. Cost if wrong: a receipt whose `total` the model returned net of tax would now be understated by the tax; the draft is reviewed before posting.

Ruling ACCT-AUDIT-3 - Expense, stock-adjustment and PO-receive journals are dated by their document (expense date, adjustment post date, PO receive date), never later than now. Cost if wrong: an expense entered with a typo'd old date moves cost into that month; the period close (ACCT-AUDIT-4) is the guard.

Ruling ACCT-AUDIT-4 - Closing the books is a server-owned store setting `settings.accountingLock = { through, untilMs }` (no schema migration; mirrored to `store_config.settings`; written only by `PUT /stores/:id/finance/period-lock`, audit-logged, merchant MFA). The DO `postEntry` refuses a MANUAL entry dated before `untilMs` (409 PERIOD_LOCKED) and posts a SYSTEM entry (a late job, a back-dated document) on the first open instant instead of failing the job, so a closed month never changes and no job retries forever. Reversals post "now". The Postgres twin does not enforce the lock (removed from production). Reopening is allowed and audit-logged. Cost if wrong: a backdated system document is booked on the first day of the open period rather than its true date, which is the safe side of a closed month.

Ruling ACCT-AUDIT-5 - A lost trigger is healed twice: the enqueue failure now posts the journal inline (idempotent), and the 01:30 Cairo `accounting-period-reconciliation` runs the DO op `journalRepostMissing` first (posted expenses and stock adjustments with no entry, every PO with received lines; bounded per run; expenses only while `accounting.expenses` is on, so turning it back on back-fills). Cost if wrong: the sweep posts a journal the merchant expected to stay unposted while the feature was off; expenses are excluded while it is off, the rest were always owed.

Ruling ACCT-AUDIT-6 - Row hashes carry an occurrence ordinal for the 2nd, 3rd ... identical line in ONE file (the first keeps its old hash, so earlier imports still match), the import stores every parsed row, and `imported` counts only rows this import stored (`alreadyImported` is returned and shown). A line already stored by an earlier statement is still skipped by the `(store_id, row_hash)` unique, now visibly. Cost if wrong: re-importing a statement whose repeated lines were collapsed by the old code stores the previously missing repeats as new rows; that is the correction, and they land unmatched for review.

Ruling ACCT-AUDIT-7 - Auto-match is tied to the statement's own GL account and the right side of it: money IN (bank credit) is a DEBIT on the bank asset account, money OUT a CREDIT (the old matcher compared debit with debit across every account in the store, which is inverted for an asset). Candidates score amount closeness minus 10 points per whole day apart; the best wins only when it strictly beats the runner-up. Historical impact: existing auto-matches stay until a re-run; re-running auto-match on a statement resets and recomputes them. Cost if wrong: a deposit booked on the credit side of the bank account (a sign error by the merchant) no longer auto-matches and shows as unmatched.

Ruling ACCT-AUDIT-8 - Bank CSV parsing: the last of `.` / `,` is the decimal mark when both appear; a lone comma is decimal when it appears once with 1-2 digits after it (`100,50`), thousands otherwise (`1,234`); several dots group thousands. Arabic headers match with or without the definite article, non-UTF-8 files decode as windows-1256, the header is the first of 40 lines that names date, description and an amount column. Cost if wrong: an amount written `1,50` as one-and-a-half thousand reads as 1.50; statements use two decimals so this is not a real form.

Ruling ACCT-AUDIT-9 - A merchant (`store_admin`) may post manual entries and reverse them: `POST /finance/journal` (was super_admin only) and `POST /finance/journal/:entryId/reverse` (reason of 3 to 500 characters required; the actor is stored on the reversal's `posted_by`, the reason in its memo). Only MANUAL entries are reversible here, once; system entries are reversed by their own flows. Cost if wrong: a merchant books a wrong manual entry; it is reversed, never deleted, and the actor and reason are on the record.

Ruling ACCT-AUDIT-10 - Expense VAT goes to Input VAT (new system account 1300) when the store's chart has it; a chart without 1300 keeps the old gross posting (never a failed job); `Seed COA` back-fills 1300. The tax report adds `totalInputTax` and `netTaxPayable`; derived rates snap to 0 / 5 / 10 / 14 when one piastre of rounding explains the gap. NOT fixed: a basket mixing 14% and exempt lines still shows one blended rate because `OrderItem` carries no tax-rate field; unblock = add a per-line rate snapshot column (schema + checkout) and split the report on it. PO VAT is not posted either (the PO model has no tax fields). Historical impact: expenses posted before this keep their gross posting and sit in the expense account; Input VAT starts accumulating from the first post after the store is re-seeded. Plan, not executed: per store run `Seed COA`, then for each past expense with tax > 0 post a manual reclass DR 1300 / CR expense account (merchant decision per expense). Cost if wrong: a merchant who cannot reclaim input VAT sees it on 1300 instead of in expenses; a manual entry moves it back.

Ruling ACCT-AUDIT-11 - Gateway fees, payouts and COD remittances are booked by an explicit entry, not guessed: `POST /finance/payouts` posts DR bank (net) + DR Bank Fees 5800 (fee) / CR the cash-in-transit account (gross, 1000 / 1010 / 1020), through the manual-journal path (idempotency key, active-account check, period lock). NOT automated: no provider webhook in the repo carries a settled fee and batch, and the COD statement import carries no bank date, so the merchant records each payout (admin: Finance, Bank reconciliation, "سجّل تحويل مستحقات"). Cost if wrong: a merchant forgets to record payouts and the in-transit accounts keep growing; the bank-rec difference report shows it.
