Ruling CHAT-ASSIST-ORDERS-1 (2026-11-24) - `getOrdersSummary(storeId, asUserId, { period: today | yesterday | this_week | last_7_days | this_month })` on `WhatsAppBridge`, for Ebda Chat's owner assistant ("how many orders today", "my sales this week").

- OWNER only, live role read (`memberRole`); store resolved + linked first; per-store token bucket.
- Windows are Cairo calendar windows: today / this week (the week starts Saturday) / this month end now, yesterday ends at today's midnight, last_7_days is rolling.
- Population = the dashboard's ONE revenue definition (`lib/revenue-sql.ts`: not cancelled / refunded / awaiting InstaPay, payment not failed / refunded, no abandoned online checkout). `orderCount` = orders in that population created in the window. `collectedOrders` / `salesMinor` = the orders of that population whose money is collected: payment `paid`, OR a delivered cash-on-delivery order (Ruling CHIP-COD-DELIVERED-1, same predicate as the launch chip), net of refunds. `refundsMinor` = refunded minor units on all the window's orders (completed non-exchange returns vs payment refunds, the larger of the two, capped at the order total: `refundedMinorByOrder`). `avgOrderMinor` = salesMinor / collectedOrders. All integer minor units + the store currency.
- Read through the store's own backend (`storeDb`: DO or Postgres) in pages of 1000; a window above 20,000 orders is refused (`unavailable` + `RANGE_TOO_LARGE`), never summed partially.
- STALENESS: BOUNDED-stale. Figures are cached per store + period for 60 s per isolate; the role and the link are re-checked on every call and a cached figure is never handed to a non-owner. Residual: an order or refund made in the last minute may be missing from an answer; the dashboard (STORE-QA-74, event-invalidated) stays the source of truth. Cost if wrong: an owner sees a number up to a minute old.
  Cost if wrong (definition): a store that marks COD paid late sees `salesMinor` below `orderCount` x average until the courier cash is recorded; the answer says "collected", never "sales booked".
