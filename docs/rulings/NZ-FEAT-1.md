# NZ-FEAT-1

> Section: NEON-ZERO feature-gated subsystems (2026-11-06)

**Ruling NZ-FEAT-1 - every feature-gated admin subsystem a merchant can switch on answers from the store's StoreDO, and the route sweep's route fixture store runs with EVERY feature key on so a gated route can no longer hide behind its 403. Ported: finance (accounts, journal incl. the manual entry as money op `journalManual`, replayable by the client's `Idempotency-Key`, fx-rates, dashboard via `stockValue`, bank statements incl. import / auto-match / manual match / difference via `bankLedgerSide`), loyalty admin lists (no Postgres history import and NO done flag written on a Worker without Postgres; names from the DO customer directory), the customer wallet reads (balances, ledger, wallet page; the movement stays the `walletEntry` op), warehouses (rows writable, the default switch in one atomic batch; stock still only through the stock ops), affiliates (config, CRUD, clicks, referrals, events, stats; balances, commission AND the referral lifecycle locked out of the generic writer: `Affiliate.totalEarned/totalPaid/pendingBalance` and `AffiliateReferral.commissionAmount/status/orderId` move only in the affiliate money ops and the `affiliateReferralLink` procedure (clicked + unlinked only, conditional on Postgres too); the generic writer never deletes an `Affiliate` or a `Warehouse` (their FKs cascade payouts / stock); the affiliate delete is the `affiliateDeleteIfClean` procedure, one conditional statement, so a commission landing first is never cascaded away; `affiliateReverse` subtracts only when its own claim moved the referral), backorders (list; cancel as money op `backorderCancel`: claim, deferred-cost flag, stock-debt heal and marker in one section; a re-cancel by anyone is a replay that answers 200 with the first cancel's figures and sends no second `order/refunded`), scan-to-pick (stock op `pickOrderItem`, capped in one section) and pick progress, campaign test-send (no Postgres transaction), abandoned-cart stats and the AI product feed bundles; suppliers / expenses / backorders answer 404/409 `AppError`s where a plain `Error` answered 500. Residuals accepted: (1) on a DO store an affiliate with any payout or a non-zero earned/pending balance cannot be deleted (409 `AFFILIATE_HAS_PAYOUTS`; suspend it instead) because payouts are money history and `AffiliatePayout` is not writable, while Postgres cascades them away; (2) bank manual-match check and update are separate RPCs (CF-WRITES-1): two admins matching one entry to two bank rows at the same instant could both pass, bookkeeping only, no GL. Evidence: PR #466 measured 33 gated routes answering 500 with all features on; this change: strict sweep 957 requests, 0 failing; `workers-test/feature-gated-do.test.ts` drives each subsystem's happy path with `/__dev/pg-reaches` empty; `packages/repo/test/do-finance-ops.test.ts`. Residual (3): if the first cancel's `order/refunded` enqueue fails after the DO committed, the request errors and a replay does not re-send it (the event must be replayed by an operator), the Postgres twin's post-commit shape. Cost if wrong: a merchant who deletes a long-running affiliate has to suspend it instead, and a simultaneous double bank match needs a manual unmatch.**
