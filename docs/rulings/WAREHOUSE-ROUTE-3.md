# WAREHOUSE-ROUTE-3

Ruling WAREHOUSE-ROUTE-3 (2026-11-17, review of #733) - an order the aggregate covers is NEVER refused for the way its stock is spread over warehouses. Amends WAREHOUSE-ROUTE-1 step (4): `NO_SINGLE_WAREHOUSE` (409) is removed.

Rule. In `planRoute` (`packages/repo/src/do/warehouse-route.ts`), after the shadow is reconciled to the aggregate: (1) if any active warehouse (`priority desc, code asc`) holds the WHOLE line, the line goes there alone (no needless split); (2) otherwise the line is split greedily in that same order: the highest-priority warehouse takes `min(what it holds, remaining)`, the next takes the rest, until the line is covered. The aggregate is decremented exactly as before (it stays the oversell guard, so an order above the aggregate is still `OUT_OF_STOCK` or follows the backorder path and changes nothing), then each chosen warehouse row is decremented by its chunk (`applyRoute`), so SUM(rows) == aggregate holds. One allocation (`orderItemId`, `warehouseId`, `warehouseCode`, `quantity`) is written per (line, warehouse) in the `warehouse_allocated` event. If the rows still hold less than the aggregate after the reconcile, the uncovered units are reconciled onto the default warehouse (ROUTE-2 rule); routing never throws.

Give-back. `releaseToWarehouses` (called by `restoreLine` for cancel, refund and return) returns units per allocation, bounded by allocated minus already released, keyed per (`orderItemId`, `warehouseId`) in the `warehouse_released` events. A partial return restores in REVERSE priority (the last chunk taken, the lowest-priority warehouse, first); a full cancel restores every chunk exactly; a replay or a second return never gives back more than was taken. Units a line never had allocated (override, backorder, pre-routing) behave as ROUTE-2 says.

Evidence: `packages/repo/test/do-warehouse-route.test.ts` (ROUTE-3 block: 2+1 split, exact-once cancel, reverse-priority partial returns, clamped give-back, whole-line-first, OUT_OF_STOCK unchanged, phone order), `packages/repo/test/do-warehouse-unpaid-cancel.test.ts` (unpaid COD and InstaPay expiry/auto-cancel restore to warehouse B once), admin `WarehouseCard.test.tsx`. Concurrency is unchanged: the aggregate guarded UPDATE inside the DO single-writer section is the oversell guard (WAREHOUSE-ROUTE-CONC-1, architecture guarantee); no concurrency test was added. Cost if wrong: a merchant may have to pick one order line from two branches (and if priorities are wrong, from the wrong one first), which is still better than refusing a sale the stock covers.

Admin how-to: the order page "Fulfilled from" card shows each line with every branch and its quantity (for example `A x2, B x1`) and a hint when a line ships from more than one branch.
