# CF-CAP-1

Ruling CF-CAP-1 (2026-10-30, INFRA-CF-1 integration 2) - `countUsage` (plan-limit.service.ts) behind `assertWithinLimit('maxProducts' | 'maxOrdersPerMonth')` counted products and orders in Postgres; a store on its Durable Object keeps them in its DO, so its count froze at the sealed value and the cap never bit. It now counts on the DO for those two keys (staff, domain and billing stay on Postgres: platform rows). RESIDUAL, accepted: `assertWithinLimit` then create is two steps on both backends (Postgres takes no lock either), so N parallel product creates by one merchant can overshoot a plan cap by up to N-1 rows; it is an entitlement nudge billed by plan, not a security or money cap, and the next create is refused. Making it one DO section needs product create (variants, images, tags) inside one op, which is out of scope. Evidence: `tests/unit/plan-limit-do-count.test.ts`. Cost if wrong: a DO store could exceed its plan product count by the number of concurrent creates.
