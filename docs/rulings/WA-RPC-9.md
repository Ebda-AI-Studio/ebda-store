# WA-RPC-9

Ruling WA-RPC-9 - an engine 5xx is never a business refusal (issue #662, amends WA-RPC-8). `refusalOf` now returns null for any error carrying status >= 500 BEFORE it consults the code sets, and `NEGATIVE_TOTAL` (a pricing invariant breach the engine raises with 500, checkout.ts and admin-order.ts) is no longer listed as a business code. A null propagates out of `placeOrder`, so `createBridge.run` logs it and the caller retries and alerts, as it did before #637; previously the PortError path returned before the log call and a money-calculation bug on a WhatsApp order vanished. Evidence: `workers-do/wa-bridge.test.ts` (`refusalOf` table: NEGATIVE_TOTAL/500, BAD_ARGS/500 and OUT_OF_STOCK/500 are null). Cost if wrong: a deterministic engine 500 retries until the bug is fixed instead of showing the buyer a refusal, which is the intent for a bug.
