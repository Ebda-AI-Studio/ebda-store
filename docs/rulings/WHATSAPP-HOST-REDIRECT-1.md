# WHATSAPP-HOST-REDIRECT-1

Ruling WHATSAPP-HOST-REDIRECT-1 - `whatsapp.ebda.app` (any path) answers a 301 to `https://wa.ebda.app/` with the path and query kept, and nothing in production says Ebda Chat is "coming soon". Evidence (measured 2026-11-10): `https://whatsapp.ebda.app/` answered 200 with «ابدأ شات جاي قريب. | ابدأ ستوديو للذكاء الاصطناعي» while Ebda Chat is LIVE at `https://wa.ebda.app/` (title «ابدأ شات | Ebda Chat», served by the ebda-whatsapp Worker: `wrangler.jsonc` custom domain `wa.ebda.app` plus the more specific route `wa.ebda.app/*`, Ruling WA-ROUTE-1). The `whatsapp` label is a reserved platform label nobody serves, so it fell through the storefront Worker's `unservedHostResponse` to `COMING_SOON_LABELS`. Change: `packages/shared/src/studio-pages` gets `REDIRECT_LABELS` (`whatsapp` → `BRAND.domains.whatsappApp`) and `studioHostPlan` returns `{ status: 301, kind: 'redirect', host }` for it; `apps/web/studio-host.ts` turns that into the 301 (`Cache-Control: no-store`), and the middleware passes the request's path and query. The `whatsapp` and `wa` coming-soon labels are removed, and so is the `'whatsapp'` member of `ComingSoonProduct` and its two "coming soon" lines (nothing else used them). `wa` is removed rather than redirected: its own Worker route serves it, and if that route ever vanished a 404 is honest while a redirect to itself would loop. The studio page's site map (on every 404 and coming-soon page) no longer lists Ebda Chat under "next"; it is now a live link to wa.ebda.app. Same defect class on ebda.app itself: the marketing 404 (`apps/marketing/src/lib/not-found-copy.ts`) listed «ابدأ شات» / "Ebda Chat" under "Coming soon"; it is now its own live group (how it works on /whatsapp, open wa.ebda.app), and `tests/unit/marketing-404.test.tsx` fails if Chat is ever marked coming soon again (mutation-checked). Unchanged: crm, erp, hub and id coming-soon labels, `parseStoreHost`, the reserved slugs, and wa.ebda.app's Worker. Tests: `tests/unit/web-cross-tenant-cache.test.ts` (whatsapp.ebda.app `/` and `/inbox?x=1` are 301s to wa.ebda.app with the path kept; wa.ebda.app reaching the storefront is a 404; crm/erp/hub/id stay 200 coming-soon; no rendered studio page pairs Ebda Chat with "coming soon"). Cost if wrong: someone who typed whatsapp.ebda.app expecting a page about Ebda Chat lands on the live product instead, which is the intended destination; the only real risk is a stale cached 200 at an edge, which `no-store` already prevents.
