# Ruling ROLE-GUARD-LAZY-1 - the Worker's BYPASSRLS guard runs on first Postgres use, not on every request

**Date:** 2026-10-31
**Decision:** the Worker's database-role guard (`cf/database-role-guard.ts`) no longer gates every request in `withWorkerContext`. It runs as the `onConnect` hook of `ConnectionScope` (`packages/database/src/client-pool.ts`): once, on the request's own freshly opened connection, the first time that request actually uses Postgres. A request served by D1 or a Durable Object never opens Postgres, so it never runs the check. A request that does use Postgres is refused (the scope rejects every query, its pool is ended) when the role is superuser or BYPASSRLS, when the role row is missing or unreadable, or when the check itself fails. Only success is cached per isolate, as before; a failed check is re-run by the next request. `/health` already reads D1 (`platform_db`) and the build identity (`commit`, `deploymentId`), never Postgres, so it is unchanged.
**Evidence:** 2026-10-31 production: all 6 stores flipped to StoreDO and the platform data on D1, Neon unreachable (quota), yet api.ebda.app answered 1101 on everything but `/cutover`, because `checkRole()` queried `pg_roles` before every request. `tests/unit/cf-role-guard-lazy.test.ts`, `packages/database/src/__tests__/connection-scope-onconnect.test.ts`, and `apps/api/workers-test/pg-unreachable.test.ts` (built Worker in workerd, Hyperdrive pointed at a dead port: `/health` 200 and a DO store read 200).
**Cost if wrong:** a new code path that reaches Postgres without a `ConnectionScope` (none exists: the leased adapter refuses queries outside a lease) would skip the role check; the lease adapter is the only way to open a Worker Postgres connection.
