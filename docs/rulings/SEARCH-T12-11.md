# SEARCH-T12-11

> Section: 2026-10-16 — Search program, PR 4 (P1c, hybrid ranking): SEARCH-T12-\*

Ruling SEARCH-T12-11 (Task 12 review M5) — the per-searcher query-embed limit is a knob, `SEARCH_EMBED_PER_SEARCHER_PER_MIN`, default raised from 20 to 60 per fixed minute. Evidence: Egyptian mobile carriers put many subscribers behind one public IPv4 (carrier-grade NAT), so at 20 a busy mobile network would turn legitimate shoppers keyword-only at scale, while the limit's only job is to slow ONE client draining the shared budgets; spend is bounded by the daily budgets (SEARCH-T12-3/10), and a spent budget is now a cached keyword-only mode, not an outage. A non-number falls back to 60; `0` stops query embeds for every searcher. Task 14's load run should confirm the default under realistic shared-IP traffic before STOP-3b. Evidence: `search-embed-budget.test.ts` "per-searcher limit: default 60/min, configurable, a bad value falls back, 0 means none" (red before). Cost if wrong: one IP (a single attacker without a botnet) can spend a store's 1 000 daily query embeds in ~17 minutes instead of ~50; the store then serves keyword-only results (cached) until the next Cairo day.
