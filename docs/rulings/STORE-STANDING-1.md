Ruling STORE-STANDING-1 (Controller, 2026-11-15, issue #839) — a store's standing reaches Ebda Chat as contract v1.6 events `store.suspended { reason: unpaid | over_store_limit | admin, at }`, `store.reactivated { at }` and `store.deleted { at }`, and Ebda Chat stops EVERY send that costs money (sends, campaigns, automatic and AI replies, background AI) while the store is suspended or deleted, including a package bought in Ebda Chat itself, until `store.reactivated`. "May this store's messaging spend" is a NEVER-stale class, so the standing is announced on every write of `stores.status` / `deletedAt` / `billingSuspendedReason` and on every Store delete (the one database observer `installWaWriteObservers` → `onStandingWrite`, which also sees D1-served writes through `notifyModelWrite`), explicitly by `afterStatusChange` (billing suspend / restore) and by `StoreService.delete` after commit (a DO store's delete never passes the Prisma observer), and re-sent for every linked store by the 12-hourly `wa-plan-sync` reconcile. The job (`lib/wa/standing-state.ts`) reads the CURRENT standing when it runs and stamps it with that read time, so the newest read wins whatever order the queue delivers in; every run is its own envelope (the read time is in the seed), so a suspend → reactivate → suspend sequence is never swallowed by Ebda Chat's dedupe. `inactive` (paused by its merchant) is sent as `store.reactivated`: not a spend risk. A deleted store is always announced (its link row is gone); any other standing only for a store with a link row. The standing branch runs before any active-store filter (PR #805 SUSPEND-OUT-1 must not gate it). Staleness bound: the queue delivery after commit (seconds); a missed observer is corrected within 12 h by the reconcile. Envelope v1.6, vendored sha256 abf04536b60312801a34aa759ae9ed138030af46a00345ccc2cc10ebd863ecac (mirrored in ebda-whatsapp). Cost if wrong: one standing envelope per linked store per 12 h reaches Ebda Chat even when nothing changed (a cheap, idempotent flag write), and a merchant paying Ebda Chat separately loses Chat sending while only the Store subscription is unpaid.
