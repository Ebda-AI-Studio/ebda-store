# PREMIUM-2

> Section: 2026-11-03 - Storefront premium defaults (PREMIUM-\*)

Ruling PREMIUM-2 - image variants made ONCE at upload, never per request (Ahmad approved 2026-11-03, via the controller). The API writes three WebP widths (480/960/1600, `fit: scale-down`, q78) beside every raster upload using the Cloudflare Images binding that already serves PWA icons (D1016-ICONS-1): `<name>.w480.webp`. The name is a pure function of the original key (`@ebda/shared` `images/variants.ts`); the storefront loader (`apps/web/src/lib/image-loader.ts`) only renames, so there is NO transformation or cost on the storefront path. Cards, carousels, categories, hero, PDP and section images carry real `sizes` (`lib/image-sizes.ts`: 46vw on phones, not 100vw) and srcset. Existing images: `POST /admin/images/backfill-variants` (super-admin, per store, resumable by cursor, dry-run first). Order of operations: (1) set repo variable EBDA_IMAGES_BINDING=true and redeploy the API (needs Images enabled on the Whisky account 69188202, steps D1016-ICONS-2); (2) backfill every store until `nextCursor` is null and `failed` is 0; (3) only then set NEXT_PUBLIC_IMAGE_VARIANTS=1 as a build variable of ebda-web and redeploy. Not flipped in code: a srcset to a variant that does not exist yet is a broken image. Cost (ESTIMATE from Cloudflare's published Images pricing, NOT checked in the dashboard): 3 unique transformations per image, 5,000/month free then $0.50 per 1,000. 2,000 new images/month = 6,000 = about $0.50/month; a one-off backfill of 10,000 existing images = 30,000 = about $12.50 once; R2 storage for the WebP set is about 20-30% of the originals ($0.015/GB-month). Alert: grep `IMAGE_VARIANTS_FAILED`. Cost if wrong: if the price is higher the bill is still bounded by 3 x uploads; if a variant is missing while the flag is on, that image is broken until the backfill reruns.
