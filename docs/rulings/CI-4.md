Ruling CI-4 (Store session, 2026-10-25) - delivery is at-least-once with a deterministic `eventId` per occurrence (seed = order / shipment id + kind + attempt number, never the clock or the source event id); duplicates are dropped by a best-effort KV marker in the sink and authoritatively by `eventId` in CI-2 readers. The first-time shipment facts (`pickedUpAt`, `deliveredAt`, `returnedAt`, `deliveryAttempts`, return reason) are stamped in the SAME update as the status, so an enqueue lost to an Inngest outage (logged, never blocks tracking) can be regenerated from the columns with the same ids. Cost if wrong: a few outcome rows missing after an Inngest outage until that regeneration is run (pre-launch there is nothing to lose).
