# WA-BRIDGE-BIND-3

Ruling WA-BRIDGE-BIND-3 - Backfill `orders.buyer_key` before the buyer proof is made mandatory. With `WA_BRIDGE_REQUIRE_BUYER_PROOF=1` the three order calls (`getPaymentLink`, `recordCodOutcome`, `attachPaymentProof`) compare the caller's `buyerKey` with the key stored on the order, so an order created before keys existed (phone, no key) would be refused. `runBuyerKeyBackfill` (`apps/api/src/lib/wa/buyer-key-backfill.ts`) stamps every such order with the SAME derivation as checkout and the CI planner (`buyerKeyFor(SUITE_BUYER_KEY_SECRET, toE164(shippingAddress.phone))`) through the fill-only-NULL `ciOrderStamp` DO op: idempotent, never overwrites a stamped key. It is dry-run by default, counts per store, is resumable through an opaque `nextCursor` (ordered by store id then order id, bounded by `budget` orders per call, max 2000), skips and reports gone stores, stores not on a Durable Object and stores whose DO errors (`gone` / `not_do` / `error`), and leaves orders with no usable phone unkeyed (counted as `noPhone`; they cannot match a buyer proof and stay out of scope). Entry points: super-admin `POST /admin/wa/buyer-key-backfill` (`dryRun` defaults to true, audited as `wa.buyer_key_backfill`) and the driver `scripts/ops/backfill-buyer-keys.mjs` (dry run by default, `--apply`, saved cursor file, follows `nextCursor`). Needs `SUITE_BUYER_KEY_SECRET` (>= 32 chars) on the Worker, else 503. Evidence: `workers-do/wa-buyer-key-backfill.test.ts` (real DOs: dry run writes nothing, same key as checkout, idempotent, no overwrite, resumable, per-store counts), `tests/unit/wa-buyer-key-backfill.test.ts` (skip paths), `tests/unit/ops/backfill-buyer-keys-script.test.ts`. NOT run against production by this PR; the operator runs it as step 3 of the rollout (Store #648 deploy, Chat #67 deploy, run the backfill dry then apply, set the flag, live check). Cost if wrong: an order whose stored phone is not a valid E.164 is never keyed and, under the strict flag, its order-call proof is refused until a human fixes the phone; a backfill run during heavy checkout traffic stamps only still-unkeyed rows, so a concurrent new order is never touched.
