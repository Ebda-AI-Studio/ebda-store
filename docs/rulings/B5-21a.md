# B5-21a

> Section: 2026-10-22 — Phase B5 Dahab (B5-\*)

Ruling B5-21a (Task 10 Step 0, measured in `cf/ioredis-cf.ts` and `lib/public-cache.ts`) — where the cache generations live, and the second named residual. Generation counters (`cachegen:*`) are routed to the AUTH_STATE Durable Object, strongly consistent and atomic, so an in-flight cache FILL always sees a bump and cannot republish the old price. The cache PAYLOADS (`cache:*`) live in KV (`KV_CACHE`), eventually consistent: on Workers a deleted payload key can still be served from another colo for KV's propagation window (about 60 s, KV's own TTL floor). Class: BOUNDED-stale, display only, up to about 60 s per colo, after a rate write. Checkout is unaffected because it reads the database, never these caches (the rate reads, the repricer and the order gate are never cached). Together with the 60 s feed/llms window of B5-21 item 9 this is the whole residual of gold pricing. Cost if wrong: a shopper in a far colo sees yesterday's price for up to a minute and gets "السعر اتحدّث" at checkout instead of being charged it.
