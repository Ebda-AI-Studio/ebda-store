# SKIN-DEL-9

Ruling SKIN-DEL-9 - the SQLite stores accept only the five current Ebda templates (`dahab`, `qamar`, `souq`, `jasmine`, `lamma`), the promise SKIN-DEL-8 made ("the new SQLite schema will only allow the live templates") and the generated schema did not keep: D1 `stores_template_chk` and the StoreDO `store_profile_template_chk` are generated from the Prisma enum, which still lists the five retired skins (SKIN-DEL-8 keeps it). Two hand-written migrations close it: D1 `packages/cf-schema/migrations/platform/0009_store_template_current.sql` and StoreDO `packages/cf-schema/migrations/store/0004_template_current.sql` (`cf-0004_template_current`). Each (a) moves any row on a retired skin to the template readers ALREADY map it to through `normalizeLegacyTemplate` (modern and minimal to souq, classic to dahab, bold and elegant to qamar; `look` untouched), so nothing changes on screen, and (b) adds a `BEFORE INSERT` and a `BEFORE UPDATE OF template` trigger that abort on any non-current value. Triggers, not a rebuilt CHECK: changing a CHECK in SQLite means rebuilding the table, D1 cannot switch foreign keys off (only defer them), and the implicit DELETE of `DROP TABLE stores` still runs ON DELETE CASCADE into its 14 child tables (billing*events, store_subscriptions, store_staff, ...); `packages/cf-schema/test/store-template-current.test.ts` measures exactly that on SQLite (child rows gone after a deferred-FK drop). The generated CHECKs stay as a looser superset; 0002_invariants already enforces invariants with triggers. R20 (owner instruction, 2026-11-10, pre-launch): this moves `qa-walk-store-1010` (inactive, `modern`, look NULL) to `souq`, the template it already renders as, and so supersedes SKIN-DEL-4's "never modified" for this one column of this one store. It is applied only by the deploy: `cf-api-deploy.yml` runs `npx wrangler d1 migrations apply ebda-platform --remote` before `wrangler deploy` (d1_migrations ledger, once), and every StoreDO applies `cf-0004_template_current` on its next start. Verified locally: all 115 cf-schema tests, the workerd DO suite (apps/api `cf:test`), and `wrangler d1 migrations apply --local` on a D1 copy at 0008 holding the QA row (`modern` became `souq`, its `store_features` row kept, a later `modern` or `elegant` write refused with SQLITE_CONSTRAINT_TRIGGER). Cost if wrong: a writer that still emits a retired value fails with a constraint error instead of storing it (every writer is already strict per SKIN-DEL-8: `updateTemplate` answers 400 TEMPLATE_RETIRED, provisioning and `applyLook` only take built skins); undo = `DROP TRIGGER stores_template_current_insert; DROP TRIGGER stores_template_current_update;` (and the `store_profile*\*`pair in a DO), plus`UPDATE stores SET template = 'modern' WHERE slug = 'qa-walk-store-1010'` to restore the old value.
