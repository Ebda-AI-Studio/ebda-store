# B5-23

> Section: 2026-10-22 — Phase B5 Dahab (B5-\*)

Ruling B5-23 — a customer reads their order without the merchant's cost and the gold margin (Task 13). `OrderItem.goldSnapshot` carries the margin, the making charge and the rate row id, which are the merchant's (B5-13). Every customer-facing order read (`GET /orders/:id` for a non-staff caller, `GET /orders/my/list`, the account data export) now passes through `redactOrderForCustomer`: the snapshot is cut to karat, weight, rate, when and unit price (what the shopper saw), and the line's `costPrice` is removed. `costPrice` leaking to customers on those reads PRE-DATES this work (the include returned every column); it is fixed in the same pass because it is the same defect class, and a customer UI that read it would be reading the merchant's margin. Admin reads are unfiltered. Both halves are mutation-tested (`money-gold-order-redaction-snapshot`, `-cost`). Cost if wrong: a customer page that wanted `costPrice` shows nothing for it (none does today; grep clean).
