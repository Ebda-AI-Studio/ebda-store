# SIGNIN-RETURN-1

> Section: 2026-11-03 - Ebda Chat sign-in hands off to the Store sign-in (branch `fix/admin-audit-polish`)

Ruling SIGNIN-RETURN-1 - the admin `/login` honours `?return=` (set by Ebda Chat via `accounts.ebda.app/login?product=chat&return=<url>`) only when the value is a full `https://` URL whose hostname is EXACTLY one of `wa.ebda.app`, `store.ebda.app`, `orders.ebda.app`, `ebda.app`, with no userinfo, no port other than the default, no backslash, control character or whitespace, no protocol-relative or relative form, no wildcard or subdomain match, and not the Store's own `/login` (it would bounce straight back). Anything else is dropped and the normal destination (`?returnTo=` in-app path, else `/`) is used. `?product=` is an allowlist (`chat` | `store`); anything else is the Store. The check is one pure function, `apps/admin/src/lib/sign-in-return.ts` (`safeSignInReturn`, `signInProduct`), used by `postLoginDestination()` for every path that ends a sign-in (password, MFA, passkey, already-signed-in); `goAfterSignIn` leaves the app only for an absolute https URL that came out of that function. A platform admin who must enrol a second factor is sent to enrolment first, ignoring `return`. `accounts.ebda.app` (`GET /`, `/login`, `/sign-in`, Ruling ACCOUNTS-ENTRY-1) now forwards only `product` (known set) and `return` (https, at most 2048 characters) to the Store `/login`; it does not validate hosts, the Store page is the boundary. Evidence: `tests/unit/sign-in-return.test.ts` (accepted hosts plus every rejection class: http, protocol-relative, relative, userinfo, other ports, backslash forms, lookalike and unicode hosts, trailing dot, control characters, length, login loop), `apps/accounts/test/sign-in-entry-params.test.ts`. `connect-src` is unchanged (CSP-ACCOUNTS-1 guard green): the redirect is a navigation, not a fetch. Cost if wrong: a host wrongly added to the allowlist (or a parser quirk the tests missed) is an open redirect from a trusted sign-in page, a phishing step after a real password entry; the allowlist is five lines in one file, so removing a host is a one-line change, and `return` is never used for anything but a final `location` navigation.
