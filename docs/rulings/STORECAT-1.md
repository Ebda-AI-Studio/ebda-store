Ruling STORECAT-1 (2026-10-27) - AI category suggestions for a store with NO categories (docs/plans/ai-features.md Feature 3, the deferred case). `POST /stores/:id/ai/suggest-store-categories` samples up to 60 non-archived products (name, Arabic name, description clipped to 160 chars; no customers, orders or reviews), the model returns 2-8 groups, the service keeps only ids it showed the model, one category per product, drops empty and duplicate-named groups, and returns a PROPOSAL (409 `CATEGORIES_EXIST` / `NO_PRODUCTS` otherwise). Product text is merchant data: a JSON string value under a system prompt that says so. Nothing is written until the merchant presses Create on the categories page, after renaming, removing or un-ticking; `POST .../apply-store-categories` re-validates names (unique, max 60) and re-checks every product id against the store, creates categories with unique slugs and links, busts `public:categories:<store>`, audits `category.created_from_ai_suggestion`. Counts toward the platform AI quota (`ai_usage` feature `store-categories`). Verified live with real Gemini on a 12-product demo store (3 categories proposed, one renamed, created). Cost if wrong: a poor grouping costs the merchant one Discard; nothing is created without their click.
