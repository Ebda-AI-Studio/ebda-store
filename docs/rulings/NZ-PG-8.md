**Ruling NZ-PG-8 - under `SWEEP_STRICT=1` the cron-tick group of `apps/api/workers-test/route-sweep.test.ts` fails when a job touches the Postgres client; the allowlist is EMPTY and must stay empty for DO stores.** The Worker counts every access to the Postgres client (`postgresReaches` in `packages/database/src/request-db.ts`, enabled only by `DEV_STATS=1`, read through the dev route `/__dev/pg-reaches`), each tagged with the cron job that made it (`withReachLabel`, set by `cf/cron.ts` and `jobs/do-guard.ts guardedRun`); a job that catches its own error is still seen. The sweep runs in the cutover target state (`JOBS_ON_DO=1`: DO stores are hidden from unported sweeps, their alarms own the ported ones). Found and fixed with it: the store-directory reconcile opened a Postgres connection for a fleet with no `pg` store. Proved red once against a deliberately unfixed caller (the reconcile guard removed: `store-directory-reconcile` reached Postgres twice, the group failed), then green with the guard back. Cost if wrong: a Postgres reach in code the sweep does not exercise (a job whose store has no data in the fixture) is not seen; the label list in the sweep output shows which jobs ran.
