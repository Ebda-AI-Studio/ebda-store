# B2-17

> Section: 2026-10-21 — Phase B2 Souq (B2-\*)

Ruling B2-17 (security review, Task 6) — the demo showroom slugs cannot be squatted, and the seed never takes over a store it does not own. Shape of the risk: the seed upserted a store BY SLUG, so a merchant who registered `storedemo` or `storedemo-souq` first would have been overwritten (catalogue, home, owner-visible settings) by the next seed run, or could have impersonated the official demo. (1) `isDemoShowroomSlug` (`@ebda/shared`, `startsWith('storedemo')`) makes `validateStoreSlug` refuse the whole family with `SLUG_RESERVED` on signup, store create, slug change and the zod edge; `allowProtected` (the super-admin brand override) never lifts it; `deriveStoreSlug` moves a name-derived `storedemo*` to `store-demo*`. It is deliberately NOT in `RESERVED_SLUGS`: a reserved label is a PLATFORM host and `storedemo.ebda.app` must keep resolving as a store (the resolver uses `validateStoreSlugFormat`, pinned by test). `demo*` in general is NOT reserved (ordinary merchants use `demo-shop`). (2) `seed.mjs` `assertSlugsClaimable` runs BEFORE the first write (owner create, store upsert): every slug the run will write must either not exist, or be an `is_demo` store owned by the seed owner (demo slugs) / a non-demo store owned by the seed owner (local review stores, `--local-look-stores`); anything else aborts with the slug and the reason and nothing is written. `scenario-stores.mjs` applies the same check. Production still needs `--yes-production` and the production asset base. Evidence: `tests/unit/demo-slug-reserved.test.ts`, `store-create-reserved-slug-route.test.ts` (create + update, 400 `SLUG_RESERVED`), `storedemo-seed-guard.test.ts` (`seedStoreClaim` cases + ordering of the check); run live against a real Postgres: a flagged-non-demo `storedemo-souq` and one owned by another user both exit 1 with the refusal and the product count is unchanged (80 before and after). NOT verified: production. The controller must run, read-only, `select slug, is_demo, owner_id from stores where slug ilike 'storedemo%';` and expect exactly `storedemo` (is_demo, owner `storedemo-owner@ebda.app`) before the Souq seed; any other row is a squat to resolve by hand. Cost if wrong: a legitimate merchant whose name derives `storedemo*` gets `store-demo*` (cosmetic); a seed run aborts instead of reseeding a hand-edited demo store (re-run after fixing ownership).
