> Section: Admin fix pass 2026-11-04, track T1 API core (branch `feat/admin-fix-t1-api-core`)

Ruling FP-1 - `goldAllowDeferredPayment` was already in `SERVER_OWNED_SETTINGS_KEYS` on main (`packages/shared/src/server-owned-settings.ts`); the open half of BE:S-8 was `mcpWriteEnabled`, which any client could flip through `PUT /stores/:id` with no audit row. It is now reserved, written only by `PUT /stores/:id/integrations/merchant-mcp/write-switch` (audit row) through `StoreService.setMcpWriteEnabled`. Both flags are listed in `ECHOED_SERVER_OWNED_KEYS`: the generic route DROPS them silently instead of answering 400, because the Delivery and Branding pages still PUT a whole copy of `store.settings` that contains them (BE:F-2), and a 400 would have broken those pages' Save until the client half (T4) lands; `ebdaWhatsApp` (a planted platform link) still answers 400. Evidence: `tests/unit/server-owned-settings.test.ts`, `tests/unit/store-settings-server-owned-route.test.ts`. Cost if wrong: a merchant who sends the flag through the generic route sees the request succeed with the flag unchanged, instead of an error that would tell them to use the dedicated switch.
