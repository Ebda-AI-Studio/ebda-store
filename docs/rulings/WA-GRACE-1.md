Ruling WA-GRACE-1 (Controller, 2026-10-26) — `store.plan_changed` carries `pastDueSince` (ISO, only while past_due) so Ebda Chat ends its grace at min(periodEnd, pastDueSince + 7 d). The date comes from `store_subscriptions.past_due_since`, maintained by a BEFORE INSERT/UPDATE trigger (set once on the transition into past_due, a later retry does not move it, cleared on any other status), so every write path (renewal failure, InstaPay due day, admin override, any future one) carries it and none can forget it; existing past_due rows are backfilled from updated_at. It is part of the dedupe seed and a write to it is announced by the plan observer. Cost if wrong: a row backfilled from updated_at can start the grace later than the true first failure by the time since its last touch.
