Ruling M003-1 (audit M-003, M-025; the legal text is the marketing agent's DOC-2) - InstaPay receipts leave Gemini and stop collecting people. (a) The screenshot is read on Cloudflare Workers AI (the Worker's `AI` binding, vision model `@cf/mistralai/mistral-small-3.1-24b-instruct`, override `INSTAPAY_RECEIPT_AI_MODEL`); nothing is sent to Google; the `callGemini` import is gone from the reader (a test fails if it comes back). (b) The model is asked ONLY for amount, reference, transfer date and time, plus its own `confidence` and `looksEdited` (judgements about the picture, not data read from it; `looksEdited` stays because it feeds the LOOKS_EDITED review flag, and the image is processed either way). The prompt tells it not to read or return any name, phone, bank or address; the JSON schema allows exactly those six keys; `normalizeReceiptExtraction` drops anything else, so payer / receiver / note / direction in the stored `extracted` JSON are always null. The payer's form is no longer pre-filled with names (the payer may still TYPE them: they are the payer's own data, shown to the approver, and are scrubbed below). Consequence: RECEIVER_MISSING / RECEIVER_MISMATCH flags now depend on what the payer typed, not on the model. (c) Retention (M-025), migration 20261106000250: the screenshot is deleted right after the approving transaction commits (both approval paths: the merchant's confirm of an order payment, the super-admin's recorded manual payment; `approveSubmitted` + `deleteImages`), 30 days after a rejection / void, 30 days after an abandoned draft, and for any receipt scrubbed by an erasure; `image_deleted_at` records it, a viewer gets 410 RECEIPT_IMAGE_DELETED. Payer / receiver / note / the AI-read JSON are scrubbed 180 days after a final decision (`personal_scrubbed_at`) and on the shopper's erasure (`eraseAccount` -> `scrubForOrders`); amount, reference, transfer time, flags, status and hashes stay as financial evidence with the payment (5 years). Enforced by the weekly `instapay-receipt-retention-daily` job (registered in jobs-map); rows in docs/RETENTION.md and docs/privacy/data-map.md; an in-product notice at the upload in English and Egyptian Arabic (the legal wording is DOC-2's to align). (d) NOT VERIFIED: the real model's accuracy on genuine Arabic / English InstaPay screenshots (no Workers AI call could be made from this machine: `wrangler dev --remote` could not open a preview session; only a fake binding is tested), that Workers AI accepts `response_format` json_schema for this model (the parser also accepts a plain `{response: "<json>"}` or chat-completion answer), and Cloudflare's no-training-on-inputs term (check at each review). A failure at runtime is manual entry, never a blocked payment. Queue for Ahmad: run 5 real receipts through staging before launch and read the amount / reference / time. Cost if wrong: a poor read means the payer types three fields; a missed image delete is retried weekly; the 30/180-day windows are one constant each.
