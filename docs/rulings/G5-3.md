Ruling G5-3 (2026-10-28) - Inngest is removed. Every background job runs on Cloudflare (Workflows for multi-step, Queues for short idempotent runs, Cron Triggers, DO alarms for per-store schedules). `inngest` (npm), the `/api/v1/inngest` serve route, its limiter and the global-limit bypass, the boot self-register, `INNGEST_*` env, the post-deploy sync step in `cf-api-deploy.yml` (Ruling INNGEST-SYNC-1, superseded), the execution-budget test (INNGEST-BUDGET-1, superseded) and the `dispatch-all` / `with-jobs` bridges are gone; `lib/inngest/client.ts` keeps the call shape (`inngest.send`, `createFunction`) as an in-repo client over `lib/jobs`, and a process without the Worker bindings (Node: tests, scripts) starts nothing. `JOBS_CF_GROUPS` is gone with the fallback it gated: with Inngest gone every mapped job runs on Cloudflare, so there is no partial state to configure (the group numbers in `jobs-map.ts` only record the order jobs were ported in). Evidence: groups 1-8 were switched on (`JOBS_CF_GROUPS=1,2,3,4,5,6,7,8` on main via #292) and each was verified on a real cron/queue tick or a manual trigger on 2026-10-27/28 (instances and queue runs read back from production, `wrangler workflows instances list ebda-jobs`, alert and Sentry paths via Ruling G5-4). Replaces #234 (rebuilt on main after #292; the old branch carried pre-squash history). Cost if wrong: a handler never run on Workflows fails loudly on its first run; there is no Inngest fallback, so the fix is a code PR or `wrangler rollback` (then `gh workflow run cf-api-deploy.yml` if the revert touches no API path).
