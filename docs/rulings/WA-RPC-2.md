# WA-RPC-2

Ruling WA-RPC-2 - Writes are replay-safe and the Store stays the only order writer. `createOrderFromChat` requires an idempotency key (prefixed `wa:`, scoped per store by the checkout engine's own key handling) and goes through the same `money.createOrder` engine the storefront uses, so stock, price, COD fee and tax are computed from rows and never taken from the caller; source is `whatsapp`. `recordCodOutcome` does NOT reimplement state changes: it feeds the proven `whatsapp.cod_outcome` consumer (row-locked, open-COD-only, one-way transitions, audited `source: whatsapp`, no Store-side commerce outcome) with an envelope id derived from the idempotency key, so a replay dedupes and a late `refused` can never cancel a confirmed, shipped or paid order. A gateway failure while minting the link for a `link` order keeps the order and returns `paymentUrl: null` (the caller asks `getPaymentLink`). Cost if wrong: a duplicate key from the caller would return the first order instead of a new one, which is the intent.
