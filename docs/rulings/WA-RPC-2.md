# WA-RPC-2

Ruling WA-RPC-2 - Writes are replay-safe and the Store stays the only order writer. `createOrderFromChat` requires an idempotency key (prefixed `wa:`, scoped per store by the checkout engine's own key handling) and goes through the same `money.createOrder` engine the storefront uses, so stock, price, COD fee and tax are computed from rows and never taken from the caller; source is `whatsapp`. `createOrderFromChat` then writes the payment row exactly as checkout does (COD: `recordCodPayment` with the engine's frozen fee; InstaPay: `InstapayService.initiate`), stamps the buyer key and announces `order/created`. `recordCodOutcome` shares one DO-side function with the queue consumer (WA-RPC-7): open-COD-only, one-way transitions, audited `source: whatsapp` with the idempotency key as reference, no Store-side commerce outcome; a replay is a no-op by state, and a refusal can never cancel a shipped or paid order (`unpaidOnly`). A gateway failure while minting the link for a `link` order keeps the order and returns `paymentUrl: null` (the caller asks `getPaymentLink`). Cost if wrong: a duplicate key from the caller would return the first order instead of a new one, which is the intent.
