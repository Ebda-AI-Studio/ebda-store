Ruling INFRA-CF-4 (2026-10-25; the controller asked for the number INFRA-CF-3, which is already the Phase 1 GO) - the ~2,200 Prisma ORM call sites reach the StoreDO through a Prisma-shaped client over SQLite (`packages/repo/src/prisma-lite`) instead of being rewritten onto Drizzle repo methods; INFRA-CF-2 (Drizzle on DO SQLite) still stands for the schema, the raw-SQL sites and every money/stock/lock section, which become explicit `StoreRepo` methods in `transactionSync`. Why: 2,489 ORM sites in 258 files make a rewrite 4 to 6 weeks (guess) with no behavioural oracle. Coverage today (measured): READS only, findMany/findFirst/findUnique/count with where (scalar ops, AND/OR/NOT, relation some/none/every/is/isNot), select/include nesting with per-parent orderBy/take/skip, `_count`, orderBy including `_count` and to-one relations, take/skip, cursor; NOT yet: writes, nested writes, aggregate/groupBy, $transaction, upsert, createMany, error codes, JSON-path filters, distinct (throws). Proof of parity: differential tests run each query through real Prisma/Postgres and prisma-lite over the same rows and demand deep equality (13 cases), then the integration suite runs with a SQLite backend before any store moves. Security surface: every SQL identifier comes from the generated schema registry (`q()` refuses anything that is not a plain identifier), sort direction/nulls accept only asc|desc|first|last, take/skip are validated integers and BOUND, findUnique requires a complete non-null unique tuple, field lookups use own-property checks (`__proto__`/`constructor` cannot resolve); `prisma-lite-injection.test.ts` fuzzes hostile strings into every argument position. GATE: an Opus review of prisma-lite as a whole must be recorded here before any slice that uses it merges. Cost if wrong: prisma-lite is additive and flag-gated; if fidelity proves too costly the services move to repo methods one by one, the repo interfaces being built either way.
