# REVIEW-FU-3

Ruling REVIEW-FU-3 - closes REVIEW-FU-2's residual: the 58 `tests/unit` files that took `indexOf` / `lastIndexOf` / `slice` positions on SOURCE text were triaged use by use (80 REAL, 10 HARMLESS; the per-use table is in the PR that added this ruling). REAL = the meaning depends on text order or a text window, so it can pass while the behaviour is wrong; each is rewritten to run the real code with fakes where practical, otherwise to a parsed structure (TypeScript AST via `tests/unit/helpers/{ts-ast,ast-query,ast-statements}.ts`, YAML via `yaml`, CSS via `postcss`, a comment-stripped tokenised IF/THEN/ELSE structure for the one SQL migration since the repo has no SQL parser), and each was shown red by putting its defect back in the production file. HARMLESS = runtime/rendered values, path trimming, or failure-message formatting; kept. The rewrite exposed three old windows that passed for the wrong reason (`store-delete-do`'s 14000-character slice, `web-refresh-token-ios-gate`'s slice to a string no longer in `logout()`, `storedemo-seed-guard`'s order check passing on a missing `guard` (-1)) and two scanners that were blind (`res.status(...).json(...)` sends, a brace inside a className string). Cost if wrong: an AST check pins structure, not runtime, so a guard made dead inside its own condition still passes those (the behaviour-tested ones do not).
