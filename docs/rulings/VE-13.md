# VE-13

> Section: Lifecycle emails and referral attribution (2026-10-22, branch `feat/lifecycle-emails`)

Ruling VE-13 (Task 8e, 2026-10-22) - page-type settings have one writer per layout key. The HOME document owns `sizing`, `bottomBar`, `locationsPage` and `productCardDefaults` (a look switch rewrites `productCardDefaults` on the home document, so a second writer would race it). A product, collection or cart document owns `productDetailPage`+`reviewSection`, `productsPage`+`filterSidebar`+`categoriesPage`, `cartPage`+`checkoutPage` (`PAGE_OWNED_SETTING_KEYS`). Publishing or rolling back one of those pages writes exactly its keys into `layout_settings` in the same transaction and nothing else; publishing home keeps the LIVE value of every key another page owns (read in that transaction), whatever its own copy says; `publishedDocumentAgrees` ignores those keys, so a product publish never makes the home document look drifted (which would drop its document-only sections); the editor opens each page on the live values of its keys. Overrides the plan's "product cards under every page": the card style panel is on the Home page and the other pages point to it. Evidence: `tests/integration/page-builder-pages.test.ts` (page-type settings block), `tests/unit/builder-page-kinds.test.ts`. Cost if wrong: a merchant sets card style from the Home page instead of any page, and a settings change on a page only reaches the storefront at that page's Publish.
