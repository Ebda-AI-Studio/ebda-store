# TAXARCHIVE-1

> Section: 2026-11-15 — Super-admin tax archive shows everything the receipt can carry (branch `feat/tax-archive-full-receipt`)

Ruling TAXARCHIVE-1 — Fiscal payload v2 + richer archive lists. (1) `payload.version` 2 (new issues only) adds seller `branchCode` / `activityCode` / `posSerial` / `branchAddress` (from the store's ETA connection), per-line VAT rate + VAT amount (the order's single VAT figure shared pro rata, last line takes the rounding remainder, so shares sum to the order VAT), per-line internal code (SKU) and EGS item code (the connection's `defaultItemCode`, goods lines only), and `paymentStatus`. Issued v1 documents are never rewritten: the renderer prints "not recorded at issue" for the fields a v1 payload lacks. (2) The ETA UUID / status / QR are NOT in the payload (submission happens after issue); the viewer reads them live from `eta_receipts` and the list reads `status` + `uuid` the same way. (3) Buyer contact stays out of the payload (MONEYB-4 minimisation); lists show the buyer NAME (payload for tax invoices, else the live order's shipping name) and a MASKED phone/e-mail from the live order, never the full value. (4) Lists use keyset pagination on `(issued_at desc, id desc)`; no new index: `(store_id, issued_at desc)` serves the date range and the ordering, `doc_type` is a 6-value residual filter, number search is a substring (no btree can serve it), order-number search goes through the unique `orders.order_number` index (prefix, 50 ids). (5) Source for the required fields: ETA Receipt v1.2 spec, https://sdk.invoicing.eta.gov.eg/documents/receipt-v1-2/ (read 2026-11-15). Residuals (accepted): the Postgres definer path (stores deleted before the hub existed) returns whole archives, so it filters and pages in memory; the deleted-store archive shows no customer / payment status / ETA state (live tables are gone); period totals count sale documents only (credit notes not netted). Cost if wrong: a very large deleted store's archive loads slowly, and a super admin reading period totals as net-of-refunds would overstate sales.
