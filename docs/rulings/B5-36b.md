# B5-36b

> Section: Lifecycle emails and referral attribution (2026-10-22, branch `feat/lifecycle-emails`)

Ruling B5-36b - a caller price that differs from the freshly re-read price is `PRICE_CHANGED`, on every path (checkout, quote, admin order, payment link), not only when a shopper quote exists. `GOLD_PRICE_DRIFT` (P1) means the STORED price differs from the recompute, and only after one re-read of price and rate (they are separate reads, so a rate write between them looks like drift). The in-transaction check re-selects the rows (price + resolved spec + rounding step) WITHOUT a row lock: `FOR SHARE` on products/variants would queue every checkout behind a hot SKU's stock decrement (DB-006). Cost if wrong: a weight edit committing in the microseconds between that re-select and the commit is still charged at the old price; the rate row itself stays `FOR SHARE`.
