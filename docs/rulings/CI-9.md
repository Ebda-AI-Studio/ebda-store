Ruling CI-9 (Store session, 2026-10-29; CI-2/CI-3) - CI-2 aggregates are additive counters (n, hit, sum, first/last day) folded from the envelopes only, never from a buyer key or order id: per store and UTC day (`aggregates/v1/store=<id>/dt=<day>.json`), a rebuilt 90-day window per store, and a cross-store cohort (`aggregates/v1/<metric>/dt=<day>.json` + `xstore/latest.json`) built ONLY from events with `xstore: true`. A cohort cell under n 100 / 5 stores / 40% max store share is written as `{suppressed:true}` and nothing else; the cohort carries no store id. `assertAggregateOnly` throws on a forbidden key, a phone/email shape, a suppressed cell with content, or a >5,000 entry array/object, before findings (`ci_insights`, rule-based `rules-v1`, a person accepts or dismisses) are built. `areaKey` was added (optional) to the cod/delivery/return event data so rates cut by area without joining events; payment-failure and onboarding/cart metrics are NOT built because the envelope has no such events yet. Replay is byte-identical (stable key order); merchant erase also deletes `aggregates/v1/store=<id>/`; published cohort cells stay (k-anonymous). Cost if wrong: a metric the plan lists (payment failure, onboarding drop-off, cart recovery) is missing until its event exists; a stale cohort cell can outlive an erased store until the next daily run rewrites it.
