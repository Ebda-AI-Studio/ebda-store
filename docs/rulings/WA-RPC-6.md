# WA-RPC-6

Ruling WA-RPC-6 - The Ebda Chat catalog has one row per sellable thing: each variant of a variant product (retailer id = variant id), or the simple product itself (retailer id = product id), because the contract's "retailer id = variant id" has no variant to name for a product that has none. `createOrderFromChat` and `createCheckoutLink` accept either kind of id. `listCatalog` pages over PRODUCTS (cursor = last product id) so a product's variants are never split across pages; a page can therefore hold more than `limit` rows, bounded by `limit` products times their variants. Evidence: `workers-do/wa-bridge.test.ts` (simple product ordered and listed on a real StoreDO). Cost if wrong: a variant-heavy page is larger than the caller's `limit`; the caller reads `items`, not a count, so nothing breaks.
