# AITOOLS-4

Ruling AITOOLS-4 (2026-11-15, Ahmad) - the AI tools page may REPLACE an existing value only with a backup and an undo: translate (to Arabic, to English), categorize and image alt text get their "Replace what's already there" switch back, honoured on the server (`force` on `POST /bulk/translate|categorize|image-alt`, kept on the job row so a resumed run stays a replace run). NEVER-OVERWRITE-1 stands for every automated job; this is the merchant-initiated exception it already allowed ("replace only with a backup + revert"). One write path: `replaceTextWithBackup` / `replaceCategoriesWithBackup` (`apps/api/src/services/catalogue-replace-backup.service.ts`) write the `ai_replace_backups` row (store, job, tool, who, entity, field, previous, new, when) and the new value in ONE atomic batch, compare-and-set on the value the sweep read, so a replace without a backup cannot happen (backup insert fails -> batch fails -> value untouched) and a value the merchant changed since the read is skipped. A retried batch cannot back up twice (unique `job_id, entity_kind, entity_id, field`). Undo (per change, per run, per product; `POST /ai/replace-backups/undo`) restores `previous` only while the field still equals what the AI wrote; a field edited since is REFUSED (`edited_since`) and reported, never overwritten; undoing an older run after a newer one replaced the same field is refused the same way (undo the newer first). Covered: product name/description (en, ar), category name/description (en, ar), product image alt, a product's category set. NOT covered: the store's own name/description (translate stays fill-only there). Viewer: AI tools page "Undo history" (runs, changes, who/when/tool) and "AI changes you can undo" on the product edit page. Storage: new StoreDO table `ai_replace_backups` (cf-0008, also in 0001; Postgres twin `20261115000100_ai_replace_backups`); the actor ids are scrubbed on user erasure, the values leave with the store. Evidence: `tests/unit/ai-replace-backup.test.ts` (real StoreDO schema), `bulk-ai-translate-replace.test.ts`, `bulk-ai-categorize-sweep.test.ts`, `bulk-ai-image-alt-sweep.test.ts`, `bulk-ai-job-service.test.ts`. Not built: retention purge of old backup rows (rows stay until the store is deleted; one row per replaced field), user names in the history (shows You / Team member), a category-set undo is read-compare-write rather than a single compare-and-set. Cost if wrong: a merchant who edits a category set in the milliseconds between undo's read and write loses that edit; backup rows accumulate slowly (text only) until a purge ships.
