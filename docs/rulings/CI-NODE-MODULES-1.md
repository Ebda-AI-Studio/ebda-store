# CI-NODE-MODULES-1

> Section: 2026-11-03 - CI speed (branch `ci/umbra-node-modules-reuse`)

Ruling CI-NODE-MODULES-1 - on the self-hosted Umbra runner only, every ci.yml job installs through `.github/actions/npm-ci` (`scripts/ci/npm-ci-reuse.sh`): a runner-local store of pristine node_modules trees keyed by sha256(package-lock.json + node major + arch) is restored by hardlink (prisma, .cache and .vite dirs copied, never linked), verified with `npm ls --depth=0 --workspaces`, and any failure falls back to `npm ci`; hosted runners still run plain `npm ci`, and no remote Actions cache is used. Evidence: run 41657142553 measured ~45 s of `npm ci` per job over ~20 jobs (~15 min of every run); ~/.npm already persists on the VM, so only the install step itself repeats. Store is 2 keys x ~2.4 GB on a VM with 37 GB free (floor 30 GB). Cost if wrong: a stale or corrupt restored tree could make a job pass or fail on the wrong dependencies; the `npm ls` check and the lockfile-hash key bound this, and deleting `$RUNNER_TOOL_CACHE/../ebda-node-modules` (or reverting the action to `run: npm ci`) restores today's behaviour. Deploy workflows (cf-\*-deploy.yml) are NOT changed.
