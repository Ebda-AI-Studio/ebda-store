# AITOOLS-5

Ruling AITOOLS-5 (2026-11-15, coordinator: fix-everything) - the undo history of AI replace runs (`ai_replace_backups`, AITOOLS-4) is kept 90 days from the run, then deleted: age only, undone or not, no "superseded" logic. Chosen over "superseded by a newer backup and older than 30 days" because it is one predicate that a merchant can state ("history kept 90 days", shown in the admin copy, ar + en), matches the storefront search log window, and a row that is neither superseded nor old is still the only way back to the previous value, so deleting on supersession would make the undo window depend on what else ran. Run by the existing daily `search-log-purge-daily` job as a second step (`purgeReplaceBackupsAcrossStores`, no new cron): every Durable Object store, at most 20 batches of 500 rows per store per run (a backlog drains over several days, never one long transaction), 8 stores at a time; a failing store is logged and counted and never stops the rest, and the run fails loudly after all stores were tried. Evidence: `tests/unit/ai-replace-backup.test.ts` (rows older than 90 days go, 89 and 1 days stay; one call is bounded by batch x maxBatches and the next call continues; the daily job calls it and the service registers no function of its own); `docs/RETENTION.md` row. Cost if wrong: a merchant who tries to undo an AI run more than 90 days later finds the old value gone and retypes it (the new AI value is still in place); and a store that replaces very many fields keeps up to 90 days of text rows (bounded by the catalogue size times runs in 90 days).
