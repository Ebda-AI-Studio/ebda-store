# D1016-ICONS-1

> Section: 2026-10-16 — Ahmad's product decisions (FU46-Y02a/b, D1016-\*)

Ruling D1016-ICONS-1 (Ahmad 2026-10-16, "cloudflare images") — PWA icons are resized by the Cloudflare Images Workers binding (`env.IMAGES.input(png).transform({ width, height, fit: 'contain' }).output({ format: 'image/png' })`, docs `developers.cloudflare.com/images/optimization/binding/`), on the Whisky account only (the API Worker `ebda-api` lives there, 69188202…): each of the 7 targets is a PNG of its own size (192, 384, 512, 180, 32, 16) and the maskable icon is the Android adaptive shape — the art scaled to 410 px (the central 80% safe zone) and padded to 512 with a 51 px `border` in the store's PWA `backgroundColor` (a hex, else white; `background` also fills transparent pixels, so the icon is opaque). The source is still stored unchanged. Each answer is checked (PNG, exact size); if the binding is absent, throws, or answers the wrong size for ANY target, the WHOLE set falls back to the FU46-8 behaviour (the source under every key) with one warning — never a mixed set. The upload contract (square PNG ≥ 512, ≤ 1 MB) and the admin hint are unchanged: the hint ("keep the art inside the central 80%") stays true in both modes. `lib/images/icon-resizer.ts`; `generatePwaIconSet(storeId, source, { background })`. Evidence: `tests/unit/pwa-icons-cloudflare-images.test.ts` (fake binding: sizes, padding op, colour sanitising, throw / wrong-size fallback, no-binding pass-through; 8 red first), `wrangler deploy --dry-run` with the binding lists `env.IMAGES  Images` (EXIT 0). Cost if wrong: the 16/32 px favicons stay the full source until the binding is switched on.
