# INV-AUDIT-1

> Section: 2026-11-14 inventory audit P1-1 (branch `fix/inventory-p1-audit`)

Ruling INV-AUDIT-1 - a stock adjustment and a cycle-count reconcile apply their DELTA to the LIVE quantity read inside the StoreDO's single-writer section; they never write a snapshot's absolute quantity. A draft adjustment's intent is `delta_qty` (new minus previous at draft time); a count line's intent is its variance (counted minus system quantity at scan time, passed as `countDelta`), so units sold between the scan and the reconcile stay sold. If live + delta would go below zero the post is refused with 409 `STALE_SNAPSHOT` (Arabic + English message), the claim rolls back and the draft stays a draft. The ledger row records the live before/after, not the stale snapshot. Evidence: `packages/repo/test/do-stock-books.test.ts` "stale snapshots never overwrite live stock" (3 tests, red before the fix, mutation-checked: writing `new_qty` back fails 2 of them); the Postgres barcode count path already used `relative: true`. Residual: the legacy Postgres `postAdjustment` for a store NOT on a DO still writes `new_qty` unless the caller passes `relative` (manual draft posts); DO stores are the live path. Cost if wrong: a merchant who meant "set this SKU to exactly N" on a stale draft gets live + delta instead and must adjust again; the refusal case asks them to redo it on the current quantity.
