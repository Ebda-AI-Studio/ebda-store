# HEALTH-ALL-1

> Section: 2026-10-29 - Close sweep 2 (N3, `fix/app-health-endpoints`)

Ruling HEALTH-ALL-1 - every Worker answers `GET /health` with 200, its `commit` and its `deploymentId`, and the Next apps (admin, orders, web) do it in the Worker entry, not in a Next route handler. Measured 2026-10-29: `store.ebda.app/health` (admin) and `orders.ebda.app/health` answered an empty 500 although `app/health/route.ts` existed (PR #511); reproduced locally with `cf-build.sh orders` + `wrangler dev`: `No such module "file:/.next/None"` thrown from `getIncrementalCache`, because admin and orders deploy the empty OpenNext cache config and every route handler (unlike pages) loads the incremental cache. The storefront Worker (web) had no `/health` at all (404 on every store host; `admin.ebda.app` is a retired host and 404 is correct). Fix: `withHealth` / `healthResponse` in `@ebda/shared` (`worker-health.ts`) answer in `apps/{admin,orders}/health-worker-entry.ts` (wrangler `main`, set by `scripts/cf-setup-local.sh`) and in `apps/web/sentry-worker-entry.ts`; `commit` comes from `BUILD_COMMIT_SHA` (`wrangler deploy --var`), `deploymentId` from the new `CF_VERSION_METADATA` binding; unknown is `null`. Each deploy workflow's `deploy-guard verify` now probes `/health|200|commit=$GITHUB_SHA` (store, orders, ebda-deploy-probe hosts), so a deploy that serves an old commit rolls back. Verified locally end to end on the OpenNext build (200, deploymentId, `/login` still 200). Cost if wrong: `/health` is shadowed on a merchant custom domain or store whose path is exactly `/health`; and the live commit match is only proven by the first real deploy of each Worker (not run here, no deploy done).
