Ruling GITLEAKS-SCOPE-1 (2026-10-27) - the gitleaks workflow scans each event's own history, never `--all`. Pull requests: `base..head`. Pushes to main: `before..after` (the commits the push added; HEAD when `before` is empty or zero). Nightly and manual dispatch: `HEAD` of the checked-out branch (main for the nightly), i.e. main's full history. Evidence: `gitleaks detect` without `--log-opts` walks `git log --all`, and with `fetch-depth: 0` that includes every open PR branch, so a sha256 pin or test token on one branch turned main red and paged `GITLEAKS` 12 times overnight. No allowlist was added (`.gitleaks.toml` unchanged): a real secret on main still fails the push scan and the nightly. Verified locally: `gitleaks detect --log-opts=origin/main` over main's full history. Cost if wrong: a secret committed to an unmerged PR branch is not found by a main-side scan; the PR's own `base..head` scan and the pre-commit hook are the controls for that branch.
