Ruling FOUNDING-2 - review fixes to FOUNDING-1 (Opus review of 22dbd898d). (a) Grant create/apply run in their OWN real transaction (`runInTenantContext`), never `withStore`: inside `runInStoreScope` (the billing routes) `withStore` has no transaction, so the advisory/row locks were released at once and 2 concurrent upgrades could take slot 21; proven by mutation (25 grants instead of 20). (b) A "paid month" must cover at least one month of the plan the payment was for (a 1-piastre charge neither earns a grant nor farms a referrer); a refunded payment is `refunded`, so it does not count, but a grant already given is NOT clawed back (cost: one month). (c) Checkout/upgrade and the renewal settle respect applied grants: the new period end is never earlier than the end a grant moved it to (`grantedPaidThrough`), and a renewal claimed before a grant landed still settles (`shiftedByGrants`, no false "charge not applied" P1). (d) Manual InstaPay payment takes the subscription row lock before computing the period, the same lock the grant apply takes. (e) The daily billing cycle runs `sweepFreeMonthGrants`: applies pending grants, re-creates lost referral grants, and while founding slots remain awards qualifying stores in first-payment order, so "first 20 to pay" holds even for stores that paid before this shipped or whose post-payment effect was lost. Cost if wrong: a grant is delayed to the next daily sweep; the sweep scans all stores only while fewer than 20 founding grants exist.
