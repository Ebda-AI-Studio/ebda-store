# WAREHOUSE-ROUTE-2

Ruling WAREHOUSE-ROUTE-2 (2026-11-12, review of #733) - four refinements of WAREHOUSE-ROUTE-1. (1) A phone order with a reasoned stock override skips warehouse routing (`placeAdminOrder`), so it is never refused `NO_SINGLE_WAREHOUSE`; it writes no allocation event. (2) Allocations and give-backs are keyed per ORDER LINE (`orderItemId`), not per product, so a return of an unrouted line cannot consume a routed line's allocation. (3) Units a line never had allocated (an override order, backorder units, an order placed before routing shipped) are restocked on the aggregate and the shadow is then reconciled to it, so the surplus lands on the default warehouse, not on the one that shipped it (known gap, in the program register). (4) A negative aggregate is backorder state, not a shortfall: `reconcileToAggregate` floors the target at 0 and logs no `reconcile_shortfall` (it also applies to the daily sweep). Evidence: `packages/repo/test/do-warehouse-route.test.ts` (override, pre-routing cancel, backorder log, two lines of one product). Cost if wrong: the per-warehouse split of a cancelled pre-routing or override order drifts until adjusted by hand; a genuine shortfall on a negative aggregate is no longer alerted, because the negative number is the backorder debt itself.
