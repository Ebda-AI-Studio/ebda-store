# NZ-AN-2

Ruling NZ-AN-2 (2026-11-04, NEON-ZERO-1 N-13 and N-11 remainder) - a background job reads a DO store's `Store` row through the store's backend (`withStoreDb(storeId, db => db.store.findUnique(...))` / `lazyStoreDb(storeId).store...`, served by `doStoreDelegate` from the DO `store_profile` / `store_config` and the D1 directory), never through `withStore` / `prisma.store` (a Postgres row a DO-native store does not have). 40 sites in `lib/inngest/functions/*`, `lib/jobs/gold-stores.ts` and `lib/jobs/store-db.ts storeNameOf` were converted; the Postgres branch of `order-created` / `order-status-changed` / `order-refunded` (a Postgres store) is unchanged. A global router for the `store` model (every `prisma.store.findUnique({ where: { id } })` of a DO store served from the DO) was REJECTED here: it would add `backendFor`'s uncached D1 read to every Store read of every Postgres store on the request path (NEON-SCALE-1). The remaining `store`-model reads on request routes and services (about 130 call sites in 45 files, listed by `git grep -nE "(prisma|tx|db)\.store\.(find|update|count)" apps/api/src`) are N-11 (c) work for the per-store admin tracks; they are not jobs. Cost if wrong: a job whose Store select needs a column or filter the DO delegate refuses (`STORE_READ_UNSUPPORTED`, `STORE_FILTER_UNSUPPORTED`) fails loudly for a DO store instead of reading a stale Postgres row.
