Ruling G5-1 (2026-10-25) - a Workflow handler touches the database and the clock only inside `step.run`. Evidence: on workerd only step bodies hold a connection and the code between steps re-runs on every replay; `tests/unit/jobs-workflow-safety.test.ts` scans every workflow-kind function (and the `step`-taking helpers in its file) and found 78 violations, all fixed; the 3 reviewed-safe patterns (sweep cutoffs that only parameterise a memoised find step or an alert age; awaits of parallel `step.run` promises) are the only RULED entries and a stale entry fails the test. `stepRunUnlessEmpty` reads inside the step on a Workflow (its un-stepped probe is an Inngest billing trick). Cost if wrong: a handler that slips a database call between steps fails on its first Workflow run, loudly, and the group flips back with one var.
