# B4-PLP-1

> Section: 2026-10-22 — Phase B4 Lamma (B4-\*)

Ruling B4-PLP-1 (Lamma fix wave 1, 2026-10-22) — the product listing grid is an auto-fill grid on EVERY template. Both Lamma audits (taste P1-1, and Souq's P1-1 before it) found three dishes as five ~160px cells in a ~900px band at 1280. The cause is shared: `lg:grid-cols-4 xl:grid-cols-5 2xl:grid-cols-6` gives a 190px cell on a 1000px column however few cards there are. `ProductsClient` now lays every template out as `repeat(auto-fill, minmax(11.5rem, 1fr))` from `lg` (generalising Souq's `chrome.plp: 'autoFill'`; `design.md` compact sizing, a card never narrower than about 184px, photo at full card width), so 3 cards fill the row and a full page still packs 4-5. Dahab keeps its own 3/4-up density control: it never used the 5-column grid and its cards are already wide (a Dahab store with `chrome.plp: 'autoFill'` still gets it). Snapshots: none pins the grid class string (searched `tests/`, `apps/`, `docs/` for the old and new strings), so no snapshot changed; the proof is a PLP shot per template at 1280 (`audit2/plp-*-1280-en.png`) and `tests/lamma/lamma-fixwave1.spec.ts` (every card >= 180px). Cost if wrong: a store with 40+ products shows 4 columns where it showed 5 on a very wide screen; reverting is one class string.
