# FOLD-VAT-1

Ruling FOLD-VAT-1 (2026-11-09) - the data side of Ebda's own VAT / ETA e-invoicing (TAX-1 of the launch map) is complete before the company registration: switching it on is the existing super-admin "Ebda VAT" setting (`system_settings` key `ebda.vat`, default OFF, fail closed), not a migration. `billing_events` on D1 already carried net, VAT rate (bp), gross, seller / buyer tax ids and ETA uuid / status / submitted_at (0003, policed by 0004); this adds `eta_long_id`, `eta_hash`, `eta_rejection_reason` (0007, generated from `cf-additions.mjs`) and a replaced fill trigger (0008) that copies the seller tax number and legal name from the charge's `vat` JSON into the columns on insert (VAT off => NULL). The super-admin ledger (`/billing-events`) shows net / VAT / gross, the buyer tax id and an ETA status column (empty while off), en + ar. Erasure: `d1:billing_events` stays a kept money record; the new columns are reviewed not-PII in `erasure-classification.json`. Merchant-side VAT (the Egypt VAT gate, PR #17) is untouched. No ETA submission code ships. Evidence: `packages/cf-schema/test/late-columns.test.ts` (0007/0008: off = identical totals and empty fields, on = seller snapshot, ETA lifecycle), `tests/unit/billing-vat-data.test.ts` (off = price unchanged, 14% half-up piastres). Cost if wrong: an invoice issued after registration carries a seller snapshot taken from the setting at charge time, so a wrong tax number typed into the setting is frozen on that invoice and needs a credit note, not an edit.
