# PUSH-AUDIENCE-1

Ruling PUSH-AUDIENCE-1 (2026-11-18, controller review of #925) - a shopper-facing web push is addressed to ONE customer and reaches only that customer's own storefront subscriptions; a staff push reaches only `orders_app` subscriptions; nothing is ever a store-wide broadcast of one person's data. Evidence: `NotificationDispatcher._dispatch` sent EVERY push event (order_confirmed, order_shipped, order_delivered, order_cancelled, refund_processed, cart_abandoned_step1-3, back_in_stock) through `pushService.sendToStore(storeId, ...)`, which read every `push_subscriptions` row of the store, so shopper A's name, order number, amount or cart total reached shopper B's device and the orders-app devices; and `POST /public/:storeId/push/subscribe` had no auth middleware, so `req.user` was never set and every storefront subscription carried `customer_id = NULL` (nothing could be addressed per person even if the sender had tried).
Rule. (1) `NotificationData.customerId` is the addressee; the dispatcher refuses the push (`no_recipient`) when it is missing, for every event, and `PushService.sendToStore(storeId, title, body, data, recipient)` requires `recipient.customerId` and returns without reading a subscription when it is missing or empty (fail closed at both layers). (2) `sendToStore` reads `{ storeId, customerId, audience: 'storefront' }`; a device's subscription is the shopper's opt-in for that channel. (3) Staff pushes use `sendToOrdersAppStaff` (`audience: 'orders_app'`) and OneSignal for admins, never `sendToStore`. (4) The subscribe route runs `optionalAuthenticate` and stores `customerUserId(req)`: a logged-in customer's device is bound to them, a guest's stays unbound and is never addressable by a per-person push. (5) Every producer passes the customer id: order-created, order-status-changed (shipped, delivered, cancelled), order-refunded, abandoned-cart steps, back-in-stock; a guest order has no customer id and therefore gets SMS and email but no push. The unit test `push-audience.test.ts` scans every `notificationDispatcher.dispatch` call site and pins `sendToStore` to the dispatcher as its only caller.
Cost if wrong: shoppers who subscribed as guests (all existing rows, `customer_id` NULL) stop receiving push until they subscribe again while logged in; merchants see fewer push deliveries, never another shopper's data. Residual: the merchant broadcast ("web push to customers", marketing) is a separate, merchant-authored message with no personal data and is unchanged.
