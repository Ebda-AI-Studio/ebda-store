# NZ-17-EX-2

> Section: NEON-ZERO N-17 Postgres removal, slice 2 (2026-11-05)

**Ruling NZ-17-EX-2 - under `packages/repo/` and `apps/api/workers-do/` the residue gate ignores hits that only NAME Prisma types or Postgres in prose.** prisma-lite, the RPC codec and the DO tests are live production code on the StoreDO: they `import { Prisma } from '@prisma/client'` for `Prisma.Decimal` and the DMMF types, list `@prisma/client` as a dependency, comment on the Postgres twin's `pg_advisory_xact_lock`, and assert that the DO client REFUSES `$queryRaw`. The rule lives in `scripts/cf/residue-exempt.mjs` (`isTypeOnlyHit`), line by line, not by file: a `PrismaClient` import, `$executeRaw`, a `pg_advisory` in code, or `DATABASE_URL`/`DIRECT_URL`/`NEON_`/`HYPERDRIVE` anywhere (comments too) still count, and nothing outside those two prefixes is exempt (the same type import in `apps/api/src` counts). Evidence: `packages/cf-migrate/test/residue-exemption.test.ts` (rule cases plus an end-to-end run in a temporary git repo: the import outside the exemption is reported, the one inside is not). Residue 428 -> 415 with this and the deletions. Cost if wrong: a Postgres client slipped into prisma-lite under a type-looking import line would not trip the gate; the `PrismaClient` clause and the Worker's `POSTGRES_REMOVED` throw still catch the usual form.
