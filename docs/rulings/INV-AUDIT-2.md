# INV-AUDIT-2

> Section: 2026-11-14 inventory audit P1-2 (branch `fix/inventory-p1-audit`)

Ruling INV-AUDIT-2 - an order whose payment is `failed` is an open stock hold exactly like an `unpaid` one: the daily auto-cancel sweep selects `paymentStatus IN ('unpaid','failed')` (releasing the units on the same 2-day timer; a `failed` order with a gateway payment is still reconciled against the provider first, so a late capture is rescued, not cancelled) and the open-hold cap counts them on both stores' paths (DO checkout `OPEN` predicate, Postgres `stock-hold-cap.ts` raw SQL). Enum values are the real `orders.payment_status` strings written by the payment webhook (`unpaid`, `paid`, `failed`, `refunded`, `disputed`); `failed` is the only non-captured state besides `unpaid`. Evidence: `packages/repo/test/money-stock.test.ts` (real DO schema: two failed COD orders still trip the cap, a paid one does not), `tests/unit/order-auto-cancel-throttle.test.ts` (sweep where-clause), `tests/unit/stock-hold-cap.test.ts` (both SQL counts); all red before the fix. Class sweep: `payment-abandonment-sweep` and `job-ops` only stamp a recovery-push marker (no stock effect) and stay `unpaid`-only on purpose; the DO `cancel` with `unpaidOnly` already accepts `failed`. Cost if wrong: a shopper whose card was declined and who retries the SAME order after day 2 finds it cancelled and must check out again (the order was never payable-forever by design).
