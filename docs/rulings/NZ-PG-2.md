# NZ-PG-2

> Section: NEON-ZERO Postgres remnants (2026-11-05)

**Ruling NZ-PG-2 - once the cutover markers are set nothing on the Worker may need Postgres, and there is no Postgres fallback for a DO store or a D1 family.** Ported: the audit-log-archive job (`auditRetention.*` answers 0 / [] after the `audit` marker; the D1 and DO legs archive), the two gold-rate crons (the cron run lists D1 stores and reads each DO; `lib/jobs/gold-stores.ts`), r2-orphan-sweep (no owner-role connection or Postgres reference scan where the D1 is bound: references come from the D1 platform tables and every store DO), the identity definers once `access` is on D1 (`getUserState` from the identity service, `findUserIdByEmail` / `refreshTokenUser` / `verificationTokenUser` / `passkeyLookup` unknown, the delete/purge definers 0, `revokeUserSessionsRow` bumps the cached token version and revokes the D1 merchant keys, `ensureAdminUser` refuses 410), `POST /admin/impersonate` (identity service for an admin account, the D1 entity index plus the store DO for a customer), `GET /payments/events/:eventId/payload` (a primary-key probe of the DOs for a verified super_admin) and `getEntityStoreId` for product, order, customer, journal entry and bulk-import job (D1 entity index for order and customer; a bounded primary-key probe of the DOs for the others, `lib/entity-store-fanout.ts`; the definer only while a `pg` store exists). Every direct `Store` write in `apps/api/src` goes through `updateStoreThrough` / `storeUpdate` (traced: 12 sites in `store.service.ts` plus `repo-factory.ts`); the two legacy `store.create` calls sit behind `storeCreateOnDo()`, whose switch is the deploy var `STORE_CREATE_ON_DO` and must be `1` before Postgres is removed. Evidence: `tests/unit/postgres-gone-definers.test.ts`, the dead-Postgres route sweep (`apps/api/workers-test/route-sweep.test.ts`, `SWEEP_STRICT=1`, cron group). Cost if wrong: an admin account unknown to the identity service cannot be impersonated or resolved by e-mail until it is created there (a 404, never a wrong account).
