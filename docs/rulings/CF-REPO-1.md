# CF-REPO-1

Ruling CF-REPO-1 (2026-10-28, INFRA-CF-1 PR C2) - services obtain their store's data client from `storeDb(storeId)` (`apps/api/src/lib/repo-factory.ts`): the existing `prisma` proxy for a store on `pg` (the default for every store, so behaviour is unchanged), a Prisma-shaped READ client over the StoreDO `query` RPC for a store on `do`, chosen by `backendFor`. Reads only in this PR; writes, raw SQL, locks, aggregate/groupBy, interactive transactions and the D1 models are PR D+ (`docs/cf/repo-factory.md` lists them with counts). Evidence: `tests/integration/repo-factory-contract.test.ts` runs every moved read (SizeChart, BlogPost, StorePage, StoreLocation, Tag with a relation filter and a relation `_count` ordering) once on Postgres through Prisma and once through the Durable Object schema (real wire codec, read executor and prisma-lite on node:sqlite) and demands deep equality; it found a real fidelity gap (prisma-lite accepted `orderBy: { _count: { rel } }`, a shape Prisma rejects, and refused Prisma's own `orderBy: { rel: { _count } }`), fixed in `engine.ts` and pinned by a new differential case against real Prisma. `tests/unit/repo-factory.test.ts` pins: unresolved store is 404, unbound DO is 503 (never a Postgres fallback), the DO client has no write operation and no raw access, a P-coded DO failure is re-raised as `PrismaClientKnownRequestError`, a failed resolution is not memoised. `apps/api/workers-do/store-do-schema.test.ts` drives the client over a real Durable Object (Date, Prisma.Decimal, include, P2025, one round trip for `$transaction`) and proves a client aimed at another store's id gets `STORE_MISMATCH`. Staleness class of the one cache here (the backend memo in `repoScope`): NEVER-stale data held for ONE request; the residual window is the request's own duration (a flip happens with writes frozen and the store sealed, so an in-flight request finishes on the backend it began on); there is no cross-request layer and therefore no invalidation to forget. Accepted residual: a service that has not moved keeps reading Postgres for a store flagged `do`; the flag stays `pg` for every store until PR D and the cutover gate. Cost if wrong: with every flag at `pg` the moved methods return what they returned before (same proxy); a wrong `do` read is reachable only for a store the operator flipped, and the flip is a single D1 UPDATE back.
