# WAREHOUSE-NEG-1

Ruling WAREHOUSE-NEG-1 (2026-10-29, controller decision, INFRA-CF-1 PR D2b) - `reconcileWarehouseStockToAggregate` never drives a warehouse row negative, on BOTH backends; this supersedes the allow-negative-on-default policy of the Task 2 reconcile (and the "FOUND, replicated, not fixed" note 4b of CF-STOCK-1). (1) A SURPLUS (aggregate above the shadow sum) still goes to the default warehouse's row. (2) A DEFICIT is spread over the SKU's warehouse rows in one fixed order shared by both backends - the default warehouse first, then `priority` desc, `created_at` asc, `warehouse_id` asc - each row giving at most its own positive quantity (`planDeficit`, a pure function kept as two byte-equal copies: `apps/api/src/lib/warehouse-deficit.ts` for the API, which must not import `packages/repo` statically, and `packages/repo/src/do/warehouse-deficit.ts` for the DO; `tests/unit/warehouse-deficit.test.ts` pins them equal). SUM(rows) still equals the aggregate. (3) If the rows cannot cover the deficit (only possible when the aggregate itself is negative, which the stock operations cannot produce) every row is floored at 0 and the shortfall is ALERTED: Postgres `logger.error '[Warehouse] reconcile_shortfall'`, the DO a JSON `console.error` line with the same text (Workers logs drain); the drift is left visible rather than hidden in a negative row. (4) A row that is already negative is never made worse and gives nothing. (5) Postgres takes the SKU's warehouse rows `FOR UPDATE OF ws` after the aggregate lock (inside the same `withMoneyTx` + `retryOnWriteConflict` as before); the DO does it inside its one `transactionSync` section. Evidence: `tests/unit/warehouse-deficit.test.ts` (6), `packages/repo/test/do-stock-ops.test.ts` (deficit spread on the DO schema), `tests/integration/warehouse/reconcile.test.ts` (the old allow-negative case now asserts default 0, other warehouse 3, SUM 3; a new shortfall case asserts floor-at-0 plus the alert), `tests/integration/repo-factory-stock-contract.test.ts` scenario "WAREHOUSE-NEG-1" (real services on Postgres 17 and on the DO schema, equal traces, rows `[0, 3]`). Cost if wrong: the per-warehouse split of a drifted SKU differs from the old default-absorbs-everything split, which only changes which warehouse the order router prefers; the aggregate the storefront sells from is untouched.
