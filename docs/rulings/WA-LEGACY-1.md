# WA-LEGACY-1

> Section: Lifecycle emails and referral attribution (2026-10-22, branch `feat/lifecycle-emails`)

Ruling WA-LEGACY-1 (2026-10-25) - the legacy in-Store WhatsApp API bridge is DELETED, not renamed, and SUPERSEDES WHATSAPP-OFF-1's "kept in the code". Gone: the `/wa-bridge/*` routes and `waBridgeAuth`, the `integrations/wbs`, `wa-templates`, `bot-analytics` routes, the merchant `payment-links` send, the meta provisioner, the `order-whatsapp-notify` and `product-meta-sync` Inngest functions, the WhatsApp step of the abandoned-cart sweep, the `order/shipped` event (its only consumer was the bridge), the storefront `waToken` hydrator, the admin `/whatsapp` hub (old URLs 301 to Settings), the WBS i18n and env vars (`WBS_BASE_URL`, `WBS_RECEIVER_BASE_URL`, the `EBDA_META_*` provisioner secrets). Kept: `wa.me` links, the `whatsapp` feature key and the `whatsappAutomation` plan limit (the Ebda Chat Store contract uses them), and `customer_addresses` (account erasure and the RLS suites use it). The separate product Ebda Chat (wa.ebda.app) replaces the bridge through `business/ebda/plans/2026-10-24-ebda-whatsapp-store-contract.md`. `tests/unit/no-wbs-refs.test.ts` fails on any case-insensitive match of the old bridge name or its inherited prefix in apps/ or packages/ source (applied migrations exempt; its allowlist can only shrink). Evidence: read-only prod counts all 0 (`stores.wbs_enabled`, `store_credentials.wbs_api_key`, `whatsapp` StoreFeature rows, `whatsapp_templates`, `bot_copy`, `customer_addresses`). Ships as two PRs in expand/contract order: code first (columns untouched so the still-running old API keeps working), then the drop migration. Security addendum (controller finding, MEDIUM): the bridge minted placeholder customer emails on a REGISTERED domain (`forcestore.kw`), and the order-created guard that skipped them is gone with the bridge, so the minting code and every placeholder check were deleted too; no flow creates placeholder addresses now, and every send path (`ResendService`, `EmailService` platform sends and queue replay) drops recipients on the RFC 2606 `.invalid` TLD via `lib/undeliverable-email.ts`; `tests/unit/email-domain-allowlist.test.ts` fails on any source address off an allow-list and on any Force/forcestore domain, `tests/unit/undeliverable-email.test.ts` pins the refusal. Prod held 0 such customers. Cost if wrong: a store that had the bridge live loses it with no switch to bring it back; none is known to be live.
