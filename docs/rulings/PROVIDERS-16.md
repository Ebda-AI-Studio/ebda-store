Ruling PROVIDERS-16 — mutation proofs for the shipping batch (each defence removed, the named test goes red, file restored byte-identical by the runner): `ssrf-carrier-merchant-base-url` (re-targeted: an unlisted credential key such as `baseUrl` is stored), `carrier-merge-base-not-cached`, `carrier-masked-field-refuses-drop` (an unreadable blob is merged over), `carrier-credentials-shape-fails-loudly`, `carrier-save-locks-row` (no row lock), `carrier-credentials-write-only` (ciphertext returned to the browser), `carrier-enable-requires-current-test`, `carrier-enable-requires-verified`, `carrier-test-fingerprint-checked`, `carrier-webhook-url-token-required`, `carrier-webhook-header-required`: 11 new or re-targeted defences, all KILLED; `ssrf-carrier-redirect-revalidation` stays KILLED by the rewritten `carrier-ssrf.test.ts`. Findings from an independent read-only review, all fixed here: concurrent saves could revert each other (row lock added), a legacy sandbox blob would have moved to the LIVE slot when its `settings.sandbox` key was stripped (re-shaped in the same write), delete / default / rotate wrote no audit row (added). Accepted, not changed: a real secret that literally starts with `****` is read as a masked echo (the same rule the payment form uses); the webhook secret sits in the callback URL path and so appears in request-URL logs and Sentry extras, which is exactly why the derived header is a second factor and the URL alone cannot authenticate a callback. Pre-existing, found while testing, NOT caused by this change: an in-process supertest call to a successful `POST /stores/:id/orders/:id/ship` hangs intermittently on `origin/main` too (2 of 4 runs timed out in a main worktree; the server's `finish`/`close` events fire, the client never resumes), so successful booking is covered through the service (`shipping-sp7-on-do.test.ts`), not over HTTP; refusal paths are covered over HTTP. Cost if wrong: a defence whose test only passes for the wrong reason would let a regression through; the mutation run is the evidence it does not.
