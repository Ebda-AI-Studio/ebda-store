Ruling WA-PLAN-1 (Store session, 2026-10-25) — `store.plan_changed` (planCode, includesWhatsApp, status trialing|active|past_due|cancelled|expired, periodEnd) is emitted from ONE observer on the database client (`setModelWriteObserver` in packages/database/src/tenant-guard.ts, installed by app.ts) that reports every write to `StoreSubscription` (plan, status, period, trial, cancel, pending plan; not order counters) and every `Store.plan` write, so no current or future write path (dunning, cancel, expiry, trial, manual payment, super-admin override) can be missed; a 12-hourly reconcile (`wa-plan-sync`, idle-exit before any step) re-sends the current state of every store with a link row as the net under it. The event is sent for any store that has a link row, including an unlinked or downgraded one (that is when the package gate must hear). Raw SQL writes to those tables are banned by a test. After the StoreDO cutover the repo layer must carry the same observer. Cost if wrong: a plan write that bypasses the client is corrected only at the next 12-hourly reconcile.
