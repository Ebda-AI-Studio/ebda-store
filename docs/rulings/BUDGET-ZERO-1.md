Ruling BUDGET-ZERO-1 - The worker startup budget's relative comparison ignores samples that recorded nothing. Evidence: #260's "Worker dry-run (api)" failed with `startup CPU not measured (pr 101.081, base 0)` although the bundle (14,787,031 B) was under the 14,800,000 B budget; the baseline samples were 127.8, 128.6, 0, 147.2, 124.9, and the script took `Math.min` of them, so one profile that recorded nothing made the whole base read 0. `minSample` takes the minimum of the real (finite, greater than 0) samples; with none it still returns 0 and the verdict still reads "not measured", so a wholly broken measurement can never pass. Unit-tested with the exact #260 samples. The budget numbers are unchanged. Cost if wrong: a run where one profile is genuinely 0 ms is no longer a hard stop, but the other samples still bound it.
