# ITEST-7

> Section: Lifecycle emails and referral attribution (2026-10-22, branch `feat/lifecycle-emails`)

Ruling ITEST-7 - tests/e2e feature-toggle: the six keys the plans engine owns (`abandoned_cart`, `whatsapp`, `remove_branding`, `b2b.wholesale`, `merchant_mcp`, `merchant_mcp_write`) are expected OFF for a subscription-less fixture store (free fallback limits); the rest still follow PLAN_BASELINE.starter. Ruling ITEST-8 - CODE: `skipPublicLimiters` no longer skips on NODE_ENV=test/VITEST; it mirrors the exact `publicLimiter` (load-test token only), so `publicReadLimit` stops bypassing the exact public limiters under test (production unaffected: NODE_ENV is never `test` there). Ruling ITEST-9 - tests/e2e order: the Tap duplicate-webhook case now asserts the removed provider is refused (400 INVALID_PROVIDER, order untouched); duplicate-delivery idempotency stays pinned per live gateway in egypt-gateway-webhooks. The bundle invoice test expects `120 EGP` (formatMoney drops an all-zero fraction). Cost if wrong: none for the product; ITEST-8 puts the public limiter back into the e2e/integration request path, so a suite firing >300 public reads/min from one IP would now see 429.
