Ruling WA-CONSENT-1 review 5 (Controller, 2026-10-25) — ownership of a consent row: `user_id` is set ONLY by a PROVEN grant (a delivered order with that number); a revoke, a STOP or an admin write never sets or overwrites it, and no unproven write by a different account changes it either (a revoke by account Y must not strip X's ownership and make X's erasure miss the row); only a PROVEN grant by another account rebinds the row, so no account can claim another person's row and then export it. The erasure's own-number proof runs on the erasure transaction with the same store id (never outside the tenant scope), and a missing store id throws. Export covers rows the account bound plus its current number's row when proven; erasure deletes the rows the account bound and its current PROVEN number's row, and KEEPS a STOP opt-out on an older number (owner cleared) because an opt-out must survive for that number's real owner. Cost if wrong: a number's opt-out record outlives the account that proved it.
