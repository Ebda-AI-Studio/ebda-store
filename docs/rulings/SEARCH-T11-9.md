# SEARCH-T11-9

> Section: 2026-10-15 — Phase B1 Qamar (B1-\*)

Ruling SEARCH-T11-9 (review M5) — only what storefront search can return is indexed: `INDEXABLE = deleted_at IS NULL AND status = 'active' AND doc IS NOT NULL` (`product-index.service.ts`; the storefront scope of `product-search.service.ts` is `status = 'active'` and not deleted, and the vector leg is storefront-only). A vector on any other product is an orphan: `planEmbedBatch` deletes it (`pruneUnindexableEmbeddings`) and the backstop's probe reports the store (review I1), so a soft delete, an unpublish or emptied text removes the vector on the next run even if the event was lost. Republishing makes the product stale again and it is re-embedded. Writers of `status`/`deletedAt` now request a reindex (ProductService.delete, ProductService.bulkUpdate with a status, BulkService.bulkDelete soft path, BulkService.bulkUpdateStatus; ProductService.update already emits `product.upserted`), and the write-path guard counts `status` and `deletedAt` as index fields. `storeIndexStatus.products` counts INDEXABLE products. Evidence: `tests/integration/product-index.test.ts` "review M5" (red before: the draft's vector survived). Cost if wrong: unpublish/republish churn re-embeds a product (one call per toggle, counted once per day by the cap).
