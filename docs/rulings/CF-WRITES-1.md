# CF-WRITES-1

Ruling CF-WRITES-1 (2026-10-29, INFRA-CF-1 PR D1) - the NON-MONEY catalogue and content writes go through `storeWriter(storeId)` (`apps/api/src/lib/repo-factory.ts`) and the StoreDO `mutate` RPC (`packages/repo/src/rpc/writes.ts`): on `pg` (the default for every store) the writer IS the `prisma` proxy, so request transaction, tenant guard and RLS are unchanged; on `do` each call is ONE atomic transaction in the Durable Object. Moved this PR: BlogPost (create/update/remove), StorePage (upsert/remove), StoreLocation (create/update/remove), SizeChart (create/update/delete), Tag (rename), Category + ProductCategory (create, update, soft delete, reorder as `$transaction([updateMany...])`), ProductOption (add/update with nested values and `hasVariants`), Product `lowStockThreshold` bulk update. The DO accepts writes for an allow-list of models only (`DO_WRITABLE_MODELS`, equal to the `WritableModel` type; a unit test pins the two) and REFUSES, as an answer and before any statement runs: any other model (`MODEL_NOT_WRITABLE`: orders, payments, refunds, ledger, stock reservations, coupons, wallet, loyalty, and the D1 platform models), any write to the stock column `inventory` of Product/ProductVariant at any nesting depth (`STOCK_WRITE_REFUSED`: stock moves only in the locked money/stock sections, D2), an op that is not a read or one of the seven write ops, a malformed model name, a batch of 0 or more than 200 ops, and a row carrying another store's id (prisma-lite's own-store check rolls the batch back). Idempotency: `$transaction([...], { idempotencyKey })` stores the batch result under the key INSIDE the same transaction; a replay returns it without running anything, the same key for different ops is `IDEMPOTENCY_KEY_REUSED`, a failed batch stores nothing so the retry runs, keys expire after 24 h and are pruned on the next keyed write; single writes carry no key (a DO RPC is not retried by the platform, and the natural unique keys already catch a duplicate). Evidence: `tests/integration/repo-factory-writes-contract.test.ts` runs every moved service call once on real Postgres (inside the store's tenant scope) and once through the DO schema on SQLite (real wire codec, `runWrites`, prisma-lite) and demands equal results AND equal resulting table state (ids and timestamps normalised), including the failure cases (taken slug 409, missing row, DUPLICATE_OPTION, P2025 swallowed on a repeat page delete), nested creates, and the reorder batch; `packages/repo/test/rpc-writes.test.ts` (atomic rollback, replay, key reuse, key expiry, every refusal, tenant isolation); `apps/api/workers-do/mutate.test.ts` on real workerd (nested transaction inside `storage.transaction`, P2002 rollback, replay, refusals, `STORE_MISMATCH`); `tests/unit/repo-factory-writes.test.ts` (pg default and `$transaction` option stripping, DO writes carry the store's own id, the READ client still has no write delegate, unbound DO is 503 never a Postgres write). `tests/unit/nested-transaction-registry.test.ts` now also sees `w.$transaction` (the guard keyed on the literal `prisma.$transaction` went blind when category.routes moved to the writer; found by running the affected unit set). Accepted residuals, each listed in `docs/cf/repo-factory.md`: (1) reads and writes of one handler are separate RPCs on `do` (the read-then-write the services do is not one atomic unit there as it is inside the Postgres request transaction); the unique indexes and the `where: { id, storeId }` scoping carry the guarantee, as they already did under concurrent requests; (2) `recordSlugRedirect(prisma, ...)` (SlugRedirect is a D1 platform model) still writes Postgres on a slug change; (3) a method that reads a not-yet-moved model (`product.getById` includes the D1 `store`) keeps reading Postgres. The flag stays `pg` for every store. Bundle: worker.js 8,081,292 -> 8,092,405 bytes (+10.9 KiB, no new dependency; budget 8.3 MB). Cost if wrong: with every flag at `pg` the moved methods run the very same Prisma calls as before; a wrong `do` write is reachable only for a store the operator flipped, and the flip is a single D1 UPDATE back.
