# DEMO-SEED-DO-1

> Section: 2026-11-09 — demo-store seed on the StoreDO (T7 follow-up)

Ruling DEMO-SEED-DO-1 - the demo HOMES are seeded on production through an operator channel on the API Worker (`/api/v1/internal/demo-home/:slug`, bearer `DEMO_SEED_TOKEN`, 404 when unset, 403 `NOT_DEMO` for any store whose `is_demo` is false) driven by `scripts/storedemo/seed-home-do.mjs`, which builds each home OUTSIDE the Worker with the same `build<X>Home` builders and publishes it through the page-builder service (same validation, revision and publish gate as the editor). Dry run by default, `--apply` writes, idempotent (a published page with the same sections is skipped; each write is read back). The catalogue half of `seed.mjs` is NOT ported: the demo catalogues already live on their DOs. Evidence: `seed.mjs` writes through Prisma and production has had no Postgres since N-17; a DO is reachable only from a Worker, and the sealed-store `__import` path refuses writes (423) by design; building the documents in Node keeps the 500 KB demo catalogues out of the Worker bundle (startup budget, Ruling STARTUP-CPU-1). `workers-test/demo-home.test.ts` runs the real seed code against a real StoreDO on local workerd + D1. Cost if wrong: a catalogue change to a demo store still needs a separate DO path.
