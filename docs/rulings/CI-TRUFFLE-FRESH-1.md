# CI-TRUFFLE-FRESH-1 - the secret scan reads a private fresh clone, not the CI workspace

Ruling CI-TRUFFLE-FRESH-1 - the Mac `Check for secrets` step runs `scripts/ci/scan-clone.sh "$AFTER" "$RUNNER_TEMP/scan" 21` (a fresh `git init`, one plain shallow fetch of the commit from the same origin with the checkout's own auth header, passed by environment) and points trufflehog at `file://$SCAN`; the since-commit ancestry is checked in that clone. It supersedes CI-TRUFFLE-PARTIAL-1 (scripts/ci/ensure-full-clone.sh, removed). Evidence (read-only diagnosis of ebda-mac-1's workspace, 2026-11-18): `remote.origin.promisor=true`, `partialclonefilter=blob:none` in .git/config, dozens of `.git/objects/pack/*.promisor` marker packs, shallow=true, no alternates; and store main run 44268095513 logged 'ensure-full-clone: the workspace is a full clone' (config keys absent at that moment) yet trufflehog's clone failed 'could not fetch ... from promisor remote': the marker packs alone make git lazy-fetch objects the shallow history never had. The writers are the `plan` jobs of the nine cf-\*-deploy.yml (checkout `filter: blob:none`, DEPLOY-PLAN-CLONE-1). Detecting every shape of that state is a losing game, so the scanner no longer reads the workspace. tests/unit/ci-scan-clone.test.ts reproduces THAT state (marker packs, no config keys): the control clone of it fails, the scan-clone result clones and reads blobs, the workspace is untouched (marker packs identical); mutation: fetching from the workspace instead of origin fails it. Cost if wrong: one extra shallow fetch (21 commits, tens of MB) per main/schedule secret scan; a GitHub outage at that moment fails the scan (red, never a skipped scan).
