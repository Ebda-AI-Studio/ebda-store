Ruling CATIMP-6 - an inactive store's expired catalogue-import originals are deleted by a daily job, `catalog-import-uploads-sweep` (cron `40 3 * * *`, no weekday field, group 2-housekeeping). It lists `stores/` prefixes with a delimiter, then each store's `catalogimport-` prefix (R2 cannot wildcard), and deletes private-bucket objects older than 31 days (30-day retention plus one day grace) whose key matches `stores/<id>/catalogimport-<job>/<file>`. Age is the clock, no database read; at most 5,000 deletes per run, the next run continues; a failed delete is counted and retried next day; logs carry counts only. This supersedes the "R2 lifecycle rule or super-admin sweep" cost line of CATIMP-3. Evidence: tests/unit/catalog-import-uploads-sweep.test.ts (keeps fresh and unrelated keys, idempotent second run, counts only). Cost if wrong: one list call per store per day grows with the store count (cheap pre-launch; shard by prefix or move to a lifecycle rule if stores pass a few thousand), and an upload whose job row is still live but older than 31 days is deleted (its file then fails uncharged, as the row would expire the same day).
