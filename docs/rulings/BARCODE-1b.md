Ruling BARCODE-1b - uniqueness. A barcode identifies ONE sellable thing per store. Database backstop: partial unique `products(store_id, barcode) WHERE barcode IS NOT NULL AND deleted_at IS NULL` and `product_variants(product_id, barcode) WHERE barcode IS NOT NULL` (migration 20261106000300; SQL only, like users_admin_email_key). The cross-table rule (a variant code may not equal any product or variant code of the same store) is enforced by `assertBarcodeAvailable` and by the allocator under `pg_advisory_xact_lock(hashtext(store_id || ':barcode'))`, because variants carry no store_id. The migration clears the barcode of NEWER duplicate rows (oldest keeps it) so the index can be built; `tests/unit/migration-lock-safety.test.ts` lists that migration as the one deliberate exception (an id-bounded `UPDATE products` that touches duplicate rows only, no NOT NULL backfill). Cost if wrong: a store that already had duplicate barcodes loses the newer duplicate's code and must regenerate it (Product labels, "Generate missing barcodes"); count the affected rows with a read-only `SELECT store_id, barcode, count(*) FROM products WHERE barcode IS NOT NULL AND deleted_at IS NULL GROUP BY 1, 2 HAVING count(*) > 1` before the deploy.
