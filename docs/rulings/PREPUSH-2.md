# PREPUSH-2

> Section: Lifecycle emails and referral attribution (2026-10-22, branch `feat/lifecycle-emails`)

Ruling PREPUSH-2 - The local pre-push gate runs the UNIT tier only; integration and E2E stay in CI. Evidence: PREPUSH-1's `vitest related` follows imports, so a change to a shared file (config, security, jobs) pulled in integration tests (refresh-token-rotation, auth-gdpr, warehouse/\*) that need the `test` role / test_db, and the push of #232 failed 71 files on the environment, not the code. `scripts/ci/pre-push-plan.mjs` now emits `exclude` (`PREPUSH_EXCLUDE`: tests/integration, tests/e2e, tests/smoke, the colocated apps/api/src tests whose shared setup needs Postgres + Redis, workers-test, workers-do) and `scripts/ci/pre-push-gate.sh` hands each glob to `vitest related --exclude`. `tests/unit/pre-push-plan.test.ts` proves it three ways: the plan carries the list for shared config / security / jobs files, the gate wires it, and a real `vitest related` over a throwaway project runs the unit test and NOT the integration test (with a control run that does pull the integration test in without the list). Cost if wrong: a regression only an excluded test would catch reaches CI before it is seen locally; CI runs those tiers on every PR and nightly.
