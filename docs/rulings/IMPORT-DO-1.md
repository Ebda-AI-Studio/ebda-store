# IMPORT-DO-1

Ruling IMPORT-DO-1 (2026-10-30, INFRA-CF-1 R3) - the CSV import (`BulkService.importProducts`) of a Durable Object store applies each Phase-4 batch as ONE DO section (`do/catalog-import.ts`, ops `importBatch` and `importVariants`): product create / update (including the opening stock and its `inventory_history` row), category / tag / image links, and the variants (options, values, variants, junction rows, swatch and barcode carry-over) commit together or not at all, like the interactive Postgres transaction. The Worker keeps parsing, validation, the plan ceiling and the category / tag creation (Phases 1-3); every read in the function now goes through `storeDb` and the category / tag writes through `storeWriter`, which are `prisma` on a Postgres store. After the commit the Worker records the slug redirects (platform data, idempotent, a failure is logged and never fails the import) and applies gold specs through `GoldRateService.setProductPricing` (its own money section, as before). A failing row names itself (`row N: ...`) and the optimistic counts are undone like Postgres. Column names are a closed whitelist and the AI-field names are checked against the real `products` columns. `distinct` was dropped from the orphan-cleanup reads (prisma-lite does not support it; the result is deduplicated in code). Not ported, stated: the post-import barcode auto-generation (`fillMissingAfterImport`) is skipped for a DO store because barcode sequences are Postgres-only (listed in `docs/cf/repo-factory.md`); the plan ceiling `assertWithinLimit` and the bundle-pinned-variant pre-check still count Postgres rows, so for a DO store they see none (the DO refuses a pinned variant delete with the FK message instead). Evidence: `tests/integration/repo-factory-import-contract.test.ts` (the same CSV on Postgres and on the DO: result, products, stock, history, links, options, variants and redirects equal, the bad row fails alone), `apps/api/workers-do/import.test.ts` (a failing row rolls the batch back; 20 concurrent imports of one new SKU leave one product; a re-import replaces variants and keeps a swatch). Cost if wrong: a DO store's import could miss a plan-limit refusal or the auto barcode fill until those two follow; the product data itself is atomic.
