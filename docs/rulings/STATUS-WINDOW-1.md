# STATUS-WINDOW-1

Ruling STATUS-WINDOW-1 - status.ebda.app headlines each component's uptime over the LAST 30 DAYS, computed from the same daily buckets as before (`uptimeOver(days, 30)` in apps/status/src/uptime.ts, the last 30 of the 90 retained days; a window with no checks is `null`, never 100 %), and keeps the 90-day figure visible beside it as the secondary number. The JSON API (`/api/status.json`) gains `uptime30d` next to `uptime`; `uptime` is NOT renamed and still means the 90-day figure, so existing readers are unchanged. The page also shows a short resolved note for the 2026-10-27..31 platform migration in Arabic and English ("admin, orders and the API were partly unavailable during a platform migration; resolved"), shown only while the 90-day history still covers any of those days (it disappears by itself from the page after 2027-01-29) and never as a live incident. Decided by Ahmad (via the main controller) because the 90-day figure was dominated by the Oct 27-31 migration outage and no longer described how the product runs now; the 90-day number stays so nothing is hidden. Evidence: apps/status/test/uptime-window.test.ts (the 30-day math incl. the 30/31 boundary, rounding, null windows; the JSON field; headline and secondary text in both languages; the note's window and escaping). Cost if wrong: a bad month stops showing in the headline after 30 days (it stays in the 90-day number and the daily bars), and the note is static text in the Worker, so a similar future outage needs a real incident, not another note.
