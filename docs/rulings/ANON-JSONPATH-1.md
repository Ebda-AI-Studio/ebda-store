# ANON-JSONPATH-1

**Ruling ANON-JSONPATH-1 - the Postgres branch of `order-anonymize-5y-monthly` selects "not already anonymized" with `OR [path IS NULL, NOT path = true]` (`order-anonymize-where.ts`), never a bare `NOT { path, equals: true }`.**
Measured on real Postgres 17 (pgvector image, Apple `container`, 2026-10-31) via Prisma 6.19 on the PrismaPg adapter, over six `orders.shipping_address` shapes. The old bare NOT compiles to `NOT (shipping_address #> '{anonymized}' = 'true')`: for an ABSENT path `#>` is SQL NULL, so the row is skipped and the old filter returned only `{"anonymized":false}` and `{"anonymized":null}` (never a normal order). `equals: Prisma.DbNull` on a path compiles to `... #> ... IS NULL`, so the OR returns absent-keys, `{}`, false, JSON null at the path, and a whole-value JSON null, and skips only `{"anonymized":true}`. `Prisma.JsonNull`/`AnyNull` variants were measured and rejected (they do not select the absent rows, or add a redundant arm). `tests/integration/order-anonymize-json-path.test.ts` pins the six shapes and runs the old form as a negative control. The Durable Object branch (`packages/repo/src/do/job-ops-b.ts`, `COALESCE(json_extract(..), 0) != 1`) already selects the same set (absent, 0, JSON null all coalesce to 0). `packages/repo/src/prisma-lite/engine.ts` (the DO-side Prisma translator; there is no `where.ts`) does not translate json `path` filters at all and throws `unsupported scalar filter path`, so no silent divergence exists there; adding one needs this same absent-row semantics. Class sweep: the only `NOT`/`not` on a json `path:` in `apps/api` and `packages` was this site (every other json-path filter is a positive `equals` / `string_contains`). Cost if wrong: the 5-year order anonymizer either skips every normal order again (retention breach goes unnoticed until the first orders reach 5 years, ~2031-04) or, on a bad OR arm, re-scrubs already-anonymized rows (idempotent, harmless).
