# CI-SPLIT-1

> Section: 2026-11-04 - use Umbra and GitHub CI together (branch `ci/split-hosted-umbra`)

Ruling CI-SPLIT-1 - the runner is chosen by two optional split variables on top of `EBDA_RUNS_ON`: `EBDA_RUNS_ON_DEPLOY` (every job of the 9 `cf-*-deploy.yml`: plan, deploy, notify) and `EBDA_RUNS_ON_LIGHT` (ci.yml `changes`/`guards`/`lint`/`typecheck`/`notify-failure`, gitleaks, blast-radius, deploy-change-label, semgrep, cf-schema-current). Each is `runs-on: ${{ fromJSON(vars.<SPLIT> || vars.EBDA_RUNS_ON || '"ubuntu-24.04"') }}`; unset = identical to before, and each job's `setup-node` cache follows its own selector. Heavy test jobs (unit, integration, workerd, app builds, E2E, RLS, mutation) stay on `EBDA_RUNS_ON` (Umbra). `timeout-minutes`: light/plan/notify <= 10, deploy <= 20. **Decision (coordinator, 2026-11-04):** set ONLY `EBDA_RUNS_ON_DEPLOY` to `"ubuntu-24.04"` now; leave `EBDA_RUNS_ON_LIGHT` unset (Umbra) until the Ebda org with its own 2,000 free minutes exists. **Evidence (Umbra times measured from recent runs; hosted assumed 1.5-2x slower plus npm ci, billed per job rounded up; volume since 2026-10-28: ~37 CI runs/day, ~5 main pushes/day):** deploy lane ~16 hosted min per merge = ~2,400 min/month = ~$19/month at $0.008/min, and deploys are the jobs that fail on Umbra's R2 tunnel (DEPLOY-R2-POPULATE-2); light lane ~11-13 min per PR push = ~12,000 min/month = ~$95/month, far above the ~$10 budget, hence it stays on Umbra. **Cost if wrong:** hosted minutes exhaust and deploys stop running (production stays on the last build) - delete `EBDA_RUNS_ON_DEPLOY` (`gh variable delete EBDA_RUNS_ON_DEPLOY -R Whisky-11/ebda-store`) and they fall back to Umbra; setting `EBDA_RUNS_ON_LIGHT` hosted before the org exists would burn ~$95/month.
