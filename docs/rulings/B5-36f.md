# B5-36f

> Section: Lifecycle emails and referral attribution (2026-10-22, branch `feat/lifecycle-emails`)

Ruling B5-36f - one store's feed failure is a P1 and the loop continues; the pending-rate email is its own step (so an email error cannot re-run `applyRates`), marked once per pending rate id. A failed email is a P1, not retried (the next 6-hourly run creates a new pending rate and mails that). Cost if wrong: an owner can miss the email for one pending rate; the rate itself is stored and shown in the admin.
