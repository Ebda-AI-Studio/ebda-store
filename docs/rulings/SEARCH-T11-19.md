# SEARCH-T11-19

> Section: 2026-10-15 — Phase B1 Qamar (B1-\*)

Ruling SEARCH-T11-19 (PR3 final review minor 2) — an account-wide ceiling on indexer Workers AI calls: `SEARCH_EMBED_GLOBAL_DAILY_CAP` (default 20 000 per Cairo day) counted in Redis, one `INCR` per provider call (a batch call, and each single-product call of an isolation pass or its retry, reserved before the call), across every store (`apps/api/src/lib/search/embed-budget.ts`). The per-store cap counts distinct products and misses retries and isolation passes; this one counts spend. Past the ceiling the indexer stops (the handler returns `capped: 'global'`, nothing is quarantined) and one P1 per day is raised (`search-index.global-cap`). It fails CLOSED: with no Redis there is no proof of budget, so the indexer spends nothing. Default sized at ≤ 25 products × ~600 input tokens per call ≈ ≤ 300 M tokens ≈ ≤ ~$3.5/day at bge-m3's $0.0118/M. Evidence: `tests/unit/search-embed-budget.test.ts` (grant up to the cap, refuse after, one alert, cap 0, no-Redis refusal, bad value → default) and `tests/integration/product-index.test.ts` "PR3 minor 2" (a budget of 2 spent by store A leaves store B's handler run `capped: 'global'` with no provider call; red before: no module). Cost if wrong: a Redis outage pauses indexing (search stays lexical for products not yet embedded) until Redis is back.
