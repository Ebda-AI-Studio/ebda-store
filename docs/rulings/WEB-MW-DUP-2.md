# WEB-MW-DUP-2

> Section: 2026-11-02 - storefront deploy unblock (branch `fix/demo-look-locale-paths`)

Ruling WEB-MW-DUP-2 - `apps/web` has exactly ONE middleware implementation, `apps/web/middleware.ts`; `apps/web/src/middleware.ts` is only `export { middleware } from '../middleware'` plus a literal copy of `config`. Next.js reads middleware from `src/` when the App Router lives in `src/app` and from the app root otherwise, and a second full copy (added by #367, with no CSP nonce and older redirect code) meant an edit could land in the file that was not running. Both locations now run the same code; `tests/unit/web-middleware-single-source.test.ts` pins the re-export, the equal `config.matcher` (a re-exported `config` is not statically analysable, so it is repeated) and the absence of a third file; `scripts/ci/assert-web-middleware.mjs`, called from `scripts/cf-build.sh` (so from the PR's "App build (web)" job and the deploy), fails the build unless `.next/server/middleware-manifest.json` has a middleware entry whose bundle contains the nonce code (`x-nonce`) and prints the manifest shape it found when not. Evidence which file production ran (an inference, not a proof): the live storefront sends a per-request `nonce-` + `strict-dynamic` CSP that only `buildStorefrontCsp`, called only from the root `apps/web/middleware.ts`, produces, and the deploy 41407371958 built with both files present; its log says only "Proxy (Middleware)" and "Bundling middleware function", never a file name. Supersedes the first draft of this ruling (delete the `src` copy), which would have removed tenant routing had Next been reading it. Cost if wrong: if production in fact ran the old `src` copy, the `?look=` and CSP behaviour seen live came from it and this change swaps in the root file's logic on the next deploy (the deploy-guard probes would roll that back); the new assertion can fail a build whose Next 16 manifest has a shape we guessed wrong, which stops a deploy rather than shipping a bad one.
