> Section: Lifecycle emails and referral attribution (2026-10-22, branch `feat/lifecycle-emails`)

Ruling VE-18 (Task 12, 2026-10-22) - `POST /admin/stores/:id/layout/preview` is removed with the classic page (its only caller, shown by grep over apps, packages, tests and scripts), but the read side of `?_layoutDraft=` stays: `public-store-layout.routes.ts`, the web middleware cookie, `StoreContext`, `layout.tsx`, `page.tsx`, `HomePageBody` and `preview-draft.ts`. With no writer the Redis lookup `layout-preview:<storeId>:<token>` always misses and falls through to the committed layout, and tokens written before the deploy expire within their one-hour TTL; removing the read side touches the middleware characterization and edge-cache tests and is a separate cleanup. Evidence: `tests/unit/classic-page-builder-retired.test.ts` (route gone), `web-middleware-characterization.test.ts` and `demo-edge-cache.test.ts` unchanged. Cost if wrong: one dead Redis GET per request that carries `_layoutDraft`, and dead branches in six storefront files until the follow-up removes them.
