# NZ-MERCHANT-1

Ruling NZ-MERCHANT-1 (2026-11-11, Postgres removed from the Worker; rows 3-5 and 9-16 of `docs/cf/neon-zero-final-classification.md`) - the remaining mechanical merchant paths read and write a store on its Durable Object through the repo, never the removed Postgres client: `variant.service` updateVariant disables / re-enables a variant through the new DO stock op `setVariantActive` (the `is_active` flip and its quantity-0 stock-history row in ONE DO transaction; the row update leaves `isActive` out); `store.routes` PATCH /stores/:id/status writes its audit row through `insertAuditLog` (DO / D1 via audit-sink); `bulk.service` skips the Postgres advisory barcode lock on a DO store (the partial unique indexes refuse a duplicate, Ruling BARCODE-DO-1); `payment-event.service` recordPaymentEvent appends through the DO `paymentEventRecord` (it was swallowed, so every merchant mark-paid / refund event was silently dropped); `promotion-resolver` counts prior orders through `storeDb` (prisma-lite gained the Json `{ path, equals }` filter: type-strict like Prisma on Postgres, plain keys only, the JSON path a bound parameter, `equals` only); the carrier-config writes take NZ-CARRIER-1; `provider-verification` modeOf reads both configs through `storeDb`; `shipment-pickup` reads and writes `ShipmentPickup` through `storeDb` / `storeWriter` (added to `DO_WRITABLE_MODELS`; the DO table already had the one-active partial unique index); the clearance coupon of a dead-stock flag is created with the flag update in ONE DO batch (a second click or a taken code is a 409 `COUPON_CODE_TAKEN`, never a duplicate coupon); the warehouse SKU search folds over the store's variant SKUs with the shared TS fold (the bundle / promotion / category search precedent); the orders-app push reads and prunes subscriptions through `withStoreRw`; back-in-stock reads the wishers from the DO and their name / phone from the store's `customers` row (`customers.user_id`), since `users` is not in the Worker. Found on the way and fixed at the source: prisma-lite stored NULL for an omitted scalar list (Prisma answers `[]`, Postgres had DEFAULT '{}'), so every coupon created without its scope lists failed P2011 on a DO store. A dev-only `/__dev/run-event` (DEV_STATS=1, never in wrangler.jsonc) runs the jobs one event triggers inline, so the workerd suite can prove the CSV-import job body. Proof: `apps/api/workers-test/merchant-orders-do.test.ts` second case (soft assertions: on the old code it lists 500s for variant disable / re-enable, SKU search, both coupon checks, carrier save / default / delete, pickup state / cancel, both clearance clicks, suspend / reactivate, plus 49 Postgres reaches including the import job); green with zero reaches. Cost if wrong: a DO-store merchant path that still reaches Postgres answers 500 or silently drops its write; the suite's zero-reach assertion is the tripwire.
