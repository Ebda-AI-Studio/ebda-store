Ruling ADM-I18N-GATE-1 (2026-10-29) - user-visible literal text in `apps/admin` JSX must go through `useT` / next-intl, and `scripts/check-admin-i18n-literals.mjs` (CI Lint job, affected lane `apps/admin`; `tests/unit/admin-i18n-literal-gate.test.ts`) fails the PR otherwise. It flags JSX text with a letter, a string literal rendered as a JSX child (also through `?:`, `&&`, `||`, `??`) and a literal in a copy-carrying attribute (placeholder, title, alt, label, aria-label, subtitle, ...). Allowlist is non-copy only: attributes that carry no copy (id, className, data-testid, aria-labelledby/-describedby ids, href), text with no letter, and machine-syntax placeholders (URL, e-mail, `@handle`, `/path`, `#hex`, CODE-TOKEN). Anything else needs `i18n-gate-allow: <reason>` on the line or the comment above (a bare marker does not waive); 17 waivers exist (keycaps, glyphs, env var names, role monograms, an HTML sample, the licence-mandated rates attribution). The first run found 190 literals in 58 files: 173 are fixed in ar and en (`common.egp` / `egpParen` replace 40 hard-coded "EGP") and the 17 waived ones are non-copy (Egyptian Arabic for sentences, neutral buttons). Content-language samples (the placeholder of an English-only or Arabic-only input, e.g. "Area name" / "اسم المنطقة") are the same string in both locales on purpose: they show what to type in that content language. Plan: `docs/superpowers/plans/2026-04-23-admin-i18n-and-extractions-plan.md`. Cost if wrong: a too-strict scan makes contributors scatter waivers, and a too-loose allowlist lets English copy reach Arabic merchants unnoticed; the scan is JSX-only, so object-literal labels rendered later (config arrays) are not covered.
