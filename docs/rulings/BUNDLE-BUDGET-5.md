Evidence nothing changed behaviourally: `tests/unit/ops/api-bundle-slimming.test.ts` (8 tests): the slimmed schema has the exact token stream of `schema.prisma`; the slim mime table resolves every extension to the same type (mime-types' preference rules) and every charset to the same value; the committed `mime-db.json` equals the one generated from the installed `mime-db`. Prisma compile parity: `findMany`/`findFirst`/`count` on the generated client emit byte-identical SQL with the original and the slimmed schema (sha1 equal). exceljs bare round-trips a workbook (write, load, rich text) in Node.

One deliberate behaviour delta: the slim mime table leaves out two defunct office types, `application/vnd.kde.kword` and `application/vnd.criticaltools.wbs+xml`, because their file extensions are repository-brand tokens that `tests/unit/no-force-branding.test.ts` and `no-wbs-refs.test.ts` forbid in any tracked file; lookups of those two extensions no longer resolve, and the API neither serves nor accepts them. The parity test pins the omission list to exactly those two.

Tried and dropped: exceljs Node build (`lib/exceljs.nodejs.js`) is 138 KB LARGER than the bare browser build, as BUNDLE-BUDGET-4 found; dynamic `import()` does not shrink a Worker bundle (one file), so `lib/lazy-modules.ts` stays a heap lever only; zod v3 + v4 both ship (~100 KB of v3) because first-party code (`error-handler.ts`, `cf/cutover.ts`, `mcp/merchant-write.ts`) and the MCP SDK import `zod/v3`, so unifying them is a behaviour change, not a trim; splitting cold admin routes into a second Worker is not supported by the architecture (one Express app, one auth/DO/Hyperdrive binding set) and the platform limit is not close. Not reached: the 600 KB target is missed by ~59 KB; the rest is real code (first-party 3.2 MB, Prisma runtime data model 247 KB, S3 schema 75 KB, passkey ASN.1 stack ~170 KB).

Wiring: `packages/database` `generate` and `build` now run `scripts/ci/slim-prisma-client.mjs` after `prisma generate` (idempotent; the Worker deploy workflow builds `@ebda/database`, CI and the startup budget job run `db:generate`). The Dockerfiles (Node) still run bare `prisma generate`: they do not bundle for Workers. Trade-off: Node and test runs also use the slimmed inline schema (parse-identical); error messages that quote schema line numbers refer to the slimmed text. `inlineSchemaHash` is left as generated (used only by the Accelerate path, not used here).

Cost if wrong: `keep_names: false` would break only code that reads `fn.name`/`constructor.name` (none in first-party, grepped; the pre-deploy smoke and the post-deploy health/404 probe with auto-rollback guard the rest); revert = delete that one line in `apps/api/wrangler.jsonc` (+243 KB). The other three levers revert by deleting their alias line or the `slim-prisma-client.mjs` call.
