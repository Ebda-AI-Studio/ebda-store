# ADMIN-GATE-1

> Section: Admin batch pre-push review (2026-11-04, branch `feat/admin-batch-2026-11-03`)

Ruling ADMIN-GATE-1 (2026-11-04) - the admin shows the plan-locked card only when the server CONFIRMED a feature is off. (a) A failed first read of the store's entitlements (`my-features`) sets `loadFailed`: `isEnabled` answers true (the API still enforces every gated route) and `<PlanGate>` shows a retry state in Egyptian Arabic instead of the upgrade lock, so a paid merchant is never told to upgrade because of an outage; a failed refresh after a good load keeps the last known flags. (b) `isPlanGateError` accepts exactly 402 and 403 `FEATURE_DISABLED` (the code `requireFeature` always sends); a bare 403 or `SERVER_ERROR` is a permission denial and reads "you don't have permission", never an upsell. Evidence: pre-push review 2026-11-04 findings 5 and 9; tests `tests/unit/admin-plan-gate.test.tsx`, `apps/admin/src/hooks/__tests__/useFeatures.refresh.test.tsx`, `tests/unit/admin-route-feature-gates.test.ts`. Cost if wrong: during an entitlements outage a store that is really on a lower plan sees pages it cannot use until its first call returns FEATURE_DISABLED from the server, which then shows the locked card.
