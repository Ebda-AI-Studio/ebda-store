Ruling DO-SEARCH-1 (2026-10-25) - search on the StoreDO is complete for the cutover. (1) The index is kept fresh by CONSTRUCTION, not by call sites: SQLite triggers on `products` (name, name_ar, search_terms, description, description_ar, sku, store_id; insert/delete), `customers` (first_name, last_name, phone, email) and guest `orders` (customer_id NULL: shipping_address, deleted_at, customer_id) write the row id into `search_dirty`; `flushSearchIndex` re-derives the TS-folded documents and runs at the start of every search, so prisma-lite, raw writers, bulk `INSERT..SELECT` and migrations are all covered, and a guard test mutates every indexed column raw. `ensureSearchIndex(db)` (idempotent; marks every existing row dirty on first install = the backfill) must run in the StoreDO bootstrap; wired in the full-schema DO (`packages/repo/workers-test`), the Phase 0 spike `apps/api/src/cf/store-do` has its own 5-table schema and is not the cutover DO. (2) Customers = the store's `customers` rows (kind user) + guest orders (shipping contact), names AND on the folded full name, phone digits in any form, email ILIKE; the Postgres definer restricted `users` to those with an order here or registered here, the DO table is already store-local so every customer row is in scope; orders by number = literal contains-match, live orders. `buildCustomerPatterns` moved to `@ebda/shared` (one source for the Worker and the DO). (3) Vectorize: Workers AI `@cf/baai/bge-m3`, 1024 dims, cosine, the two vectors per product of SEARCH-T13-7 (doc = names + descriptions, words = search_terms), namespace = store id, ids `<productId>:d|w` (Vectorize ids max 64 bytes), distance = 1 - score <= 0.55, topK 100 (no metadata) = at least 50 products; the DO table `product_vector_state` holds the text hashes (cyrb53, staleness only) so staleness, quarantine (permanent for the exact text, 24 h for transient kinds) and the daily cap need no Vectorize read (the cap is a per-store per-day counter of TEXTS SENT to Workers AI, `vector_usage`, reserved atomically before every provider call incl. fallback singles and query embeds, so edit spam cannot exceed it; an unchanged text hash is never re-embedded); state is committed only if the product still hashes to what was embedded, vectors of a product unpublished meanwhile are deleted; storefront visibility is decided by the DO rows (active, not deleted, public, vectors of this model), never by Vectorize metadata. The backfill is `backfillProductVectors` (passes until nothing is stale; call from a DO alarm, retry flag on transient failures). NOT VERIFIED: a real Workers AI / Vectorize call (fakes only: deterministic embedder and an in-memory namespaced cosine index with Vectorize's id/topK limits), the hybrid fusion with the keyword leg (RRF, `rrf.ts`) and the query-time race/budget stay in the Worker. Cost if wrong: if Vectorize's real score scale or metadata filter differs from the fake, the vector leg returns nothing or too much until `DEFAULT_VECTOR_MAX_DISTANCE` is tuned; keyword search is unaffected.
