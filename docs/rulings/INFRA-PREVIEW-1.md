# INFRA-PREVIEW-1

Ruling INFRA-PREVIEW-1 (Ahmad 2026-10-24, binding until launch; filed as a file 2026-11-11, audit M-180) - no preview or staging environments are created for any Ebda app before launch: no workers, queues, buckets, KV, Hyperdrive, databases or subdomains, including the help, docs and status sites, the Cloudflare migration spike and Ebda Chat (WhatsApp runs production-only). Test locally and in CI, release behind flags. This overrides the "preview isolation" production gate for Ebda pre-launch only. Evidence: EBDA-PROGRAM-REGISTER 2026-10-24 entries (StoreDO ships inside ebda-api behind a per-store flag, INFRA-CF-2 spike deployed nothing); the WhatsApp brief lists it in its shared decisions table. Revisit after launch only if needed. Cost if wrong: a bad deploy is caught by CI and flags, not by a staging soak, so a defect only visible on real infrastructure reaches production first.
