# B4-4

> Section: 2026-10-22 — Phase B4 Lamma (B4-\*)

Ruling B4-4 — the card stepper is a state of the one CTA, gated by look data, and reads a context that is null off a Lamma look. As planned, with three as-built decisions. (1) It is gated by `chrome.cardStepper: 'inline'` (Lamma looks only) rather than by the plan's bare predicate, so every other look and every legacy store keeps the add control byte-identical (the characterization suites ran unchanged: 14,110 unit tests green). (2) The card pieces read a dedicated `CardStepperContext` (provided by `ShopChrome`) and not the store/cart contexts, because ~35 existing test files mock those two contexts with fixed exports and a card that suddenly read a new export from them failed 479 tests; the provider-less default is "no stepper", which is also the right behaviour at checkout and in captures. (3) Required-note products: the card has no `personalisation` field, so the stepper keys off the cart line instead (one plain line of a non-variant product); the first add of a required-note product keeps going through the existing add path, which the server refuses without a note. Cost if wrong: a card that should route to the page shows a stepper only after the product is already in the cart (harmless); a missing `personalisation` on card data would need a listing select change.
