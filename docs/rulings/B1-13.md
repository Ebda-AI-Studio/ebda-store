Ruling NZ-DEMO-OWNER-1 (2026-11-23) — B1-13's demo-owner mail ban now holds on the Postgres-less Worker. Evidence: the identity D1 holds an active, verified `store_admin` row for `storedemo-owner@ebda.app`, and the Worker's store-less forgot-password path handed every address to the identity service (`forgotPasswordFor` mails any active account), so a reset request mailed the dead address; the Postgres-only `ownsDemoStore` never ran there. The guard (`services/demo-owner-guard.ts`) asks identity for the account id (`accountIdByEmail`, Service Binding) then platform D1 `stores` for `owner_id` with `is_demo = 1`; it runs inside the deferred mail job (no timing signal), and guards the merchant-signup resend too. The auth route's resend on the Worker never reaches identity for a store-less address (generic answer). Failure posture: a failing lookup does not refuse (warn + hand over). Cost if wrong: a reset or verification for a real merchant is silently dropped if a non-demo account ever owns a store flagged `is_demo`; a degraded identity or D1 at the moment of a demo-owner request still mails the dead address once. Deploy order: `ebda-accounts` before the API (an API that calls a missing RPC fails open and mails as before).
