# STORE-EDGE-2

> Section: 2026-11-09 — S2-REVIVE (launch map, inside SCALE-READY-1 items 2-3)

Ruling STORE-EDGE-2 (2026-11-09) - the store HTML edge cache (STORE-EDGE-1, `apps/web/store-edge-cache.ts`) is ON for every active store, and that is how "cacheable storefront routing" comes back for launch; the tenant-path rewrite (`STOREFRONT_TENANT_ROUTING`, plan `2026-07-12-tenant-cacheable-routing`) STAYS OFF per TRC-8. Evidence: TRC-8's blocker is still true on main (the root `app/layout.tsx` reads `headers()`/`cookies()`, so the tenant tree renders dynamic and Next's route cache never holds a page; lifting it needs the root-layout decomposition and a consent-gating sign-off, plan section 3.6). The Worker-level layer needs neither: it keys by store host + path (+ `__lang` on unprefixed paths), stores only cookie-less renders (so the SSR consent gate is unchanged: a cached page is the no-consent page every first visitor already gets) and is invalidated per store by the R2 purge epoch that every API write path already triggers (`revalidateStorefront`). Changes: (1) `STOREFRONT_HTML_EDGE_HOSTS=all` (deploy default) admits every host the API resolver vouches for as an active store; (2) on a `/ar|/en` page the URL decides the language, so the first-visit `Set-Cookie: force-language=<url locale>` no longer blocks storage: it is stripped from the stored copy and re-issued per visitor; any other Set-Cookie still refuses storage. Measured 2026-11-09 on prod `storedemo.ebda.app/ar` (DEMO-EDGE-1, same rule, fixed in the same change): 2.95 s TTFB cookie-less = never cached, vs a HIT with the cookie, i.e. the viral first-visit path was the one path neither layer served; (3) click-tracking parameters (utm\_\*, fbclid, gclid, ttclid, ...) are dropped from the key AND from the render request on a `/ar|/en` page; (4) concurrent misses for one key share one render per isolate (`COALESCED`); (5) each isolate trusts an epoch it read for 2 s (the NZ-D3 window), the isolate that records a purge forgets at once; (6) personalised roots bypass with or without a language prefix (cart, checkout, account, auth, wishlist, search, compare, review, unsubscribe, sms-unsubscribe, affiliate, q, landing-preview, og, feeds); (7) purge epochs are recorded even while the layer is off; (8) category writes now purge the storefront `categories:<id>` tag (`invalidateStoreCategoriesCaches`, which had zero call sites); (9) `invalidateStoreBundlesCache` (zero call sites) is DELETED, not wired: every bundle write (create, update, deactivate) already calls `invalidateStoreProductCaches`, which clears the bundle-list key and sends `bundles:<storeId>` in its one purge, and a bundle's price/availability also depends on its component products, which only that function covers; wiring both would re-create the double purge of issue 2202. A guard fails on any exported `invalidate*` in `public-cache.ts` with zero call sites. Off in one step without a build: Worker secret `STOREFRONT_HTML_EDGE_OFF=1` (docs/ENVIRONMENT.md). CACHE CLASSES: price, stock, gold-rate price, store status and theme/layout are NEVER-stale and purge on every write path (price/stock/gold via `invalidateStoreProductCaches`, order stock via `...AfterOrder`, suspend/theme via `bustStoreCaches`); categories, blog and static pages are BOUNDED-stale under the same purge; the 60 s fresh / 600 s stale TTL is an outer bound only. Residuals: <= 10 s order-purge coalescing; <= 2 s cross-isolate epoch memo; a fill right after a purge can carry the API's KV L1 lag (<= 60 s, NZ-D1); an undelivered purge falls back to the TTL. Checkout, cart and order creation re-read price and stock from the store and never use this layer. Tests: `tests/unit/store-edge-cache.test.ts` (key includes the store, no Set-Cookie/private response stored, first-visitor cookie, tracking params, coalescing, memo), `tests/unit/storefront-html-cache-invalidation.test.ts` (each NEVER-stale write class -> real tags -> epoch -> that store dropped, the other kept; category source guard), `tests/unit/demo-edge-cache.test.ts`. Cost if wrong: a shopper sees a listing price or stock figure up to the residual window old (the charged price is always current), or a merchant's edit takes one window to show; turning the secret on restores live rendering at once.
