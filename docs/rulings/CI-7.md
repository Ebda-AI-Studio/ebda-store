Ruling CI-7 (Store session, 2026-10-25; security review) - a buyer key is a hash of a phone someone typed at checkout, so it is NOT proof of identity. Customer export and the default erase on the Postgres path are scoped to the account's OWN order ids in the request's store (`lib/ci/erase.ts` `exportCiForOrders` / `eraseCiForOrders`); a buyer-key erase runs only for a phone the account PROVED it holds (the WA-CONSENT-1 `phoneOnOwnOrder` proof, computed before the scrub) and ONLY IN THE STORE that proof was made in; its tombstone is keyed by store + buyer, so a single-store proof never touches another store. Erasure writes tombstones first (`tombstone/order/<id>`, `tombstone/buyer/<storeId>/<key>`, 30-day lifecycle): the sink drops an event for an erased order and de-keys one for an erased buyer, and the `account/erased` job runs a second erase pass 2 hours later. Dead-lettered events are parked in R2 `dlq/` (14 days, shorter than the 30-day tombstone) before the ack; erasure deletes the in-scope parked bodies, and `lib/ci/replay.ts` refuses a body older than the tombstone TTL or one that was erased. Index entries are never deleted by an erase (a delete cannot be conditional): they are rewritten by compare-and-set, an entry whose partition is not there yet is kept, and the second pass lists the store's partition prefix instead of trusting the index. Return-reason and envelope sanitizers normalise Arabic-Indic and Persian digits before matching phones. Residuals accepted: names are not scrubbed from the 200-char return reason (it is carrier text; the 24-month raw copy is erasable by order); a stored `pickedUpAt`/`returnedAt` can be overwritten by a concurrent poll+webhook with an equal-or-later value (events keep the deterministic id). Accepted: the proof is the WA-CONSENT-1 one (a delivered order in the store with that phone, no OTP), so within that one store a proven-key erase can remove other people's rows under the same typed phone; the export of a proven phone stays own-orders-only (narrower than the erase, by design). Cost if wrong: another person's CI rows in that one store lost, or a buyer-key erase missed for a customer who never proved the number (their own-order rows are still erased).
