# WH-6

> Section: 2026-10-15 — Phase B1 Qamar (B1-\*)

Ruling WH-6 (2026-10-21) — SSRF policy for merchant webhook URLs: https only, port 443 only (no allowlist exists), no credentials, no IP literal in any spelling, no `localhost`/`.local`/`.internal`; DNS resolved at registration and at every send (test send and resend use the same sender), every answer checked against private, loopback, link-local/metadata, CGNAT, TEST-NET, multicast/reserved, IPv6 ULA/link/site-local, `::/96`, NAT64, 6to4, Teredo, documentation and IPv4-mapped IPv6; no redirects. Residual (restated after the security review, M11): `fetch` re-resolves the name after our check and neither Node's global fetch nor Workers' can pin the validated address, so check-then-connect DNS rebinding is open. Production is bounded because the API is a Cloudflare Worker, which cannot reach private ranges. On the Node path (local docker, any future Node host) a TTL-0 name that alternates between a public and a private address, combined with repeated Send test, lands POSTs on internal hosts on roughly half the tries, and the first 200 characters of each response are stored and shown in the delivery log: that is a 200-character read, not a blind write. If Node ever serves production, pin the address with an undici `Agent({ connect: { lookup } })` that validates each resolved address first. Cost if wrong: on a Node host, an attacker-chosen internal HTTP endpoint answers a POST and 200 characters of its reply reach the attacker.
