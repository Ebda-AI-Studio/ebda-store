# PERF-TIMEOUTS-1

> Section: 2026-11-02 - SCALE-READY #6, outbound timeouts (branch `feat/perf-fetch-timeouts`)

Ruling PERF-TIMEOUTS-1 - every outbound HTTP call from `apps/api` goes through ONE helper, `apps/api/src/lib/fetch-with-timeout.ts` (`fetchWithTimeout(url, init, {label, class, timeoutMs})` and `timedFetch(label, class, timeoutMs)`), so a stalled third party cannot hold a Worker or queue slot open. Defaults by class: `payment` 10 s (Paymob, Kashier, Fawry, Geidea), `ai` 30 s (Gemini, OpenAI, Perplexity, embeddings), `default` 8 s (OneSignal, SMS, Meta/TikTok pixels, PostHog, Cloudflare hostnames, GSC, alerts, couriers' safe-fetch, DoH, webhooks, storefront revalidate 4 s). The timer covers headers and body; a caller's own `signal` still works (first to fire wins). On timeout the helper throws `FetchTimeoutError` (`name === 'TimeoutError'`, like the platform's own `AbortSignal.timeout`, so existing catch blocks keep working), logs only the label and limit (never the URL, headers or body), and each caller keeps its existing failure path (queue retry, user-facing error). Streaming (SSE) is exempt from the total limit with `timeoutMs: 0` plus `withIdleTimeout`; no call site streams today. Enforcement: `tests/unit/api-no-raw-fetch.test.ts` parses every file under `apps/api/src` and fails on any use of the global `fetch` (call, reference, or `globalThis.fetch`) outside the helper; `.fetch(` on a service binding or Durable Object stub is not third-party and is not flagged. Residual, not covered by the helper: third-party SDKs that make their own HTTP calls (their own client timeouts apply, audit them when one is added); `apps/orders` and `apps/web` browser/server fetches to the first-party API and accounts Worker (not third parties); `carrier-http` and `gateway-http` keep their own typed deadline on top of the helper. Cost if wrong: a slow-but-healthy upstream that legitimately needs more than its class limit (a large AI generation, a big image fetch through safe-fetch) now fails at the limit instead of hanging; raise that one call's `timeoutMs` at the call site.
