# B3-11

> Section: 2026-10-21 — Phase B3 Jasmine (B3-\*)

Ruling B3-11 — implementation deviations from the plan text, each with its reason. (1) The tag filter is `?tag=<tag NAME>` (URL-encoded), not a hyphenated slug: `Tag` has no slug column and a new one would be a schema change; the name is matched exactly inside the store. (2) `steps` is a section of `step` blocks (like `trust-badges`), each with an optional `productIds[0]`, so the existing ref collection, validation and the homepage product pool work unchanged. (3) The routine "add all" and the PDP bundle line read one live endpoint (`bundle-savings`) instead of a number in the document, and the steps tick when the routine's exact bundle is in the cart. (4) The second cart line of the purchase-path pack is an option-less product (the shoot action taps add without choosing options), not "another variant product". (5) The hero's 78svh cap already exists as `HeroBanner`'s 45vh mobile cap. (6) The plan's Apothecary ground and Clinic green were re-derived (B3-2, B3-3). (7) The browser suite runs against a PRODUCTION build: it refuses `<slug>.localhost` store hosts, so the local stores carry a custom domain `<slug>.localhost-b3.test` (the name contains "localhost" so the API's dev CORS rule admits the origin) and the browser maps it to loopback; the build sets `OPEN_NEXT_CLOUDFLARE=1` so images are served unoptimised exactly as on the Workers (the Next optimizer cannot fetch itself on a host Node cannot resolve). Cost if wrong: each is a local edit; none changes a schema or a public contract.
