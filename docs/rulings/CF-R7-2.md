# CF-R7-2

Ruling CF-R7-2 (2026-10-30, INFRA-CF-1 R7, Ahmad via the controller) - COD remittance lines live WITH THE STORE: for a store on its Durable Object the settlement import writes the DO's own `cod_remittances` table, whose `shipment_id` references the DO's own `shipments` (the DO schema keeps the foreign key, `ON DELETE SET NULL`), instead of the Postgres table whose `CodRemittance.shipmentId` is a foreign key to Postgres `shipments` (a DO store's shipments are never there, so a line matching one could not be inserted). Considered and rejected: a soft reference on Postgres validated through `storeRepo` (it splits one reconciliation across two databases, so a line and its shipment can disagree after a failure and the report needs two reads that cannot be one snapshot). The import is one operation, `importCodRemittances`, ONE section: the shipments are matched by (store, carrier, tracking number) (the newest wins a tie) and the lines are inserted together, so a line never carries a shipment id that is not in the store. SETTLEMENT CORRECTNESS: no double-settle, because `(store_id, carrier, line_ref)` is unique and the insert is `ON CONFLICT DO NOTHING`, so importing the same statement twice (or two uploads racing, which the single-threaded DO serialises) books every amount once and reports the repeats as `duplicates`; amounts reconcile, because a row whose net is not gross minus fee is refused as a whole BEFORE any row is written (the table's own CHECK would otherwise abort mid-file with an opaque constraint error); a partial match keeps the unknown tracking as an unmatched line (shown, never dropped) exactly as on Postgres. The report reads lines and the has-a-remittance filter through `storeDb`, so one read path serves both backends and the earlier Postgres-side lookup for DO stores (CF-R6B-1) is gone. Lines imported on Postgres before a store's cutover travel with the generic table copy. Evidence: `packages/repo/test/do-stock-books.test.ts` (settlement matching a DO shipment, the same file imported twice, a partial match, another store's shipment never matched, a refused row writes nothing), `tests/integration/repo-factory-r7-books-contract.test.ts` (the same three scenarios through the real `CodReconciliationService` on Postgres and on the DO, equal import counts, equal report rows and equal remittance tables), `tests/integration/repo-factory-r6b-contract.test.ts` (the COD report, now seeded in the DO). Cost if wrong: a statement imported on a store whose flag later returns to `pg` is on the DO side only until the rollback replay copies the table back (the rollback already carries every store table); with every flag at `pg` nothing here changes behaviour.
