# TRACES-WINDOW-1

Ruling TRACES-WINDOW-1 - ebda-api turns on Workers tracing at `observability.traces.head_sampling_rate` 0.01 (apps/api/wrangler.jsonc); Workers Logs stay at 0.1, unchanged. Why: the 2026-11-19 cold store-resolve investigation (1-2 s on a fresh host, AuthState DO wallTime p99 <= 480 ms) needs the per-call spans (Worker to AuthState JS-RPC session and call spans, with the DO's own invocation span beside them), and the dashboard showed "No spans found". Cost, from Cloudflare docs (not measured on our account): no measurable request overhead and unsampled requests skip tracing; stored traces are free until 2026-12-01; from then traces and Workers Logs share one account allowance (Workers Paid: 50 GB ingestion and 10 GB-month storage per cycle, then $0.25 per GB ingested and $0.10 per GB-month stored; 7-day retention). Decision due by 2026-11-28: read Billable Usage in the dashboard (measured GB/day for traces and logs together) and either keep at <= 0.01 or revert this line, and record the choice here. Proof the key is accepted: `wrangler deploy --dry-run` (wrangler 4.116.0) prints no warning for the new block, and a control run with an extra key inside `traces` prints "Unexpected fields found", so a rejected key would have shown. Debug-header trace rules exist (Cloudflare Traces, per zone, dashboard or API with the Zone Observability permission) but are a zone setting, not part of this file. Cost if wrong: from 2026-12-01 an unreviewed 1% could add billable GB beyond the shared 50 GB allowance (extra ingestion $0.25 per GB); sampling is head-based, so reverting the one line stops it within one deploy.
