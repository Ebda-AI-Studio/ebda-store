Ruling WA-HEALTH-VECTOR-1 (Controller, 2026-10-27) - GET /health on the API adds `buyerKeyVector`: the first 16 lowercase hex chars of HMAC-SHA256(key = SUITE_BUYER_KEY_SECRET as UTF-8, message = "suite-buyer-key-probe:v1" as UTF-8). It lets Ebda WhatsApp (and an operator) prove both Workers hold the same secret without the secret ever travelling; a mismatch is visible at once, instead of showing up as one customer with two buyer keys. The probe message is a constant, so the value is not derived from any phone, order or customer, and 64 bits of an HMAC output reveal nothing usable about the key. The field is OMITTED, never a placeholder, when the secret is unset. A test pins the value for a fixed key and asserts /health carries only status, timestamp, commit, deploymentId and buyerKeyVector, with no buyer key, E.164 or long digit run. Cost if wrong: 64 bits of a keyed HMAC of a public constant leak; rotating the secret changes the value and every buyer key.
