# CF-R6A-2

Ruling CF-R6A-2 (2026-10-30, INFRA-CF-1 PR R6a) - e-mail campaigns of a DO store run on the DO: `Campaign` and `CampaignRecipient` are DO-writable models, the admin API (create, list, detail, recipients, edit, send, cancel, delete), the public unsubscribe pair, the rolling send-cap count (`sentInLast24h`) and the `campaign-send` job read and write the store's own rows through one helper (`inCampaignStore`: the Postgres tenant scope for a Postgres store, none for a DO store), and `campaign-send` is a PORTED job. Differences from Postgres, each handled: the recipient's subscriber is read by id (no relation join on a DO); the send flip is not inside the request's Postgres transaction, so when the enqueue throws the route puts the campaign back to `draft` itself (only the same `scheduled` row, guarded by its `scheduledAt`) before answering 503, per the queue-then-send rule; the delete guard (`recipients: { none: { sentAt: { not: null } } }`) stays ONE statement; the claim, the per-recipient `queued` guard and the materialise `skipDuplicates` are single statements the DO thread makes exactly-once. Evidence: `tests/integration/repo-factory-campaign-contract.test.ts` (the real router, public router and job on real Postgres vs the DO schema: consented subscribers mailed once in their language, a rejected mailbox marked failed, the same counts and statuses; daily-cap and empty-audience aborts; consent withdrawn mid-send skipped; the admin API sequence incl. the enqueue failure returning to draft; unsubscribe preview, POST and repeat), `apps/api/workers-do/campaigns.test.ts` (real workerd: 30 claims, one winner; 25 sends of one recipient, one `sent`; 30 materialisations leave 3 rows; a delete racing the first send never loses send history). Residual: the per-store pacing sleep and the platform send pacer are unchanged (platform-wide, not store data). Cost if wrong: a campaign stuck `scheduled` or a doubled mail; the claim is a conditional write and Resend's idempotency key `campaign-recipient/<id>` is the last guard.
