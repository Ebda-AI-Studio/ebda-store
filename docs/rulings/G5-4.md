Ruling G5-4 (2026-10-26) - a job's final failure alerts directly, not through an `inngest/*` event. `reportJobFailure` (lib/jobs/failure.ts) calls the existing `sendAlert` path (P1 platform; P0 for payment-webhook-process) and Sentry from the Workflow end, the queue's last attempt, the gate-never-freed path, the DLQ and a given-up alarm start. It carries job id, group, instance id, trigger event name and the truncated error message only, and never throws. Why: the failure event went to Inngest, whose API refuses reserved `inngest/*` names (400), so a failed run raised no alert while alerts-failure-watch was not yet on Cloudflare. Cost if wrong: a flapping job pages once per final failure (sendAlert throttles the same title for 5 min).
