## Findings that change the plan

1. **Bug independent of the builder (#19):** layout save does not purge the storefront data cache. It is cheap to fix (use `bustStoreCaches`-equivalent + tagged storefront fetch) and Phase 3 needs it anyway. Recommend landing it first as its own fix PR, verified live (`/health` commit, then change a layout and time the storefront).
2. **Save == publish today (#8, #9, #10).** Any "draft" that exists is a 1-hour Redis blob. Phase 3's draft/publish is net-new data model, not a toggle on existing state.
3. **The key list is duplicated 3x (#1, #21)** and each section costs hand-edits in 4 files. The registry's first payoff is deleting that class of silent-strip bug, before any new UI.
4. **Reinstating desktop/tablet preview (#6) reverses a 2026-06-22 request from Ahmad.** Roadmap explicitly requires 3 viewports; ask before building. **Answered 2026-10-07: yes (BUILDER-PREVIEW-1).**
5. **Existing tests that must stay green through every phase:** `tests/unit/layout-schema-parity.test.ts`, `packages/shared/src/types/__tests__/store-layout-resolve.test.ts`, `tests/unit/store-update-persists-every-accepted-field.test.ts`, `tests/unit/mass-assignment-prohibited-fields.test.ts`, `tests/unit/admin-page-builder-preview-csp.test.ts`, `tests/unit/storefront-frame-ancestors-prod.test.ts`, `tests/unit/admin-i18n-*`. No builder E2E, no save/reload round-trip test, no two-store render test exists today (roadmap Phase 0 evidence is therefore unproduced; the first task of Phase 1 is to write them against current code as characterization tests).
