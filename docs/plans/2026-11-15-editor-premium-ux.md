## Root causes found in the code (measured by reading, then confirmed in the DOM classes)

1. **Viewport breakpoints used inside a fixed-width pane.** `ZoneEditor` grid is `grid gap-3 sm:grid-cols-2 lg:grid-cols-3`; `FontsCard` actions are `grid sm:grid-cols-2`. The left pane is `lg:w-72` (288 px) and the right `lg:w-80` (320 px), but the breakpoints react to the window (>= 1024 px), so at every desktop width a 288 px pane gets 3 columns (about 80 px each). That one cause produces the truncated placeholders, word-per-line hints, truncated selects and the overlapping buttons (nowrap buttons in two ~140 px cells, one 144 px label + padding wider than its cell).
2. **Contrast "auto-fix" 1.0:1 is a real bug, not a display issue.** `resolveColor('token:primary', theme)` returns the string `hsl(var(--primary))` when the theme has no `primaryColor` (legacy fallback, `packages/shared/src/utils/color.ts:156`). `parseColorToRgb` cannot parse a CSS-variable reference, `contrastRatio` returns `1` for any unparseable input, and `pickReadableForeground` returns `undefined` which `ColorContrastPreview` coerces to `#000000`. Result: black text, ratio 1.0, red cross, on a colour nobody measured. Same defect class: `contrastRatio` returning a _number_ for "unknown" is consumed as if it were a measurement everywhere it is called.
3. **CSS vocabulary is shown to merchants.** `ColorContrastPreview` prints `Background: Primary (hsl(var(--primary)))` and the raw `autoFixedLabel` string; the token dropdown is a native `<select>` with no swatch.
4. **No shared control scale in the editor.** Raw `<input>`/`<select>` classes vary: `px-2.5 py-1.5`, `px-3 py-2`, `px-2 py-1 rounded` (bare radius, banned by ADM-DS-1), `min-h-11`, `h-11 w-28`; segmented buttons use `min-h-11` while toolbar buttons are `size="sm"` (32 px) and tabs are plain `<button>`s with `px-2 py-2.5 text-xs`. `tokens.ts` and `Button.tsx` already define the scale; the editor panes bypass it.
5. **Tabs.** Start-pane tabs are `flex-1 px-2 py-2.5 text-xs` with no `whitespace-nowrap`, so "Colours and fonts" wraps in a 288 px pane; the active state is a 2 px underline in one place and a soft tint in another (`navItemClasses` exists and is not used).
6. **Native `<details>` disclosures** in `ThemeSettingsPanel` (tiers, Advanced), `SettingsPanel`, `PageSettingsPanel`: default ▶ marker (wrong side in RTL for some browsers, not themable), no chevron animation, open state not controlled for keyboard users beyond browser default.
7. **Template switching is buried and cramped, and not a preview.** `LookPicker` (15 static 360x450 first-screen webp crops, none missing) renders inside the 320 px right inspector with `sm:grid-cols-3` (window breakpoint again), so three thumbnails of ~85 px sit side by side with their forWhom/idea text. The real preview exists (`previewLook`, proposal rendered in the canvas) but only after: toggle top-bar button, pick, choose keep/reset, press Preview. The toggle is also hidden once any section is selected (`if (selection) setLookOpen(false)`), which looks like "the feature is gone". Thumbnails are static assets generated once, not rendered from this store's content, and there is no larger preview before the choice.

## Plan by PR

### PR A: control scale + layout (findings 1, 2, 7, 8, 9, 10, 12, 13, 15, 16, 18-23)

1. `apps/admin/src/components/ui/Field.tsx` (+ tests): `Field`, `TextInput`, `SelectInput`, `Segmented`, `Stepper`, `Disclosure`, `IconSegmented`. Heights from `CONTROL_HEIGHT`; radius `rounded-md`; label above; hint on focus; error with `role="alert"`; logical props only.
2. Rewrite `ZoneEditor` single column using the primitives (props unchanged so the legacy typography page and Smart Palette keep working; the grid becomes container-aware only where the host is wide, via `@container`, never window breakpoints).
3. `FontsCard`: stacked actions; font rows with live specimen ("Aa" in the family, Arabic "أبجد" for the Arabic-capable ones).
4. `BuilderEditor` tab strip on `navItemClasses`, pane widths, toolbar icon set; `ThemeSettingsPanel`/`PageSettingsPanel`/`SettingsPanel` details -> `Disclosure`.
5. Tests (jsdom, vitest): `Field.test.tsx`, `ZoneEditor.layout.test.tsx` (no `sm:`/`lg:` grid classes on the pane host; every label/option text present and not clipped by `truncate`/`overflow-hidden` ancestors; stepper allowed values), `FontsCard.layout.test.tsx` (actions stacked, no shared row), `Disclosure.test.tsx` (aria-expanded/controls, Enter/Space, RTL chevron, reduced motion class), tab strip test (`whitespace-nowrap`, roving keyboard). jsdom has no layout engine: overlap/truncation are asserted structurally (class contract + DOM nesting) and verified for real by the Playwright geometry check below.
6. Playwright geometry spec `tests/e2e/editor-layout.spec.ts` (runs on a built admin with the fixture store): at 1280/1440/1920 in ltr and rtl, for each pane control assert `getBoundingClientRect` has no overlap between sibling interactive elements and `scrollWidth <= clientWidth` on labels. Added to the nightly set, not the PR gate (CI discipline).

### PR B: colour editing (findings 3, 4, 11, 14, 17)

1. `packages/shared/src/utils/color.ts`: `resolveColorForMeasure`, `contrastRatioOrNull`, 8-digit hex alpha handling; keep `contrastRatio` signature (blast radius) but document and stop using it for decisions in the admin.
2. `ColorPopover` (swatch trigger, brand chips with swatches and plain names from `components.colorField.tokens`, hex input with live validation, native picker row, recents per store in `localStorage` with try/catch, reset to template colour). Replaces the select + native input + hex box in `ColorField` (same props: `label`, `value`, `onChange`, `hint`, `theme`, `previewFg`, `inheritFromToken`, `showContrastPreview`).
3. `ColorContrastPreview` rewritten as a real mini preview with plain-language verdicts; no CSS variables or raw hex shown unless the merchant opens "Details".
4. Tests: `color.contrast.test.ts` (known WCAG pairs, unresolved token returns null, theme without `primaryColor` resolves via defaults, never reports 1.0 for unknown), `ColorField.popover.test.tsx` (keyboard open/close/Escape, chips are `role="radio"` with names, hex paste, invalid message), `ColorContrastPreview.test.tsx` (no `var(--` text rendered; verdict words; unresolved state), ar + en snapshot of strings.

### PR C: template gallery (findings 5, 6, 24, 25)

1. `TemplateGallery` sheet (portal, full-height, focus trap via existing `use-drawer-a11y`), opened from the always-present "Change template" button; tabs per template family (existing `LookPicker` registry logic reused, it stays the only source of looks); grid of look cards (name, one line, preview, "Current" badge).
2. Preview per card: static webp immediately; if the store has content, the card upgrades to a live scaled render from the preview endpoint already behind `previewLook` (no new server contract; if that endpoint cannot render a non-current look without writing, we keep the webp and the large preview uses the existing canvas proposal; this is the one open technical question, resolved in the first hour of PR C by reading `previewLook`).

## Rulings

Ruling EPUX-1 - Pane controls are sized by the pane (container), never by the window. Evidence: root cause 1, the same bug produced findings 1, 2, 7, 13 and 15. Cost if wrong: a wide inspector would show one column where two would fit; harmless.

Ruling EPUX-2 - A contrast number is only shown when both colours resolve to real RGB; otherwise the UI says it cannot measure. Evidence: finding 4 (1.0:1 on an unmeasured colour). Cost if wrong: a few colours show "cannot measure yet" instead of a number until the theme resolves.

Ruling EPUX-3 - Template gallery is a sheet over the editor, not a mode of the 320 px inspector. Evidence: finding 5/6/25. Cost if wrong: one more full-screen surface to maintain.

Ruling EPUX-4 - Previews and every setting in this surface stay draft-only until Publish (THEME-DRAFT-1, VE-4); Apply of a template keeps the existing server guard (DRAFT_MOVED). Cost if wrong: none new; behaviour unchanged.

## Decisions only Ahmad can make (defaults taken, none block)

1. Resizable panes (drag handle) - default: not now, fixed 320/360 at >= 1280. Cost if wrong: power users want wider panels; add later.
2. Live per-store thumbnails in the gallery - default: yes if the preview endpoint can render without writing, else webp thumbnails plus the large live preview. Cost if wrong: thumbnails show demo content instead of the store's own.
3. Rename tab "Colours and fonts" to "Style" - default: only if it still wraps at 288 px after the fix. Cost if wrong: one label change.
