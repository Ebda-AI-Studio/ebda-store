Surface: `apps/admin/src/app/stores/[id]/builder/**` plus the shared admin components it embeds (`ZoneEditor`, `ColorField`, `ColorContrastPreview`, `section-design/*`, `looks/LookPicker`) and the canvas toolbar in `apps/web/src/builder/preview/CanvasToolbar.tsx` (toolbar chrome only).
Trigger: Ahmad (owner) reviewed it live on 2026-11-15: errors in sizes and UI/UX, ugly, hard to use, no template previews. Relayed bar: "very detailed, make it the best, premium and easy to use".
Out of scope (another agent owns it): canvas iframe framing / CSP ("This content is blocked"). Nothing here touches `Canvas.tsx` framing.

Evidence labels: **M** = measured from the source (class lists, props, data) in this worktree; **I** = inferred from M, to be confirmed in the browser during the PR's rendered check. No finding below was seen on a rendered screen by this agent (the admin needs a signed-in session); Ahmad's screenshots confirm findings 1-4, 8, 9, 19, 20, 22, 23.

## Finish line

- Must work: every control, in every pane, is legible, untruncated and operable at the real pane widths, in en and ar (RTL), at 1280 / 1440 / 1920 and a 1024-1180 narrow laptop, by mouse and by keyboard.
- Exercised: all 4 start tabs, top toolbar, Add section dialog, drag/move, every section inspector type, page settings, template gallery, colour and font controls, history/restore, AI pane, save/publish/error/conflict states.
- Must NOT change: stored data shapes (`StoreTheme`, `ZoneOverride`, `PageDefinition`, look ids), draft-only semantics (THEME-DRAFT-1, VE-4), canvas framing/CSP, `data-setting-id="builder.*"` anchors (admin search registry), no-orange defaults (merchant colours are never validated).
- Done: every PR ships component tests that fail when its defect returns, ar+en strings (`check:admin-i18n`), `tsc`, admin lint, slop guard, `admin-design-tokens` baseline that only shrinks, `impeccable detect` clean, and a rendered check with DOM geometry at the 4 widths x ltr/rtl. Ahmad's post-deploy checklist = the **Acceptance** column below.

## Root causes (each explains a class of findings)

- **RC1 Window breakpoints inside fixed-width panes.** `ZoneEditor` `grid sm:grid-cols-2 lg:grid-cols-3`; `FontsCard` `sm:grid-cols-2`; `LookPicker` `sm:grid-cols-3`; the panes are `lg:w-72` (288) and `lg:w-80` (320) so every desktop window gets the widest layout in the narrowest box. Produces F1, F2, F7, F13, F30. (M)
- **RC2 Unmeasured colour treated as measured.** `resolveColor('token:primary', theme)` returns `hsl(var(--primary))` when the theme lacks `primaryColor` (`packages/shared/src/utils/color.ts:156`); `parseColorToRgb` cannot parse it; `contrastRatio` returns `1`; `pickReadableForeground` returns `undefined` which `ColorContrastPreview` turns into `#000000`: black text, "1.0:1 ✕" on a colour never measured. (M)
- **RC3 The control scale exists and the editor bypasses it.** `ui/tokens.ts` + `ui/Button.tsx` define heights (32/40/44), one radius, type scale; the builder panes hand-write `px-2.5 py-1.5`, `px-3 py-2`, `px-2 py-1 rounded` (bare radius), `min-h-11`, `h-11 w-28`, `text-base sm:text-sm`, `rounded-2xl`, `shadow-2xl`, plain `<button>` tabs. (M)
- **RC4 Developer vocabulary leaks.** `hsl(var(--primary))`, `Auto-fixed`, `WCAG 1.0 : 1`, `Bare number auto-converts to px`, `Allowed: 12 / 14 / 16 / 18 / 22px`, raw `fontFamily` text input, weight typed as a number. (M)
- **RC5 Surfaces hidden behind state.** Template flow exists but is a mode of the right pane that closes when a section is selected (`if (selection) setLookOpen(false)`), shows 15 static 360x450 thumbnails in a 320 px box, and previews only after four steps. (M)
- **RC6 Chrome built from glyphs and browser defaults.** `⋮⋮ ↑ ↓ ◌ ◉ ⧉ ↶ ↷ +` as icons; native `<details>` markers; native `<select>` for page, product, colour token, font, weight; default focus/selection/scrollbar. (M)

## Premium bar (what "premium" means here, and how it is verified)

1. **Chrome typography.** One family (admin sans), scale from `TYPE`; panel titles 14 px semibold, field labels 13 px medium, hints 12 px muted-ink; Arabic leading >= 1.6, no negative tracking, no uppercase kickers; tabular numerals for sizes/ratios. Verified by reading computed styles in the rendered check.
2. **Spacing rhythm.** 4 px base: field gap 12, group gap 24, pane padding 16; more space above a group heading than below. Zero ad hoc `px-2.5/py-1.5`.
3. **States for every control**: default, hover, focus-visible (gold ring), active, selected, disabled, loading, error, edited. Selected/active = Ebda gold tint + marker, never orange, never colour alone.
4. **Inline live previews before applying**: font picker rows in their face; size/weight/spacing steps change a live specimen; colour popover shows a heading/body/button preview with the real verdict; template cards show the store's own content; AI changes show before/after.
5. **Motion** (state only, 150-250 ms, `cubic-bezier(0.2,0,0,1)` from `MOTION`): disclosure height/chevron, popover rise, drag lift + settle, toast, tab underline slide (mirrored in RTL). One authored moment: the template apply cross-fade of the canvas. Everything off under `prefers-reduced-motion`.
6. **Micro-interactions**: hover on a canvas section highlights its tree row and vice versa (exists, keep); hover a colour chip previews it on the canvas for 1 s; copy-hex button; undo toast on every destructive/bulk action; saved check animates once.
7. **Metal, not orange**: night chrome with Ebda gold #B08D57 for primary actions/selection, brass/silver for secondary accents (Ruling METAL-1); merchant colours are never validated.
