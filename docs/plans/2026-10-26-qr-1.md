# QR-1 Merchant QR Codes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox syntax.

**Goal:** Merchants get scannable, branded, tracked QR codes for their store, any product or category, and their WhatsApp chat, with an admin settings page (live preview, scan self-check, PNG/SVG/PDF downloads).

**Architecture:** Codes are generated and styled entirely client-side in admin (no server rendering, nothing to port to Cloudflare). A QR encodes a stateless short link on the storefront host: `/q/s`, `/q/p/<slug>`, `/q/c/<slug>`, `/q/w`. A web route handler asks the API to resolve + count the scan, then 302s to the target with `utm_source=qr&utm_medium=print&utm_campaign=<kind>`. Design settings live in the existing `Store.settings.qr` JSON (no column). One new aggregate counter table `qr_scan_daily` (mirror of `product_daily_views`, no PII).

**Tech Stack:** `qr@0.7.2` (paulmillr; MIT OR Apache-2.0; published 2026-09-28; zero deps; encode + decode in one package) replaces the 2024-08 `qrcode@1.5.4` for all NEW code (older than 12 months, so rejected; the MFA use in apps/api stays untouched). Zod, Express, Prisma, Next.

**Spec:** Ruling QR-1 in `Ebda-AI-Studio/business/ebda/EBDA-PROGRAM-REGISTER.md`.

## Global Constraints

- No orange in Ebda defaults (merchants may choose any colour; default palette = night + Ebda gold `#B08D57` on white).
- Tenant resolution throws/404 on unknown store; never default-to-first.
- Zod at the API edge. Arabic-first, RTL-correct admin; copy in ar + en.
- QR scan safety: foreground must be darker than background and contrast >= 4.5:1 (AA); ECC `high` forced when a logo is shown; logo <= 18% of code area.
- Docs/help updated in the same PR.

## Cloudflare-move compatibility (PRs #205 / #229)

- Those PRs add `packages/cf-schema` which classifies every Prisma model in `model-split.json` (platform vs store) and generates D1/StoreDO SQL. `qr_scan_daily` is store-scoped (same class as `product_daily_views`, `search_query_daily`). **Migration note:** whichever of #205/#229/this PR merges second must add `QrScanDaily` to the store side of `model-split.json` and regenerate. Design settings need nothing (inside `Store.settings`). Scan write uses `withStore` + a single upsert (no pg-only SQL beyond `ON CONFLICT`, which SQLite also supports).

## Review Focus

- Unknown/garbage slug or foreign-store slug in `/q/...` -> 404, no counter row (bloat/oracle).
- Merchant picks light-on-dark or low-contrast colours -> blocked with a reason, never silently saved.
- Logo that is huge/non-square/transparent -> still decodes (self-check) or logo is refused.
- Arabic CTA with long text -> truncated by the frame layout, not overflowing.
- Product slug renamed after printing -> scan still lands (slug-redirect fallback).
