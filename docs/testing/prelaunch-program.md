# Pre-launch test program

Everything Ebda Store can test without the company papers, automated. Launch waits for the papers (payment-provider live
verification, Meta business verification, ETA e-invoice), so those journeys are out of scope here.

## The QA store

The Amelia Aurum store (`ameliaaurum`, custom domain `ameliaaurum.com`) is the production QA store (Ruling DOMAIN-TEST-2).
It stays noindex until its real catalogue exists. Every test order on it is cancelled after it is checked. Its products are
fake (names, prices, photos) and are replaced before the brand sells.

## Automated pieces

| Piece                                      | What                                                                                                                                                                                                                                                                                                                                      | How to run                                                                                                                                                                              |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tests/prelaunch/shopper-journey.spec.ts`  | Home, search, PDP, add to cart, cart, checkout form; Arabic + English; 390 px + 1440 px; no sideways scroll; no console errors. `PRELAUNCH_WRITE=1` also places one COD order, checks it in the merchant API (what admin + the orders app read), moves it confirmed -> processing -> shipped, checks the shopper's view, then cancels it. | `PRELAUNCH_STORE_SLUG=<slug> npx playwright test -c playwright.prelaunch.config.ts shopper-journey` (+ `PRELAUNCH_WRITE=1 PRELAUNCH_EMAIL=… PRELAUNCH_PASSWORD=…` on the QA store only) |
| `tests/prelaunch/signup.manual.spec.ts`    | Merchant sign-up at store.ebda.app up to "check your email" (the code is read from the inbox by a person).                                                                                                                                                                                                                                | `PRELAUNCH_SIGNUP_EMAIL=… PRELAUNCH_SIGNUP_PHONE=… PRELAUNCH_SIGNUP_PASSWORD=… npx playwright test -c playwright.prelaunch.config.ts signup.manual --project=desktop`                   |
| `.github/workflows/prod-smoke-journey.yml` | The read-only journey every 3 hours on GitHub-hosted runners. Writes `prod-smoke-result.json` (`{ ok, runs: [...] }`) and exits non-zero on any failure, for the alert path. Never orders.                                                                                                                                                | Actions > prod-smoke-journey (input `stores`)                                                                                                                                           |
| `scripts/qa/prelaunch-summary.mjs`         | Folds a Playwright JSON report into the small result; an empty run is a failure.                                                                                                                                                                                                                                                          | `node scripts/qa/prelaunch-summary.mjs <report.json> [out.json]`                                                                                                                        |
| `scripts/qa/prelaunch-provision.mjs`       | Idempotent: shipping zone, COD + InstaPay, go-live for the QA merchant's store (`PRELAUNCH_SEED_CATALOGUE=1` adds 8 demo products; the Amelia catalogue is entered through the admin UI instead).                                                                                                                                         | `PRELAUNCH_EMAIL=… PRELAUNCH_PASSWORD=… PRELAUNCH_STORE_SLUG=… node scripts/qa/prelaunch-provision.mjs`                                                                                 |
| `load-test` workflow, `pages` scenario     | Storefront page loads at a stated rate (docs/load-testing.md).                                                                                                                                                                                                                                                                            | Actions > load-test, scenario `pages`                                                                                                                                                   |

Credentials come from the environment only (the QA passwords live in the operator's keychain), never from the repo.
The journey inventory (automated / needs a phone / blocked on papers) and the findings live in the operator's handoff, not here.
