# B2B wholesale pricing API

Plan: `docs/plans/2026-10-21-b2b-wholesale.md`. Rulings: `docs/RULINGS.md` (B2B-\*). Feature key `b2b.wholesale` (Business plan, comped). All money is integer piastres. A write that turns a benefit on needs the entitlement; reads, deletes and turning things off never do (Ruling B2B-1b).

## Storefront (public base `/api/v1/public`)

| Method and path                                        | Auth                             | Notes                                                                                                                                                                                                                                                        |
| ------------------------------------------------------ | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /products`, `/products/:slug`                     | none                             | Always the anonymous view: retail price, public tiers (`priceTiers`), `moq`. Wholesale-only products are absent (404 on detail). Cacheable.                                                                                                                  |
| `POST /pricing/resolve`                                | session (optional)               | Body `{ items: [{ productId, variantId?, qty }] }`, strict, max 50. Returns the buyer's `unitPrice`, `listPrice`, `priceSource`, `priceTierMinQty`, `belowMoq`, `moqRequired`. `private, no-store`. A price in the body is a 400.                            |
| `POST /orders/quote`                                   | session (optional)               | The exact total the order would charge (the create function in dry-run). Send it back as `expectedTotal`; a change returns 409 `PRICE_CHANGED`. The storefront always sends it (QA-COUPON-1), even when the quote request failed (then the total on screen). |
| `POST /wholesale/apply`                                | customer session, verified email | Body `{ businessName, phone, commercialRegNo?, notes?, consent: true }`, strict. 409 `ALREADY_PENDING` / `ALREADY_APPROVED`, 429 `REAPPLY_COOLDOWN` (30 days after a rejection or a revoke).                                                                 |
| `GET /wholesale/status`                                | customer session                 | Own latest application and `isWholesale`. `private, no-store`.                                                                                                                                                                                               |
| `GET /wholesale/products`, `/wholesale/products/:slug` | approved wholesale session       | The wholesale-only catalogue. 404 for everyone else (no existence oracle). `private, no-store`.                                                                                                                                                              |

Cart and order endpoints take the buyer from the session only; a typed phone or email never selects a group (Ruling B2B-2c).

`POST /:storeId/coupons/validate` keeps `orderTotal` / `cartItems` as the base-priced basis (tier / group lines excluded, Ruling B2B-5) and also takes optional `looseOrderTotal` / `looseCartItems`, the whole loose cart: a `free_shipping` code's minimum, quantity and scope are judged on those, as at order creation (Ruling B2B-M2). A client that omits them keeps the base-basis judgement.

Atomic: the loser of a race gets 409 `NOT_PENDING`.                                                                                                                                                                    |

### Returns (tier-aware partial refunds, Rulings B2B-14, B2B-15, B2B-17, B2B-18, B2B-20)

`GET /returns/admin/:id/refund-preview[?overrides=<json>]` adds `lines[]` (`standardRefund`, `adjustment`, `adjustedRefund`, `shortfall`, `keptQty`, `tierMinQty`, `keptUnitMinor`, `reason`) and `tierAdjustmentTotal`. The adjustment is computed per PRODUCT across every loose line of it (`keptQty` is the product's kept quantity) and spread over the return's items of that product; `shortfall` is reported once per product, on its first item, and is carried forward: `carriedIn` (also on the first item) is the shortfall earlier returns of the product carried, collected first by this one (Ruling B2B-20); `reason` follows the applied adjustment. The shopper's `refundAmount` estimate at creation uses the same computation. `POST /returns/admin/:id/complete` accepts `refundOverrides: { [returnItemId]: { amountMinor, reason } }` (needs `orders:refund`; 400 `OVERRIDE_OUT_OF_RANGE`, `OVERRIDE_UNKNOWN_ITEM`, `OVERRIDE_NOT_APPLICABLE`). An override on a product's items waives its carry; the response's `tierCarryWaived` is the waived amount and is written to the `return.completed` audit log.

## Realtime and jobs

Socket notification `wholesale.application.received` (`data.kind` is `received` or `nudge`) to the store room; an admin push and an owner email go with it. Inngest cron `wholesale-pending-nudge` runs daily at 07:00 UTC.
