## Tiers

1. **Source-delivered** — the code exists and reads correctly, but has not been run this cycle. Weakest tier; a stale doc claiming "done" at this tier is exactly the failure mode this document exists to stop.
2. **Local/historical proof** — passed a local test, local workerd run, or a prior session's live check, but not re-verified fresh in this pass. Can go stale; re-check before relying on it for a decision.
3. **Fresh runtime proof** — verified THIS session (or the most recent autonomous run) against a real running system: local dev stack, a worktree's CI, or a direct query/curl.
4. **Production proof** — verified against the live production system (`api.ebda.app`, `store.ebda.app`, `ebda.app`, `orders.ebda.app`, or prod Neon) this session or the most recent autonomous run.

A capability's overall tier is its WEAKEST evidenced sub-claim, not its strongest. "Tier 4 overall, with a tier-1 sub-claim" means the sub-claim is the thing to distrust.
