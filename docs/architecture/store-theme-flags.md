# Per-store visual configuration — flags, owners, invariants

Moved verbatim from `CLAUDE.md` (2026-07-11). Canonical reference for StoreTheme flags, canonical editors after the Page-Builder consolidation, and the product-card customization system. Update in the SAME session as any change to these systems (documentation-parity rule).

**Page Builder + Smart Palette are the CANONICAL design system** for all color, font, hero, and per-section layout controls as of 2026-06-09 (PRs #86–#90). The Branding tab's manual color pickers (`ColorPalettePicker`), global font-family picker (`TypographyPicker`), and `backgroundPreset` selector are **retired inputs** — "edit in Page Builder" pointers or read-only swatches. Any code or doc referencing those as the primary color/font editors is stale.

## Product-card CTA + OOS-label + name-case (2026-06-24)

`ProductCardDefaults` (store layout JSON, Page Builder → "Product cards (everywhere)") carries an opt-in CTA/label system applied across ALL 8 render paths (7 product-render-paths + `ProductListItem`): `ctaShape` (rounded/pill/square/soft), `ctaSize` (sm/md/lg), `ctaColor`/`ctaTextColor`, `ctaLabel`+`ctaLabelText{En,Ar}`; `oosLabel`+`oosLabelText{En,Ar}`, `oosLabelShape`, `oosLabelPlacement` (top/bottom × start/end), `oosLabelColor`/`oosLabelTextColor`, `oosDimColor`; `productNameCase` (normal/uppercase). All optional + neutral-default EXCEPT `productNameCase` defaulting to **normal** (intentionally removed forced ALL-CAPS on elegant/minimal/bold).

Invariants:

- Class helpers live in `apps/web/src/templates/shared/card-size.ts` (`ctaShapeClass`/`ctaSizeClass`/`labelShapeClass`/`oosPlacementClass`); Zod-validated in `store-layout.routes.ts` `productCardDefaults` (silent-strip trap — every key must be listed).
- Cards read via `useStore().layout?.productCardDefaults` with prop fallback (the #380 "T.ProductGrid threads zero props" lesson).
- **`ctaShape`/`ctaSize` MUST merge via `cn()` (tailwind-merge), NOT string concat** — base buttons hardcode `rounded-2xl`/`rounded-xl` + padding/`min-h`, and Tailwind's fixed source order makes those win over later-in-string classes; plain concat silently dropped every shape except `pill`. Fixed across all 8 paths.
- **The PDP carries the OOS system too** — `ProductDetailClient.tsx` mounts `OosImageDim` + `OutOfStockRibbon` on the main image from the same `productCardDefaults`, honoring backorder (`orderable = !outOfStock || canBackorder`).
- **Backorder-aware CTA**: cards compute `orderable = product.inStock !== false || product.acceptsBackorder === true`; CTA pressable + OOS label hidden when orderable. `inStock` still used separately for NEW-badge suppression / BrandPill.

## PLP / PDP context (2026-06-24)

- `ProductsClient.tsx` derives the active category into breadcrumb + H1 + contextual subtitle. PDP breadcrumb: `home / products / <category> / <product>`, category segment links to `/products?category=<slug>` (locale-aware, only with a primary category).
- **PLP default page size is 96 (2026-07-10, was 12).** `apps/web/src/app/products/page.tsx` requests `limit: '96'` by default; `PER_PAGE_OPTIONS` is `[12, 24, 48, 96]` (falls back to 96 on an invalid stored preference). A category browse shows the whole category by default.
- **PLP variant-option facet filters**: FWB's "Size" is a `ProductOption`→`ProductOptionValue` (OSOSS variant import), NOT a generic attribute. `product.service.ts` `listPublic` returns `facets` (snapshotted BEFORE the option filter so selecting a value doesn't hide siblings) and accepts an option filter (multi-value = OR within option, multi-option = AND). URL: `?opt_<Name>=<v1>,<v2>` (capped 10×20). `ProductsFilterSidebar.tsx` renders one checkbox group per facet (bilingual, themed, mobile-sheet aware); selections count toward the active-filter badge.

## AI description language balancer (2026-06-24)

Per product: detect the richer of `description`/`descriptionAr` (`description-richness.ts` → `richerSide`), translate into the thinner language. **Revert** backed by `Product.aiBalanceBackup Json?` (snapshots once on first balance; revert restores + clears). Engine: `balanceProductDescription`/`revertProductBalance` in `ai-autofill.service.ts`. Surfaces: bulk (AI-tools page, `BulkAiJobKind.description_balance`, Inngest, 2.5s throttle), per-product (`BalanceDescriptionButton`), autopilot (3-day sweep calls with `{force:false}`).

## Layout / sizing invariants

- **SectionDivider ↔ backgroundPreset mutex**: when `backgroundPreset !== 'none'`, `SectionDivider` returns null (color alternation IS the divider).
- **Hairline accents**: `SectionHeading` flanks `kicker` + `subtitle` with `bg-foreground/30` hairlines automatically when set.
- **Card-size:font-size locked table**: sizes come from `getProductCardTextSizes(cardSize)` in `@force/shared`; pack-styles carry flavor only (weight/tracking/color/family).
- **Per-template branded baseline (Brand Engine Phase 2, 2026-06-05)**: empty `layoutSettings` inherits `resolveLayoutSettings(saved, store.template)` from `packages/shared/src/types/template-baselines.ts` (`BASE_BRANDED_LAYOUT` + `TEMPLATE_IDENTITIES` → `TEMPLATE_LAYOUT_BASELINES`). Colors `token:*` only. Saved values win; wadyaljuz unchanged (immutability gate: `verify-baseline-nodrift.mjs`).
- **Logo bounding box** (2026-06-17): `h-14 max-h-14 max-w-[150px]` mobile / `md:h-20 md:max-h-20 md:max-w-[210px]` desktop, `w-auto object-contain`; row container `h-32 / md:h-44` with `overflow-hidden` in modern+bold headers. The "still huge" cause was the missing WIDTH cap. Platform-wide across all 5 theme headers.
- **Mobile chrome**: `BottomTabBar` mounts in `ShopChrome`, hidden on PDP/checkout/auth. Header cart icon + mobile search hidden `hidden md:inline-flex` in all 5 theme headers (no duplication with tab bar).
- **Bottom-reserve invariant**: `<body>` carries `pb-32 md:pb-0` in root `layout.tsx`; ShopChrome carries NO additional pb. Cookie consent lifts via `bottom-[calc(56px+env(safe-area-inset-bottom))]`.
- **Cart icon canonical SVG path** (commit `e6ae439`): the shopping-cart-on-wheels glyph `M3 3h2l.4 2M7 13h10l4-8H5.4M7 13L5.4 5M7 13l-2.293 2.293c-.63.63-.184 1.707.707 1.707H17m0 0a2 2 0 100 4 2 2 0 000-4zm-8 2a2 2 0 11-4 0 2 2 0 014 0z` — used across 11 surfaces. Do NOT use the old shopping-bag path.
- **data-zone wiring rule**: any storefront text element exposed in Admin → Typography MUST carry matching `data-zone="<zoneKey>"` and use Tailwind size classes (never `text-[Xpx]`) — otherwise merchant overrides silently no-op. Audit recipe: `feedback-fwb-data-zone-hardcoded-size-trap` (scoped memory).
